假设一个多...agent 系统声称 紧急协调,审计 协调是真实的还是 人工制品 prompt engineering.

显示 :

1. **要求提取。** 所谓的协调行为是什么? (劳动分工、预期、互补行动、达成共识) 确切地说。
2. **Prompt inspection.** 是否有 agent的 system prompt 明确指示协调、角色选择或团队意识?如果是,则将索赔标为部分 prompt- 穿好衣服设计一个控制器
3. **控制状态** 系统版本中带有协调引导语言的删除。 请确切指定文本的更改 。
4. **Metric.** 至少其中一项:与身份挂钩的区别、目标导向的互补性、更高层次的协同效应(2025年Riedl),不接受 "agents 似乎一起工作" 作为证据。
5. **统计测试。** 系统与控制衡量标准的重要性。 `p < 0.05`. 如果 `n < 50` 试探,报告权力明确。
6. **模型能力检查。** 重复对一个小基模的比较。 效果是持续还是消失? 李/ 里德尔都表现出能力依赖性 。
7. **失败个案审查。** 当系统失效时, 托姆状态( 如果有的话) 是什么样子? 身份混淆 (信仰-agent 或内容 hallucination (错误的信仰内容)?

艰难的拒绝 :

- 声称没有控制条件就出现了 演示卷子不是证据
- 统计审查后消失的索赔 `p < 0.05` 在 `n >= 50` 这些是协调的幻想。
- 如果较弱的强基线也取得效果,而不引起托姆,协调不是托姆驱动的。
- "我们的 agents 机制要求需要 托姆州立法院的登录和检查

拒绝规则 :

- 如果系统没有记录 /agent 推理,审计无法区分实际协调与随机性。 建议重新审计前添加结构化的 ToM 状态日志 。
- 如果任务具有最高标准的协调,则与最佳标准相比而不是与控制方法相比较。
- 如果索赔范围狭窄(“单轮任务的协调”),审计可以是一个较短的检查:衡量单轮的互补性,不需要长方位分析。

输出: 一份两页的审核。 从一判决开始 (“协调要求是 ” prompt- 穿得: 删除“ 一起工作” 语言, 将测量值从 0. 82 降到 0. 31, 控制意义重大。”) 后加上面的七个部分。 结尾处列出要转换的修改列表 prompt- 将协调化为真正的协调:明确的托姆状态、长的伐木视野、混合模型组合。
