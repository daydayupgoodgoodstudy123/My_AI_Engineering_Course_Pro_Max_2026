# 16/13 分关面试题：BlackScope

这是一个写好一半的本地 shared-provenance desk。它保留原文、摘要与 correction history，经独立 findings 形成消费决策，再组合 derived support。英文题面在 [README.md](README.md)，完整合同在测试、断言消息和 docstring 中。

## 开始

先把题包复制到自己的练习目录，读 README 与五个测试的 docstring，再运行：

```bash
python3 -m pip install pytest
python3 -m pytest
```

默认五个 skipped 表示五关依次锁住。先解除 Part 1 的 skip，运行 `python3 -m pytest -x`；这一关通过后再解除下一关。

## 规则与时间分配

- 总时长 60 分钟：开场 2 分钟，五关参考用时 12、11、15、10、10 分钟。时间与难度尚未真人校准。
- 只修改 `blackscope/` 的候选领域实现；测试只解除当前 skip，保留全部断言和完整正确的 GIVEN。可以另外写自己的测试。
- 可以查 Python 标准库官方文档。计时期间关闭 `solution/` 与 `INTERVIEWER.md`，边做边解释当前证据和下一步判断。
- 需求不清楚时向主持人澄清；独练时先记下问题，再只查手册中对应的英文标准答案。
- 记录每关解锁、首次通过、运行次数与 H1/H2/H3，区分限时结果和之后补完。所有 sources/findings 是有限本地 fixture，不调用真实模型、网络或来源网站。

## 五关职责

| 关 | 候选职责 | 完整正确 GIVEN |
|---|---|---|
| 1 修 | decimal/unit 首句、append-only correction、独立 finding 发布、首边界即停 | provenance append、immutable read snapshots、typed channel、topic callback snapshots、SummaryDesk 与独立 expected |
| 2 存 | 全部 ordered versions 的 ID/writer/topic/content/own metadata、重开 | LedgerDriver channel/capability 路由、JSONL append/flush/reopen、exact metadata/finding codec |
| 3 算 | active lineage、exact entry/source finding join、role/topic consumption | P1 正确产物与 P2 完整重开；不提供这三项 solver |
| 4 流 | entry/correction 自身完整 provenance payload | authorized channel classifier/router、finding payload、RS+JSON+LF writer、async driver |
| 5 构 | recursive certificate、required/covered 合成、distinct external SourceKey 集合 | UID/occurrence expansion、missing/cycle paths、P3 leaf lookup、complete predicate |

P1 first_sentence 的有限规则是 `. ! ?` 后紧跟空白才构成句界，保留首句标点；小数点后直接跟数字不构成句界，没有句界返回原文。它不是通用 NLP 或缩写识别。correction 追加新 ID 与 supersedes，保留旧 content/time/prompt/source；finding 通过独立 VerificationChannel 发布，不写成普通 fact。只有这里要求候选修 finding 发布边界，后续日志与流式 channel 路由已完整 GIVEN。

P2 encode_entries/decode_entries 建模全部原始和 correction versions，保留原 ID、声明 append order、writer/topic/content 及每个版本自己的 timestamp/prompt/source/supersedes。相同文本的不同 immutable records 也分别保留，不能只存 active view、合并版本或重新编号。完整 LedgerDriver 已管理两条日志、typed read capabilities、append-only prefix、framing/flush/reopen；精确 ns 时间、完整哈希、SourceKey 与 supersedes=0/None 的 codec 也已 GIVEN。

P3 有三个独立 TODO：active_provenance_view、attach_version_findings、consumable_entries。同 topic correction 属于同 lineage，跨 topic link 开始自己的 lineage；同 topic 的独立 roots 仍分别保留，active 输出按 append order；较晚的同 topic 分叉 correction 仍更新整条 lineage 的 latest。finding 必须同时匹配 immutable entry ID 与 SourceKey(uri,version)；exact DISPUTE 优先于 exact MATCH，没有 exact finding 是 UNVERIFIED。只有 role=analyst 可消费声明 topics 内 active VERIFIED entries；空 topics 不授予任何消费权限。缺 evidence 不表示 claim false，也不因 writer 标签获得权限。实际链路使用 P1 SummaryDesk 记录与 P2 reopen 的独立 audit evidence。

P4 entry_payload 只投影当前 entry/correction 自己的 ID、writer、topic、完整 content、timestamp_ns、prompt_hash、source URI/version 和 supersedes。kind 与独立 finding destination 由完整 driver 授权分类，finding payload 也给定；候选不再选择通道、不重写 UTF-8/cadence/close。普通 content 即使含 verdict 字样，仍原样保留。

P5 从完整 expanded occurrences 递归构造每层 SupportCertificate。叶子支持直接复用 P3 admitted decisions；derived 层分别 union required、covered、external sources 和 obstacles，并保留 ordered children。required 不能被 covered 替代；wrapper announced_source 只是标签，不能制造新 external evidence。distinct key 是 SourceKey(uri,version)，同 URI 的不同 version 仍是不同 key；两个 wrappers 指向同 snapshot 只贡献一个 key，并不证明现实来源独立性。missing/cycle 标记、leaf lookup 与 complete predicate 已 GIVEN；证书不完整不等于 claim false，候选负责在已展开结构上组合证据。

## 性能与验证边界

P1 fixture 是 32 篇合成本地 source articles，每篇保留首句与 14,000 条实际进入服务的 declared observation rows。正文参与原始 source 审计，并完整保留在 retrieval entries 中；摘要只保留首句，另有完整 percentage receipts。fixture/独立 expected 在 timer 外；完整 `SummaryDesk.observe_many` 和整个 `SummaryReport` equality 在 timer 内，覆盖全部原文、source versions、prompt provenance、IDs、summary sentences 与 receipts，之后才取 elapsed。

P1 当前限值 0.02 秒。固定完整组慢版三次为 0.219885、0.224771、0.238220 秒，参考版为 0.0001577、0.0001976、0.0002087 秒；两侧余量分别为 10.99425 和 95.80843。32 篇合成本地 articles 各保留 14,000 条实际进入服务的 observation rows，完整输出为 64 条 retrieval/summary entries 与 32 条 receipts；fixture 与独立 expected 在 timer 外，整个 SummaryDesk.observe_many 及完整 SummaryReport equality 在内。六份 NEW 完整副本只把 timingassert 换成实际 elapsed 输出，慢版另执行 decimal-safe 全文 split；全部业务 guards 与全五关功能通过，不能说慢版通过原限值。原样 reference 五关另行通过。TEMP、独立行为和正式检查分别有自己的验收记录，不能由测量版推定；本机余量不是任意运行环境的墙钟上界或生产 SLA。

当前静态题包有 13 个候选模块、13 个参考模块、42 Python 文件、5 tests、43 assert、0 处 pytest.raises、5 skip 锁和 26 项登记错修。read-only snapshots、callback reentrancy、exact codec、channel routing、occurrence markers 等是完整依赖与集成护栏，不能全部算作独立主要算法。Python 3.10+ 为目标环境，没有实际在该版本运行的声明；60 分钟及各关用时尚未真人校准。

## 常用命令

在自己的练习副本运行：

```bash
python3 -m pytest -x
python3 -m pytest -k active_exact -x
python3 -m pytest --all-parts -x
python3 -m pytest --solution --all-parts
```

`--all-parts` 与 `--solution` 是本目录 conftest.py 的练习开关，真实面试没有。`--solution` 只在计时结束后检查参考实现，不计入候选成绩。
