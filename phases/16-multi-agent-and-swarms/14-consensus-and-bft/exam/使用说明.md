# 16/14 分关面试题：RobustCenter

这是一个写好一半的本地 scalar-confidence desk：保留 Proposal 与实际 Probe，做离散簇检查、位置 weighted median、radius support 和 Core/Edge following 审计。英文题面在 [README.md](README.md)，完整合同在测试、断言消息和 docstring 中。

## 开始

先把题包复制到自己的练习目录，读 README 和五个测试的 docstring，再运行：

```bash
python3 -m pip install pytest
python3 -m pytest
```

默认五个 skipped 表示五关依次锁住。先解除 Part 1 的 skip，运行 `python3 -m pytest -x`；当前关通过后再解除下一关。

## 规则与时间分配

- 总时长 60 分钟：开场 2 分钟，五关参考用时 12、11、15、10、10 分钟。时间与难度尚未真人校准。
- 只修改 `robustcenter/` 的候选领域实现；测试只解除当前 skip，保留所有断言与完整正确的 GIVEN。可以另外写自己的测试。
- 可以查 Python 标准库官方文档。计时期间关闭 `solution/` 和 `INTERVIEWER.md`，边做边解释当前证据与下一步判断。
- 需求不清楚时向主持人澄清；独练时先记下问题，再只查手册中对应的英文标准答案。
- 记录每关解锁、首次通过、运行次数与 H1/H2/H3，区分限时结果和计时后补完。所有 ballots/probes/truth labels 都是声明的本地 fixture，不调用真实模型或网络。

## 五关职责

| 关 | 候选职责 | 完整正确 GIVEN |
|---|---|---|
| 1 修 | signed numeric key、ABSTAIN 排除、confidence-mass threshold、exact D 提速 | lexical intake、cluster-equivalence consumer、legacy confidence scorer、完整 ConfidenceDesk/fixture |
| 2 存 | 每 run 完整 snapshot 的 own Proposal/Probe 字段、ordinal 与重开 | schema、原子 run replacement、SQL 声明序、exact Fraction codec 与 raw text storage |
| 3 算 | weighted median interval、lower/upper/midpoint、inclusive-radius support/minority | comparable-unit intake、exact scalar arithmetic、P1 positions 投影、独立 truth comparison |
| 4 流 | 七个 own proposal 字段并组合给定 probe payload | typed observation/probe binding、numeric/Fraction primitives、probe projection、length frame/async driver |
| 5 构 | nested CoreAudit/EdgeAudit、own declared epoch/value、edge parent/epoch/value reports | original core admission、UID/reference catalog、finite-tree validation、真实 P3 sealed decisions |

P1 数值 key 保留正负号与 percent/scalar 单位。ABSTAIN 保留完整 audit 和 probe metadata，但不进 answer clusters 或 answer mass 分母；全零 eligible mass 不接受。threshold 使用实际 probe confidence 质量，等于阈值时接受。D=Σ(i<j)|c_i−c_j| 是本地 Inspection 字段，包含所有声明 probe confidences（含 abstention/zero）与 multiplicity；它不求 answer-position center，也不是 source 原公式。

P2 save(run,ballots) 用提供的完整 ordered snapshot 替换该 run，load 按 ordinal 重开。每个 proposal UID 与它的一个原始 Probe 都保留；同 agent 的不同 UIDs 仍是不同记录，不按 agent 去重；zero-probe 记录也保留，probe_uid 使用实际 evaluator 记录，不能由 proposal UID 推造。不推断 retry lineage，不保存未提供的旧 snapshot 或多 probe 历史。self-confidence 与实际 Probe.confidence/evaluator/assessment 分开存，不能替换为自报值。schema、事务、排序与精确 codec 已完整 GIVEN。

P3 有三个独立 TODO：weighted_median_interval、choose_interval_center、audit_center_support。按 positive probe mass 求真正一维 weighted-median 的完整最小化区间；zero mass 即使位于区间内部也不决定端点，全零 total 明确拒绝。exact half mass 时可有一段 interval，再按请求选择 lower、upper 或精确 midpoint。radius 内质量与 threshold 都含边界，minority 保留原声明序的 positive-mass proposal UIDs。独立 truth comparison 已完整 GIVEN，缺 label 为 None，agreement accepted 不证明 truth。

P4 候选七字段为 kind、proposal_uid、agent、原 answer、signed position、unit、self_confidence。使用完整 numeric_fields/fraction_pair，并组合完整 probe_payload；分类、原 probe binding、ABSTAIN view、数值原语、4-byte length+UTF-8 JSON 与 async close 都 GIVEN。候选不重做 calibration、framing 或 cadence。

P5 每个 CoreGroup 从自己的 SealedCore 取 authoritative epoch/CenterAudit。core 声明与 own edges 分别对照 sealed：core epoch/value 不一致形成 core finding；edge 检查当前所属 core UID、sealed epoch/value，并调用完整 reference helper。一个 edge 匹配 sealed decision 时，不因 CoreGroup declaration 错误而继承其 finding。edge-before-core 只表示 sealed decision.accepted=False，不表示必须没有任何 core finding。children 各用自己的 sealed result，保留 ordered nested reports；edges 不增加 support mass 或 truth verdict。

## 性能与验证边界

P1 fixture 是 2,400 个合成本地 ballots，probe confidence 按声明模式取 0/1，所有原 Proposal/Probe、canonical keys、support/abstentions、legacy scores、exact D 与 dispersion_alert 都真实进入完整 Inspection。fixture/独立 expected 在 timer 外；完整 `ConfidenceDesk.inspect` 和整个 `Inspection` equality 在 timer 内，之后才读 elapsed。

P1 当前限值为 0.15 秒。固定完整组慢版三次为 2.089669、2.736338、2.203572 秒，参考版为 0.014413、0.015047、0.013903 秒；两侧余量分别为 13.93112 和 9.96901。2,400 个合成本地 Ballots 的完整 Proposal/Probe、canonical keys、support/abstentions、source-style legacy scores、exact D 与 dispersion_alert 全部保留，D 的独立 closed-form expected 为 ones×zeros。fixture 与独立 expected 在 timer 外，整个 ConfidenceDesk.inspect 与完整 Inspection equality 在 timer 内，之后才读 elapsed；不能删 zero/abstention、只求 extreme gap、裁 records 或预填 report。六份 NEW 完整测量副本只把 timingassert 换成实际 elapsed 输出，慢版另枚举所有真实 unordered confidence pairs；全部业务 guards 和全五关功能通过，不能说慢版通过原限值。原样 reference 五关另行通过。TEMP、独立行为与正式检查有各自验收记录，不能由测量版推定；本机测得余量受运行环境影响，不构成通用墙钟上界或生产 SLA。

当前静态题包有 14 candidate modules、14 reference modules、45 Python 文件、5 tests、37 assert、1 处 pytest.raises、5 skip 锁和 26 项登记错修。typed intake、exact codecs、truth comparison、probe projection、reference binding 等是完整依赖与集成护栏，不全部构成独立候选算法。Python 3.10+ 为目标环境，没有实际在该版本运行的声明；60 分钟及各关时间尚未真人校准。

## 常用命令

在自己的练习副本运行：

```bash
python3 -m pytest -x
python3 -m pytest -k weighted_median -x
python3 -m pytest --all-parts -x
python3 -m pytest --solution --all-parts
```

`--all-parts` 与 `--solution` 是本目录 conftest.py 的练习开关，真实面试没有。`--solution` 只在计时结束后检查参考实现，不计入候选成绩。
