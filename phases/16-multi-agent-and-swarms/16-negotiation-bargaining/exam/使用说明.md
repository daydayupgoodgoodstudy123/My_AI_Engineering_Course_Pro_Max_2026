# 16/16 分关面试题：BargainKit

一个写好一半的本地议价服务，五个测试用 `@pytest.mark.skip("Part N")` 锁住，一次解锁一关。英文题面在 [README.md](README.md)，具体合同在 typed records、函数 docstring 和测试里。

本题从“数字机制决定报价，叙述只负责展示”出发：清算已给定的报价，保存双方续接状态，实现让步和有界交替机制，输出公开事件，再审计嵌套多议题 proposal。exact Decimal tick、own-only policy input、dual JSONL、narration revision 和 nested utility tree 都是显式本地适配。来源 demo 本已使用 standing price 和 inclusive reservation 边界；本题这两处是教学回归。来源没有真实 narrator，也不能把固定比例让步称为 Zeuthen 或 Rubinstein 实现。

## 开始

先把整个 `exam/` 另存为自己的作答副本，在该副本目录打开终端：

```bash
python3 -m pip install pytest
python3 -m pytest
```

五个 skipped 表示分关锁仍在。照 README 解除 Part 1 的 skip，先运行并读第一个失败。程序只用标准库和 pytest，不需要 API key、网络、模型或来源脚本。

## 规则与时间

- 总计60分钟：开场2分钟，Part 1–5分别12、11、15、10、10分钟，共58分钟编码。这个安排没有经过真人面试校准，实际用时需记录。
- 只改 `bargainkit/`。测试除解除对应 skip 外保持原样；不要修改完整 Given、fixture、限时断言或期望来绕过失败。可在作答副本另建自己的测试文件。
- 可以查 Python 官方文档。计时期间关闭 `solution/`、`INTERVIEWER.md` 和本题讲解；独立练习先写下澄清问题，再只看手册中对应答案。
- 说明每次修改的输入、输出和依据。P1只处理 supplied quotes；P3的有向 gap、Fraction 让步、tick量化／进展／clamp和交替 runner 仍需自己实现。
- 合法价格为有限非负 Decimal，tick严格为正。策略开局与保留价在声明网格上，concession为exact Fraction或有限Decimal、数值在(0,1]，own opening处于本方可行方向；策略输入只包含本方私有参数和公开报价。
- 使用当前有限 typed 合同。JSONL 是正常进程中的逻辑公私通道，不表示文件权限隔离或双文件崩溃原子提交。嵌套审计是声明条件的可行性检查，不要求优化收益或求均衡。

## 常用命令和练习开关

```bash
python3 -m pytest -x
python3 -m pytest -k standing_clearing -x
python3 -m pytest -k directional_concession -x
python3 -m pytest --all-parts
python3 -m pytest --solution --all-parts
```

`--all-parts` 忽略五个 Part skip；`--solution` 将导入切到参考实现。这两个开关由本目录 `conftest.py` 提供，只在计时结束后用参考模式核对。退出该命令并关闭答案，再去掉 `--solution` 检查自己的代码；参考结果不能计入个人成绩。
