# 16/09 分关面试题：WorkPull

这是一个写好一半的本地 pull-worker 工作台。独立任务在整数逻辑时间到达，空闲 worker 拉取任务，真实本地 payload 转换产生结果，arrival、pull 和 completion 分开记录。英文题面在 [README.md](README.md)，完整合同在测试、断言消息和 docstring 中。

## 开始

在自己的练习副本打开终端，先读 README 和五个测试的 docstring：

```bash
python3 -m pip install pytest
python3 -m pytest
```

默认五个 skipped 表示五关按顺序锁住。先解除 Part 1 的 skip，运行 `python3 -m pytest -x`；这一关通过后再解除下一关。

## 规则与时间分配

- 总时长 60 分钟：开场 2 分钟，五关参考用时为 12、11、15、10、10 分钟。时间和难度尚未经过真人校准。
- 只修改 `workpull/` 的候选领域实现；测试只解除当前 skip，保留全部断言与完整正确的 GIVEN 依赖。可以另外写自己的测试。
- 可以查 Python 标准库官方文档。计时期间关闭 `solution/` 和 `INTERVIEWER.md`，边做边说明当前证据与判断。
- 需求不清楚时先问主持人。独练时先写下问题，再只看手册澄清表中对应的英文答案。
- 记录每关开始、首次通过、运行次数和提示级别；限时完成与计时后补完分开记录。

## 五关职责

| 关 | 候选职责 | 完整正确 GIVEN |
|---|---|---|
| 1 修 | task result identity、future-arrival 终止条件、稳定 event calendar | 完整逻辑事件 driver、payload 转换、结果 reader/card、worker histogram、零 duration 处理 |
| 2 存 | task/worker/event 领域行、观察到的 lifecycle 重放、actual worker | signed64/text/tuple 编解码、WPJ1 追加 framing、读取顺序和文件生命周期 |
| 3 算 | topic/arrival eligibility、pull 时刻 aging、同批 worker 独占 claim | P1 calendar/driver、ready/free view、声明 task sequence、P2 reopen 产物 |
| 4 流 | phase-specific payload、记录时间、实际 worker/result | 完整 JSON UTF8 编码、4-byte length frame、async pull/publication/close |
| 5 构 | 祖先 topic 交集、private/shared pool 边界、actual leaf completions | 完整 full UID resolver、ancestor tests 和一次构建的 subtree catalog |

P1 基础 desk 使用 FIFO，不实现 P3 的 specialist、aging 或 claim policy。结果按 task ID 保存，实际 worker 单独保留；同一个 worker 完成多项任务时不能覆盖别的 task。ready/running 暂时为空仍可能有 future arrivals。calendar 按 `(time_us, sequence)` 稳定取下一事件；Event 本身不可比较，不能让 heap 在平局时比较 Event。worker histogram 和零 duration 的事件处理已经完整给定，不是主要候选缺陷。

P2 输入是声明一次的 typed task/worker 定义和真实 driver lifecycle，保留声明顺序和观察顺序，不按 arrival time 重排 task 定义。声明但未 arrival 是 not-arrived，arrival 后是 ready，pull 后是 running，只有 completion 才是 complete。`pre_assigned` 只是固定分配的提示，重放使用实际观察的 worker 和结果。大整数时间、UTF8 和残缺 frame 拒绝属于给定 codec/framing 的集成护栏；候选不重写字节格式。

P3 是三个独立 TODO：`eligible_ready_tasks`、`effective_priority`、`claim_free_workers`。先按实际 arrival 和每个 worker 的 topic 字符串精确匹配过滤（没有 `*` wildcard），再在实际 pull 时刻计算 `priority + (now - arrival_us) // aging_interval`。free workers 按声明顺序领取，各自取有效分最高的剩余任务；同分按原 task sequence，领取后立即从本批 remaining 中移除。running work 不抢占，duration 不参与优先级，也不做全局最优匹配。正确 desk 已校验 `aging_interval` 是 positive int。

P4 投影真实 trace，不重新调度或执行。arrival 只带 queued priority；pull 保留这条记录的 worker/start/finish，不制造 result；completion 才带自身实际结果和完成时刻。通用 framing、UTF8 byte count 和传输节奏都已完整给定。

P5 的有效 topic 是 worker subscriptions 与每个已声明祖先 restriction 的交集，空交集保持为空。worker 可见本组 pools，以及祖先明确 shared 的 pools；不继承 sibling pools 或 ancestor private pools。完成量来自实际 Completion 的 full worker UID，group 汇总本组及后代 worker 的真实完成数，不把 queued、running 或 unserved 算完成。catalog 已给出身份与 subtree membership，不要求重写 shortname 解析或 shared occurrence 遍历。

## 性能与证据边界

P1 fixture 包含 3,000 个真实本地 Task，每个任务都运行实际 payload 转换并进入完整 trace、completion、count 和 receipt。fixture 与独立 expected `RunReport` 在 timer 外构造；完整 `CompletionDesk.run` 和整个 report 的相等检查在 timer 内，包含全部 inputs、trace、实际结果/worker、counts、cards、unfinished 和 finished time。

性能 workload 为 12×250 个真实任务，批次在逻辑微秒 5000×批序到达，duration=1+i%3，限值为 0.14 秒。本机 Python 3.12.14 的固定三慢三快校准组，慢版业务 timer 为 1.2555–1.2973 秒，快版为 0.01660–0.01749 秒；按整组最小慢值和最大快值计算，双侧余量为 8.9679× / 8.0034×。快版余量接近 8× 门槛，不能视为宽裕余量。精确数值见 [校准报告](/tmp/exam-11-16-work/draft16-09/actual/group03-summary.json)。

六个独立测量副本仅把 elapsed 限值断言换成测量打印，慢版另仅还原真实 calendar 的 min/remove；完整 run、整个 report equality 与其余四关保留，六份均为测量版五关功能通过。这不表示慢版运行过原 0.14 秒限值断言。最慢业务 timer 为 1.2973 秒（小于 3 秒），六份完整五关进程 wall 最大为 1.4465 秒（小于 5 秒）。保留原计时断言的 reference 完整五关另已通过，进程 wall 约 0.2282 秒。

这些是本机环境中的指定路径记录；业务 timer、逻辑微秒和整个 pytest 进程 wall 各不相同。测得余量不是任意系统负载下的通用墙钟上界、生产 SLA 或真实 LLM speedup。60 分钟与关卡用时仍未经过真人校准。

当前静态题包有 45 个 Python 文件、五个测试函数、36 条 assert、2 处 `pytest.raises`、五个 skip 锁和 24 项登记错修。静态数量不是运行结果；上述 reference 与测量版本记录也不计入候选的 starter 成绩。原规定 TEMP checker 的默认五锁、参考全五关、逐层和全部 24 项登记错修检查已通过，具体结果见 verification.txt 与独立验收记录；这些检查不计作候选成绩，也不宣称 Python 3.10 实际运行。

当前题包有 36 条 assert、2 处 raises、五个测试与五个 skip 锁，登记 24 项错修。独立 source-first 验证覆盖 6 个领域错修：等 payload 的不同 task identity、完整 aging interval、声明 worker 次序、arrival 的 signed priority、显式空 topic restriction，以及 shared sibling pool 的祖先边界。6 个错修均在 NEW 完整副本中只使指定关失败、其余四关通过，配对 reference 均为五关通过；原规定 TEMP --write checker 的默认五锁、参考全五关、starter 五失败、逐层与全部 24 项错修检查通过。完整执行命令、内容 SHA、权限记录和日志见 exam 外 fresh-review.json。

## 常用命令

在自己的练习副本运行：

```bash
python3 -m pytest -x
python3 -m pytest -k specialist -x
python3 -m pytest --all-parts -x
python3 -m pytest --solution --all-parts
```

`--all-parts` 和 `--solution` 是本目录 `conftest.py` 提供的练习开关，真实面试没有。`--solution` 只用于计时结束后检查参考实现，不能算作候选实现成绩。
