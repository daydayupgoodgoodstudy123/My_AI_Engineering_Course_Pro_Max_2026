# 16/10 分关面试题：FloorFair

这是一个写好一半的本地 conversation desk。selector 读取有界最近消息，产出 Decision，接受的 Proposal 才提交 Utterance；完整审计记录与真实发言统计分开保存。英文题面在 [README.md](README.md)，完整合同在测试、断言消息和 docstring 中。

## 开始

在自己的练习副本打开终端，先读 README 和五个测试的 docstring：

```bash
python3 -m pip install pytest
python3 -m pytest
```

默认五个 skipped 表示五关按顺序锁住。先解除 Part 1 的 skip，运行 `python3 -m pytest -x`；这一关通过后再解除下一关。

## 五关职责

| 关 | 候选职责 | 完整正确 GIVEN |
|---|---|---|
| 1 修 | exact terminal、最近窗口、真实发言计数、先取窗口再格式化 | 完整 ChatDesk/ReplaySelector、typed intake、whole-message renderer、approval reader/card |
| 2 存 | 完整 Decision input/choice/reason、Utterance 与 decision_id 关联、conversation snapshot/reopen | event_tag、完整 schema、精确 scalar codec、transaction、restore_event、archive_counts |
| 3 算 | named-question obligations、weighted actual-turn deficits、consecutive cap 与 tie policy | typed validation、committed_messages 分类、P1/P2 真实产物 |
| 4 流 | 每条 observation 自身的公开字段与 private/public 边界 | observe_turn 分类/binding/delta、精确 formatter、logfmt 编读码、async driver |
| 5 构 | own cumulative per-agent quota、首条超限证据、own pending、subtree/ancestor total budget | 完整 reply_evidence、全局 question ID resolver、ancestor/subtree、committed 分类与 cap 校验 |

P1 只有整条消息去首尾空白后恰好等于 `TERMINATE` 才终止；`Please do not TERMINATE` 是普通文本。这是本地明确合同，不是框架官方默认规则。selector 使用最近 window 条完整消息并保持顺序；完整 transcript 仍保存。Decision 是诊断记录，只有真实 Utterance 增加 agent 计数，接受的空文本也算一轮。性能修复在格式化前选窗口，不能用空 context 或删历史替代。

P2 保留每个 Decision 自己的 context、选择、reason、accepted 与 private audit 字段，也保留每个 Utterance 的内容、identity 和自己的 decision_id。只替换请求的 conversation，保留其他 conversation。schema 在构造 archive 时由完整 `ensure_schema` 建立，`archive_counts` 已完整正确，不要求候选再实现建表或发言计数；大整数、Unicode、空文本与 record 类型辨别是完整 codec/helper 的集成护栏。

P3 有三个独立 TODO：`update_question_obligations`、`speaker_deficits`、`select_next_speaker`。合法输入为同一 conversation 的 typed records、唯一 question IDs、positive integer weights 和 positive consecutive cap。只有结构化 question metadata 创建义务；回答必须引用 exact ID，并由同 thread 的 named addressee 发出。active speaker 的 deficit 为 `(active_actual_turns + 1) × weight / active_weight - actual_count`，用精确 Fraction 表示；inactive 的 weight/count 不参与。先应用 consecutive cap，再优先最早仍未答且 addressee eligible 的问题，否则按最大 deficit、原 roster 顺序选人。没有 eligible speaker 返回 None，受 cap 阻塞的问题仍 pending。

P4 `observe_turn` 已产生正确 reject/commit/stop 分类、实际 speaker/turn 与 deficit delta。候选只投影每条 observation 自己的 `thread/turn/kind/speaker/reason/deficit`，使用给定精确 formatter；private_prompt 不进入公开字段。通用 escaping、分类、计数和传输 cadence 都已完整给定。

P5 有 `audit_speaker_quotas` 与 `inspect_threads` 两个 TODO。按 `max_speaks` 声明序审计各 agent 在本 thread 的累计实际 Utterance：其他 speaker 穿插不清零，超限发言也计入 used，remaining=`max(0, cap-used)`。第 cap 条合法；`first_excess` 只保留第 cap+1 条实际 message ID 的零或一个元素 tuple，cap=0 时首条即超限，空 ID 也保留。未声明的 agent 不产出 quota 行，默认空声明得到空 tuple；quota 不继承，也不计 child speech。完整 `reply_evidence` 已提供授权 answered IDs 与全部 issues，候选据此计算 own pending/complete 并保留 issues。每个 total `limit` 则覆盖 subtree 的真实 Utterance，remaining 取自身与全部祖先 residual 的最小值再截到 0。输入为 finite typed tree、全局唯一 question IDs、可解析 refs 与非负整数 caps；唯一 speaker 名、cap 校验、identity、ancestor/subtree 和 cycle 拒绝都 GIVEN。

## 性能与验证边界

P1 fixture 有 8,000 条真实 archived user messages，并运行 80 次真实本地 `ContextDigestSelector` callback，window=3。每次 callback 读取当前完整渲染窗口并计算 SHA256 reason，每个 Decision/Utterance 都真实产生并保留。fixture 与独立 expected 在 timer 外；完整 `ChatDesk.run`、整个 `ChatReport` equality 和 callback count 护栏在 timer 内，覆盖 8,080 条 archived/new messages、160 条真实 observations、完整 input/choice/reason/counts。

当前限值 0.05 秒。本机 Python 3.12.14 的完整固定三慢三快组，慢版业务 timer 为 0.567921–0.585339 秒，快版为 0.0004762–0.0005414 秒；最小慢值/限值为 11.3584×，限值/最大快值为 92.3503×。精确数值及六份结果路径见 [校准报告](/tmp/exam-11-16-work/draft16-10/actual/group02-summary.json)。不能靠清空 context、截断 raw transcript、跳过 callback 或预填固定结果提速。

六个独立完整测量副本仅把 elapsed 限值断言换成测量打印，慢版另仅恢复真实的 whole-history-format-before-window；正确 recent input、完整 run/report/callback 护栏与其他四关保留，六份均为带测量打印的五关功能通过。这个结果不表示慢样本通过了原 elapsed 限值断言。最慢业务 timer 约 0.58534 秒，小于 3 秒；六份完整五关进程 wall 最大约 0.738924 秒，小于 5 秒。保留原计时断言的 reference 完整五关另通过，进程 wall 约 0.183642 秒。

业务 timer 与整个 pytest 进程 wall 分开记录。这些结果仅覆盖本机指定 workload 和环境，不保证任意负载下的通用墙钟上界，也不是生产 SLA；60 分钟真人用时仍未校准。

静态题包有 45 个 Python 文件、五个测试、39 条 assert、2 处 `pytest.raises`、五个 skip 锁和 32 项登记错修。两项 reply-authority 错修只验证完整 GIVEN 的集成，不是候选主要算法。静态数量不是运行结果；P1 校准报告中的 reference 与六个测量版本不计入候选 starter 成绩，也不宣称实际运行了 Python 3.10。


P1 的固定性能路径有校准报告中的本机测量记录。当前原规定 TEMP checker 已通过默认五锁、参考全五关、逐层与全部 32 项登记错修检查，其中两项 reply-authority 错修验证完整 GIVEN 的集成。Part 5 配额的三项独立实际错修分别覆盖 per-agent 归属、首条超限边界与累计历史保留；每项均为 Part 5 失败、其他四关通过，各对应 reference 全五关通过。这些结果不计作候选成绩，具体记录见 verification.txt 与独立验收报告。

## 常用命令

在自己的练习副本运行：

```bash
python3 -m pytest -x
python3 -m pytest -k named_question -x
python3 -m pytest --all-parts -x
python3 -m pytest --solution --all-parts
```

`--all-parts` 和 `--solution` 是本目录 `conftest.py` 的练习开关，真实面试没有。`--solution` 只用于计时结束后检查参考实现，不能算作候选实现成绩。
