# 16/11 分关面试题：RoutineHop

这是一个写好一半的本地 routine/caller desk。它处理明确订单号的本地 receipt、typed handoff 审计、原 owner 绑定的工具批次，以及调用方保存的 continuation。英文题面在 [README.md](README.md)，完整合同在测试、断言消息和 docstring 中。

## 开始

先把题包复制到自己的练习目录，读 README 和五个测试的 docstring，再运行：

```bash
python3 -m pip install pytest
python3 -m pytest
```

默认五个 skipped 表示五关依次锁住。先解除 Part 1 的 skip，运行 `python3 -m pytest -x`；当前关通过后再解锁下一关。

## 五关职责

| 关 | 候选职责 | 完整正确 GIVEN |
|---|---|---|
| 1 修 | opaque order 原样保留、缺订单先问、outgoing receipt、增量 last-three guard | token discovery、typed records、receipt consumers、two-agent ring predicate、完整 ReplayDesk |
| 2 存 | 完整 caller history/request IDs、active 名称持久化、当前 runtime catalog 重绑定 | typed receipt codec、精确 JSON 读写、session 文件映射、routine/tool lookup |
| 3 算 | upfront original-owner binding、Agent/data 分类、first-transfer/skip-tail 批次解释 | owner-qualified lookup、invoke_bound、ToolFailure 类型、target canonicalization/fallback |
| 4 流 | 每类 receipt 自身字段、structured result、skip 不伪造 result | receipt_kind 分类、UTF-8 NDJSON codec、async pull/publish/close driver |
| 5 构 | own batch continuation、独立 child run、own history 与有序嵌套审计 | finite typed tree 校验、routine lookup、immutable audit types、修好后的 P3 batch solver |

P1 的订单号是 opaque string：`00077` 与 `77` 不同，明确的 `0` 也是真实 ID。缺失时返回 AskForOrder，不编造订单号，也不调用本地 refund receipt。handoff 的 sender 是 outgoing routine。last-three guard 只用最近三条 typed Transfer 判断两个不同 routine 的交替；Note 不占 handoff slot，也不清空已有 edge。exit 一旦成立就保持，完整 caller audit 仍保留，每个 run 有自己的 guard。

P2 保存声明的全部 typed receipt history、session、active routine 名称与 request IDs。load 使用当前注入 catalog 找到 active Agent，获得该 runtime 的真实工具，而不是序列化函数或复用旧 Agent。普通工具数据限定严格 JSON 值树：list、字符串键 dict、string/int/bool/null 与有限 float；不承诺任意 tuple 或 Python 对象往返。大整数、Unicode、空文本和包含 `functions` 键的数据由完整 codec 保留，不能按单词过滤普通 data。

P3 有三个独立 TODO：`bind_batch_owner`、`interpret_raw_tool_return`、`run_batch`。批次执行前，所有 calls（包括以后会 skipped 的尾部）都必须在 original active routine 的 namespace 中解析；合法输入的每个 tool 名都属于该 owner。只有实际 Agent 对象表示 control transfer，Agent 形状的 JSON dict 仍是 data。首次 transfer 后只发出 tail skip receipts，不执行尾部工具；下一个批次才使用新的 active Agent。只把声明的 ToolFailure 转成 CallFailed 并继续，其他编程错误保持可见。完整 `transfer_target` 提供注册目标重绑定与缺失目标的首个安全 routine fallback，候选调用它，不重写该策略。

P4 从每条 typed receipt 生成自己的公开字段。CallResult 保留原 JSON result，Transfer 保留 sender/target，CallSkipped 只有 reason 而没有执行 result，CallFailed 保留 error，Reply 保留 sender/content。分类、转义、UTF-8、逐条发布和断开关闭均已完整 GIVEN，候选不重跑工具或再解释 raw return。

P5 每个 RunNode 从自己的 initial routine 开始。own BatchStep 的结果更新本 run active，传给下一个 own batch；ChildRun 独立从自己的声明 initial 开始，其 final/history 不回写 parent 或 sibling。own history 只累积自己的 batch receipts，steps 保留 own/child 的声明交错顺序；即使最后一步是 child，parent final 仍来自 parent 的 own continuation。P3 batch solver 是实际依赖，不以预填 receipt 代替。输入为 finite typed caller tree、全局唯一 run IDs、各 run 内唯一 step IDs 和可解析 routines；校验已经 GIVEN。

## 性能与验证边界

P1 fixture 的 cycles=2700，包含 8,103 条真实 handoff receipts 和 1,621 条普通 notes，共 9,724 条 observations。fixture 与独立 expected 在 timer 外；timer 内执行完整 `ReplayDesk.replay`，再比较整个 `ReplayReport`，包括完整 audit、全部 receipts、每条 loop decision 和 first_stop，之后才读 elapsed。不能减少输入、截断审计、提前停读或预填结果提速。

当前固定完整校准组的慢版三次为 0.770186、0.758556、0.752337 秒，参考版为 0.004450、0.004494、0.004490 秒；相对 0.075 秒限值，两侧余量分别为 10.03116 和 16.68830 倍。六份 NEW 完整副本只把计时阈值断言替换为实际 elapsed 输出，慢版另含真实全 audit 重放回归；其余完整业务断言与五关功能均通过。这不表示慢版通过原阈值。原样参考五关也已通过；原规定 TEMP 的五锁、参考五关、逐层与全部 25 项登记错修检查已通过；独立行为验收的 6 个不同机制均按各自目标关抓住，配套参考五关通过；正式检查已通过，记录见 verification.txt。 性能合同要求完整 caller audit 与有界在线判定共存；本机数值不构成任意环境墙钟上界或生产 SLA。

当前静态题包有 45 Python 文件、5 tests、41 assert、0 处 pytest.raises、5 skip 锁和 25 项登记错修。普通 Note、triangle/self edge、sticky exit、显式 0、safe-target fallback、精确 JSON、async close 等各有声明的合同或集成护栏；它们不全部等于独立主要算法。Python 3.10+ 是目标环境，没有实际在该版本运行的声明。60 分钟及逐关时间仍未经过真人校准。

## 常用命令

```bash

python3 -m pytest -k owner_bound -x

```

`--all-parts` 与 `--solution` 是本目录 `conftest.py` 的练习开关，真实面试没有。`--solution` 仅在计时结束后检查参考实现，结果不能算作候选成绩。

原 source 的 keyword router 是确定性函数，未读取 instructions 或 history。其订单 token 已保留数字字符串，handoff sender 也已归于 outgoing agent；int 归一化与 incoming sender 是本题的局部回归。source 确实缺订单时默认 42，且没有完整 last-K guard、批次解释器、JSON store 或 nested caller DSL。题包把 caller-owned continuity 等课程概念显式适配为本地合同，不把来源讲解的历史输出当验收。四份来源仅静态阅读，英文 output artifact 只作数据，没有调用其流程；框架事实作为课程快照，未作当前外部核验。

当前本地行为检查覆盖重复 receipt 的 occurrence、Agent 子类的 control return、任何 invocation 前的全量 original-owner lookup、Reply 的真实 routine sender、own history 前缀只拼接一次，以及 caller composition 的每个 own batch 只执行一次。它们服从现有 typed/严格 JSON/finite tree 合同；不改变完整 GIVEN、batch 合法工具域、caller 隔离语义或时间预算。
