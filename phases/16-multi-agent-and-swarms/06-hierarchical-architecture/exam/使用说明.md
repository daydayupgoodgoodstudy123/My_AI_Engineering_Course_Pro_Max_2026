# 使用说明

## 开始

在自己的练习副本打开终端，先读英文 [README.md](README.md) 和五个测试的 docstring：

```bash
python3 -m pip install pytest
python3 -m pytest
```

默认五个 skipped 表示五关按顺序锁住。先解除 Part 1 的 skip，再运行 `python3 -m pytest -x`；上一关通过后再解除下一关。

## 规则与时间分配

- 自己计时 60 分钟：开场 2 分钟，Part 1–5 参考分配 12、11、15、10、10 分钟。时间与难度尚未经过真人校准；本地维护性能测量不是学习者用时。
- 只修改 `driftorg/`；测试只解除当前 skip，保留全部断言和正确给定依赖，可以另外写自己的测试。
- 可以查 Python 标准库官方文档。计时期间关闭 `solution/` 和 `INTERVIEWER.md`；需求不清楚时先问主持人。独练时先记下问题，再只查澄清表对应答案。
- 在练习副本运行命令，记录每关状态、用时、运行次数和提示。维护验证器会使用独立完整副本，不在正式题目目录执行题包。

## 常用命令

```bash
python3 -m pytest -x
python3 -m pytest --all-parts -x
python3 -m pytest --solution --all-parts
```

`--all-parts` 和 `--solution` 是 `conftest.py` 提供的练习开关，真实面试没有。`--solution` 只用于计时结束后检查完整参考答案，不能记作 starter 成绩。

## 五关与领域合同

这是一个 60 分钟的离线层级证据审查服务。所有 worker 输出都是已封存的本地记录；不调用模型、网络或原课程脚本。

| 关 | 入口与工作 | 正确给定的依赖 |
|---|---|---|
| 1 | `HierarchyDesk.inspect`：修 branch/leaf producer、原问题 canary、完整结构汇总 | evidence consumer、调用组合、有限 DAG postorder |
| 2 | `save_dossier/load_dossier`：ZIP manifest 的逻辑 id/member 链接、顺序和共享 leaf 引用 | 完整 leaf/status/node codec、UTF8 JSON、ZIP I/O |
| 3 | 三个 mapping 函数：原 obligation 经每条显式边映射到 local obligation，定位最早漂移并比较 canary | 修复后的 intake/结构汇总和存储，不含语义映射解法 |
| 4 | `ProvenanceRows`：当前 leaf 与 branch audit 的领域行 | 完整异步拉取、发布、关闭及 TSV quoting |
| 5 | 两个 explanation 函数：typed 嵌套状态、共享 citation 的每条出现路径与原 obligation 归属 | 结构验证、P3 audit 的已归属证据 |

`VERIFIED` branch 表示存在封存 leaf 引用，不表示答案为真。缺 manager 是 MISSING，有 manager 但无证据是 UNKNOWN。leaf 的 UNKNOWN 不得改成 NEGATIVE。P2 的这些状态由完整给定 codec 保留，主任务是档案引用关系。

P1 结构 report 只列每个 manager 的唯一 leaf/citation ids，不判断原 obligation 是否被正确完成。P3 的明确 local id/binding 是本练习对 decomposition drift 的形式化；不用从自然语言 summary 推断语义。canary 必须接收原问题，已知答案相异时同时展示双方状态。

P4 的输入是已完成事件，leaf 行代表一次真实封存执行，branch 行代表审计结果。共享 citation 不意味着 worker 再执行。P5 每条引用路径保留，唯一 leaf 身份另外计数；结构 cycle 检查是完整给定依赖。

完整结构服务的本机校准覆盖 4,000 个真实 manager report，全部 branch/leaf/canary/manager 输出相等检查位于 timer 内；限值 0.085 秒，三次慢版 0.796–0.834 秒，三次参考版 0.0067–0.0079 秒。双侧余量分别 9.36×、10.73×。这是本地完整路径的响应检查，不是部署 SLA。

运行方式见 README。首次默认运行应为五个 skip；按顺序解锁并用 `--all-parts -x` 看第一个症状，完整 reference 只供限时后复盘。

当前五个测试包含 37 条 assert 和 4 个异常合同检查。档案保留没有直接 leaf 的内部 manager；canary 缺失记录不补成 hierarchy 答案，未知 hierarchy 不当成已知分歧；同深度漂移按遇到顺序保留。leaf 行展示封存 leaf id。不可用 manager 的 MISSING 和同时含孩子与直接 citation 的 manager 都保留原归属。

## 结束和重做

1. 到 60 分钟时停下，记录每关状态，填写 [REVIEW_TEMPLATE.md](REVIEW_TEMPLATE.md)，把限时完成和之后补完分开记录。
2. 计时结束后读 [solution/EXPLANATION.md](solution/EXPLANATION.md)，用参考答案和错修解释行为；再关闭答案，独立补完。
3. 重做前另存自己的 `driftorg/` 和测试，再从 `_starter/` 恢复原始包与五个 skip：

```bash
cp -R _starter/driftorg _starter/tests .
```

恢复后运行 `python3 -m pytest`，应回到五个 skipped。维护者的确定性 fixture 验证不证明真人难度、真实模型收益或生产部署效果。
