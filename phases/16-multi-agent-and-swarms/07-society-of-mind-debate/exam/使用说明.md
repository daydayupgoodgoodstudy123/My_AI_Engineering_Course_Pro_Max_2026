# 使用说明

## 开始

在自己的练习副本打开终端，先读英文 [README.md](README.md) 和五个测试的 docstring：

```bash
python3 -m pip install pytest
python3 -m pytest
```

默认五个 skipped 表示五关按顺序锁住。先解除 Part 1 的 skip，再运行 `python3 -m pytest -x`；上一关通过后再解除下一关。

## 规则与时间分配

- 自己计时 60 分钟：开场 2 分钟，Part 1–5 参考分配 12、11、15、10、10 分钟。时间与难度尚未经过真人校准；本地维护性能测量不是学习者用时。
- 只修改 `mindsync/`；测试只解除当前 skip，保留全部断言和正确给定依赖，可以另外写自己的测试。
- 可以查 Python 标准库官方文档。计时期间关闭 `solution/` 和 `INTERVIEWER.md`；需求不清楚时先问主持人。独练时先记下问题，再只查澄清表对应答案。
- 在练习副本运行命令，记录每关状态、用时、运行次数和提示。维护验证器会使用独立完整副本，不在正式题目目录执行题包。

## 常用命令

```bash
python3 -m pytest -x
python3 -m pytest --all-parts -x
python3 -m pytest --solution --all-parts
```

`--all-parts` 和 `--solution` 是 `conftest.py` 提供的练习开关，真实面试没有。`--solution` 只用于计时结束后检查完整参考答案，不能记作 starter 成绩。

## 五关与领域合同

这是一个 60 分钟的离线 numeric debate 五关练习，没有真实模型、网络或原课程脚本执行。

| 关 | 候选职责 | 完整正确 GIVEN |
|---|---|---|
| 1 | raw 数值 producer、agreement 与 truth 分类、完整人口 diameter | finite intake、最终数值 renderer、无权均值/误差诊断、RoundDesk |
| 2 | 全局名字表和每轮 answer/confidence 对齐、完整轮记录布局 | binary64/UTF8/可选 truth 编解码与文件生命周期 |
| 3 | own+others 加权 revise、自己 confidence/history commit、固定追加轮数 | 正确 frozen snapshot、初始独立 agent 构造、P1/P2 产物 |
| 4 | 一个完整封口 vector 的 agent 行和一条诊断行 | 完整 async pull/publication/close、CSV codec 与标量展示 |
| 5 | 每轮一个共享 vector、前轮权重来源、非零因果初始输入 | 完整 RoundCatalog 的 round/agent 身份与 previous handle 查询 |

输入 answer 为有限 binary64，confidence 是 [0,1] 的脚本权重，truth 是有限数或 None。intake 正确拒绝非有限、负权重、重复名字和空 team；总 confidence 为零由 revise 明确拒绝。rounds 是非负整数，表示初始作答之外追加的交换次数；0 仍有初始记录。

P1 的 agreement 是离无权均值 tolerance 内的比例，不是字面多数投票；tight consensus 也能错。truth 是外部评测标签，缺席时 correctness/error 不制造值。diameter 只求一维最大绝对差，不实现 P3 加权求解器。原数值留在 record，显示格式只用于最后呈现。

P2 的完整 scalar codec 保留 binary64，包括 subnormal 与 signed zero；候选主要处理名字对齐、answer/confidence 配对和轮记录。即使相邻封口轮的全部数值不变，每个已完成轮次仍各自保存；truth=0.0 与 None 分开。P3 对输入 binary64 做精确有理加权累计并在最后舍入，属于本地数值合同，不照搬源码逐 float 求和次序。每轮读取真正冻结的上一轮答案/权重；confidence 每轮乘 1.05、上限 1.0，历史记录初值及每次新答案。

P4 的所有同行 diagnostics 来自同一完整 vector，不能对每个 agent 当成 singleton 重算。P5 的 round/name 查询是实际正确 GIVEN；候选保留共享向量结构、前轮 confidence 和非零证据祖先。truth 不进入数值更新的因果根。根按初始 agent 顺序输出，不按名字排序。

7,000 位参与者只构成纯数值诊断的完整输出压力 fixture，不是建议的真实 LLM agent 数量；没有逐行模型调用或 sleep。

完整 RoundDesk.record 的 7,000 位参与者输出全部在 timer 内检查。独立完整校准组限值 0.10 秒，三次慢版 0.896–0.904 秒、三次快版 0.0054–0.0065 秒，双侧余量 8.96×/15.41×。六个测量副本仅把 elapsed 限值断言换成实际测量打印，慢版另换 diameter 实现，其余五关功能检查保留；原样计时断言由规定 checker 验证。这是本机数值服务检查，不是生产 SLA。

这套题有五个测试函数、38 条 assert、1 处异常断言和五个 skip 锁，错修登记 25 项。60 分钟是练习预算，尚未做真实候选人的人类计时校准。

命令见 README。默认运行应为五个 skip；限时后用 reference 和错修登记解释具体行为。不要把数值共识当成 LLM 事实收益。

## 结束和重做

1. 到 60 分钟时停下，记录每关状态，填写 [REVIEW_TEMPLATE.md](REVIEW_TEMPLATE.md)，把限时完成和之后补完分开记录。
2. 计时结束后读 [solution/EXPLANATION.md](solution/EXPLANATION.md)，用参考答案和错修解释行为；再关闭答案，独立补完。
3. 重做前另存自己的 `mindsync/` 和测试，再从 `_starter/` 恢复原始包与五个 skip：

```bash
cp -R _starter/mindsync _starter/tests .
```

恢复后运行 `python3 -m pytest`，应回到五个 skipped。维护者的确定性 fixture 验证不证明真人难度、真实模型收益或生产部署效果。
