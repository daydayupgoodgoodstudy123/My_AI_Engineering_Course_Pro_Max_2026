# LeadSynth 使用说明

这是监督者/worker摘要服务的60分钟原创结对练习，只有注入的本地完成观察，不执行LLM、网络或源demo。先读README和tests，每次只解锁一个skip；五关建议12/11/15/10/10分钟，开场2分钟，可按现场调整，没有真人校准。

运行`python -m pytest`默认五关skip；逐个注释对应skip后运行。`python -m pytest --all-parts`解锁全部，`--solution --all-parts`检查参考答案，不代表自己的实现通过。计时期间关闭solution、INTERVIEWER和外部答案，允许澄清合同、查标准库。重做前先把自己的 `leadsynth/` 和 `tests/` 另存一份，再将 `_starter/leadsynth/` 和 `_starter/tests/` 完整复制回来并恢复五个 skip，其他文件保留。

P1只是窄摘要/自己的cap/已封口时长诊断；P3仍需实现独立的typed证据合并。P2给定内容寻址/JSON原语；P4给定异步发布、关闭和Markdown封套，候选负责当前领域内容。P5是本地任务档案，不运行worker调度。同一query重存替换当前assignment快照；来源按首次出现保序。空summary仍是已完成结果，leaf的原scope顺序也属于归属。

这套题证明了什么，没证明什么：确定性fixture验证字段、归属、显式矛盾与有限树；不证明真实研究质量、生产收益、框架兼容、真实token用量或线程杀死能力。性能记录只适用于本机声明业务fixture。

本机完整业务校准：11500个真实封口worker观察，完整输出核验在timer内。3慢3快双10.7855×/9.6082×、maxslow2.9441s；不外推真实worker执行或研究收益。
