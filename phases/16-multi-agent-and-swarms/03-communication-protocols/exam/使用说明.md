# AuditMesh 使用说明

这是一套约60分钟的结对编程练习。服务接收一个本地委派操作，保存私有输入、输出和工具观察，再按声明的规则输出公共记录。所有 handler、信任结果和时钟均来自本地 fixture。

## 开始

先读 README.md、tests/test_parts.py 和 auditmesh/。逐关注释 skip 锁，保留测试内容与公共签名。建议用时：修15分钟、存10分钟、算15分钟、流10分钟、构10分钟。

```bash
python -m pytest -q
python -m pytest -q --all-parts -k test_single_execution_and_private_audit
python -m pytest -q --all-parts
```

先定位异常实际发生的消费者，再追到产生错误数据的调用。观察轨迹中的一个位置不等于一个工具名，也不由时间戳唯一确定。P1不含信任或公共脱敏策略；P3仍有独立的准入、模态验证和投影职责。

## 给定边界

models.py 的有限消息形状检查、value_codec.py 的精确值编解码和 db_support.py 的 schema/事务是可用依赖。P4的 stream_support.py 负责拉取、SSE编码、发布时机和关闭；候选填写同步 AuditProjection 的领域工作。修好P3后，其 public_step 可供P4调用。DID的字段是结构证据，不执行URL，不检查真实密钥。

独立作答时保持 solution/、INTERVIEWER.md 和原课实现关闭。测试和参考答案不能证明真实协议兼容、密码身份、网络安全或模型效果。

## 复盘和重做

```bash
python -m pytest -q --solution --all-parts
```

复盘后填写 REVIEW_TEMPLATE.md。重做时用 _starter/auditmesh/ 和 _starter/tests/ 覆盖对应目录；不要把 solution/ 作为自己的作答成果。保持5个原测试及其断言。

同一agent/session里的多次run保持创建顺序；修改公共tool输入输出不改变其私有来源。封口轨迹即使条数相同，内容也必须与已观察记录一致。同一DID引用的controller和purpose问题分别保留。
