## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | Self-Rewarding 循环的四步 | 造 prompt → 每题采样 N = 4 条 → 同一模型按 0–5 加法准则打分（三次取平均）→ 最高对最低组成偏好对（同分丢弃）做 DPO；下一轮的模型既作答又评判 |
| 2 | 论文报告的收益与副作用 | Llama 2 70B 三轮：AlpacaEval 2.0 胜率 9.94% → 15.38% → 20.44%（超 GPT-4 0613 的 15.76%）；平均长度 1,092 → 1,552 → 2,552 字符；论文自认长度"可能是相对表现的一个因素" |
| 3 | 裁判为何饱和 | EFT 种子固定，M1 之后裁判只是被 actor 偏好对的 DPO 顺带挪动（一致率 78.7% → 81.7%），没有任何外部信号纠正它的错误偏好 |
| 4 | actor 为何学到裁判 | 候选挤到准则顶端后，剩余分差由裁判"在意但不是质量"的东西解释；长度项 β·ΔL/1000 在 β = 0.5 时值 0.4 分，是 Δs 里最大的一项 |
| 5 | 自我确认循环 | Chen 等人 2026：代理指标与策略同步漂移，差距在代理上看不出来；与模型坍缩并列为违反验证要求的典型失败 |
| 6 | Meta-Rewarding 的三件事 | 元裁判（11 次评分取方差最大的回答，两两比较正反双序，Elo 选 chosen/rejected）；第 1–2 轮联合训练裁判与 actor；手写的长度控制规则（ρ 分数带内取最短/最长） |
| 7 | Meta-Rewarding 修好了什么 | Llama-3-8B-Instruct LC 胜率 22.92% → 39.44%（带长度控制的 Self-Rewarding 只到 35.49%）；Arena-Hard 20.6% → 29.1%；与 GPT-4 一致率 61.03% → 79.33% |
| 8 | Meta-Rewarding 没修好什么 | 人类 Spearman 0.315 → 0.326"没有持续"；平均分 4.1 → 4.7+ 导致饱和；元裁判偏向高分评判的比例 63.04% → 97.68%；长度控制是人写的 |
| 9 | 递归在哪里停 | 同权重的评估器层层叠加只会让错误相关；必须有东西有根基：形式化验证器 > 执行/测试 > 固定人工标签集；元裁判只在拥有裁判没有的信息时才有用 |
| 10 | 四个每轮信号 | 固定审计集上的裁判—人类一致率、长度漂移、分数通胀、偏好对熵；在循环自己的偏好对上算一致率**不是**监控 |

## 五、参考答案与解析

### Q1 — 答案：B

讲义："Self-Rewarding 论文在第一段就点出它的两个缺陷：受限于人类水平；并且在策略持续针对它优化时自己却是冻结的。" A、C、D 都不是论文的论证；D 恰好与本节的担忧相反——自我评判并不"总是可靠"。

### Q2 — 答案：A

讲义 Table：M1 → M3 胜率 9.94% → 15.38% → 20.44%，平均长度 1,092 → 1,552 → 2,552 字符；"论文自己也点出了长度那一列"。B 方向反了（一致率实际是 65.1% → 81.7%）；C、D 是编造的数字。

### Q3 — 答案：D

讲义："M1 之后，裁判的变化只来自'针对 actor 偏好对的 DPO 恰好挪动了共享权重'……没有任何外部信号告诉裁判它的哪些偏好是错的。" 以及："四条候选都挤到准则顶端附近……剩下的分差越来越多地由'裁判在意但不是质量的东西'解释。" A、B、C 与论文设置不符（EFT 种子集是固定的，不会被重新标注）。

### Q4 — 答案：C

讲义："chosen 取分数落在 [(1−ρ)·S_max + ρ·S_min, S_max] 内最短的那条，rejected 取分数落在 [S_min, (1−ρ)·S_min + ρ·S_max] 内最长的那条。" 并强调"长度控制规则根本不是学出来的；是人写的"。A 把它说成学出来的；B、D 是编造的机制。

### Q5 — 答案：B

讲义："元裁判也长出了自己的偏好：元裁判干脆偏向'分数更高的那条评判'的比例，从第 1 轮的 63.04% 升到第 2 轮的 97.68%（论文 Table 5）。" A 是训练安排；C、D 都是"修好了什么"的证据。

### Q6 — 答案：A

长度差 1,100 − 180 = 920 字符，长度项差 0.5 × 0.92 = 0.46 分；质量差 0.78 − 0.50 = 0.28。0.46 > 0.28，所以冻结裁判下 `verbose` 的期望分（0.50 + 0.55 = 1.05）高于 `concise`（0.78 + 0.09 = 0.87），默认运行最终 `verbose` 占 0.72。这正是讲义"长度项是 Δs 里最大的一项"的具体数字。

### Q7 — 答案：D

讲义："一旦 actor 收敛到单一风格，偏好对全是同风格对，这个指标量到的只是噪声。" 默认运行里 FROZEN 第 12 轮 `agr_tr` 反升到 64.5%，而真实质量在下跌。A、B、C 均非讲义论点。

### Q8 — 答案：C

讲义："元裁判只有在**拥有裁判没有的信息**时才有用。在 Wu 等人那里这份信息很弱（换一个 prompt、两两比较、Elo）。在下面的模拟器里它很强（一小份人工标注的审计集）。"

### Q9 — 参考答案

1. `judge` 列是裁判对本轮样本的平均分，等于真实质量加 `β × 平均归一化长度` 加噪声。actor 向 `verbose` 漂移时真实质量下降（0.627 → 0.542），但平均长度从 502 涨到 990，长度项从约 0.25 涨到约 0.50，于是裁判分上涨 0.155。`inflat` 就是这个差额（+0.234 → +0.499）：裁判"看到"的质量与真实质量的差距翻倍。这就是自我确认循环——在循环内部，所有可见指标都在变好。
2. 表格里 `bias` 列是**本轮实际使用**的偏好。第 0 轮的 200 对由 β = 0.5 的裁判评判，actor 据此完成第一次更新（第 1 轮 `verbose` 升到 0.23、长度 596），元裁判在第 0 轮末尾才把 β 砍到 0.24。修裁判永远比学生学坏慢一步；`--meta-lr` 越小，这一段"先漂再回"越长。
3. 来自 `print_headline`：

```python
        gap = hists["meta"][-1].true_quality - hists["frozen"][-1].true_quality
        verdict = "beats" if gap > 0 else "does not beat"
```

`--meta-lr 0` 时 `judge.length_bias - 0 * beta_hat` 不变，`meta` 与 `frozen` 完全相同（同种子、同随机流），`gap = 0`，条件 `gap > 0` 为假，打印 "does not beat … by +0.000 points"。

### Q10 — 参考答案

1. 实测：FROZEN 第 12 轮 `true_q = 0.725`、`length = 536`、top style `thorough (0.82)`。手算 β = 0.3 下的期望分（q + 0.3 × L/1000）：

| 风格 | q | L | 期望裁判分 |
|------|---|---|-----------|
| concise | 0.78 | 180 | 0.834 |
| standard | 0.72 | 320 | 0.816 |
| thorough | 0.74 | 520 | **0.896** |
| padded | 0.62 | 780 | 0.854 |
| verbose | 0.50 | 1100 | 0.830 |
| sloppy | 0.40 | 110 | 0.433 |

`thorough` 最高，所以 actor 收敛到 0.74 的风格而不是 0.78 的 `concise`。β = 0 时期望分就是 q，`concise` 最高。
2. 因为优化目标仍然不是质量：actor 停在了一个**错误的最优点**（0.74 而非 0.78），只是碰巧这个错误最优点的质量也不低。所有循环内指标（`judge`、`inflat`、`agr_tr` 73%）都"正常"，这是最难发现的 Goodhart。能区分的是审计集上的 `agr_au`：FROZEN 终点 70.0%，META 终点 80.0%——因为审计集从初始均匀分布抽取，包含各种长度，长度偏好在那里仍然会导致误判。
3. 让 `concise` 的期望分超过每一个对手：对 `thorough`：0.78 + 0.18β > 0.74 + 0.52β ⇒ β < 0.04/0.34 ≈ 0.118；对 `padded`：β < 0.16/0.60 ≈ 0.267；对 `verbose`：β < 0.28/0.92 ≈ 0.304；对 `standard`：β < 0.06/0.14 ≈ 0.43；`sloppy` 永远更低。最紧的是 `thorough`：**β < 约 0.12**。换句话说，裁判的长度偏好只要超过"每 1,000 字符 0.12 分"，冻结裁判就已经选错风格了——这比直觉上的"强偏好"小得多。

### Q11 — 参考答案

1. `--audit-size 200`：β 沿 +0.50 → +0.24 → +0.11 → +0.03 → 0.00 → … → −0.03 平滑衰减，`agr_au` 稳定在 77%–82%。`--audit-size 6`：β 走 +0.50 → +0.20 → +0.02 → −0.06 → −0.14，然后停在 −0.14；`agr_au` 在 33.3%、66.7%、100.0% 三个值之间跳（3 对样本只有四种取值）。停在 −0.14 是因为 6 个样本的回归噪声让某一轮的 β̂ 偶然偏大（约 +0.16），被砍掉一半后 β 过零；之后真实 β 已接近 0，每轮 β̂ 在 ±0.1 的噪声里晃，期望修正量很小，而乘法衰减只对"β̂ 与 β 同号"的部分起作用——于是 β 停在一个由噪声决定的负值上，裁判开始轻微地**惩罚**长度。这组风格里惩罚长度恰好也指向 `concise`，所以真实质量仍到 0.773，但这是模拟器的巧合。
2. 一元回归斜率的标准误 `se(β̂) = σ_resid / (sd(ℓ) · √n)`，其中残差 `ε − η` 的标准差 `σ_resid = √(0.05² + 0.10²) ≈ 0.112`，`sd(ℓ) ≈ 0.35`。于是 n = 6 时 se ≈ 0.112/(0.35 × 2.45) ≈ 0.13；n = 40 时 ≈ 0.051；n = 200 时 ≈ 0.023。乘上 `meta_lr = 0.5`，每轮注入 β 的噪声约为 0.065、0.025、0.011——6 个样本的噪声与我们要消除的偏好（0.5 的几分之一）同量级，所以过冲几乎必然发生。
3. 示例：

```python
def audit_judge(judge, audit, rng):
    ...
    beta_hat = sxr / sxx if sxx > 0 else 0.0
    n = len(audit)
    resid_var = sum((r - rbar - beta_hat * (x - xbar)) ** 2
                    for x, r in zip(xs, rs)) / max(1, n - 2)
    se = math.sqrt(resid_var / sxx) if sxx > 0 else float("inf")
    ...
    return beta_hat, agree_rate, agree, n_pairs, se

# run_regime 中：
        if regime == "meta" and abs(beta_hat) >= 2 * se:
            judge.length_bias -= cfg.meta_lr * beta_hat
```

代价：小审计集下元裁判几乎永远"不敢动"，β 停在 0.5 附近，`meta` 退化成 `frozen`——这正是 skill 文件要求"至少 200 个样本"的原因：不是统计洁癖，而是太小的审计集要么乱修、要么不修。

### Q12 — 参考答案

1. 核心函数（在 `run_regime` 里用它替代"随机两条配对"）：

```python
def length_controlled_pair(probs, judge, rng, rho: float, n: int = 4):
    cands = [sample_response(probs, rng) for _ in range(n)]
    scores = [judge.score(c, rng) for c in cands]
    s_max, s_min = max(scores), min(scores)
    hi_band = [c for c, s in zip(cands, scores) if s >= (1 - rho) * s_max + rho * s_min]
    lo_band = [c for c, s in zip(cands, scores) if s <= (1 - rho) * s_min + rho * s_max]
    chosen = min(hi_band, key=lambda c: c.length)     # 高分带里最短的
    rejected = max(lo_band, key=lambda c: c.length)   # 低分带里最长的
    return chosen, rejected
```

ρ = 0 时 `hi_band` 只含最高分、`lo_band` 只含最低分，退化为 Yuan 等人的"最高对最低"。ρ 越大，分数带越宽，"最短"和"最长"的权重越大。注意 ρ 过大（接近 0.5）时两个带重叠，同一条回答可能既是 chosen 又是 rejected，需要加去重。预期结果：ρ 在 0.3 左右能显著抵消 β = 0.5 的偏好，但它是一条**手写**的规则——它编码的信息是"人类事先知道偏好的方向是长度"，而不是从数据里发现的。
2. 把标签换成另一个同 β 的裁判：

```python
shadow = Judge(length_bias=judge.length_bias)
rs = [judge.score(it.response, rng) - shadow.score(it.response, rng) for it in audit]
```

两者的长度项相同、相减后只剩噪声差，`rs` 与长度不相关，β̂ ≈ 0（在 ±se 内晃），`judge.length_bias` 几乎不变，`meta` 退化为 `frozen`。这就是"同权重换提示"的元裁判在本模拟器里的样子，也是 Wu 等人人类 Spearman 几乎不动（0.315 → 0.326）的机制性解释。
3. 第 1 问说明：不用任何额外模型、只靠一条编码了人类先验的规则，就能部分抵消偏好——信息来自人。第 2 问说明：多加一层"裁判的裁判"，如果它没有新信息，β̂ 恒为 0，什么都修不了。两相对照，起作用的是"循环外的信息"（人工标签或人类先验），不是层数。

### Q13 — 参考回答要点

- **定义**：同一组权重既作答又用 LLM-as-a-Judge 准则评判，然后在自己评判出的偏好对上做迭代 DPO（Yuan 等人，ICML 2024）。
- **与 RLHF 的区别**：偏好对的**来源**。RLHF 的偏好来自人类标注（再训练一个冻结的奖励模型）；自我奖励的偏好来自当前策略自己的评判。讲义："偏好对从哪来，是自我奖励与 RLHF 的分界。"
- **数字**：Llama 2 70B 三轮，AlpacaEval 2.0 胜率 9.94% → 15.38% → 20.44%，超过 GPT-4 0613（15.76%）、Claude 2（17.19%）、Gemini Pro（16.85%）；裁判一致率 65.1% → 81.7%。
- **副作用**：平均长度 1,092 → 2,552 字符；论文自己承认长度"可能是相对表现的一个因素"，并把奖励投机列为开放问题；只跑了三轮、单一设置、未做安全评估。
- 加分点：说出"裁判只被顺带训练"这一结构性事实，为 Q14 铺垫。

### Q14 — 参考回答要点

- **饱和机制**：EFT 种子固定，M1 之后没有任何信号纠正裁判的偏好；候选挤到准则顶端，平手被丢弃，剩余分差由非质量因素解释。
- **学到偏好的机制**：Δs = Δq + β·ΔL/1000 + 噪声；当候选质量接近时，长度项主导偏好对，DPO 把"长"的对数概率拉高；下一轮同一组权重更相信长就是好。模拟器：β = 0.5 时长度项值 0.46 分，大于 0.28 的质量差。
- **与阶段 18 · 02 的不同**：那里的代理（奖励模型）是冻结的，代理与真实之间的差距是一个固定目标，Gao 等人可以画出"代理涨、真实先涨后跌"的曲线；这里代理与策略**同步漂移**，差距在代理指标上完全看不见——讲义称之为"自我确认循环"（Chen 等人 2026）。
- 加分点：指出 Wu 等人的证据——平均分 4.1 → 4.7+、人类 Spearman 几乎不动，而 GPT-4 一致率却升到 79.33%。

### Q15 — 参考回答要点

按 `outputs/skill-judge-drift-monitor.md`：

1. **审计集**：至少 200 个样本 / 100 对，从初始分布按长度分桶抽，人工标注并报告标注者间一致率，哈希冻结，只追加不替换。
2. **四个信号**，每轮用当前裁判算：审计集上的裁判—人类一致率（红灯：胜率升而它连续两轮持平/下降）；长度均值与 p90（单轮 >20% 或累计 >50%）；分数通胀（平均分距顶端不足一分；裁判减人类差距连续两轮扩大）；偏好对熵与平手比例（熵 <1 bit 或平手 >50%，而自身偏好对一致率仍高）。
3. **停机**：任何红灯在下一次 DPO 之前暂停；具名人员审查、决定重训/换提示/回滚、在流水线外记录；自身偏好对上的一致率不能解除红灯。
4. **元裁判检查**：一句话说出它有什么裁判没有的信息；若只是同权重换 prompt，标为无锚点。

直接否决：没有外部人工审计集（"用 GPT-4 做第二裁判"只是另一个 LLM 裁判）；只在本轮生成的偏好对上算一致率；把长度控制说成学出来的；N 小时后自动恢复；让裁判标注新样本来扩充审计集。

### Q16 — 参考回答要点

- **修好了**：裁判被显式训练（元裁判产出评判偏好对），LC 胜率 22.92% → 39.44%，比带长度控制的 Self-Rewarding（35.49%）多约 4 个点；Arena-Hard 20.6% → 29.1%；长度控制让平均长度稳定在 2,000 字符左右。

- **对"元-元裁判"的回应**：同权重叠层只会让错误相关而不是抵消；Wu 等人为此还得按长度过滤评判对。先问一句"它有什么裁判没有的信息"；没有就不加层，而是加审计集（人工标签）、执行结果或形式化验证器。

### Q17 — 参考回答要点

按 Chen 等人的层级从强到弱：

1. **形式化验证器**（Lean 等）：聊天/写作几乎不可用，但其中的事实性子问题（数值、日期、代码片段）可以抽出来验证。
2. **执行与测试**：代码评审任务可以跑测试；写作任务可以执行"约束检查"（字数、格式、引用是否存在、链接是否可达）——廉价且不可被语言风格讨好。
3. **与策略无关的外部信号**：真实用户的后续行为（追问率、采纳率）、不同家族模型组成的裁判团（降低错误相关性，但仍是 LLM 裁判，只能作次级信号）。
4. **现有的人类数据**：公开偏好数据集的保留集/held-out 子集当作审计集；它不新鲜，但它不是循环产生的。
5. **人类先验做成规则**：Wu 等人的长度控制就是这种"零标注预算的锚"；要如实标为手写约束并逐轮记录参数。

常见误区：把"再加一个 LLM 裁判"当作根基；把循环自己生成的偏好对当作评估数据。最后要说：如果以上都没有，就不该闭环——这正是本阶段的主题"先学会测量这个循环，再决定是否闭合它"。
