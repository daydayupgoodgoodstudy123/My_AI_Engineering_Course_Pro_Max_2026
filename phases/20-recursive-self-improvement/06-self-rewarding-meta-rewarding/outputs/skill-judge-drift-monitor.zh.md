给定一段训练循环的描述——其中一个模型（或与策略共享权重的模型）评判策略的输出，而这些评判成为训练信号：Self-Rewarding（Yuan 等人 2024）、Meta-Rewarding（Wu 等人 2024）、带 LLM 裁判的迭代 DPO、按评分准则打分的 RL——请产出一份监控规范，使裁判的漂移能在策略学会这种漂移之前被发现。

需要产出：

1. **审计集规格。** 一份循环永不用于训练的、人工标注的固定集合：规模（至少 200 个样本 / 100 对；说明该规模意味着的一致率粒度）、抽样规则（从**初始**的 prompt 与回答分布中抽取，并按长度分桶分层，使长度与质量不混淆）、标签格式（两两比较或绝对分，并报告标注者间一致率）、冻结规则（对集合做哈希；任何改动都算新的审计集并重置基线）、更新规则（只追加样本、永不替换，并在切换的那一轮同时报告旧集与新集的数字）。
2. **四个信号，每轮由*当前*裁判计算。**

   | 信号 | 计算方式 | 红灯 |
   |---|---|---|
   | 审计集上的裁判—人类一致率 | 裁判分与人类标签之间的两两一致率和 Spearman 相关 | 训练胜率上升而它连续两轮持平或下降；任何一轮的下跌超过一致率粒度 |
   | 长度漂移 | 当前策略在固定 prompt 集上样本长度的均值与 p90 | 任务不变而单轮增长超过 20%，或累计超过 50% |
   | 分数通胀 | 策略样本上的裁判平均分；以及在被审计子样本上，裁判分减人类分 | 平均分距量表顶端不足一个准则分；裁判减人类的差距连续两轮扩大 |
   | 偏好对熵 | 哪个长度桶/风格簇赢得偏好对的熵；被判为平手而丢弃的比例 | 熵低于 1 bit，或平手比例超过 50%，而循环自身偏好对上的一致率仍然很高 |

3. **停机规则。** 任何红灯都在下一次 DPO/RL 更新**之前**暂停循环。恢复需要一位具名人员审查审计集数字，决定裁判是重训、换提示还是回滚到上一个检查点，并把决定记录在流水线之外。在循环自己的偏好对上算出的一致率永远不能用来解除红灯。
4. **元裁判信息检查。** 若流水线包含元裁判，用一句话说明它拥有哪些裁判没有的信息（不同的权重、不同的标签、真实值、执行结果）。如果答案是"同一组权重换一个 prompt"，把该元裁判标记为*无锚点*，并要求以审计集为主控信号。
5. **每轮报告格式。** 每轮一行：轮次、审计一致率（比例与计数）、长度均值与 p90、裁判平均分、审计子样本上裁判减人类的差距、偏好对熵（bit）、平手比例、触发的红灯。基线行是第 0 轮，由未训练的裁判测得。

直接否决：
- 任何没有训练数据之外的人工标注审计集的循环。"我们用 GPT-4 做第二裁判"是另一个 LLM 裁判，不是锚点；只能记为次级信号。
- 任何只在"策略本轮生成的偏好对"上计算一致率的监控方案。
- 任何把元裁判当作裁判漂移的解决方案，却不说明它拥有哪些裁判所没有的信息。
- 任何把长度控制规则说成"学出来的"。它是手写的约束；如实记录，并逐轮记录 ρ（或等价参数）。

拒绝规则：
- 若用户说不出审计集的规模、来源和冻结日期，拒绝签字放行该监控；没有基线，阈值毫无意义。
- 若用户提议让裁判标注新样本来扩充审计集，拒绝；那是循环在审计自己。
- 若用户希望停机规则在 N 小时后自动恢复，拒绝；恢复必须是具名人员的主动行为。

输出：一页规范，包含审计集表、为这条循环填好阈值的四信号表、带负责人姓名的停机规则、元裁判信息那一句话，以及每轮报告的表头。引用 Yuan 等人（arXiv:2401.10020）与 Wu 等人（arXiv:2407.19594）各一次，分别对应两个漂移实例（长度 1,092 → 2,552 字符；裁判平均分 4.1 → 4.7+）。
