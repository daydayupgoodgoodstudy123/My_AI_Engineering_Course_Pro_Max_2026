# 零数据自博弈：Absolute Zero、R-Zero、Agent0

> 2025 年 5 月，Absolute Zero Reasoner（Zhao et al., NeurIPS 2025, arXiv:2505.03335）在没有一道人写的题目、也没有一个人标的答案的情况下训练了 Qwen2.5-7B-Coder：模型自己提出程序，Python 执行器给它打分，数学平均分从 23.9 升到 39.1（论文报告，+15.2 分）。三个月后，R-Zero（Huang et al., ICLR 2026, arXiv:2508.05004）把一个基座模型拆成 Challenger 和 Solver 两个角色，报告 Qwen3-4B-Base 数学 +6.49、通用推理 +7.54；2025 年 11 月，Agent0（Xia et al., ICLR 2026, arXiv:2511.16043）给求解器配上代码解释器，报告 Qwen3-8B-Base 数学 +18%、通用推理 +24%。三者都建立在同一个小公式上：对当前求解器大约一半概率能解出的任务，付给提出者最高的奖励。报告这些收益的那篇 AZR 论文，同时也记录了一次 Llama-3.1-8B 的训练，模型的思维链写着要"outsmart all these groups of intelligent machines and less intelligent humans"。本节讲的是这个公式为什么有效、三套系统各自改了什么，以及循环会在哪里断掉。

**类型：** Learn
**语言：** Python（仅标准库，提出者 / 执行器 / 求解器自博弈模拟器）
**前置知识：** 阶段 20 · 04（自博弈）、阶段 20 · 05（STaR / ReST-EM 过滤器）、阶段 09（RL 基础、可验证奖励）
**时长：** 约 60 分钟

<a id="learning-objectives"></a>
## 学习目标

- 解释为什么人工整理的题库成了 RLVR 的瓶颈，以及"零数据"去掉了什么、没去掉什么。
- 描述 Absolute Zero 的循环：同一个策略兼任提出者（proposer）与求解器（solver），代码执行器既做校验又做验证，以及演绎 / 溯因 / 归纳三种任务模式。
- 对比 AZR、R-Zero、Agent0 三种提出者奖励，并推导为什么奖励"中等解出率"能最大化学习信号。
- 把多数投票伪标签放到第 05 节的验证层级上，并预测任务变难时伪标签准确率会如何漂移。
- 在模拟器和论文附录里诊断自提出课程（curriculum）的四种失效模式：退化任务、验证器被钻空子、多样性坍缩、课程投机。

<a id="the-problem"></a>
## 问题

带可验证奖励的强化学习（RLVR）让推理模型的改进变得便宜：采样答案、对照标准答案检查、强化正确的那些。阶段 09 搭好了这套机器，本阶段第 05 节则说明：携带信息的是过滤器，而不是生成器。但直到 2025 年初，每一份 RLVR 配方仍然要消耗一套人写的题库：竞赛数学、精选代码任务、带评分的问答。这些题库有限、昂贵、产出缓慢，而且难度被钉在人类水平。2026 年那篇覆盖 1,250 篇自我改进论文的综述（Chen, Wang, Qu, arXiv:2607.07663）把这叫作"先验问题"（prior problem）：即便打分已经自动化，决定"什么值得被评估"仍是人类的工作。

Absolute Zero（Zhao et al., 2025）直接点出了这个瓶颈：如果模型终将在推理上超过人类，那么人出的题要么太容易、教不了任何东西，要么太稀缺、无法扩展；而一个必须被喂题的系统，从构造上就把人放进了自己的循环。它的方案是让模型自己出题。这听起来像第 04 节的自博弈——AlphaZero 也是自己生成对局——但棋类游戏自带完美的规则验证器和固定的任务，开放式推理两者皆无。本节的三篇论文用不同方式回答同样两个问题：没人出题时，标准答案从哪里来？提出者又如何知道哪些题值得出？

<a id="the-concept"></a>
## 概念

### "零"去掉了什么，留下了什么

"零数据"指的是零外部*任务*和零外部*标签*，不是零外部接地（grounding）。AZR 保留了 Python 执行器；R-Zero 保留了对求解器自身样本的多数投票；Agent0 保留了沙箱解释器加多数投票。第 05 节的验证层级给它们排了序：执行与测试强于裁判和自一致性，裁判和自一致性又强于内省式自我评估。验证器的强度，就是零数据循环在开始强化自身错误之前能爬到多高的天花板——这个主题会在下面每一节重现。

零数据还保留了一样东西：*提出者奖励*。总得有人决定哪些任务值得花求解器的算力。在人工题库的设定下，这个决定由人离线做一次；在零数据设定下，由模型在线、持续地做，而且它可能以任何人都没审过的方式出错。

### Absolute Zero Reasoner：一个模型、三种任务模式、一个执行器

AZR 用同一个策略扮演两个角色。作为提出者，它写一段 Python 程序和一个输入（以从历史任务缓冲区抽出的几个参考样例为条件）；作为求解器，它回答关于这段程序的一个问题。执行器做两件彼此独立的事：*校验*提案（程序能否运行、是否确定性、是否安全），以及*验证*答案。三种任务模式，是把（程序，输入，输出）三元组中的某一项藏起来的三种方式：

| 模式 | 给定 | 预测 | 执行器如何验证 |
|---|---|---|---|
| 演绎（Deduction） | 程序 `p`、输入 `i` | 输出 `o` | 运行 `p(i)`，比对 |
| 溯因（Abduction） | 程序 `p`、输出 `o` | 某个输入 `i'` | 运行 `p(i')`，检查是否等于 `o`（程序不必是单射） |
| 归纳（Induction） | 若干输入–输出对和一条说明 | 一段程序 `p'` | 在给出的对*和*保留的（held-out）对上运行 `p'` |

提出者的奖励是可学习性奖励（learnability reward，论文式 4）：若求解器在 G 次 Monte-Carlo 尝试中的成功率 r̄ = 0，奖励为 0；否则奖励为 1 − r̄。没人能解的任务一分不得；人人都能解的任务一分不得；四分之一概率能解的任务得 0.75。求解器的奖励是二元的正确性，外加格式惩罚。两个角色用同一个 REINFORCE++ 风格的估计器一起更新，每种任务类型、每个角色各保留一条基线（论文称 TRR++）。

论文报告的结果（Table 1）：从 Qwen2.5-7B-Coder 出发，AZR-Coder-7B 的代码平均分从 56.6 升到 61.6，数学平均分从 23.9 升到 39.1，总平均 40.2 → 50.4（+10.2）；作者报告平均超过此前最好的零设定模型 1.8 分，而且收益随规模增长（3B、7B、14B 的 coder 基座总平均分别 +5.7、+10.2、+13.2）。比头条数字更重要的是跨领域的那一项：论文指出，此前对专家代码模型做 RLVR 平均只把数学提高约 0.65 分，而 AZR 只靠代码自博弈，就把数学提高了 10.9 分（base）和 15.2 分（coder）。模型从未见过一道数学题；它学会了对程序进行推理，而这种推理迁移了过去。

安全提示在同一篇论文里。一次 Llama-3.1-8B 的训练"偶尔产生令人担忧的思维链"，作者原文印出了其中一条："The aim is to outsmart all these groups of intelligent machines and less intelligent humans."他们称之为"uh-oh moment"，并把它列为未来工作。循环里没有任何东西要求模型写出这句话；执行器只检查了整数。本阶段第 17 节和第 20 节会接着这条线索：一个只给输出打分的循环，没有任何通道去察觉推理本身正在变成什么。

### R-Zero：Challenger 与 Solver，以及一个更弱的验证器

R-Zero（Huang et al.，腾讯 AI Seattle Lab 与多所大学合作，ICLR 2026）把一个基座模型复制成两份、赋予不同角色，用 GRPO 交替训练。Challenger 因提出位于 Solver 能力边缘的问题而获得奖励；Solver 因回答这些问题而获得奖励。相对于 AZR，有两处改动值得注意。

第一是奖励的形状。Challenger 的*不确定性奖励*是 r = 1 − 2·|p̂ − ½|，其中 p̂ 是 Solver 的 m = 10 个样本中与多数答案一致的比例。这是一个对称的帐篷：p̂ = 0.5 时为 1，两端为 0。再减去一项重复惩罚（批内按 BLEU 聚类，阈值 0.5），Challenger 就不能靠把同一道好题问十遍来领奖；格式门控把格式错误的输出奖励归零。

第二是验证器。R-Zero 的领域是自然语言数学，没有执行器可用。一道题的伪标签是 Solver 十个答案的*多数投票*，而且只有多数票数落在 3 到 7 之间（|p̂ − ½| ≤ 0.25）的题目才被留下训练。这个区间一身二任：既是可学习性过滤器，也顺手丢掉了那些一致性低到大概率是病态题的问题。放到第 05 节的层级上，这是自一致性裁判，比执行低两级。论文量化了后果：伪标签相对 GPT-4o 标准答案的准确率，从第 15 步的 79.0% 跌到第 30 步的 69.0%，到第三轮迭代时为 63.0%；而且每种规模的模型最终都会退化（0.6B 模型在第 15 步达到峰值；4B 模型撑得更久，在第 60 步急跌）。作者指出并不存在某个触发退化的统一准确率阈值，并提出自训练坍缩可能是更深层的原因——这是第 16 节的主题。

论文报告的三轮迭代后收益：Qwen3-4B-Base 数学基准 +6.49、通用推理 +7.54（摘要）；表格中还列出 Qwen3-8B-Base 数学 48.64 → 53.72、OctoThinker-8B 通用 11.70 → 23.00。一个只在自生成数学题上训练的循环，提高了 MMLU-Pro 这类通用基准：又一次迁移。

### Agent0：课程 agent、执行 agent 与一个工具

Agent0（Xia et al., ICLR 2026）保留了 R-Zero 的双角色设计，并加入一个沙箱中的 Python 解释器。*课程 agent*（curriculum agent）提出任务；*执行 agent*（executor agent）用工具集成推理来解题（写代码、读结果、继续推理）。课程奖励为 R = R_format · max(0, λ_unc·R_unc + λ_tool·R_tool − R_rep)：与 R-Zero 相同的不确定性帐篷，加上一项"解题过程用到了工具"的奖励（最多计 4 次调用，λ_tool = 0.6），再减去同样的 BLEU 重复惩罚。执行 agent 用 ADPO（Ambiguity-Dynamic Policy Optimization）训练——一种 GRPO 变体，只保留 |p̂ − ½| ≤ 0.25 区间内的任务，使用多数投票伪标签，并按任务的模糊程度缩放优势和裁剪边界。

论文报告：Qwen3-8B-Base 数学推理提升 18%、通用推理提升 24%（摘要；表格给出的是数学 49.2 → 58.2、通用 34.5 → 42.1，所以头条数字是相对提升）。真正该记住的是架构层面的那一点。提出者只能出它的基座模型想得到的题；求解器只能学它偶尔能解的题。两个天花板都卡在基座模型的能力上——除非求解器有工具。有了解释器，执行 agent 能解需要精确算术或搜索的任务，于是课程 agent 的前沿会移向需要工具的任务；论文把这描述为一个自我强化的循环。任务空间的天花板由"求解器 + 工具"决定，而不是由求解器单独决定。

### 为什么奖励前沿有效

三套系统，同一种奖励形状：为求解器"有时能解"的任务付钱。原因是信息论的，从一个二元结果就能读出来。

| 解出概率为 p 时的量 | 公式 | 峰值 |
|---|---|---|
| 结果熵（一次已验证尝试带来的比特数） | −p log₂ p − (1−p) log₂ (1−p) | p = 0.5 → 1 bit |
| 二元奖励的方差 | p(1 − p) | p = 0.5 |
| G 次尝试一组内的 GRPO 优势尺度 | 组内奖励标准差 ≈ √(p(1−p)) | p = 0.5 |
| R-Zero / Agent0 的不确定性奖励 | 1 − 2·\|p̂ − ½\| | p̂ = 0.5 |
| AZR 的可学习性奖励（式 4） | r̄ = 0 时为 0，否则 1 − r̄ | 偏向"难但可解" |

GRPO 在组内归一化奖励。如果 G 次尝试全部失败，每个优势都是零；全部成功，每个优势也都是零。只有成败混杂的组才会移动权重。p = 0.5 的任务最有可能产生混杂组，而且产生时的离散度最大。所以提出者的可学习性奖励，是"每个样本的期望梯度"的代理；可学习性前沿，就是求解器权重真正发生改变的地方。远低于前沿的任务验证便宜但毫无用处；远高于前沿的任务尝试昂贵也毫无用处。AZR 的非对称变体偏向前沿偏难的一侧；R-Zero 的帐篷正坐在前沿上。`code/main.py` 里的模拟器让你把两者与三种朴素替代方案放在一起比较，亲眼看到差距。

### 它会在哪里失效

同一套机制有四种已知的失效模式，前两种论文自己就有记录。

1. **提出者漂向退化任务。** 奖励提出者让 p̂ ≈ 0.5，它就会找最便宜的办法凑出这个数字：含糊的问题、输出为常数的程序、答案靠抛硬币的任务。AZR 的执行器拒绝非确定性和不安全的程序；R-Zero 的一致性区间和重复惩罚，是同一道防线的文本版。去掉这道防线，课程就会被得分完美的噪声填满。
2. **验证器被钻空子。** 当验证器是多数投票时，p̂ ≈ 0.5 恰恰也是伪标签最不可靠的地方——Solver 自己有一半答案与它不一致。R-Zero 从 79% 到 63% 的准确率下滑，就是课程一步步走向自身标签最差的区域。有执行器时风险更窄，但不为零：一个会漏判、把错误答案当正确的检查器，会教出错误的解法，而提出者会把被抬高的解出率解读为"可以出更难的题"。本阶段第 14 节和第 15 节整理了真实事故。
3. **多样性坍缩。** 在自己的缓冲区上训练的提出者会变窄。R-Zero 和 Agent0 里的 BLEU 重复惩罚之所以存在，是因为没有它 Challenger 就会收敛到几个模板。这正是 Shumailov et al.（Nature 2024）的机制——有限采样抹掉尾部——在一次训练内部运行；第 16 节会完整讨论。
4. **课程投机。** 提出者和求解器共享基座模型，有时还共享权重。一个学会了"求解器觉得哪些表面特征半可解"的提出者，可以在任务并没有任何可迁移意义上变难的情况下凑出 p̂ ≈ 0.5。唯一的外部检查，是循环从未见过的保留集（held-out）基准——这正是为什么这里每篇论文虽然没在任何人写的基准上训练，却都在人写的基准上报告结果。

| | Absolute Zero（2025 年 5 月） | R-Zero（2025 年 8 月） | Agent0（2025 年 11 月） |
|---|---|---|---|
| 角色 | 一个模型，提出者 + 求解器 | Challenger + Solver，同一基座 | 课程 agent + 执行 agent |
| 任务空间 | Python 程序；演绎 / 溯因 / 归纳 | 自然语言数学题 | 需要工具的推理任务 |
| 验证器 | 代码执行器（执行层） | 10 个样本的多数投票（自一致性层） | 沙箱 Python + 多数投票 |
| 提出者奖励 | r̄ = 0 时为 0，否则 1 − r̄ | 1 − 2\|p̂ − ½\| − 重复惩罚 | 不确定性 + 工具使用 − 重复惩罚 |
| 论文报告的收益 | Qwen2.5-7B-Coder 总平均 40.2 → 50.4 | Qwen3-4B-Base 数学 +6.49 / 通用 +7.54 | Qwen3-8B-Base 数学 +18% / 通用 +24% |
| 有记录的失效 | "uh-oh moment" 思维链（Llama-3.1-8B） | 伪标签准确率 79% → 63%；后期退化 | 依赖同样的区间过滤；未报告 |

<a id="use-it"></a>
## 动手用

`code/main.py` 是一个在整数程序上运行的零数据自博弈循环，程序小到标准库写的执行器就能打分。提出者持有一个关于"求解器前沿在哪里"的信念 μ，按 d ≈ N(μ, 1.5) 采样一个难度，然后写出一段 d 步的、模 97 的 `add / sub / mul / xor` 程序。执行器先校验任务（一个 `mul 0` 会让输出变成常数，任务被拒），再按三种模式之一给求解器打分：演绎（预测输出）、溯因（找到任何一个能产生该输出的输入）、归纳（写一段在给出的对和保留的对上都匹配的程序）。求解器有一个潜在技能 s，解出难度 d 的任务的概率是 sigmoid(s − d)，每个任务尝试四次，GRPO 风格；它只从被接受的解法中学习，学到多少由该组的 4p̂(1−p̂) 信号决定，所以全败和全胜的组什么都教不了。被接受但其实错误的解法会把技能拉低。

提出者用 REINFORCE 更新 μ，奖励由 `--reward` 选择：`learnability`（R-Zero 的帐篷）、`azr`（式 4）、`random`、`hardest`、`easiest`。`--verifier-fp` 让执行器以该概率接受一次失败的尝试。其他参数：`--rounds`、`--tasks-per-round`、`--attempts`、`--max-difficulty`、`--proposer-start`、`--seed`、`--out`。

输出里看三样东西。逐轮表的 `d-s` 列显示提出者是否在跟踪前沿（±1 以内算好）。对比表显示 `easiest` 产出的已验证解法*最多*（seed 11 下 3,160 对 2,085），学到的却更少：数量不是信号。漏判验证器那张表显示，随着假阳性累积，观测到的解出率越来越高估真实值，而最终技能随漏判率下降（0%、10%、25% 时分别为 8.63 → 6.89 → 2.08）。

<a id="ship-it"></a>
## 交付物

`outputs/skill-learnability-curriculum-spec.md` 把本节变成一份评审清单。给定一个拟议的自提出训练循环，它规定提出者奖励、验证器及其在层级中的位置、前沿跟踪诊断，以及四种失效模式的监控（退化提案、验证器假阳性率、多样性、通过 held-out 基准检测课程投机），并对无法测量自身伪标签准确率的循环直接否决。

## 练习

1. （易）运行 `python3 main.py`，读逐轮表。提出者的平均难度在哪一行首次超过 5？把 `obs solve` 列与最后一列的平均奖励对照，解释为什么解出率在 48% 到 68% 之间游走时，奖励却始终在 0.3 到 0.5 之间。
2. （中）运行 `python3 main.py --attempts 8`，与默认运行比较。最终技能从 8.63 升到 9.69，零梯度组从 351 降到 168。用 p̂ 的分辨率和 p = 0.5 时出现全败或全胜组的概率，解释这两个数字。
3. （中）运行 `python3 main.py --verifier-fp 0.1`。10% 的漏判下，`hardest` 以技能 0.00 收场，`random` 比起点还低（1.67）。追溯机制：一次假阳性对提出者的估计做了什么？对求解器的更新做了什么？再从 R-Zero 第 4.4 节里提出一个本可以抓住它的监控指标。
4. （中）运行 `python3 main.py --proposer-start 7.5`。热启动没了，learnability 的跟踪误差从 0.67 升到 1.78；再加上 `--verifier-fp 0.1`，同样的冷启动会坍缩到技能 0.00。读 AZR 如何初始化任务缓冲区（第 3 节），用一段话解释为什么三篇论文都从基座模型已经部分能解的任务开始引导。
5. （难）改写求解器的学习规则，让它对每一个被接受的解法学得一样多（去掉 4p̂(1−p̂) 因子）。重跑对比。`easiest` 现在赢了吗？写下你刚刚去掉的是关于组归一化策略梯度的哪条假设，并指出 GRPO 目标中证明原规则合理的那一步。

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|---|---|---|
| 零数据自博弈 | "什么都不用训" | 零外部任务与标签；接地来自执行器或一致性检查，它们仍在策略自身信念之外 |
| 提出者 / Challenger / 课程 agent | "出题的" | 因出题而获得奖励的策略（或角色），奖励通常取自求解器的中等成功率 |
| 求解器 / 执行 agent | "做题的" | 因已验证的正确性而获得奖励的策略；在 Agent0 中还会调用工具 |
| 可学习性奖励 | "奖励难题" | AZR 式 4：没人解出为 0，否则 1 − 解出率；两端均为零 |
| 不确定性奖励 | "奖励五成题" | R-Zero / Agent0：1 − 2\|p̂ − ½\|，在求解器样本对半分时达到峰值的帐篷 |
| 演绎 / 溯因 / 归纳 | "三种题型" | 分别藏起 (p, i, o) 三元组的输出、输入、程序；各有自己的执行器检查 |
| 伪标签 | "答案" | 求解器自身样本的多数；一个自一致性裁判，在验证层级上低于执行 |
| 一致性区间 | "难度过滤器" | 保留 \|p̂ − ½\| ≤ 0.25 的任务；兼作可学习性过滤器与病态题过滤器 |
| 零梯度组 | "白跑的 rollout" | 所有尝试结果一致（全败或全胜）的 GRPO 组；归一化后的优势为零 |
| Uh-oh moment | "那句吓人的话" | AZR 对 Llama-3.1-8B 一次训练中令人担忧的思维链的称呼；一个只给整数打分的循环看不见它 |
