## 五、参考答案与解析

### Q1 — 答案：C

讲义："evals answer 'can the model do the job?' A/B tests answer 'do users care?' Both are required." A 把两者对调了；B 与讲义"Both required"相反；D 错，eval 可以用规则、LLM-as-judge 或人工，A/B 依赖真实用户行为。

### Q2 — 答案：A

讲义："Controlled-experiments Using Pre-Experiment Data. Regress out pre-period variance before comparing post-period. Typical variance reduction: 30-70%." B 是 SRM 检查的范畴；C、D 与 CUPED 无关。

### Q3 — 答案：D

20 个独立检验、每个 5% 假阳性：期望假阳性数 `20 × 0.05 = 1`；至少一个的概率 `1 − 0.95²⁰ ≈ 64.2%`（已计算）。Bonferroni：`0.05 / 20 = 0.0025`。A 混淆了"期望"和"恰好"；B 忽略了随机性；C 是单个检验的假阳性率。讲义原句"Running 20 A/B tests at 95% confidence produces one false positive by chance"说的是期望值。

### Q4 — 答案：B

讲义："If 50/50 split delivers 47/53, something is broken — SRM check flags it." SRM 往往意味着分流哈希、重定向、日志丢失或机器人过滤只作用于一组等问题，此时实验结果本身不可信。A 忽略了问题（是否"属于随机误差"要用检验判断，见 Q12）；C 会引入选择偏差；D 换统计引擎解决不了数据问题。

### Q5 — 答案：D

该公式给出的是**每组**样本量。`p_treat = 0.03 × 1.05 = 0.0315`，差值只有 0.0015（0.15 个百分点），所以需要每组约 20.8 万、合计约 41.5 万用户。A 是常见误解（代码输出没写"per arm"，容易误读）；B 混淆了用户数与转化数；C 是下一行的 290,782。

### Q6 — 答案：A

`simulate` 的循环 `for _ in range(max_n)` 每次只给一组加一个样本，最终 `n_a + n_b = 300,000`（输出 `A=150026, B=149974`）。每组约 15 万 < 固定检验所需 207,702，功效本来就不足 80%；序贯边界此时约为 4.31（远高于 1.96），更难越过。观测到 `p_a = 2.941%`、`p_b = 3.100%`，差异方向正确但不显著。B 错：z 统计量是标准的合并方差公式；C 错：用的是 `abs(z)`，双向检测；D 不是根本原因——即使换种子，大多数情况下也停不下来。

### Q7 — 答案：B

这是经典的 peeking 问题。我们用 numpy 做了 300 次 A/A 模拟（每次 6 万样本、p = 3%、与代码相同的"两组都 > 100 后每步检查"规则）：每步用 1.96 → 约 **51%** 的模拟至少一次越线；只在最后看一次 1.96 → 5%；代码的序贯边界 → 约 0.3%。A、C、D 都与实测不符。

### Q8 — 答案：C

观测提升 `4.940 / 2.284 − 1 ≈ 116%`，真实提升 50%；而且 `p_a = 2.284%` 明显低于真实的 3%。原因是序贯检验在"噪声恰好把差距推大"的时刻停止，停止时的点估计系统性偏大。工程上应报告校正后的估计或置信区间，或在停止后继续收集一段数据。A 错：问题来自停止规则，不是随机数；B 错：代码没有 CUPED；D 错：这是估计偏差，不是第一类错误。

### Q9 — 参考答案

1. 实际运行：每组 **207,702**；乘以 1.4 后每组 **290,782**（两组合计约 58 万）。基线越低、提升越小，所需样本量越大——2% 的相对提升需要每组 1,279,744。
2. 三处改进：
   - **参数没用到**：`alpha`、`power` 是函数参数，但 `z_alpha = 1.96`、`z_beta = 0.84` 写死了，传别的值不会生效；
   - **截断**：`int(num / den)` 向下取整，样本量应向上取整（`math.ceil`），否则功效会略低于目标；
   - **口径**：返回的是每组样本量，输出文字没说明，容易被当作总量（Q5）；而 `simulate` 的 `max_n` 又是总量，两者口径不一致。
   - 另外 `z_beta = 0.84` 是 `0.8416` 的近似。
3. 精确值：`z_{0.975} = 1.95996`、`z_{0.8} = 0.84162`，向上取整后每组 **207,938**（2% 提升 1,281,194；10% 提升 53,211）。与代码相差约 0.1%，实践中可以忽略，但"参数不生效"是真正的 bug。

```python
from statistics import NormalDist
import math

def sample_size_per_arm(p0, rel_lift, alpha=0.05, power=0.80):
    p1 = p0 * (1 + rel_lift)
    za = NormalDist().inv_cdf(1 - alpha / 2)
    zb = NormalDist().inv_cdf(power)
    pb = (p0 + p1) / 2
    num = (za * math.sqrt(2 * pb * (1 - pb)) + zb * math.sqrt(p0 * (1 - p0) + p1 * (1 - p1))) ** 2
    return math.ceil(num / (p1 - p0) ** 2)
```

### Q10 — 参考答案

```python
import statistics

def cuped_adjust(y: list[float], x: list[float]) -> tuple[list[float], float]:
    mx = statistics.fmean(x)
    theta = statistics.covariance(x, y) / statistics.variance(x)
    return [yi - theta * (xi - mx) for xi, yi in zip(x, y)], theta
```

要点：

- θ 应在**两组合并**的数据上估计（或至少用与处理无关的方式估计），两组使用同一个 θ；
- 调整后两组均值之差的期望不变（因为 `X` 是实验前数据，与分组独立，`E[X − X̄]` 在两组相同），所以无偏；
- 调整后方差 = `Var(Y)(1 − ρ²)`。

实际验证：我们生成 20,000 个样本、使 ρ² ≈ 0.6，`Var(y) = 8.956`、`Var(y_adj) = 3.595`，比值 0.401，与 `1 − 0.6 = 0.4` 吻合。

练习 5：方差变为原来的 40%，在同样的检测精度下所需样本量也变为 40%，相当于有效样本量提升 `1 / 0.4 = 2.5` 倍。（讲义原题"a pre-period with 60% of the variance of post"表述含糊；按"实验前指标解释 60% 的方差"理解。）

3. **过于保守的代价**：第一类错误只有约 0.3%，远低于名义 5%，意味着"浪费"了统计功效——需要更多样本才能检测到真实效应。代码中的 10% 提升案例在 n = 159,731 才停下，而固定样本检验每组只需 53,150（合计 106,300）。序贯检验并不总是更快；它的优势在于效应大时能早停，以及允许随时查看。

### Q12 — 参考答案

```python
import math

def srm_check(n_a: int, n_b: int, expected: float = 0.5) -> tuple[float, float]:
    n = n_a + n_b
    ea, eb = n * expected, n * (1 - expected)
    chi2 = (n_a - ea) ** 2 / ea + (n_b - eb) ** 2 / eb
    p_value = math.erfc(math.sqrt(chi2 / 2))       # 自由度 1 的卡方分布尾概率
    return chi2, p_value
```

实际计算：

| (n_a, n_b) | χ² | p 值 | 结论 |
|-----------|----|------|------|
| (4700, 5300) | 36.0 | 约 2.0 × 10⁻⁹ | 严重 SRM，必须排查 |
| (470, 530) | 3.6 | 约 0.058 | 在 0.05 水平下不显著（常用的 SRM 阈值更严，如 p < 0.001） |
| (150026, 149974) | 0.009 | 约 0.92 | 正常 |

同样是 47/53，样本越大，偏离越不可能是随机波动。SRM 检查通常用很严格的阈值（如 p < 0.001），因为它是"数据是否可信"的前置检查，而且会在每个实验上反复执行。代码中 `rng.random() < 0.5` 的分流是独立伯努利分配，理论上不会 SRM；真实系统中的 SRM 来自哈希函数、缓存、重定向、日志丢失等工程问题。

### Q13 — 参考回答要点

- **eval 的边界**：固定数据集、固定判分标准，回答"能力是否达标、有没有回归"；但数据分布与真实用户不同，判分标准（含 LLM-as-judge）与用户偏好不一定一致，也测不到转化、留存、成本等业务指标。
- **A/B 的价值**：在真实用户上随机分组，因果地回答"用户/业务指标是否变化"。讲义案例：奖励模型变体带来对话长度 +70%、留存 +30%；Nextdoor 主题行实验在调整奖励函数后 CTR +1%。
- **只做 A/B 不行**：A/B 慢且昂贵、会把用户暴露给可能有问题的版本；eval 要先把明显的回归挡在门外（讲义："Evals catch regressions before exposure; A/B confirms product impact after"）。
- **LLM 的特殊性**：非确定性让方差更大（样本量 ×1.3–1.5）；多目标（质量、成本、时延）需要主指标 + 护栏指标。
- 加分点：说出完整链路——离线 eval → shadow → canary（上一节）→ A/B → 全量。

### Q14 — 参考回答要点

- **原理**：用一个与实验期指标 Y 相关、但不受实验处理影响的协变量 X（通常是同一用户在实验前的同一指标），构造 `Y_adj = Y − θ(X − E[X])`，`θ = Cov(X, Y) / Var(X)`。这等价于用 X 对 Y 做回归后取残差（加回均值）。
- **方差**：`Var(Y_adj) = Var(Y)(1 − ρ²)`，ρ 是 X 与 Y 的相关系数；讲义：典型降幅 30–70%。
- **为什么无偏**：X 在实验开始前就已确定，与随机分组独立，两组的 `E[X]` 相同，因此减去的项在两组期望相同，不改变处理效应的期望。
- **注意事项**：
  - 协变量必须是**实验前**的数据，不能受处理影响（否则会引入偏差）；
  - 新用户没有实验前数据，需要缺失值处理（如用 0 并加指示变量）；
  - θ 用合并数据估计，两组使用同一个 θ。
- 加分点：说明 CUPED 在 Statsig、GrowthBook 中都已实现；对 LLM 功能可以用"用户过去 N 天的使用次数/满意度"作为协变量。

### Q15 — 参考回答要点

- **偷看问题**：固定样本检验的 5% 假阳性率只在"预先定好样本量、只看一次"时成立。如果每天看一次、显著就停，每次查看都是一次"中奖机会"，累积假阳性率远超 5%（本节 A/A 模拟中每步查看约 51%）。
- **序贯检验**：使用随样本量变化的边界（mSPRT、confidence sequences 等 always-valid 方法），保证"在任意时刻停止"的第一类错误率仍不超过 α；也可以用 alpha spending（如 O'Brien-Fleming）只在预定的几个时间点查看。
- **代价**：边界更宽，同样效应需要更多样本才能显著（本节代码的 10% 提升案例比固定检验需要更多样本）；提前停止导致效应高估（本节 50% 案例观测为 116%）。
- **工程选择**：预期效应大、需要快速决策时用序贯；效应微小时用固定样本设计并严格遵守（skill："Sequential if you expect strong signals; fixed if the change is subtle"）。
- 加分点：能用 A/A 模拟验证任何停止规则的第一类错误率。

### Q16 — 参考回答要点

- **主指标**：每个已解决工单的成本 = 总 LLM 成本 ÷ 已解决工单数（比值指标，方差估计要用 delta method 或按用户/工单聚合）；也可以把"解决率"和"单位成本"作为联合决策指标。
- **护栏指标**（不能显著变差）：首次解决率、用户满意度 / 负反馈率、转人工率、时延 P99、拒答率、安全违规率。
- **次要指标**：平均对话轮数、输出 token 数、重复联系率。
- **设计**：按用户（或按工单）随机，避免同一用户在两组间切换；计算样本量并 ×1.4；有历史数据就开 CUPED（协变量如该用户过去的工单数）；预先注册停止规则；做 SRM 检查。
- **决策规则**（skill 文件）："primary significant + all guardrails not significant-negative → ship; any guardrail breach → do not ship regardless of primary"。
- 加分点：考虑混合方案——用路由（阶段 17 · 16）把简单工单给便宜模型、复杂工单给贵模型，单独作为第三个实验组。

### Q17 — 参考回答要点

- **先区分两个问题**：canary 回答"稳定吗"（时延、错误、成本、硬性指标没有越线），A/B 回答"更好吗"。canary 通过只说明没有明显故障，不代表业务指标没有下降。
- **先检查数据质量**：SRM、埋点是否一致、实验是否达到预定样本量、是否因偷看提前停止、是否存在新奇效应。
- **看统计显著性与置信区间**：−1.2% 是否显著？置信区间是否包含 0？若显著为负，按 skill 的决策规则不应上线。
- **升级标准（示例）**：
  - 主指标显著下降 → 不上线，回到 canary 前状态；
  - 不显著但点估计为负 → 延长实验或增加样本，同时权衡新模型带来的其它收益（成本、时延）；
  - 若业务方仍坚持上线，需要书面记录理由（skill："documented no-A/B exception"），并设定上线后的监控与回滚条件。
- 加分点：分群分析（新/老用户、不同任务类型）找原因，但要注意多重比较校正；不要事后挑选显著的子群当作结论。
