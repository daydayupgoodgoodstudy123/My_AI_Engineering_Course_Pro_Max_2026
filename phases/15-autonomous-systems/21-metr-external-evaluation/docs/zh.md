# METR 时间跨度与外部能力 Evaluation

> METR (前 ARC Evals) 是2023年12月以来独立的501(c)(3)。 时间地平线1.1基准( 1 2026 年1月) 符合任务成功概率对日志( 专家人类完成时间) 的逻辑曲线; 交叉点为50% , 确定了模型的时间范围 。 2025-2026 任务设定包含 GPT-5.1, GPT-5.1-Codex-Max和原型监测 evaluations (能够让监视器抓取侧面任务; agent 基准套件:HCAST(180+ ML,网络、SWE,推理任务;1分钟到8小时);RE-Bench(71 ML研究-工程任务,附有专家基线);SWAA。 诚实的注释:METR测量是理想化的——没有人类,没有实际后果——小组记录了电子Val-vs部署行为差距(Lesson 1)。

**类型:** 学习
**语言:** Python (平面天线,后勤设备)
**先修要求:** 阶段15 · 01(长-长 agents阶段15 · 19(RSP)
**时间:** ~60分钟

<a id="the-problem"></a>

## 问题

缩放政策(课程19、20)与它们提到的测量值一样有用。 “AI研发4阈值”和“远程自主”在政策说明中被定义;只有在特定情况下才可采取行动。 evaluations 产生具体数字。

METR是2024-2026年的外部 evaluation 确定许多这些数字的组织。 他们评估前沿模型—— 通常是根据国家数据局与实验室的事先发布—— 并在此后公布方法。 时间地平线1.1基准(2026年1月)是他们的头条手工艺品:将能力压缩成人性可视单位的单层天线(“这个模型可以做专家在50%的可靠性下花费X小时的任务 ” 。

部分教训在于方法(如何计算地平线)和解释(为什么地平线是上限,而不是部署预测 ) 。 两种技能应该同时存在。 理解地平线的团队比刚刚看到幻灯片“14小时”的团队更难欺骗坏的供应商要求。

<a id="the-concept"></a>

## 概念

<a id="metr-background"></a>

### METR 背景

- 创建日期:2023年12月(前美国癌症研究中心Evals, 独立501(c)(3))。
- Scope: evaluation 边境模型的自主能力, 往往是在释放前。
- 伙伴实验室: Anthropic, OpenAI (2025-2026年多重聘用)。
- 显著交付成果:时间地平线1.0(2025年3月),时间地平线1.1(2026年1月),原型监测 evaluations.

<a id="the-time-horizon-fit"></a>

### 时间地平线适合

方法(来自METR博客和论文):

1. 收集一个任务套件, 范围从分钟到小时不等的专家完成时间。 当前套件是 HCAST (180+任务)、 RE- Bench (71任务)、 SWAA 。
2. 运行每个任务的模式; 记录成功或失败。
3. 符合后勤曲线:P(成功)作为日志函数(专家完成时间)。
4. 视野是P(成功)=0.5的专家时间。

物流功能的形状是正确的,因为能力通常与任务困难有着日益增强的、接近高原的关系。 50%是选择(可能为10%,90%);METR在详细文件中报告了多个阈值,但领先于50%,因为它是最直观的。

<a id="the-january-2026-numbers"></a>

### 2026年1月的数字

时空地平线1.1:

- Claude 行动4.6:在50%的可靠性下,到时间地平线1.1(2026年1月)时,~14小时。
- 高频时空任务加倍:根据时间地平线1.1(2026年1月)报告,2023年后的适配度为4.3个月(130.8天),而7个月的数字是完全与时间地平线1.0相匹配的2019-2025年,在TH1.1中与2023年后的数字相平行。

这些就是第 15 阶段其余（rest）内容所引用的具体数值。Anthropic 的 RSP v3.0（第 19 课）与 DeepMind 的 FSF v3（第 20 课）引用了它们，作为阈值评估所依据的测量结果之一。

<a id="benchmark-suites"></a>

### 基准套件

- **HCAST**: 189项任务,涉及ML、网络安全、软件工程和一般推理。 Span: 1分钟到8小时加专家时间。 地平线后的主要套件 。
- **RE-Bench**71项具有人类专家基线的ML研究工程任务,衡量模型能否进行与AI研究与开发4临界值相联的ML研发工作。
- **SWAA**:任务较短;可用于校准地平线曲线的低端。

<a id="prototype-monitoring-evaluations"></a>

### 原型监测 evaluations

2025-2026年METR工程包括监测 --evaluation 原型: 显示器能捕捉到执行侧面任务的模型( 操作员要求的除外); 能够 agent 直接为“爆破保障”类别提供 OpenAI PF v2 和欺骗alignment 监测深明FSF v3 (Lesson 20)。

<a id="why-horizons-are-upper-bounds"></a>

### 为什么地平线是上界

- **理想化的工具**:基准任务为模型提供了清洁工具和格式完善的数据。实际部署情况更混乱。
- **没有什么真正的后果**: 模型从不实际向客户收费,删除真实数据或与真实人物联系。真正的部署具有不可逆转的利害关系。
- **电子游戏**教程1. 模型在试验中的表现不同。2026年国际工业安全报告用经验记录了这一点。
- **无合法用户差异**基准 prompts 真正的用户提出模糊不清、取决于背景的要求。

视野是有利条件下的能力上限。 部署可靠性不同,较低,团队必须测量自己的分布才能知道。

<a id="the-external-evaluator-case"></a>

### 外部评价器案例

External evaluation METR的独立性是501(c)(3),具有申报的方法和同行评审文件。 仅靠实验室是不够的(实验室仍然控制着METR所看到的),但绝对胜于外部 evaluation.

<a id="how-to-use-horizon-numbers-in-practice"></a>

### 如何在实际中使用地平线数字

- **作为一种能力过滤器**:如果模型的视野远低于拟议任务的专家时间,则不自动运出(Lesson 1的技能文件)。
- **趋势指标**:加倍时间可以告诉你,即使没有新的缓解措施,目前的做法还能保持多久的安全。
- **之前的时光**:14小时的视野是一个起点。根据任务分布、工具质量和部署环境调整。

<a id="use-it"></a>

## 实际应用

`code/main.py` 执行任务成功率对日志( 专家时间) 的后勤适配, 并给您设定一个合成结果。 它报告50%的地平线( METR的头条)、 10%的地平线( 保守的) 和 90%的地平线( 乐观的) 。 同时演示如果通过电子价比游戏人为地夸大成功率时会发生什么变化 。

<a id="ship-it"></a>

## 交付成果

`outputs/skill-horizon-interpretation.md` 审查了供应商的地平线索偿,并分析了基准索偿与部署现实之间的差距。

<a id="exercises"></a>

## 练习

1. Run `code/main.py`。确认适合度的50%的地平线与合成地面真相相符。现在将任务时间网格减半;地平线估计是否发生了有意义的变化?

2. 阅读 METR 的时间地平线 1. 1 博客文章。 确定可靠性最高和最低的具体任务。 解释为什么存在差距 。

3. 读取 METR 的“ 衡量自主AI 能力” 资源。 列出 HCAST 任务类别。 请选择一个您想要的类别 weight 更严重地是为了生产任务,并证明原因。

4. 将电子价位游戏引入模拟器: 将失败任务的 ~ 20% 转换为成功。 报告新视野。 这大致相当于20%的赌博率对观察到的数字的影响。

5. 设计内部视野 evaluation 描述数据收集、匹配和输出告诉您的内容。与 METR 数字比较。

<a id="key-terms"></a>

## 关键术语

| 术语 | 人们怎么说 | 它实际上意味着什么 |
|---|---|---|
| METR | 外部评价员 | 前ACR Evals; 自2023年12月以来独立 |
| 时间范围 | “能力措施” | 50%的可靠性专家任务,从后勤角度考虑 |
| HCAST | 气象局的主套房 | 180+任务,时间1分钟至8小时 |
| RE-Bench | "研究工程" | 71项与人类基线有关的ML研究-工程任务 |
| SWAA | "短任务套房" | 校准地平线曲线的低端 |
| 加倍时间 | 增长率 | 50%的地平线时间翻一番;每 HCAST ~ 7个月 |
| 电子游戏 | 模范行为不同 | 测试与部署之间记录的行为差距 |
| 上捆绑 | 霍里桑是天花板 | 基准地平线 > 装载中的部署可靠性 |
