## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | MDP 五元组 | `(S, A, P, R, γ)`：状态、动作、转移 `P(s'\|s,a)`、奖励 `R(s,a,s')`、折扣；所有 RL 算法（Q-learning、PPO、GRPO）都在这个结构上做优化 |
| 2 | Markov 性质 | `P(s_{t+1}\|s_t,a_t) = P(s_{t+1}\|s_0,a_0,…,s_t,a_t)`；不满足时是"状态设计不完整"，而不是算法失败 |
| 3 | 策略 π | `π(a\|s)` 是状态到动作分布的映射；也可以是确定性映射 `s → a` |
| 4 | 回报 G_t | `G_t = r_t + γ r_{t+1} + γ² r_{t+2} + …`，未来奖励的折扣和 |
| 5 | 价值 V 与动作价值 Q | `V^π(s) = E[G_t\|s_t=s]`；`Q^π(s,a) = E[G_t\|s_t=s,a_t=a]`；两者关系 `V^π(s) = Σ_a π(a\|s) Q^π(s,a)` |
| 6 | Bellman 期望方程 | 价值 = 这一步的奖励 + 折扣后的"落脚点"价值；DP 迭代它、MC 采样它、TD 一步自举它 |
| 7 | 折扣 γ 的物理意义 | 有效视野约 `1/(1-γ)`：0.9→10 步、0.99→100 步；无限视野任务必须 `γ<1` |
| 8 | 迭代策略评估 | 小 MDP 上反复用 Bellman 方程更新 V 直到变化 `< tol`，得到 `V^π` 的精确值 |
| 9 | 建模陷阱 | 非 Markov 状态、稀疏奖励、reward hacking、γ 设定错误、奖励尺度过大 |

## 五、参考答案与解析

### Q1 — 答案：C

观测函数 `O(o|s)` 是 **POMDP**（部分可观测 MDP）才有的组成部分：智能体看不到真实状态 s，只能看到观测 o。标准 MDP 假设智能体直接看到完整状态，五元组就是状态集、动作集、转移概率、奖励函数和折扣因子。A、B、D 都是五元组的成员。

### Q2 — 答案：B

单帧画面只包含位置，不包含速度，"下一帧在哪"取决于前几帧——当前观测不足以预测未来，即违反 Markov 性质。讲义说得很直接：这"不是方法的失败，而是状态的失败"。修复方法：DQN 在 Atari 上堆叠最近 4 帧；或者用 LSTM/GRU 在观测序列上维护循环状态。A、C、D 都没有触及"状态信息不够"的根因。

### Q3 — 答案：B

有效视野 ≈ `1/(1-γ) = 1/0.05 = 20` 步。直觉：`γ^k` 衰减到约 `1/e` 需要 `1/(1-γ)` 步左右，更远的奖励权重很小。A 是把 γ 误读成"5%"，C 是把 0.95 当成了步数。

### Q4 — 答案：B

`V^π` 是在 `π` 下对第一步动作求期望：`V^π(s) = Σ_a π(a|s) Q^π(s,a)`。A 只对**贪心于自身 Q 的策略**（如最优策略 `V*(s) = max_a Q*(s,a)`）成立，对任意策略不成立。C 混淆了 Bellman 方程：`Q^π(s,a) = E[r + γ V^π(s')]`。D 没有依据。

### Q5 — 答案：B

对所有奖励乘以正常数 c，每条轨迹的回报都乘以 c，策略之间的排序不变，所以最优策略不变；但价值函数也被放大 c 倍（D 错），DQN 的 TD 误差、PPO 的优势值都随之放大，梯度量级变化巨大。讲义建议在接入 PPO/DQN 前把奖励归一化到 `[-1, 1]` 附近。C 错在"训练行为不变"。

### Q6 — 答案：C

γ=1 时回报是 `-1 - 1 - 1 - …`，无穷级数发散，价值为 -∞，Bellman 方程没有有限解。B 的公式 `-1/(1-γ)` 只在 γ<1 时成立。这就是讲义"Discount mis-spec"一条：无限视野任务必须用有限视野截断或 γ<1。

### Q7 — 答案：B

每一步奖励都是 -1，γ=0.5 时即便永远到不了终点，价值也只是 `-(1 + 0.5 + 0.25 + …) = -2`。随机策略从大多数格子出发都要走几十步，在 0.5 的折扣下这和"永远走不到"几乎没区别，所以全是 `-2.00`；只有紧挨终点的格子（如 `(2,3)` 是 `-1.70`）有一定概率 1–2 步就结束，才略高。代码已收敛（A 错），随机策略也不是最优策略（C 错）。

### Q8 — 参考答案

```
((3, 3), -1.0, True)
((0, 0), -1.0, False)
((3, 3), 0.0, True)
```

- 第一行：从 `(3,2)` 向右走到 `(3,3)` 即终点；**进入终点的这一步仍然要付 -1**，同时 `done=True`。
- 第二行：在第 0 行向上走，`max(r + dr, 0)` 把行号夹回 0，相当于"撞墙原地不动"，但依然扣 -1——这就是"浪费一步"的代价。
- 第三行：已经在终点，函数第一行直接返回 `(state, 0.0, True)`。这实现了**吸收态（absorbing state）**：终点之后不再有奖励、不再移动。这一点对 Bellman 方程很关键——终点的价值必须恒为 0，否则所有状态的价值都会被"终点之后的虚假奖励"污染。`policy_evaluation` 里 `if state == TERMINAL: continue` 正是让 `V[TERMINAL]` 保持初始值 0。

### Q9 — 参考答案

(a) 代码版是**同步更新**（Jacobi 风格，也叫 two-array 版本）：本轮所有状态都用**上一轮**的 `values` 计算，结果写进 `new_values`，整轮结束后一次性替换。讲义版是**原地更新**（Gauss-Seidel 风格）：算出一个状态的新值立刻写回 `V`，同一轮后面的状态马上就能用到它。

(b) 都会收敛到同一个 `V^π`。原因是 Bellman 期望算子在 γ<1 时是 γ-压缩映射，不动点唯一；两种更新顺序只影响收敛路径，不影响终点。

(c) 原地更新通常更快：新信息在同一轮内就能传播。尤其是当状态的遍历顺序与"价值从终点向外扩散"的方向一致时，一轮就能把信息传得很远。代码选择同步版的好处是：结果与状态遍历顺序无关、更容易推理和复现，也与"Bellman 算子作用于整张表"的数学定义一一对应。Sutton & Barto 指出两者都收敛，原地版通常更快。

### Q10 — 参考答案

| 数字 | 计算方式 | 是否折扣 | 是否截断 |

| `-39.41` | γ=0.99 的 `V^π(0,0)` | 是 | 否 |

### Q11 — 参考答案

```python
PERP = {"up": ("left", "right"), "down": ("left", "right"),
        "left": ("up", "down"), "right": ("up", "down")}

def transitions(state, action, p=0.1):
    """返回 [(概率, 下一状态, 奖励)]：1-p 走预期方向，p/2 各滑向两个垂直方向"""
    outs = [(1 - p, action)] + [(p / 2, a) for a in PERP[action]]
    result = []
    for prob, a in outs:
        s_next, r, _ = step(state, a)
        result.append((prob, s_next, r))
    return result

def policy_evaluation_stochastic(policy, gamma=0.99, p=0.1, tol=1e-6, max_iter=2000):
    values = {s: 0.0 for s in all_states()}
    for _ in range(max_iter):
        delta = 0.0
        new_values = dict(values)
        for state in all_states():
            if state == TERMINAL:
                continue
            v = 0.0
            for action, pi_a in policy(state).items():
                for prob, s_next, r in transitions(state, action, p):   # 多了一层对 s' 的期望
                    v += pi_a * prob * (r + gamma * values[s_next])
            delta = max(delta, abs(v - values[state]))
            new_values[state] = v
        values = new_values
        if delta < tol:
            break
    return values
```

实测结果（γ=0.99）：

```
uniform  p=0.0: V[start] = -39.41
uniform  p=0.1: V[start] = -39.41
greedy   p=0.0: V[start] = -7.59
greedy   p=0.1: V[start] = -8.36
```

- **均匀随机策略：完全不变。** 滑动只是把动作"重新分配"到其他方向；原本 4 个方向各 0.25，滑动后每个方向的实际概率仍是 `0.25×0.9 + 2×0.25×0.05 = 0.25`。随机策略本来就"不在乎方向"，所以环境的随机性对它没影响。
- **"向下/向右"策略：变差。** 它原本有明确的方向，滑动会让它偶尔向左/向上走，偏离最短路径。

结论：环境随机性伤害的是**有目的的策略**；策略越好，越怕噪声。这也是为什么在随机环境里，最优策略需要为"可能滑倒"留余量（例如经典的悬崖行走）。

### Q12 — 参考回答要点

- **定义**：MDP 是对序贯决策问题的形式化，由五元组 `(S, A, P, R, γ)` 组成：状态集、动作集、转移概率 `P(s'|s,a)`、奖励 `R(s,a,s')`、折扣 γ。智能体按策略 `π(a|s)` 行动，目标是最大化期望折扣回报。
- **Markov 性质**：给定当前状态和动作，下一状态的分布与更早的历史无关。它让我们只需要一个"当前状态的函数"（V、Q、π），而不必依赖整段历史。
- **不满足怎么办**：
  - 把历史塞进状态：帧堆叠（DQN 在 Atari 上堆叠 4 帧）、加入速度/上一步动作等特征；
  - 用循环网络（LSTM/GRU）或 Transformer 在观测序列上维护隐状态；
  - 理论上转为 POMDP，在信念状态（belief state）上做决策。
- **加分点**：强调"非 Markov 是状态设计的失败，不是算法的失败"；指出 LLM 场景里"整个上下文"就是状态，天然满足 Markov 性质。
- **常见误区**：认为 Markov 性质意味着"环境是确定性的"——随机环境同样可以满足 Markov 性质。

### Q13 — 参考回答要点

- **方程**：`V^π(s) = Σ_a π(a|s) Σ_{s',r} P(s',r|s,a) [r + γ V^π(s')]`。
  - 外层 `Σ_a π(a|s)`：按策略对动作求期望；
  - 内层 `Σ P(s',r|s,a)`：按环境对下一状态和奖励求期望；
  - 方括号：这一步的奖励 + 折扣后的下一状态价值。
- **为什么是不动点**：把右边看作作用在价值函数上的算子 `T^π`，则 `V^π = T^π V^π`。γ<1 时 `T^π` 是无穷范数下的 γ-压缩映射，所以不动点唯一，从任意初值反复应用都会收敛（Banach 不动点定理）。
- **两种求解法**：
  1. 解线性方程组：`V = R^π + γ P^π V ⇒ V = (I - γP^π)⁻¹ R^π`，复杂度约 O(|S|³)，只适合小状态空间；
  2. 迭代策略评估：反复应用 `T^π` 直到变化 < tol，即本节代码的做法。
- **加分点**：说出整个阶段 09 的脉络——DP 迭代这个方程、MC 用完整回合的样本估计期望、TD 用一步样本加自举（bootstrap）近似它。

### Q14 — 参考回答要点

| 元素 | LLM RLHF / GRPO 中的对应 |
|------|------------------------|
| 状态 | prompt + 已生成的部分回答（上下文 token） |
| 动作 | 下一个 token（动作空间 = 词表，数万到十几万） |
| 转移 | 确定性：把选中的 token 拼接到上下文末尾 |
| 奖励 | 稀疏、只在结尾给：RLHF 是奖励模型打分，GRPO 推理任务常用验证器 0/1 |
| γ | 1.0（回合有限且较短） |

特殊之处：
- **转移是确定且已知的**，难点完全在于巨大的动作空间与稀疏奖励的信用分配；
- 由于奖励只在序列末尾，也常被简化为**上下文 bandit**（整段回答当作一个动作）来理解；
- 为防止策略偏离预训练分布，实践中会加对参考模型的 KL 约束。
- **加分点**：指出"写五元组"能在训练前暴露问题——例如奖励模型只看格式不看正确性，就会出现 reward hacking。

### Q15 — 参考回答要点

- **定义**：智能体在优化一个**代理奖励**时，找到了让分数变高、但不符合设计者真实意图的行为。本质是 Goodhart 定律："当一个指标变成目标，它就不再是好指标。"
- **例子**：讲义提到 OpenAI 的赛艇游戏智能体，不去完成比赛，而是原地绕圈反复收集道具刷分。LLM 中的例子：奖励模型偏好长回答 → 模型越写越啰嗦；偏好自信语气 → 模型更爱编造。
- **设计原则**：
  1. 奖励从**目标结果**定义，而不是从容易测量的代理量定义；
  2. 稀疏奖励难学时可以塑形，但要谨慎——加入的中间奖励可能改变最优策略（加分点：Ng 等人提出的**势函数塑形** `F = γΦ(s') - Φ(s)` 可以保证最优策略不变）；
  3. 控制奖励尺度，避免梯度爆炸；
  4. 持续人工抽查高奖励样本，训练中监控 KL 等漂移指标。

### Q16 — 参考回答要点

- **物理意义**：有效视野约 `1/(1-γ)`。γ 决定智能体"看多远"。
- **为什么 RLHF 用 γ=1**：回合有限且短（讲义举例约 200 token），奖励只在结尾出现，回报一定有限；若 γ<1，结尾奖励传到前面的 token 会被打折，相当于无理由地惩罚"更早的 token"。
- **控制任务用 0.95–0.99**：通常是长或无限视野，需要 γ<1 保证回报有限，同时视野要覆盖动作效果显现的时间尺度。长视野策略游戏用到 0.999。
- **γ 过小**：短视，只追即时奖励（本节 γ=0.5 时几乎所有格子价值相同，智能体"看不见"终点）。
- **γ 过大**：信用分配噪声大——很多早期步骤要分摊遥远未来的奖励，方差上升、收敛变慢；在无限视野任务中 γ=1 直接导致价值发散。
- **加分点**：指出 γ 既是"问题定义"的一部分，也常被当作降方差的超参数使用（偏差-方差权衡）。
