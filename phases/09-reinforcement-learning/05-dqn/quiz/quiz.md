## 五、参考答案与解析

### Q1 — 答案：B

讲义：回放"breaks temporal correlation (successive frames are nearly identical), lets the network learn from rare rewarding transitions many times, and decorrelates consecutive gradient updates"。SGD 假设样本近似独立同分布，而连续帧几乎一样、且分布随策略变化，直接按顺序训练会让网络过拟合最近的经历、遗忘之前的经历。A、C 与回放无关；D 说反了——回放之所以可行，正是因为 Q-learning 是 off-policy 的（旧策略产生的数据仍可用）。

### Q2 — 答案：B

如果目标 `r + γ max Q(s', ·; θ)` 和预测 `Q(s, a; θ)` 用同一组参数，每次更新 θ 都会同时移动目标，回归目标永远在变，容易振荡或发散。目标网络让目标在 C 步内固定，近似变成一个普通的监督回归问题。动作选择用的是在线网络（A 错）。

### Q3 — 答案：B

Sutton & Barto 提出的致命三角：函数近似（不同状态共享参数，更新一个会影响其他）+ 自举（目标依赖当前估计）+ off-policy（训练分布 ≠ 目标策略分布）。三者同时出现时没有收敛保证。C 是 DQN 用来缓解它的技巧。

### Q4 — 答案：C

Double DQN 把"选"和"评"拆开：用**在线网络** θ 选 `argmax`，用**目标网络** θ⁻ 评估该动作的值。A 是不用目标网络的朴素版；B 是标准 DQN（选与评都用 θ⁻）；D 把两者用反了。

### Q5 — 答案：B

裁剪统一了不同游戏的奖励量级，使"同一套超参解决几十个游戏"成为可能（讲义：Atari 奖励从 1 到 1000+ 不等）。代价是丢失大小信息：在很多任务里，回报大小正是目标的一部分（比如交易收益），裁剪会改变最优策略，所以 C 错。讲义："Wrong when reward magnitude matters; fine for Atari where only sign matters."

### Q6 — 答案：B

`V + A` 有一个自由度：`V' = V + c`、`A' = A − c` 给出完全相同的 Q，网络无法从 Q 的监督信号中唯一确定 V 和 A。减去 `mean_a A(s,a)`（原论文也讨论过减 max）把 A 的均值固定为 0，使分解可辨识。讲义术语表："Decompose Q = V + A − mean(A); same output, better gradient flow."

### Q7 — 答案：A

`ep=100`：`1.0 − 100/200 = 0.5`；`ep=250`：`1.0 − 1.25 = −0.25`，被 `max(0.05, …)` 截到 0.05。ε 在第 190 回合降到 0.05 后保持不变。B 忘了 `max` 的下限。

### Q8 — 参考答案

(a) **676 个参数**：
- `W1`：32 × 16 = 512
- `b1`：32
- `W2`：4 × 32 = 128
- `b2`：4

合计 `512 + 32 + 128 + 4 = 676`。对比：表格 Q 需要 16 × 4 = 64 个数。这里网络比表格还大——在玩具环境中函数近似并不省参数，它的意义在于状态空间巨大、需要**泛化**的场景。

(b) `max(0.0, z)` 是 ReLU。它的导数：`z > 0` 时为 1，`z ≤ 0` 时为 0。因为 `h = max(0, z)`，`h > 0` 当且仅当 `z > 0`，所以反向传播里用 `if h[j] > 0` 判断导数是否为 1，不需要额外保存 z。不满足条件的隐藏单元，`grad_h[j]` 保持 0，梯度在此"截断"。

### Q9 — 参考答案

(a) 损失 `L = ½(q[a] − y)²`，对 `q[a]` 求导得 `q[a] − y`，即 `td_error`。写成 `½` 正是为了让导数没有系数 2。注意这里的 `td_error` 符号与第 04 节相反（第 04 节 `δ = target − Q`），所以这里做的是**梯度下降**：参数 `-= lr × 梯度`。

(b) 网络输出 4 个 Q 值，但损失只涉及**实际执行的动作 a** 的那一个输出 `q[a]`，其他动作的输出没有出现在损失里，梯度为 0；而 `q[a] = b2[a] + Σ_j W2[a][j]·h[j]` 只依赖第 a 行。所以只更新 `dW2[a]`、`db2[a]`。对隐藏层而言，梯度也只经由 `W2[a]` 这一行传回：`grad_h[j] = td_error × W2[a][j] × ReLU'`。

(c) DQN 把目标 `y` 当作**常数**——不对它求梯度。这叫**半梯度（semi-gradient）**方法。原因：①y 是用目标网络 θ⁻ 算出来的，θ⁻ 不参与训练；②即使不用目标网络，TD 方法的标准做法也是只对预测 `Q(s,a;θ)` 求导，对目标求导（"残差梯度"方法）在实践中通常学得更慢、在随机环境下还会收敛到错误的解。在 PyTorch 中，这对应于用 `torch.no_grad()` 计算目标或对目标调用 `.detach()`。

### Q10 — 参考答案

```python
        if done:
            y = r
        else:
            # Double DQN：在线网络选动作，目标网络评估
            q_next_online, _ = forward(online, state_features(s_next))
            a_star = max(range(len(q_next_online)), key=lambda i: q_next_online[i])
            q_next_target, _ = forward(target, state_features(s_next))
            y = r + gamma * q_next_target[a_star]
```

要点：
- 多了一次在线网络对 `s'` 的前向传播（计算量增加，但不需要新网络）。
- `a_star` 由在线网络决定；评估用目标网络。若某动作只在其中一个网络中被噪声高估，它被选中后会由另一个网络给出"较冷静"的估值，从而削弱 `max` 的上偏。
- 与第 04 节的 Double Q-learning 对比：那里维护两张对等的表并随机交替更新；DDQN 直接复用 DQN 已有的 online/target 两个网络，是"drop-in replacement"（讲义）。
- 要看到效果，需要讲义练习 3 那样的**带噪声奖励**环境；本节确定性环境中两者差别很小。

### Q11 — 参考答案

**不能说明它们没用**，原因在于这个环境太"友好"：

1. **one-hot 输入 ≈ 查表**：16 维 one-hot 状态下，每个状态只激活 `W1` 的一列，不同状态的输入层权重互不共享（只有 `b1`、`W2`、`b2` 是共享的），函数近似带来的"更新一个状态、干扰另一个状态"的泛化效应比 Atari 的卷积网络弱得多——致命三角中"函数近似"这一角被大大削弱。
2. **确定性、奖励恒为 -1**：目标几乎没有噪声，量级也很小（Q 值在 -1 到 -7 之间）。
3. **轨迹很短**：一个回合几步到几十步，样本相关性的危害有限；网络很小，学习率适中。

在 Atari 这种场景下情况完全不同：输入是高维像素，卷积网络在相似画面之间强烈泛化；连续帧几乎相同，按顺序训练会严重过拟合；奖励稀疏而多变。讲义："Without it, … diverges on Atari."

能体现价值的实验设计（任选）：
- 把 one-hot 换成**连续/共享特征**（如归一化坐标 `[r/3, c/3]`，或更大的网格配上粗编码），让网络必须泛化；
- 加大学习率（如 0.2）或折扣（γ=0.999），放大自举误差的传播；
- 用更大的网格（如 20×20）和稀疏奖励，让轨迹更长、相关性更强；
- 多个随机种子统计：记录最大 |Q| 是否发散、回报方差是否增大，而不是只看单次运行的均值。

### Q12 — 参考回答要点

- **改动**：Q 表 → 神经网络 `Q(s, ·; θ)`（一次前向输出所有动作的 Q 值）；表格更新 → 对 TD 目标做回归（梯度下降）；再加上三个稳定性技巧。
- **经验回放**：①打破样本时间相关性，使 SGD 的独立同分布假设近似成立；②每条转移可以被多次使用，提高样本效率，尤其是稀有的奖励转移；③平滑数据分布，避免网络追着当前策略的分布跑。
- **目标网络**：把移动的回归目标冻结 C 步（Atari 约 1 万环境步），切断"更新 θ → 目标变化 → 再更新 θ"的正反馈环。
- **奖励裁剪**：统一梯度量级，使一套超参通用。
- **加分点**：说出 Atari DQN 的具体配置（4 帧堆叠、约 1M 回放容量、1 万步同步、ε 从 1 衰减到 0.1/0.01）；提到 Huber 损失（对大 TD 误差用线性惩罚，相当于梯度裁剪）。

### Q13 — 参考回答要点

- **三要素**：函数近似、自举、off-policy。
- **为什么发散**：
  - 函数近似 → 更新 `Q(s,a)` 会改变其他状态的 Q（泛化）；
  - 自举 → 目标 `r + γ max Q(s', ·)` 依赖自身估计，误差会被带进目标、再被学进估计；
  - off-policy → 训练数据的状态分布不是目标策略的分布，被高估的 `s'` 未必会被充分更新纠正。
  - 三者叠加会形成正反馈：经典的 Baird 反例中，即使是线性函数近似也会让参数趋向无穷。
- **DQN 是缓解而非解决**：目标网络削弱了自举的正反馈，回放让分布更平稳，但没有理论收敛保证。讲义 Pitfalls："DQN mitigates with target net + replay; do not remove either."
- **加分点**：提到 Gradient-TD 等有收敛保证的方法、离线 RL 中保守 Q 学习（CQL）针对分布外动作的过高估计。

### Q14 — 参考回答要点

- **原因**：目标里的 `max_a' Q(s', a'; θ⁻)` 对一组含噪估计取最大值，`E[max] ≥ max E`，被噪声抬高的动作更容易被选中；自举又把高估传播到前面的状态，层层累积。
- **Double DQN**：`y = r + γ Q(s', argmax_a' Q(s', a'; θ); θ⁻)`——选动作用在线网络，评估用目标网络。两个网络的误差不完全相关，选中的"幸运高估"动作在另一个网络中不一定被高估。
- **不需要额外网络**：DQN 本来就有 online 和 target 两个网络，DDQN 只是改变了它们在目标中的分工；代价仅是多一次前向传播。讲义："Drop-in replacement, consistently better. Use it by default."
- **加分点**：区分 Double Q-learning（两张对等的表交替更新）与 Double DQN（复用 target 网络）；TD3 在连续控制中用"两个 critic 取最小"进一步压制高估。

### Q15 — 参考回答要点

按优先级排查：
1. **目标网络**：是否真的在用 θ⁻ 计算目标？同步频率是否过高（≈没有目标网络）或过低（目标过时）？讲义经验：约为训练总步数的 1/100，Atari 为 1 万步；或改用软更新 τ。
2. **Double DQN**：Q 值持续上升往往是最大化偏差，切换到 DDQN。
3. **损失与梯度**：用 Huber 损失代替 MSE；加梯度范数裁剪（如 10）；降低学习率。
4. **奖励尺度**：裁剪或归一化奖励；讲义："the gradient magnitude is proportional to reward magnitude."
5. **终止 / 截断处理**：done 时是否误用了自举？超时截断是否被当成终止？
6. **回放缓冲区**：是否有足够的预热（讲义：几千条再开始训练）？容量是否太小导致数据高度相关？
7. **探索**：ε 衰减是否太快，导致陷入局部？
8. **状态表示**：是否满足 Markov 性质（是否需要帧堆叠）？观测是否归一化？
- **监控指标**：平均最大 Q 值、TD 误差、梯度范数、评估回报（ε=0）、多种子曲线。
- **加分点**：先在小环境（CartPole 或本节 GridWorld）与已知正确答案对照，再上复杂环境。

### Q16 — 参考回答要点

- **动作空间**：每一步的动作是一个 token，词表有数万到十几万；DQN 需要对每个动作输出 Q 值并取 max，而 LLM 的语言模型头本身就是一个**策略**（输出 token 分布），直接用策略梯度微调它最自然。
- **奖励结构**：奖励通常只在整段回答结束时给出（奖励模型或验证器），讲义 Use It 表："Sequence-level, not step-level; different loss." 基于 token 级自举的 Q 学习在这种稀疏、长序列的信用分配上很困难。
- **稳定性与约束**：PPO 的裁剪、对参考模型的 KL 约束能直接限制策略偏离预训练分布；DQN 的 `argmax` 是贪心的，与"保持生成多样性和流畅性"的需求冲突，也容易被奖励模型的漏洞利用。
- **工程**：on-policy 采样 + 策略梯度更容易在大规模分布式系统上扩展；GRPO 进一步去掉了价值网络，用组内相对奖励做基线。
- **加分点**：DQN 的思想并没有消失——目标网络 / 软更新出现在 SAC、TD3，回放思想出现在离线 RL 和 AlphaZero 的自对弈缓冲区；在推荐系统等"大但离散、奖励即时"的场景中，DQN 类方法仍有应用。
