## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | DP 的前提 | 已知模型：可以对任意 `(s, a)` 查询 `P(s'\|s,a)` 和 `R`；没有模型时才需要 MC/TD 等 model-free 方法 |
| 2 | 策略评估 | 对固定策略反复应用 Bellman **期望**方程，得到 `V^π` |
| 3 | 策略改进 | 对 `V^π` 取贪心：`π(s) ← argmax_a Σ P [r + γV(s')]`；新策略不会比旧策略差 |
| 4 | 策略迭代（PI） | 评估 ↔ 改进交替，直到策略不再变化；外层迭代次数少，但每次评估要跑到收敛 |
| 5 | 值迭代（VI） | 直接迭代 Bellman **最优**方程 `V(s) ← max_a Σ P [r + γV(s')]`，最后一次性提取贪心策略 |
| 6 | 压缩映射 | `‖TV − TV'‖∞ ≤ γ‖V − V'‖∞`：γ<1 ⇒ 唯一不动点 + 几何收敛；γ=1 需要有限视野或吸收终止态 |
| 7 | 广义策略迭代（GPI） | 价值与策略相互逼近的统一框架；Q-learning、actor-critic、PPO 都是 GPI 的实例 |
| 8 | 同步 vs 原地更新 | Jacobi（两份表）易分析；Gauss-Seidel（原地）实践中收敛更快 |
| 9 | 工程细节 | 终止态守卫、用 sup-norm 判收敛、稳定的 tie-break、状态空间爆炸（约 10⁷ 以上要用函数近似） |

## 五、参考答案与解析

### Q1 — 答案：B

DP 需要**已知模型**（转移概率和奖励）且状态空间可枚举。B 的需求分布已知 → 转移概率可算；1000×4 的规模一次扫描微不足道。A 只能交互采样（无模型），C 的状态空间（像素）无法枚举，D 的状态空间是"所有可能的 token 序列"，天文数字。它们都需要 model-free 方法或函数近似。

### Q2 — 答案：C

VI 的迭代只依赖价值表本身（`max_a` 已经隐式包含了"当前最好的动作"），**只需在最后提取一次**贪心策略，代码中 `value_iteration` 正是收敛后才调用 `greedy_from_V`。A、B、D 都正确：PI 评估用期望方程、VI 用最优方程；PI 外层少但每层贵；两者有同一个不动点 `V*`。

### Q3 — 答案：A

`V* = TV*` 是不动点，所以 `‖V_k − V*‖∞ = ‖TV_{k−1} − TV*‖∞ ≤ γ‖V_{k−1} − V*‖∞`，递推得 `γ^k ‖V₀ − V*‖∞`——**几何（线性）收敛**。这也解释了为什么 γ 越接近 1 收敛越慢：γ=0.99 时误差每次只缩小 1%。

### Q4 — 答案：B

收敛保证（压缩性）是在无穷范数下给出的。用平均变化量判断，可能出现"大部分状态已稳定、少数关键状态（例如离终点很远的状态）还在大幅变化"，平均值却已经很小的情况，导致过早停止。B 正确，其他选项不是根本原因。

### Q5 — 答案：B

当两个动作 Q 值相等时，它们都是最优的，策略在其中任意切换都不改变价值；但 `new_policy == policy` 的判断会因为平局被随机打破而频繁为 False，导致外层循环不停止（或跑到上限）。讲义建议用稳定的 tie-break（按固定顺序取第一个）。Python 的 `max(ACTIONS, key=...)` 恰好在相等时返回**第一个**，天然稳定。

### Q6 — 答案：C

GPI 指"价值估计"与"策略改进"交替/同时进行、彼此趋向一致的一类方法。Q-learning（Q 估计 + 隐式贪心策略）、Actor-Critic（critic 估值 + actor 改进）、异步值迭代都属于此类。线性回归的正规方程是一次性的最小二乘求解，没有策略、也没有价值-策略的相互改进。

### Q7 — 答案：B

每个状态对每个动作枚举后继并求和：`|S| × |A| × (后继数)`。本节后继数是常数 3，所以与 `|S|·|A|` 成正比，这也是讲义说的 `O(|S|·|A|)`。如果转移是**稠密**的（每个 `(s,a)` 可以到任意 `s'`），则是 `O(|S|²·|A|)`（C），这在大状态空间下更加昂贵。

### Q8 — 参考答案

```
[((0, 2), -1.0, 0.9), ((0, 1), -1.0, 0.05), ((1, 1), -1.0, 0.05)]
[((3, 3), 0.0, 1.0)]
```

- 第一个元素永远是预期方向：`(0,1)` 向右到 `(0,2)`，概率 `1 − 0.1 = 0.9`。
- `perpendiculars("right")` 返回 `("up", "down")`：向上撞墙停在 `(0,1)`，向下到 `(1,1)`，各 `0.1/2 = 0.05`。
- 终止态返回唯一结果 `(自身, 0 奖励, 概率 1)`，构成吸收态。
- 注意元组顺序是 `(s', r, p)`，与讲义一致；`q_value` 中解包写成 `for s_next, r, p in ...`。

### Q9 — 参考答案

(a) **`V(0,0) = -100`。** "向上"的滑动方向是左/右，永远不会向下，所以第 0–2 行的状态**永远到不了终点**，每一步 -1 一直持续：`-(1 + 0.99 + 0.99² + …) = -1/(1−0.99) = -100`。实测第一轮评估结果正是 `V00 = -100.0`。这种永不终止的策略叫"不恰当策略（improper policy）"。

(b) 价值从 0 向 -100 收敛，每次扫描误差只缩小 1%（γ=0.99），需要约 `ln(10⁻⁶)/ln(0.99) ≈ 1375` 次扫描才能让单次变化 < 1e-6（实测第 1、2、3 轮分别 1329、1313、1056 次）。而且每轮 `policy_evaluation` 都从 `V=0` 重新开始。对比之下，最优策略很快到达终点，价值只有 -6 左右，信息从终点向外传播几步就稳定，VI 只要 15 次扫描。实测 PI 外层 5 轮共约 3700 次内层扫描，远多于 VI 的 15 次——"外层迭代少"不等于"总计算量少"。

(c) `sweeps` 每个外层迭代加 1，统计的其实是**外层迭代次数**，与返回值 `it + 1` 完全重复，而且从未被使用（死代码）；名字也误导（并不是内层扫描次数）。改进：
- 让 `policy_evaluation` 返回实际扫描次数，累加到 `sweeps` 并一并返回，便于完成讲义练习 2 的"比较扫描次数"；
- 用上一轮的 V 热启动策略评估，而不是每次从 0 开始；
- 选更好的初始策略（例如随机策略或对 V=0 的贪心策略）。

### Q10 — 参考答案

实测的 Q 值（收敛后）：

```
(0, 0) {'up': -7.314721, 'down': -6.428252, 'left': -7.314721, 'right': -6.428252} down
(0, 1) {'up': -6.378494, 'down': -5.47811, 'left': -7.215451, 'right': -5.433337} right
```

(a) 由于网格和终点关于主对角线对称，`(0,0)` 处 down 和 right 的 Q 值**完全相等**。`max(ACTIONS, key=...)` 在相等时返回迭代顺序中**第一个**最大值，`ACTIONS = ("up", "down", "left", "right")` 中 down 在 right 之前，所以选 down。这就是讲义说的"稳定 tie-break"。

(b) 预期方向的结果几乎一样，差别在**滑动**：
- 选 down：滑向左到 `(0,0)`（-6.43，倒退），滑向右到 `(0,2)`（-4.43）；
- 选 right：滑向上撞墙留在 `(0,1)`（-5.43），滑向下到 `(1,1)`（-4.42）。

right 的滑动结果整体更好（"贴墙走"时，往墙的方向滑只是原地不动，而不会倒退），所以 `Q(right) = -5.433 > Q(down) = -5.478`。这说明在随机环境中，最优策略不仅看"想去哪"，还要看"失手时会去哪"。

### Q11 — 参考答案

```python
from main import states, TERMINAL, ACTIONS, q_value, greedy_from_V, value_iteration


def modified_policy_iteration(k, gamma=0.99, tol=1e-6, max_outer=10000):
    V = {s: 0.0 for s in states()}
    policy = {s: "up" for s in states()}
    total_sweeps = 0
    for outer in range(max_outer):
        # 1) 截断的策略评估：只做 k 次扫描，并且从上一轮的 V 热启动
        for _ in range(k):
            for s in states():
                if s == TERMINAL:
                    continue
                V[s] = q_value(s, policy[s], V, gamma)
            total_sweeps += 1
        # 2) 策略改进
        new_policy = greedy_from_V(V, gamma)
        # 3) 停止条件：策略稳定，且 V 已满足 Bellman 最优方程
        bellman_gap = max(
            abs(max(q_value(s, a, V, gamma) for a in ACTIONS) - V[s])
            for s in states() if s != TERMINAL
        )
        if new_policy == policy and bellman_gap < tol:
            return V, policy, outer + 1, total_sweeps
        policy = new_policy
    return V, policy, max_outer, total_sweeps


V_star, _, _ = value_iteration(gamma=0.99, tol=1e-10)
for k in (1, 2, 5, 10, 50):
    V, pi, n_outer, n_sweeps = modified_policy_iteration(k)
    err = abs(V[(0, 0)] - V_star[(0, 0)])
    print(f"k={k:2d}: outer={n_outer:3d}  sweeps={n_sweeps:4d}  |V(0,0)-V*(0,0)|={err:.1e}")
```

实测输出：

```
k= 1: outer= 15  sweeps=  15  |V(0,0)-V*(0,0)|=5.2e-07
k= 2: outer= 10  sweeps=  20  |V(0,0)-V*(0,0)|=5.1e-07
k= 5: outer=  7  sweeps=  35  |V(0,0)-V*(0,0)|=2.2e-08
k=10: outer=  6  sweeps=  60  |V(0,0)-V*(0,0)|=9.0e-12
k=50: outer=  6  sweeps= 300  |V(0,0)-V*(0,0)|=6.8e-12
```

解读：
- **k=1 ≈ 值迭代**：评估一步就改进，相当于每次扫描都对当前贪心动作做一次备份，外层迭代数 15 与 VI 的 15 次扫描一致。
- **k 越大，外层迭代越少**（趋近策略迭代的 5–6 轮），但**总扫描数越多**：每轮评估的大部分扫描都浪费在"把一个马上要被替换的策略评估得很精确"上。
- 关键还有**热启动**：同样是"评估到很精确"，从上一轮 V 出发的 k=50 只用了 300 次扫描，而代码里每次从 0 开始的 PI 用了约 3700 次。
- 结论：评估/改进的最佳平衡通常在中间——不必把每个中间策略评估到底，这正是 GPI 思想的体现。

### Q12 — 参考回答要点

- **PI**：评估（Bellman 期望方程迭代到收敛）→ 改进（对 `V^π` 贪心）→ 重复直到策略不变。外层迭代少（讲义：通常 5–20 轮），每轮代价高；可在有限步内**精确**终止。
- **VI**：直接迭代 Bellman 最优方程，每次扫描便宜，但需要更多次扫描；收敛是渐近的，靠阈值 ε 停止，最后提取贪心策略。
- **选择**：
  - 状态少、动作多、γ 接近 1 时，PI 的外层少的优势更明显（也可用线性方程组精确求解评估步）；
  - 实现简单、只要近似最优时，VI 更常用；
  - 实践中多用折中的**修正策略迭代**（评估只做 k 步）。
- **加分点**：指出二者都是 GPI 的特例；VI 也可以理解为"评估只做 1 步的 PI"。
- **常见误区**：认为 PI "迭代次数少所以更快"——本节代码实测 PI 内层总扫描约 3700 次，VI 只要 15 次。

### Q13 — 参考回答要点

- **VI 收敛**：Bellman 最优算子 T 在 sup-norm 下是 γ-压缩（关键一步：`|max_a f(a) − max_a g(a)| ≤ max_a |f(a) − g(a)|`）。由 Banach 不动点定理，T 有唯一不动点 `V*`，且 `‖V_k − V*‖∞ ≤ γ^k ‖V₀ − V*‖∞`。
- **PI 有限步终止**：
  1. **策略改进定理**：若 `π'` 对 `V^π` 贪心，则对所有 s 有 `V^{π'}(s) ≥ V^π(s)`；若没有严格改进，则 `V^π` 已满足 Bellman 最优方程，即 π 最优。
  2. 确定性策略只有有限个（`|A|^|S|`），且每次严格改进不会回到旧策略，所以有限步内终止。
- **γ=1 的情形**：压缩性丢失，需要有限视野或吸收终止态（且所有策略最终都能终止）来保证收敛——本节 Q9 的"永远向上"策略在 γ=1 下评估就会发散。
- **加分点**：能写出 max 的不等式那一步；能指出实际中 PI 的轮数远小于 `|A|^|S|`。

### Q14 — 参考回答要点

- **思路**：在一个**小型可枚举**的环境（GridWorld、FrozenLake、CliffWalking）上，用 DP 算出精确的 `V*`/`Q*` 和最优策略作为 ground truth。
- **具体做法**：
  1. 同一环境上跑你的 Q-learning，比较 `max_a Q(s₀, a)` 与 `V*(s₀)`；讲义举例：差距 30% 基本可以断定有 bug；
  2. 逐状态比较贪心策略与 DP 最优策略，定位出错的状态（往往在终止态附近 → 检查 `done` 时是否还在自举）；
  3. 检查 γ、奖励符号、终止处理是否与 DP 使用的模型一致；
  4. 在确定性环境中先跑通，再加随机性。
- **加分点**：提到"先在表格环境验证算法逻辑，再上函数近似和大环境"是 RL 工程的标准排错流程；DP 结果也可以用来画学习曲线的"天花板"。

### Q15 — 参考回答要点

- **函数近似**：用神经网络表示 V/Q（DQN、Fitted Q-Iteration），本质是"近似 DP"（approximate DP / neuro-dynamic programming）。
- **采样代替求和**：不枚举所有 `s'`，用样本估计期望——MC（完整回合）和 TD（一步自举）就是"采样版的 DP"。
- **只更新相关状态**：异步 DP、实时 DP（RTDP）、优先级扫描，只备份从起点可达或误差大的状态。
- **规划/搜索**：MCTS（AlphaZero、MuZero）从当前状态出发，在局部搜索树上做 Bellman 风格的备份。
- **离线 RL**：CQL、IQL 等在固定数据集上做"保守的 Q 迭代"。
- **关系**：这些方法几乎都保留了 Bellman 备份这个核心，只是把"精确、全量、已知模型"中的一项或几项换成"近似、局部、采样"。

### Q16 — 参考回答要点

- **原地更新更快的原因**：同一次扫描中，先更新的状态的新值马上被后面的状态使用，信息传播得更远。若扫描顺序恰好与价值传播方向一致（如从终点往外），一次扫描就能把信息传到底。
- **代价**：结果依赖扫描顺序，理论分析稍复杂；同步更新则天然可并行（所有状态独立计算）。
- **进一步加速**：
  - 优化扫描顺序（从终点反向扫描）；
  - **优先级扫描（prioritized sweeping）**：按 Bellman 误差大小用优先队列决定先更新谁；
  - 修正策略迭代、策略评估热启动。
- **异步 DP**：不要求每次扫描遍历所有状态，按任意顺序、任意频率更新个别状态；只要每个状态被无限次更新，仍收敛到 `V*`。这也是 Q-learning 等在线方法的理论基础之一。
- **加分点**：指出本节代码的 `policy_evaluation` / `value_iteration` 都是原地更新，而第 01 节的 `policy_evaluation` 是同步更新，可以对比两者收敛所需的扫描次数。
