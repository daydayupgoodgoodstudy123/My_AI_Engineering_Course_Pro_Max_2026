# 参考答案讲解：LongForm（06/05）

计时结束后再看。参考实现在同目录的 `longform/` 里，`python3 -m pytest --solution --all-parts` 应该显示 5 passed。

## Part 1 修窗口计划

**现象**：解锁后的第一个错误是 `encoder_positions` 里的 ValueError：`a window holds 0 to 3000 mel frames, got -1`。`encoder_positions` 的检查本身没有错。

**顺着往上找**：−1 是 `mel_frames(160)` 算出来的。它用的是课里 `encoder_frames` 的公式 `1 + (n - 400) // 160`，这是不补边的分帧：160 − 400 = −240，Python 的整除向下取整得 −2，再加 1 就是 −1（课后测验 Q10 问的就是这一点）。Whisper 的 STFT 是 center=True，两端各补 200 个样本，帧数是 1 + n // 160，Whisper 再丢掉最后一帧，所以是 n // 160：10 ms 是 1 帧，30 秒正好 3000 帧。这一关想练的是：报错的位置往往不是出 bug 的位置。

**依次修四处**：

1. `mel_frames` 改成 `n_samples // HOP_LENGTH`，和 docstring 一致。
2. `encoder_positions` 改成 `(n_frames + 1) // 2`。第二层卷积 kernel 3、stride 2、padding 1，输出长度是 ⌊(n + 2 − 3) / 2⌋ + 1 = ⌈n / 2⌉：3000 帧是 1500 个位置，201 帧是 101 个。不要写 `round(n / 2)`：Python 的 round 是银行家舍入，`round(0.5)` 是 0。
3. 去掉“之前的窗口里有没有一个包含它”的扫描。每个新窗口都扫一遍所有旧窗口，是 O(n²)，60 小时的录音（8,640 个窗口）要 1.2 秒左右；修好以后只要几毫秒。
4. 去掉扫描以后，30 秒的录音会多出一个 25–30 秒的窗口，这才是根因：`range(0, n, step)` 不管上一个窗口是不是已经到达结尾，都会再起一个窗口。改成“有一个窗口到达结尾就停”，和课里 `chunk_schedule` 的 `if end == total_seconds: break` 一样。也可以改循环的范围：`range(0, max(n - overlap, 1), step)`，起点到了最后一段重叠区就不再起窗口，结果相同。只和上一个窗口比较也能通过，但那是在掩盖多余的窗口，不是不生成它。

**护栏**：最后一个样本也要被覆盖。常见的改坏写法是把录音截到整帧（“反正 Whisper 会丢掉不满一帧的部分”），或者跳过只多出不到 1 秒的尾窗。55 秒加 1 个样本的录音会在这里挂掉。长音频转写不能为了凑整丢尾巴，一句话的最后一个词常常就在那里。

参考实现全程用整数样本，不用浮点秒数。课里的 `int(seconds * sr)` 会截断，`int(2.01 * 16000)` 是 32159；`start += step` 在步长不是整数秒时还会累积误差。

## Part 2 decoder 序列

参考实现写出时按顺序拼：可选的 `<|startofprev|>` 加上文，`<|startoftranscript|>`、语言、任务，然后是 `<|notimestamps|>` 加文本，或者一组组“时间戳、文本、时间戳”，最后是 `<|endoftext|>`。解析时用正则把特殊 token 切出来，按同样的顺序读，读完再写一遍，和输入不同就报错。所以凡是能解析的文本，一定能原样写回去。

容易漏的几点：

- **前导空格**：BPE 的词 token 自带前导空格，`" Hello"` 和 `"Hello"` 是两个不同的 token。文本要原样保留，`strip()` 会破坏往返。
- **两位小数**：时间戳 token 是 `<|0.70|>`。`str(0.7)` 是 `"0.7"`，而 `35 * 0.02` 是 0.7000000000000001。
- **格点**：0.02 在二进制里不能精确表示，`0.58 % 0.02` 是 0.0199…，连 `30.0 % 0.02` 都不是 0。要先 `round(t / 0.02)` 得到格数，再看差值。`int(t / 0.02)` 会把 0.58 截成 28 格（写出 `<|0.56|>`），把 1.16 截成 57 格。
- **容差只盖浮点误差**：先取到百分位再看奇偶（`round(t * 100) % 2`），会把 1.081 当成 1.08 收下，写出去再读回来就不是原来的值。参考实现的容差是 1e-9，只吸收 0.02 在二进制里的表示误差。
- **范围**：时间戳 token 只到 `<|30.00|>`，30.02 秒没有 token，要报错。窗口里出现 30 秒以后的时间，多半是上游忘了减去窗口起点。
- **空的 decoding**：没有 segments、text 是 None 时，不写 `<|notimestamps|>`；text 是 `""` 时才写。写成 `<|notimestamps|>` 加空文本，读回来就成了 `text=""`，和原来的不相等。
- **读回的时间**：直接 `float("0.70")`，得到的就是写进去的 0.7。用“格数 × 0.02”还原，得到的是 0.7000000000000001，往返不相等。
- **课里的 build_prompt**：task 只要不是 "transcribe" 就当成翻译，拼错的 "transcription" 也不报错；语言用 `LANG[language]` 查，报的是 KeyError。这里都要报 ValueError。

时间戳 token 从 `<|0.00|>` 到 `<|30.00|>` 共 1,501 个，排在多语种词表的最后：50,364 + 1,501 = 51,865，这就是课里说的 51,865。large-v3 多了一个语言 token（粤语），所以 Part 5 里 Turbo 的词表是 51,866。

## Part 3 拼接重叠窗口

相邻两个窗口的重叠区从后一个窗口的起点到前一个窗口的终点，分界点取它的中点。一个词按中点归属：中点在分界点之前，归前一个窗口；在分界点上或之后，归后一个窗口。参考实现把所有时间换成样本，并且比较“两倍的中点”和“两倍的分界点”，这样全是整数：

```python
low = windows[k - 1].end + window.start      # 两倍的前一个分界点
high = window.end + windows[k + 1].start     # 两倍的后一个分界点
midpoint = 2 * window.start + start + end    # 两倍的词中点，都以样本为单位
```

- **为什么用整数**：27.24–27.76 的 " split" 中点正好落在 27.5 秒的分界点上。浮点秒数里 25.0 + 2.24 是 27.240000000000002，这组数据的误差恰好互相抵消，用浮点数比较也能通过，但在这种边界上，归属取决于舍入误差。整数样本没有这个问题。输出时才除以采样率，并保留两位小数。
- **为什么按中点**：按起点归属时，横跨分界点的词会被分给前一个窗口，而它的大半段在后一个窗口里。
- **首尾不裁**：第一个窗口的开头和最后一个窗口的结尾没有邻居，不裁剪。课后练习“每块只保留距离块边界超过 2.5 秒的词”只适用于相邻窗口之间的边界。
- **分界点跟着实际重叠走**：`overlap_s=2.0` 时重叠区是 28–30 秒，分界点在 29 秒，不是固定的“起点后 2.5 秒”。
- **补零里的词**：最后一个窗口只有 15 秒真实音频，positions 是 750，真实音频到 750 × 0.02 = 15 秒为止。从 15 秒起才开始的词来自补零的静音，是幻觉，要丢掉。这是课里 Pitfalls 的“Short-clip padding”。
- **看起点，不看终点**：最后一个词 " end" 是 14.8–15.4 秒，结束时间越过了真实音频，但它是在真实音频里开始的，要保留，时间也不截。Whisper 给最后一个词的结束时间可能落进补零里。按结束时间或中点判断，会丢掉录音的最后一个词，和 Part 1 的护栏是同一个道理。

最后的端到端检查把 Part 1–3 串起来：70 秒的录音分成 3 个窗口，模拟的 Whisper 在窗口边缘只听到半个词，最后一个窗口还在补零里说了一句 " Thanks for watching!"。拼接后每个词恰好出现一次，时间和原稿一致。

## Part 4 流式转写

和 Whisper 自己读长音频一样，用首尾相接的 30 秒窗口，把已经保留的文本作为上文喂给下一个窗口：

```python
async for chunk in chunks:
    buffer.extend(chunk)
    while len(buffer) >= window:
        for event in events(buffer[:window]):
            yield event
        del buffer[:window]
        offset += window
if buffer:
    for event in events(buffer):
        yield event
yield "data: [DONE]\n\n"
```

- 窗口在缓冲区里跨块拼好，所以不管怎么切块，结果都一样；窗口一满就解码、输出，第一个事件出来时只拉取了 30 块。
- 流结束时剩下的样本作为最后一个较短的窗口解码，但缓冲区空了就不再调用 decode。
- `events()` 先把整个窗口的文本拼起来再查循环。`is_loop` 把文本转成小写、只取单词，再逐词滑动着数三词组：三个 segment 各说一遍 “thanks for watching”，合起来就是同一个三词组出现三次。分开看每个 segment 是查不出来的。
- 这个窗口以 " Okay." 开头，循环从第 2 个词才开始。每 3 个词切成一组再数，切出来的组和循环错开一个词，同一组最多出现两次，查不出来。真实的循环也常常接在一段正常的话后面。
- 只查这个窗口自己的文本。上文累积了上次重置以来的全部文本，拼进去一起查的话，一句常见的话在长录音里说上三次，正常的窗口就会被丢掉。测试里 5 个窗口都说 " hi"，5 个都要输出。
- 判成循环的窗口什么都不发，并且把上文清空。下一个窗口拿到的 previous 是 None，幻觉不会沿着 `condition_on_previous_text` 传下去。这是课里 Pitfalls 的级联问题，也是课里建议默认关掉它的原因。
- 时间用整数样本下标除以采样率，再加上窗口内的时间，保留两位小数：最后一个窗口从 90 秒开始，90 + 8.46 是 98.46000000000001。每个事件是 `data: <json>` 加一个空行，最后是 `data: [DONE]`，这是 server-sent events 的格式，测试按 `\n\n` 切开再逐个解析。

## Part 5 LoRA 参数

先递归遍历模块树，记下每个模块的路径，以及每个参数的形状或共享对象：带 `"type"` 的 dict 是层，其他 dict 是命名的子模块，list 是编号的子模块，路径里用下标。然后对每个 target，把它按点分成几段，和每个模块路径的最后几段逐段用 `fnmatchcase` 比较。比较的是整段名字，`"proj"` 不会命中 `q_proj`。命中的模块必须是 Linear 层；一个都没命中，或者命中了别的东西，就报 ValueError。

一层可能被几个 target 同时命中，比如 `["q_proj", "v_proj", "encoder_attn.q_proj"]` 里的 cross-attention q_proj，它也只挂一个 adapter。所以参考实现先把命中的路径放进 set，最后按树里的顺序列出来。

这里的规则和 PEFT 有两处不同。PEFT 的 target_modules 列表只按名字后缀匹配，不认通配符，要用模式得传一个正则字符串；PEFT 也只在整张列表一个模块都没命中时报错，而且 Embedding、Conv1d 上也能挂 LoRA。这里的通配符和两条 ValueError 是这套代码自己的约定，写在 docstring 里。

Turbo 上的数字：

- encoder 32 层，每层 self-attention 的 q_proj、v_proj，共 64 个 adapter；decoder 4 层，每层 self-attention 和 cross-attention 各有 q_proj、v_proj，共 16 个。每个 adapter 是 16 × (1280 + 1280) = 40,960，合计 3,276,800，约占总数的 0.4%，和课里的 “~3M trainable / 809M total” 一致。
- 课里的 `lora_params` 对 Turbo 给出 655,360：它把 encoder 也按 4 层算，还漏了 cross-attention。PEFT 按名字匹配，`"q_proj"` 会命中 `encoder_attn.q_proj`。
- 底座 808,878,080，约 809M：encoder 636,968,960（32 层共 629,637,120），decoder 171,909,120（其中词嵌入 51,866 × 1280 = 66,388,480）。`proj_out` 和 `embed_tokens` 共享同一个权重，只算一次，重复算会多出 66,388,480。
- 非方阵要用 rank × (in + out)：fc1 是 [5120, 1280]，rank 8 时一个 adapter 是 8 × 6,400 = 51,200。课里的 `2 * d * rank` 只对方阵成立。
- 给 `proj_out` 加 adapter 时，它自己没有形状，要从共享的 `model.decoder.embed_tokens.weight` 拿 [51866, 1280]。

## 这套题证明了什么，没证明什么

通过了说明你能在这个规模的代码里调试帧预算和切块计划、把 decoder 的特殊 token 序列原样存取、按时间戳拼接重叠窗口、写带上文和幻觉过滤的流式生成器，以及在嵌套的模块树上像 PEFT 那样按名字匹配、统计 LoRA 参数。它不涉及真实的 Whisper 推理、log-mel 计算、BPE 分词、训练循环和 WER 评估，也不涉及 VAD 门控和 wav2vec 2.0 词级对齐。课里 Step 1 的推理参数、Step 3 的微调和 Step 4 的 cross-attention 可视化需要另外动手跑。
