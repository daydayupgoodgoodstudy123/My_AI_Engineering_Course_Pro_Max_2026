## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | 波形（waveform） | 一维 float 数组，取值在 `[-1.0, 1.0]`，按样本下标索引；秒数 `t = n / sr`，10 秒 16 kHz 音频 = 160,000 个 float |
| 2 | 采样率（sample rate, sr） | 每秒采样次数：8 kHz 电话、16 kHz ASR 标准、24 kHz 现代 TTS、44.1/48 kHz 音乐与影视 |
| 3 | Nyquist-Shannon 采样定理 | 采样率 `sr` 只能无歧义表示 `≤ sr/2` 的频率，`sr/2` 叫 Nyquist 频率 |
| 4 | Aliasing（混叠） | 高于 Nyquist 的能量会"折叠"到低频：10 kHz 采样的 7 kHz 正弦会显示为 3 kHz；降采样前必须先低通滤波 |
| 5 | Bit depth（位深） | 16-bit PCM（int16，±32,767）是通用交换格式；库通常读出 float32 并缩放到 `[-1, 1]` |
| 6 | DFT 与频率 bin | `N` 个样本 → `N` 个复数系数；第 `k` 个 bin 对应 `k·sr/N` Hz，频率分辨率 `sr/N`；幅度 = 振幅，角度 = 相位 |
| 7 | FFT | DFT 的 `O(N log N)` 快速算法，手写 DFT 是 `O(N²)`；所有音频库底层都用 FFT |
| 8 | 分帧 + 加窗 = STFT | 不对整段做 FFT，而是切成重叠帧（典型 25 ms 帧长 / 10 ms 帧移），乘 Hann/Hamming 窗消除边缘不连续，再逐帧 FFT |
| 9 | 先对齐采样率 | "match sample rate before you match anything else"：Whisper 要 16 kHz 单声道 float32，喂 44.1 kHz 立体声会得到像"模型 bug"的垃圾输出 |

## 五、参考答案与解析

### Q1 — 答案：C

Nyquist 频率 = `sr / 2` = 8 kHz。A 是采样率本身，不是可表示的最高频率；B 把关系弄反了；D 是 8 kHz 电话音频的 Nyquist。讲义特别指出：8 kHz 采样只能保留 4 kHz 以下，会"kill consonants"（清辅音能量多在高频），所以 ASR 尽量不用 8 kHz。

### Q2 — 答案：C

Nyquist = 5 kHz，7 kHz 超出了它，会折叠到 `sr − f = 10 − 7 = 3 kHz`。这正是代码 Step 5 的演示，实测报告 `3007.8 Hz`（bin 分辨率 `10000/512 ≈ 19.5 Hz`，3000 Hz 不正好落在 bin 上）。A 是"真实频率"，采样后已经无法与 3 kHz 区分；B 是 Nyquist 本身；D 是镜像的另一种写法，但超过了 `sr/2`，在 `[0, sr/2]` 的频谱里看不到。

### Q3 — 答案：B

bin `k` 对应 `k·sr/N = 28 × 8000 / 512 = 437.5 Hz`，分辨率 `sr/N = 15.625 Hz`。这就是代码 Step 3 的真实输出：440 Hz 正弦被报告成 437.5 Hz，因为 440 落在第 28 和 29 个 bin 之间，离 28 更近。D 的"乘以 2"是常见误解。

### Q4 — 答案：C

一帧是从连续信号里硬切出来的，帧的首尾通常不衔接，等价于乘了一个矩形窗，会把能量"泄漏"到很多相邻 bin。Hann 窗让帧两端平滑衰减到 0，减少泄漏。A 错：频率分辨率由帧长 `N` 决定，加窗反而会让主瓣略微变宽；B 错：加窗多了一次乘法；D 错：aliasing 发生在采样时，加窗无法挽回。

### Q5 — 答案：B

降采样到 16 kHz 后 Nyquist 是 8 kHz，原始 48 kHz 录音里 8–24 kHz 的能量如果不先滤掉，抽取后会折叠进 0–8 kHz 的语音频段。A 就是讲义练习 2 里的"naive decimation"，会产生 aliasing；C 多此一举且仍没有低通；D 归一化只改变幅度，与频率无关。工程上直接用自带抗混叠滤波器的 `torchaudio.transforms.Resample` 或 `librosa.resample`。

### Q6 — 答案：B

实数信号满足 `X[N−k] = conj(X[k])`，幅度谱关于 `N/2` 对称，后一半不提供新信息；前一半恰好对应 `0 ~ sr/2`，即 Nyquist 以内的频率。A 把"镜像"误当"噪声"；C 错：截取发生在 DFT 算完之后，并没有省掉计算；D 没有意义。补充：严格说 `0 ~ N/2` 共 `N/2 + 1` 个 bin 都有意义，`numpy.fft.rfft` 就返回 `N/2 + 1` 个，代码里的 `[:N//2]` 少取了 Nyquist 那一个 bin，演示中无影响。

### Q7 — 答案：A

分辨率 `Δf = sr/N`：`N` 越大，bin 越密；但一帧覆盖的时间 `N/sr` 也越长，帧内发生的变化（比如两个音素）会被平均掉。这就是时频不确定性（time-frequency trade-off）。语音选 25 ms，是因为在这个尺度内声道形状近似不变（短时平稳），同时频率分辨率也够用。

### Q8 — 答案：B

`16384 / 32768 = 0.5`。int16 的范围是 `[-32768, 32767]`，除以 32768 把它映射到 `[-1, 1)`。A 是没做归一化；C、D 是算错。

### Q9 — 参考答案

输出：

```text
(437.5, 28)
(440.0, 44)
```

- 第一行：`N = int(8000 × 0.064) = 512`，分辨率 `8000/512 = 15.625 Hz`。440 / 15.625 = 28.16，不是整数，能量主要落在最近的 bin 28 上，报告 `28 × 15.625 = 437.5 Hz`。这不是 bug，而是 **DFT 的频率被量化到 bin 网格上**；同时 440 Hz 的正弦在 512 点窗口里不是整数个周期，还伴随频谱泄漏。
- 第二行：`N = 800`，分辨率 `10 Hz`，440 正好是第 44 个 bin，所以精确。
- 规律：让 `f·N/sr` 为整数（即窗口里恰好装下整数个周期），峰值就会精确落在 bin 上。实际音频做不到这一点，所以工程上常用加窗 + 抛物线插值来估计 bin 之间的频率。

### Q10 — 参考答案

两个误差来源：

1. **`int()` 是向零截断而不是四舍五入**：`int(0.7) == 0`，量化误差最大接近 1 个 LSB（`1/32767 ≈ 3e-5`），而四舍五入的最大误差只有半个 LSB。
2. **缩放系数不对称**：写入时乘 32767，读回时除以 32768，相当于把整体幅度缩小了 `32767/32768`，对 0.5 振幅的信号会再引入约 `0.5/32768 ≈ 1.5e-5` 的误差。

修改（写入四舍五入，读写用同一个系数）：

```python
# write_wav 中
frames = b"".join(
    struct.pack("<h", max(-32768, min(32767, round(s * 32767)))) for s in samples
)

# read_wav 中
return [x / 32767.0 for x in ints], sr
```

实测最大误差从 `4.45e-05` 降到 `1.53e-05`（≈ 半个 LSB，即 16-bit 量化的理论下限）。说明：业界读取时普遍除以 32768（`soundfile` 等的约定），写入时乘 32767 再裁剪以防溢出，这点不对称通常可以忽略；本题是为了让你看清误差从哪里来。

### Q11 — 参考答案

```python
def alias_freq(f, sr):
    f = f % sr                 # 采样后频率以 sr 为周期
    return sr - f if f > sr / 2 else f   # 再关于 sr/2 镜像折回 [0, sr/2]
```

预测：`alias_freq(9000, 10000) = 1000`，`alias_freq(12000, 10000) = 2000`。

验证（`sine(f, 10000, 0.0512)` 得到 512 个样本，分辨率约 19.53 Hz）：

| 真实频率 | 采样率 | `alias_freq` | `peak_freq` 实测 |
|---------|-------|-------------|----------------|
| 7000 | 10000 | 3000 | 3007.8 Hz |
| 9000 | 10000 | 1000 | 996.1 Hz |
| 12000 | 10000 | 2000 | 1992.2 Hz |
| 7000 | 8000 | 1000 | 1000.0 Hz |

实测值与预测只差不到一个 bin。要点：采样把频率轴"卷"成周期为 `sr` 的圆，再关于 `sr/2` 对折——所以 12 kHz 先变成 2 kHz（减去一个 sr），9 kHz 先变成 9 kHz 再镜像为 1 kHz。

### Q12 — 参考答案

```python
import numpy as np

def peak_freq_np(samples, sr):
    x = np.asarray(samples, dtype=np.float32)
    mags = np.abs(np.fft.rfft(x))          # 长度 N//2 + 1，覆盖 0 ~ sr/2
    k = int(np.argmax(mags[1:])) + 1       # 跳过 bin 0（直流分量）
    return k * sr / len(x), k
```

- 对 512 点的 440 Hz 正弦，返回 `(437.5, 28)`，与原函数一致；`rfft` 返回 `512/2 + 1 = 257` 个 bin（包含 0 Hz 和 Nyquist）。
- 速度差：手写 DFT 对每个 `k` 都遍历所有 `n`，是 `N²` 次乘加且全在 Python 解释器里执行；4000 个样本就是 1600 万次循环，实测约 2 秒。`np.fft.rfft` 是 `O(N log N)` 的 FFT，并且由 C 实现、向量化执行，实测约 0.3 毫秒。
- 跳过 bin 0 的原因：真实录音常有 DC offset，直流分量可能是最大的"峰"。原函数没有跳过，在纯正弦上没问题，但对真实音频会出错。

### Q13 — 参考回答要点

- **定理**：带宽限制在 `B` 以内的信号，只要采样率 `sr > 2B`，就能从样本中完整重建；`sr/2` 称为 Nyquist 频率。
- **Aliasing**：高于 `sr/2` 的分量在采样后与某个低频分量的样本**完全相同**，无法区分，于是"折叠"到 `[0, sr/2]` 里：频率 `f` 先对 `sr` 取模，再关于 `sr/2` 镜像。讲义例子：10 kHz 采样的 7 kHz → 3 kHz。
- **为什么先低通**：aliasing 一旦发生就和真实信号混在一起，事后无法分离，只能在采样（或降采样）**之前**把 Nyquist 以上的能量滤掉。所以 ADC 前有模拟抗混叠滤波器，软件重采样器（`torchaudio.transforms.Resample`、`librosa.resample`）内置数字低通。
- **常见误区**：以为"降采样就是隔几个取一个"；以为上采样能"补回"高频（上采样只能插值，原本没有的频率信息不会出现）。
- **加分点**：能举出语音中的具体后果——混叠的高频噪声落入语音频段，模型训练正常但 WER 变差，属于"静默 bug"。

### Q14 — 参考回答要点

- **bin 的含义**：`N` 点 DFT 的第 `k` 个系数衡量信号与频率 `k·sr/N` Hz 的正弦/余弦的相关程度；幅度 = 该频率的振幅，相角 = 相位。实信号只需看 `k = 0 … N/2`。
- **分辨率**：`Δf = sr/N`，只由**分析窗口的时长** `N/sr` 决定（`Δf = 1 / 窗口秒数`）。补零可以让频谱看起来更平滑，但不能提高真实分辨率。讲义例子：1024 点 FFT @16 kHz → 约 15.6 Hz 分辨率，覆盖 0–8 kHz。
- **为什么要 STFT**：语音是非平稳信号，音素每几十毫秒就变化。对整段做一次 FFT 只能得到"整段平均频谱"，丢失了"什么时候出现什么频率"。切成 25 ms 帧（在这个尺度内近似平稳），每 10 ms 移一次（相邻帧有重叠，时间轴平滑），加 Hann 窗减少泄漏，每帧 FFT，就得到时间 × 频率的矩阵——频谱图，也就是下一节的起点。
- **复杂度**：DFT `O(N²)`，FFT `O(N log N)`；16 kHz 下 25 ms = 400 点，常用补到 512 点做 FFT。
- **加分点**：时频分辨率的权衡（窗口越长频率越细、时间越粗）；说出 1 秒音频在 400/160 设置下不补边约 98 帧。

### Q15 — 参考回答要点

按讲义的"三个问题"排查，先查最便宜、最常见的：

1. **采样率**：新 SDK 输出是不是 44.1/48 kHz，而服务端当成 16 kHz 读？用 `ffprobe` / `soxi` 看文件头，对比模型期望。采样率被"当错"会让语速和音高同时失真。
2. **重采样方式**：如果服务端自己做降采样，是不是 naive decimation 没有低通？对比一段测试音频重采样前后的频谱，看 Nyquist 附近有没有折叠进来的能量。
3. **声道**：立体声是否被当成单声道交错样本读取？应先 mean 混成单声道。
4. **dtype / 取值范围**：int16 是否忘了除以 32768（数值变成几千几万）；是否有 clipping（峰值贴着 ±1）或 DC offset。
5. **编解码**：新 SDK 是否加了有损压缩、降噪、AGC（自动增益）。

工程实践：在服务入口加**输入断言**（`sr`、声道数、dtype、取值范围、时长下限），出问题时立即报错而不是"安静地输出垃圾"；保存一批"黄金样本"做回归测试。常见误区：直接怀疑模型、开始调参或重新训练。

### Q16 — 参考回答要点

- **直接上采样不能"补回"信息**：8 kHz 录音只含 0–4 kHz 的内容，上采样到 16 kHz 后 4–8 kHz 是空的。模型在训练时见到的都是满带宽语音，遇到"上半频段全空"的输入属于分布偏移，效果会下降（尤其是依赖高频的清辅音 s/f/sh）。
- **但上采样仍是必需的一步**：模型只接受 16 kHz，所以要先用正规重采样器上采样到 16 kHz（满足输入格式），再解决分布偏移：
  1. 先在一个带人工标注的小测试集上测 WER，确认差距有多大；
  2. 数据增强：把 16 kHz 训练数据先降到 8 kHz 再升回 16 kHz（模拟电话带宽），加上编解码失真，混入训练或微调；
  3. 用电话域数据微调（参见后续 Whisper 微调一节）。
- **加分点**：提到"先对齐采样率再谈别的"这条讲义里的决策规则；指出评估必须用同域的测试集。

### Q17 — 参考回答要点

- **除以 32768**：int16 的范围是 `[-32768, 32767]`，除以 `2¹⁵ = 32768` 把它映射到 `[-1, 1)`，且 0 仍是 0、缩放是 2 的幂（在浮点里是精确的）。写回时乘 32767 并裁剪，防止 `1.0 × 32768` 溢出。
- **float32 的 24-bit 精度**：float32 有 23 位尾数 + 1 位隐含位，共 24 位有效精度，所以在 `[-1, 1]` 里表示 16-bit 或 24-bit 的样本都没有精度损失，是内部 DSP 的通用格式。
- **检测 clipping**：统计 `|x| ≥ 0.999` 的样本比例，或连续多个样本贴在极值上（波形顶部被"削平"）；技能文件 `skill-audio-loader` 要求对峰值超过 ±0.999 的文件告警。
- **检测 DC offset**：计算整段均值 `mean(x)`，绝对值超过约 0.01 就告警；修复方法是减去均值或用高通滤波去掉直流。
- **加分点**：区分峰值归一化与 RMS 归一化（后者让响度一致，前者只保证不溢出）；说明 clipping 是不可逆的失真。
