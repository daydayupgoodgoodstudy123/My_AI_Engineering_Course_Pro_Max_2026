# 使用说明

本题来自 prompt caching 的写入、读取、前缀布局与费用模拟。开场2分钟，五关12、10、16、10、10分钟，合计60分钟；没有真人用时校准。所有费率、TTL和最小长度都是离线输入，不表示当前任何厂商政策或价格。

作答目录 `prefixmeter/`，五个测试位于 `tests/test_parts.py`。默认 `python -m pytest -q` 全跳过；每次仅移除当前 `@pytest.mark.skip("Part N")`，运行对应测试，保留全部断言。重做覆盖前，先把本人作答的 `prefixmeter/` 与 `tests/` 另存一份，保留当前解答和解锁状态。重置时递归复制 `_starter/prefixmeter/` 和 `_starter/tests/`。

- Part 1：`traffic.py`；`python -m pytest -q -k test_typed_traffic_and_write_lifetimes`。恢复完整 typed usage、每次真实写入的观察寿命及完整收集响应速度；不计算价格。
- Part 2：`journal.py`；`python -m pytest -q -k test_typed_accounting_journal`。追加给定 typed records，重开后保留每个 run/profile 的完整证据与关联。
- Part 3：`pricing.py`；`python -m pytest -q -k test_exact_role_storage_and_strict_inverse`。精确计算各角色前缀、完整 suffix、观察到的存储寿命和严格净节省的最少追加读取次数。
- Part 4：`accounting_stream.py`；`python -m pytest -q -k test_csv_real_clock_accounting`。投影真实时间、角色、每次新对象的费用与累计 totals。实际异步拉取、当前记录身份、CSV 编码和关闭源已给定。
- Part 5：`layout.py`；`python -m pytest -q -k test_nested_exact_prefix_breakpoint`。按原始顺序保留所有 section，以真实共同 token 前缀选择首个 volatile leaf 之前的完整合法断点。

`contracts.py`、`collection_runtime.py`、`event_driver.py` 是正确给定代码：形状/时间检查、fixed-from-write 生命周期、完整 record codec、CSV 和驱动不需重写。Part 3依赖修好的 Part 1事实；Part 4依赖修好的 Part 1和 Part 3，不再实现缓存命中或计费公式。Part 2的原始 rate 词面编码整体给定，主考 run/profile/object 证据关联。

输入时间均为整数微秒；报告 horizon 是观察截止，不删除缓存。一次写入的观察区间为 `[created_us, min(expires_us, horizon))`；每次写入即使后来覆盖也有独立对象。CSV 成本使用给定精确有理数字符串（整数或 `分子/分母`），可由 `Fraction` 读取，避免把非终止小数假装成无限精度 decimal。费率原始十进制词面在 journal 中完整保留。

布局的 token tuple 是明确提供的教学数据，不调用真实 tokenizer。Section 层级是本地输入扩展；空 section 保留在完整布局中，但断点必须由当前非空 leaf 提供，不能阻断后续稳定 leaf。本题不重排工具或动态字段，不发真实请求，不验证任何 provider cache hit。卡住时依次使用 H1/H2/H3；完成后填 REVIEW_TEMPLATE，再读 solution。
