# 使用说明

本题实现课程Exercise3的结构化问题→推荐与解释，框架名字和profile是固定课程快照，不是当前产品选型建议或能力保证。没有真实SDK、LLM或网络。开场2分钟，五关12/10/16/10/10分钟，共60分钟；没有真人用时校准。

作答`shapecompass/`；五个测试默认`@pytest.mark.skip("Part N")`。默认`python -m pytest -q`全跳过；每次只移除当前skip，保留所有断言。重置递归复制`_starter/shapecompass/`和`_starter/tests/`。

- Part1 `intake.py`：`python -m pytest -q -k test_problem_intake_and_complete_comparison_report`。保留完整Problem字段、独立有序case_id、完整批次布局。recommender为注入fixture，不含完整正确selector；严格JSON/primitive/default与文本row formatter给定。
- Part2 `catalog.py`：`python -m pytest -q -k test_ini_catalog_and_bound_decision_evidence`。INI保存全部场景，JSON保存完整决策证据，按case_id绑定后按catalog顺序重开。INI no-interpolation、文字JSON包装和完整Decision codec给定；候选处理字段投影、显式boolean语法与归属。
- Part3 `selector.py`：`python -m pytest -q -k test_fixed_course_rule_precedence_and_actual_trace`。实现全部规则与真实evaluation prefix。固定顺序hard→tiny→dialogue→roles→session→typed→fallback；true requirements按FLAGS顺序。仅first match停止，false operands也保留。
- Part4 `cards.py`：`python -m pytest -q -k test_isolated_markdown_cards_and_complete_evidence`。每个scenario形成独立Markdown card，JSON-string heading隔离多行输入；六个JSON-valued bullets完整组成该场景证据。真实pull-through/current-case/source-close driver已给定，不用重写异步驱动。
- Part5 `explanation.py`：`python -m pytest -q -k test_nested_observed_decision_path_only`。只消费已求值Decision.trace，将实际false/true边组成有限嵌套路径与decisive leaf；没有Problem输入，不再运行selector或反事实搜索。

固定规则：hard是resume/interrupt/fanout任一；tiny必须calls<=2且七个flags全false；dialogue和roles都排除typed_state，dialogue先；session要求memory且无roles/dialogue，排在typed之前，因此typed+session、无roles/dialogue会选Agno。这是明确课程合同。hard true证据保留全部已满足硬需求，requirements保留全部true signals。finish_decision只提供已选rule的固定文本/codec，未提供谓词。

P1报告使用Python字符宽度`max(60,所有label长度)`，不截断、不按UTF8 byte数布局。prepared rows已含Recommendation；计时只测完整报告格式化，包含布局计算和全部输出消费，不宣称真实推荐或LLM运行性能。来源原_check为固定60宽，本题动态批次宽度是明确教学扩展。

P2是single-writer local completed-save合同，不承诺两个文件的崩溃事务。case_id采用给定安全标识语法，label可重复、多行、Unicode和百分号；二者不能混为身份。缺省flags=false、calls=1；所有七个flags和非负整数调用次数均精确保留，调用次数没有浮点精度上限。P4每张card有一个heading，依次为Case/Framework/Rule/Requirements/Reason/Evaluated六条，Case是稳定case_id，末尾LF；是本地报告格式，不是框架协议。P5只画已走过分支，缺口、多余evaluation、没有true leaf或decisive不一致均拒绝。

卡住用H1/H2/H3，结束后先填REVIEW_TEMPLATE再读solution。不重做coderpad route_task/evidence_gate。

INI给定parser使用不在合法case_id语法中的`@defaults`作为特殊配置区名称，`DEFAULT`、`default`、`Default`均是彼此独立的普通合法场景ID；候选仍按完整case_id保存和关联证据。
