# QuotaFlow 使用说明

从 `quotaflow/` 与 `tests/test_parts.py` 开始。这是离线小服务，时钟、配额与价格全部由本地 fixture 提供。

## 开始与规则

在本目录启动终端，使用已有 pytest 环境。先读英文题面与函数 docstring。一次只移除当前关的 `@pytest.mark.skip("Part N")`，保留五个测试及全部断言；先解释实际失败，再改候选实现。`solution/` 是练习参考，正式计时不先读。

```bash
python -m pytest -q
python -m pytest -q -k legacy_quota
```

开场 2 分钟；五关分别 12、10、16、10、10 分钟，合计 58 分钟，总计 60 分钟。这是出题预算，没有真人校准记录。

## 每关交付

1. 让既有准入调用保留精确额度与记账证据。
2. 实现完整 BucketState 的 SQLite save/load，重开后不补发余额；让状态更新与给定 journal 的唯一请求 append 共用一个事务，失败时两者不拆开。
3. 使用已修好的补充/记账依赖，完成原子决策与共同重试时间。
4. 每个完成批次输出一份累计 Prometheus 文本；只有拒绝记录的身份也保留完整系列，模型调用、token 与成本为零。测试里的 parser 决定本题有限格式。
5. 输出 user/model/token-category 层级的精确用量、账单、缓存节省与基线；拒绝记录在 model、user、account 各层都不增加 token 用量。

Part 2 的 `UsageJournal` schema、完整 Usage 编解码、原始成本词面、append、读取顺序，以及 LedgerStore 的连接/初始化/ledger 包装均完整给定。journal 使用 LedgerStore 的同一 SQLite connection，不自行开始、提交或回滚事务；候选只实现桶状态存取与 save_and_log 的事务组合，直接使用 journal。

所有价格是示例数据；不调用模型、网络或真实计费服务。RPM 是已准入时间戳的 60 秒滑动窗口，token 是可补充的桶；没有每日限额。给定的 deque 过期、基础类型检查、锁 primitive 与精确 Decimal 加法直接使用。
