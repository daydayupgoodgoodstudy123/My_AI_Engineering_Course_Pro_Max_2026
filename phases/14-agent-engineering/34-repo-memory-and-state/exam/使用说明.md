# 14/34 分关面试题：Statefile

形式照 Edison 那场面试：一个写好一半的服务，5 个测试用 `@pytest.mark.skip("Part N")` 锁住，一次解锁一关，要求测试原样全部通过。题面只有英文的 [README.md](README.md)，和真实面试一样；具体要求在测试、断言消息和 docstring 里。

内容来自本课：agent 的状态放在仓库里的 JSON 文件中，先有 schema 再写入（bad write 就是被拒的 write）；写文件用临时文件、fsync、rename 的原子写法；schema 升级时带上迁移脚本，读不懂的版本拒绝加载。还有测验里展开的几处：本课验证器的 `$` 会放过结尾换行、隐式禁止多余字段（Q5、Q8），`mkstemp` 留下的 0600 权限、`kill -9` 留下的临时文件、目录也要 fsync（Q12），两个会话读改写同一个文件时的丢失更新（练习 5、Q11），以及在 CI 里验证每个旧版本都能迁移到最新版本（Q17）。

## 开始

在本目录打开终端（需要 macOS 或 Linux，Part 2 会检查文件权限和目录 fsync）：

```bash
python3 -m pip install pytest      # 只需一次
python3 -m pytest                  # 5 个 skipped 说明环境正常
```

然后照 README 注释掉 Part 1 的 skip，再运行 `python3 -m pytest`。

## 规则

- 建议 60 分钟，自己计时。参考分配：Part 1 12 分钟，Part 2 14 分钟，Part 3 10 分钟，Part 4 12 分钟，Part 5 12 分钟。难度和用时还没有经过实测校准。
- 只改 `statefile/` 里的代码。测试不能改（解除 skip 除外），可以另外新建自己的测试文件。
- 可以查 Python 官方文档（json、os、tempfile、stat、re、copy、asyncio、collections）。计时期间不要打开 `solution/` 和 `INTERVIEWER.md`。
- 有需求不清楚的地方就问面试官。自己练的时候，先把问题写下来，再去 INTERVIEWER.md 的“澄清问题”一节里只看这一条的答案。

## 常用命令

```bash
python3 -m pytest -x                       # 跑已解锁的关，遇到第一个失败就停
python3 -m pytest -k snapshot -x           # 只跑名字里带 snapshot 的测试
python3 -m pytest --all-parts              # 不解除 skip，一次看所有关的状态
python3 -m pytest --solution --all-parts   # 计时结束后：参考答案应该 5 passed
```

`--solution` 和 `--all-parts` 是本目录 conftest.py 提供的练习开关，真实面试里没有。

Part 1 的类型化 enum 与单次调用缓存已经正确提供，给定 helper 有大仓库验证计时护栏。候选人还要处理一次多字段状态变更：先合并完整 changes，再整体验证并原子写入一次；空变更只读取并验证，不重写。批量检查点另有计时断言，测的是真实 JSON 编码、文件 fsync 和替换。

## 结束和重做

1. 到 60 分钟时停下，记下每关的状态，填 [REVIEW_TEMPLATE.md](REVIEW_TEMPLATE.md)。
2. 再看 [solution/EXPLANATION.md](solution/EXPLANATION.md)，然后关掉答案，把没做完的关重写一遍。
3. 重做前把自己的 `statefile/` 另存一份，再用 `_starter/` 里的原始文件覆盖：

```bash
cp -R _starter/statefile _starter/tests .
```
