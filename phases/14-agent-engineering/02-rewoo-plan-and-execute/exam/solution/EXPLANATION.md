# 参考答案讲解：ReWOO（14/02）

计时结束后再看。参考实现在同目录的 `rewoo/` 里，`python3 -m pytest --solution --all-parts` 应该显示 5 passed。

## Part 1 修 Workers

**现象**：解锁后第一个失败是答案不对：`#E2 has more people: 3.7 million against 2.1 million ("Paris proper").`。没有任何异常，`largest` 工具也没有 bug。

**顺着往上找**：答案里的 `#E2` 是 E3 的证据。E3 是 `largest`，它收到的 `items` 里还是 `{"name": "#E1", "population": "#E4"}` 这样的原文：它把 `"#E4"` 读成了 4，把 `"#E5"` 读成了 5，于是选了第二项的名字 `"#E2"`。原文没有被替换，是因为 `resolve_references` 遇到不是字符串的值就原样返回，列表和字典里的引用都没碰。而 `topological` 用 `str(step.args)` 找依赖，嵌套引用照样找得到，所以执行顺序是对的，错的只是值。这一关想练的是：报错的地方（答案）离出 bug 的地方（替换）隔了两层。

**依次修四处**：

1. `resolve_references` 递归处理列表和字典，每次返回新的容器，不改计划本身。
2. `run_workers` 在调用工具之前看它引用的步骤：只要有一个是 failed 或 skipped，这一步就记 `Evidence("skipped", MISSING)`，不调用工具。失败步骤自己保留错误文本，讲义说 Solver 要看到它；跳过会沿着依赖一路传下去。
3. `topological` 先对照整个计划的 id 检查引用，不存在的报 `KeyError` 并点名（E9）；剩下排不出来的才是环，报 `ValueError`。
4. 排序改成 Kahn 算法：每步只抽一次引用，记下入度和“谁依赖我”，入度归零的进队。参考实现用堆按计划顺序出队，3000 步约 6 毫秒；原来一轮只放行一步、每轮重扫全部待定步骤，约 1.8 秒。“谁依赖我”这张表省不得：每出队一步就把全部步骤扫一遍找下游，仍然是平方级。

**护栏**：
- 逐个 `str.replace("#E1", ...)` 会把 `#E10` 改成 `Paris0`，正则写成 `#E\d` 也一样。用 `REF.sub` 加回调，一次替换完，`#E(\d+)` 本身就会把 `#E10` 整个吃掉。
- 引用要去重后再算入度。E3 在 items 和 title 里各提到一次 `#E1`、`#E2`，入度和释放次数对不上的话，它会在 E4、E5 之前被放行。
- 校验要在任何工具运行之前做完；递归 DFS 在 3000 层上会 RecursionError；在 `json.dumps(args)` 的文本上替换，遇到带双引号的证据（`("Paris proper")`）就坏了。

## Part 2 蒸馏数据集

讲义说 Planner 看不到观察结果，所以大模型写的 (问题, 计划) 可以离线攒下来，微调一个小规划器。这个文件就是攒数据的地方。

参考实现每次 append 都用 `"a"` 模式打开、写一行、关闭，所以 append 一返回记录就在文件里，另一个 `PlanDataset` 随时能读到。读的时候按文件行迭代，逐行 `json.loads`，再还原成 `Example`、`Plan`、`Step`。

- **读回完全一致**：JSON 本身就分得开 1、1.0、True、None，也保留键的顺序。别用 `sort_keys`，别把 score 转成 float，steps 要还原成 Step 的列表。测试比较 `repr`，因为 `1 == 1.0`，`==` 看不出区别。
- **U+2028**：默认的 `ensure_ascii=True` 会把它写成 `\u2028`。如果写成原字符，再用 `str.splitlines()` 读，一条记录就被切成两行。
- **去重**：键是问题和 steps 的 JSON 文本 `json.dumps([question, steps])`。answer 和 score 不进键。1、1.0、True 写成 JSON 是三段不同的文本，而 Python 的 `==` 和 `hash` 把它们当成一样，所以不能用 `example in existing` 或元组集合去重。去重集合在第一次 append 时从文件重建，重开以后也认得旧记录。
- **先校验再写**：`not 0 <= score <= 1` 能拦住 NaN（比较全是 False），`score < 0 or score > 1` 拦不住；两端的 0 和 1 都合法，整数也合法；bool 要单独排除。引用检查用和 Part 1 一样的递归抽取。
- 文件不存在时 `examples()` 返回空列表；`min_score` 是“至少”。

## Part 3 局部重规划

讲义里 Plan-and-Execute 比 ReWOO 多一个 replanner：看过执行结果，再改计划。这里只改坏掉的那一块。

参考实现的循环最多走 `max_replans` 次：把存活的步骤和证据交给 replanner；它返回 None 就停，不再问它，返回补丁就应用补丁，只跑补丁里的步骤，然后进入下一轮。最后 Solver 只看存活的步骤。存活的步骤包括失败和跳过的：replanner 要看到它们才知道该补哪里，Solver 要看到它们才能如实说明缺了什么。交给两者的计划和证据是同一批步骤。

应用补丁（`_apply`）的顺序：

1. 检查 `replaces` 里的 id 都在计划里。
2. 算出要丢弃的集合：被替换的步骤，加上它们的传递下游。依赖关系从参数的任意深度里抽，在整个计划上算，包括前几轮补丁的步骤。
3. 校验补丁的每个引用：`#E` 指向被丢弃的步骤报 ValueError，指向不存在的步骤报 KeyError；`#P` 指向补丁里没有的步骤报 KeyError。全部通过之后才改状态、才执行。
4. 编号：`first = max(number(step.id) for step in steps) + 1`，`steps` 包括被丢弃的。按数字取最大，不按字符串，也不用 `len`。
5. 用正则一次把 `#P<k>` 改成新 id，嵌套的也改。

执行用 Part 1 的 `run_workers(Plan(added), tools, known=kept)`：给它加了 `known` 参数，存放计划外已有的证据。拓扑排序把 known 里的 id 当成已经完成，引用照常替换，失败和跳过的规则照常生效。

这一关的触发不是异常：Rome 的人口是 `no data`，状态是 ok，E9 的合计、E10 的取整也都是 ok，但都建立在没用的证据上。所以要丢哪些步骤只能从依赖图上算，不能从状态推。

## Part 4 流式计划

用一个字符串缓冲区，按换行切出完整的行，最后一段留到下一块；流结束时把剩下的那段当最后一行。每一行：

- 用 `#(E\d+)\s*=\s*([A-Za-z_]\w*)\[(.*)\]` 做 fullmatch，贪婪的 `.*` 正好取到最后一个 `]`。不匹配的行（推理文字、空行）忽略。
- id 重复报 ValueError，第一次那行跑没跑都一样，所以要记下所有写过的 id，不能只看证据表。新步骤放进等待列表，然后“结算”：从头扫等待列表，找到第一个依赖都有证据的步骤就执行，执行完再从头扫，直到一个都跑不了。所以就绪的步骤按行的先后执行，一步完成能连锁放行后面的步骤。执行完不能接着往下扫：刚放行的步骤可能排在前面。
- 执行：依赖里有 failed 或 skipped 的，记 `skipped`，输入保持原样；否则替换引用、调用工具，输出 `#E<k> = tool[替换后的输入] -> 证据`。输入和证据里的换行都改成空格：替换进来的证据本身就可能有好几行。

流结束后还有步骤在等：如果它等的 id 从没出现，报 KeyError 点名那个 id；否则就是互相等待，报 ValueError。

每处理完一行就把产生的记录 yield 出去，所以第一条记录在读第二块之前就出来了。

## Part 5 子计划展开

递归展开，每一层维护一张“本层名字到扁平 id”的映射表：

1. 先检查：子计划不能为空，id 不重复，output 必须是它自己的步骤。
2. 处理 imports：import 的名字不能和本层步骤同名；它指向的名字必须在直接外层的映射表里，查到的扁平 id 填进本层的表。
3. 给本层每一步定扁平 id：output 那一步拿子计划自己的 id，其余按列出的顺序取下一个空号（从顶层最大步骤号往上数）。
4. 逐个展开：普通步骤用本层的表改写参数里的引用，表里没有的名字报 KeyError；嵌套子计划带着本层的表递归下去。

改写用 `REF.sub` 加回调，一次完成。逐个 `str.replace` 在 population_of("E4", "E2") 上会出错：映射是 `E1→E2、E2→E7`，`#E1` 先变成 `#E2`，接着又变成 `#E7`。

因为外层只是把映射表传给内层、不会把自己的名字直接放进去，“子计划只能经 imports 看到外层”这条规则自然就成立了。output 拿子计划的 id，所以外层引用 `#E3` 拿到的就是子计划的结果，不需要额外的转发步骤。

## 这套题证明了什么，没证明什么

通过了说明你能在一个 ReWOO 执行器里顺着证据追到替换的 bug，能把失败隔离在节点上；能设计一个类型精确、可以一边写一边读的 JSONL 数据集；能在依赖图上做局部重规划，把编号、作用域和预算都管住；能边读模型的输出边执行；也能处理带作用域的嵌套计划。它不涉及真实的 LLM 规划质量，也没有真的训练小规划器，没有在真实工具和真实延迟下测过并行执行（讲义练习 1）。小模型做 Planner、大模型做 Solver 时质量差在哪里（练习 3），需要接上真实模型另外去测。
