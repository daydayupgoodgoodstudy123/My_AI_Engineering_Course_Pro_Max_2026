# 14/32 分关面试题：Workbench

形式照 Edison 那场面试：一个写好一半的服务，5 个测试用 `@pytest.mark.skip("Part N")` 锁住，一次解锁一关，要求测试原样全部通过。题面只有英文的 [README.md](README.md)，和真实面试一样；具体要求在测试、断言消息和 docstring 里。

内容来自本课：`AGENTS.md`、`agent_state.json`、`task_board.json` 三个文件、短router按需加载深文档，课里一次推进一步的回合和 AGENTS.md 写的完成定义，练习 3 的 JSON Lines 看板，练习 1 和练习 2 的 24 小时过期确认与优先级取任务，课里说要打印却没有打印的每回合 diff，以及在看板上加一层 epic。验收命令由测试里的假 runner 返回退出码，不会真的执行。

## 开始

在本目录打开终端：

```bash
python3 -m pip install pytest      # 只需一次
python3 -m pytest                  # 5 个 skipped 说明环境正常
```

然后照 README 注释掉 Part 1 的 skip，再运行 `python3 -m pytest`。

## 规则

- 建议 60 分钟，自己计时。参考分配：Part 1 12 分钟，Part 2 11 分钟，Part 3 11 分钟，Part 4 14 分钟，Part 5 12 分钟。难度和用时还没有经过实测校准。
- 只改 `workbench/` 里的代码。测试不能改（解除 skip 除外），可以另外新建自己的测试文件。
- `check_board`、context_paths和read_document是起始正确的helper；Part1上下文性能考按本回合请求直接读取，不建全workspace文档catalog、不跨回合缓存。
- Part 2 复用 Part 1 的 `check_board` 和任务读写函数，不依赖 Part 1 的修复。Part 4 跑的是 Part 1 的回合，要在 Part 1 修好之后才能通过，所以按顺序做。
- 可以查 Python、json、datetime、difflib 的官方文档，以及 RFC 6902（JSON Patch）和 RFC 6901（JSON Pointer）。计时期间不要打开 `solution/` 和 `INTERVIEWER.md`。
- 有需求不清楚的地方就问面试官。自己练的时候，先把问题写下来，再去 INTERVIEWER.md 的“澄清问题”一节里只看这一条的答案。

## 常用命令

```bash
python3 -m pytest -x                       # 跑已解锁的关，遇到第一个失败就停
python3 -m pytest -k board -x              # 只跑名字里带 board 的测试
python3 -m pytest --all-parts              # 不解除 skip，一次看所有关的状态
python3 -m pytest --solution --all-parts   # 计时结束后：参考答案应该 5 passed
```

`--solution` 和 `--all-parts` 是本目录 conftest.py 提供的练习开关，真实面试里没有。

## 结束和重做

1. 到 60 分钟时停下，记下每关的状态，填 [REVIEW_TEMPLATE.md](REVIEW_TEMPLATE.md)。
2. 再看 [solution/EXPLANATION.md](solution/EXPLANATION.md)，然后关掉答案，把没做完的关重写一遍。
3. 重做前把自己的 `workbench/` 另存一份，再用 `_starter/` 里的原始文件覆盖：

```bash
cp -R _starter/workbench _starter/tests .
```
