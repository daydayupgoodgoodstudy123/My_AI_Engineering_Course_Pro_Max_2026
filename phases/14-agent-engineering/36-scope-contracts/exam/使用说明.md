# 14/36 分关面试题：TaskScope

形式照 Edison 那场面试：一个写好一半的服务，5 个测试用 `@pytest.mark.skip("Part N")` 锁住，一次解锁一关，要求测试原样全部通过。题面只有英文的 [README.md](README.md)，和真实面试一样；具体要求在测试、断言消息和 docstring 里。

内容来自本课：落盘的 scope contract（allowed / forbidden 两张 glob 表、验收命令、时间预算、`network_egress` 的 `None` 和 `[]`、violation budget），按最小权限合并项目合同和任务合同，scope check 就是 diff check，“Globs, not raw paths”，合同关闭后归档到 `closed/`，以及 feature 和 task 两个高度的范围一层套一层。

## 开始

需要 Python 3.11 以上。3.10 的 `fnmatch` 只缓存 256 条编译好的模式，Part 1 修完前三处以后，那一次计时要跑两三分钟才报超时。

在本目录打开终端：

```bash
python3 -m pip install pytest      # 只需一次
python3 -m pytest                  # 5 个 skipped 说明环境正常
```

然后照 README 注释掉 Part 1 的 skip，再运行 `python3 -m pytest`。

## 规则

- 建议 60 分钟，自己计时。参考分配：Part 1 12 分钟，Part 2 12 分钟，Part 3 12 分钟，Part 4 14 分钟，Part 5 10 分钟。难度和用时还没有经过实测校准。
- 只改 `taskscope/` 里的代码。测试不能改（解除 skip 除外），可以另外新建自己的测试文件。不联网，不调用 LLM；diff 是测试里写好的字节串。
- 可以查 Python 官方文档（fnmatch、re、json、os、pathlib、urllib.parse、asyncio、dataclasses）。计时期间不要打开 `solution/` 和 `INTERVIEWER.md`。
- 有需求不清楚的地方就问面试官。自己练的时候，先把问题写下来，再去 INTERVIEWER.md 的“澄清问题”一节里只看这一条的答案。

## 常用命令

```bash
python3 -m pytest -x                       # 跑已解锁的关，遇到第一个失败就停
python3 -m pytest -k archive -x            # 只跑名字里带 archive 的测试
python3 -m pytest --all-parts              # 不解除 skip，一次看所有关的状态
python3 -m pytest --solution --all-parts   # 计时结束后：参考答案应该 5 passed
```

`--solution` 和 `--all-parts` 是本目录 conftest.py 提供的练习开关，真实面试里没有。

Part 1 有一个计时断言（0.1 秒）。按目录建索引、只编译可能匹配的 glob，本机是 5 到 12 毫秒，离上限很远；如果你的写法要几十毫秒，时过时不过，说明每次检查还在为全部 3,000 条 glob 付钱，即使这一次过了，也应该改成只处理可能匹配的那几十条。Part 2 的测试会建一个符号链接，需要在 macOS 或 Linux 上跑。

## 结束和重做

1. 到 60 分钟时停下，记下每关的状态，填 [REVIEW_TEMPLATE.md](REVIEW_TEMPLATE.md)。
2. 再看 [solution/EXPLANATION.md](solution/EXPLANATION.md)，然后关掉答案，把没做完的关重写一遍。
3. 重做前把自己的 `taskscope/` 另存一份，再用 `_starter/` 里的原始文件覆盖：

```bash
cp -R _starter/taskscope _starter/tests .
```
