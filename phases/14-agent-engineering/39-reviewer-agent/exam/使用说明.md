# 14/39 分关面试题：Reviewer

形式照 Edison 那场面试：一个写好一半的服务，5 个测试用 `@pytest.mark.skip("Part N")` 锁住，一次解锁一关，要求测试原样全部通过。题面只有英文的 [README.md](README.md)，和真实面试一样；具体要求在测试、断言消息和 docstring 里。

内容来自本课：五个维度的 reviewer rubric（problem fit、scope discipline、assumptions、verification quality、handoff readiness，每维 0 到 2 分，满分 10，低于 7 是 soft fail，低于 5 或任一维 0 分是 hard fail；scope discipline 问的是改动有没有留在合同里，或者合同是不是有意扩大的），review report 的落盘，评审者和构建者是两个角色、评审者不能改 diff，报告说要修就由下一轮构建者去修，以及 skill 里的硬性要求：每个分数都要指向一个文件或一条 trace。打分器、构建者和两个评审都是按脚本返回的假实现，不调用 LLM，不联网。

## 开始

在本目录打开终端：

```bash
python3 -m pip install pytest      # 只需一次
python3 -m pytest                  # 5 个 skipped 说明环境正常
```

然后照 README 注释掉 Part 1 的 skip，再运行 `python3 -m pytest`。

## 规则

- 建议 60 分钟，自己计时。参考分配：Part 1 10 分钟，Part 2 12 分钟，Part 3 12 分钟，Part 4 14 分钟，Part 5 12 分钟。难度和用时还没有经过实测校准。
- 只改 `reviewer/` 里的代码。测试不能改（解除 skip 除外），可以另外新建自己的测试文件。
- 可以查 Python 官方文档（hashlib、json、csv、asyncio 等）。计时期间不要打开 `solution/` 和 `INTERVIEWER.md`。
- 有需求不清楚的地方就问面试官。自己练的时候，先把问题写下来，再去 INTERVIEWER.md 的“澄清问题”一节里只看这一条的答案。

## 常用命令

```bash
python3 -m pytest -x                       # 跑已解锁的关，遇到第一个失败就停
python3 -m pytest -k history -x            # 只跑名字里带 history 的测试
python3 -m pytest --all-parts              # 不解除 skip，一次看所有关的状态
python3 -m pytest --solution --all-parts   # 计时结束后：参考答案应该 5 passed
```

`--solution` 和 `--all-parts` 是本目录 conftest.py 提供的练习开关，真实面试里没有。

## 结束和重做

1. 到 60 分钟时停下，记下每关的状态，填 [REVIEW_TEMPLATE.md](REVIEW_TEMPLATE.md)。
2. 再看 [solution/EXPLANATION.md](solution/EXPLANATION.md)，然后关掉答案，把没做完的关重写一遍。
3. 重做前把自己的 `reviewer/` 另存一份，再用 `_starter/` 里的原始文件覆盖：

```bash
cp -R _starter/reviewer _starter/tests .
```
