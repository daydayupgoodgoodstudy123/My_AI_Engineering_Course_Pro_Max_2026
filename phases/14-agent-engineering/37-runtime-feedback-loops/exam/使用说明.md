# 14/37 分关面试题：FeedLog

形式照 Edison 那场面试：一个写好一半的服务，5 个测试用 `@pytest.mark.skip("Part N")` 锁住，一次解锁一关，要求测试原样全部通过。题面只有英文的 [README.md](README.md)，和真实面试一样；具体要求在测试、断言消息和 docstring 里。

内容来自本课：feedback runner 把每条命令的 argv、stdout 和 stderr 的尾部、退出码、耗时和 agent 写下的预期记成一条结构化记录；拿不到退出码时记 `exit_code: null`，循环拒绝推进（No exit, no progress）；写入前脱敏（redact at write, not at read），而且要先脱敏再截断；确定性的头尾截断和 `...truncated N lines...` 标记；JSONL 按大小轮转到 `.1`、`.2`；用 `parent_command_id` 把重试串成链，复盘时高亮最近一次非零退出。

## 开始

在本目录打开终端：

```bash
python3 -m pip install pytest      # 只需一次
python3 -m pytest                  # 5 个 skipped 说明环境正常
```

然后照 README 注释掉 Part 1 的 skip，再运行 `python3 -m pytest`。

## 规则

- 建议 60 分钟，自己计时。参考分配：Part 1 12 分钟，Part 2 12 分钟，Part 3 10 分钟，Part 4 15 分钟，Part 5 11 分钟。难度和用时还没有经过实测校准。
- 只改 `feedlog/` 里的代码。测试里的 `FakeShell` 是 `subprocess.run` 的替身，`FakeProcess` 是 `asyncio.subprocess.Process` 的替身，都按测试写好的脚本输出，不碰你的 shell。只有 Part 1 和 Part 4 各用 `python -c` 跑一个真实的小进程。测试不能改（解除 skip 除外），可以另外新建自己的测试文件。
- 可以查 Python 官方文档（subprocess、asyncio、json、re、collections、pathlib、tracemalloc）。计时期间不要打开 `solution/` 和 `INTERVIEWER.md`。
- 有需求不清楚的地方就问面试官。自己练的时候，先把问题写下来，再去 INTERVIEWER.md 的“澄清问题”一节里只看这一条的答案。

## 常用命令

```bash
python3 -m pytest -x                       # 跑已解锁的关，遇到第一个失败就停
python3 -m pytest -k follow -x             # 只跑名字里带 follow 的测试
python3 -m pytest --all-parts              # 不解除 skip，一次看所有关的状态
python3 -m pytest --solution --all-parts   # 计时结束后：参考答案应该 5 passed
```

`--solution` 和 `--all-parts` 是本目录 conftest.py 提供的练习开关，真实面试里没有。

Part 3 有一个计时断言，Part 4 有一个内存断言和几个按真实时间算的超时用例。机器很忙时如果偶尔失败，先重跑一次再判断。Part 4 的假进程在一次写入 3 秒没人读时会自己放弃退出，所以读管道的写法有问题时，测试会失败而不是一直卡住。

## 结束和重做

1. 到 60 分钟时停下，记下每关的状态，填 [REVIEW_TEMPLATE.md](REVIEW_TEMPLATE.md)。
2. 再看 [solution/EXPLANATION.md](solution/EXPLANATION.md)，然后关掉答案，把没做完的关重写一遍。
3. 重做前把自己的 `feedlog/` 另存一份，再用 `_starter/` 里的原始文件覆盖：

```bash
cp -R _starter/feedlog _starter/tests .
```
