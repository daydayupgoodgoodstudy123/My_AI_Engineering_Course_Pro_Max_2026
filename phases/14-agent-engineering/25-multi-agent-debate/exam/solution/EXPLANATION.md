# 参考答案讲解：Debate（14/25）

计时结束后再看。参考实现在同目录的 `debate/` 里，`python3 -m pytest --solution --all-parts` 应该显示 5 passed。

## Part 1 修课里的 runner

**现象**：解锁后第一个失败是星形的 ops：算出 24，课里是 12。

**依次修四处**：

1. `sparse_star_round`：课里的数字是“spoke 只读 hub”，N=5、R=3 时 4 个 spoke × 3 轮 = 12。原代码让 hub 也读所有 spoke，每轮多 4 次。修法是 hub 拿一个空的 Counter，谁也不读，每轮 ops 等于 spoke 的个数。只删掉 ops 那一行不够：测试用记录输入的假辩手在星形上跑一轮，hub 收到任何票都会挂。
2. `majority()`：`Counter.most_common` 平票时按插入顺序选，插入顺序就是座次。测试让同样四个辩手正着坐、倒着坐各辩一次，按 docstring 都应该是 Madrid，原代码得 Porto。断言报在 `run_debate` 的结果上，根因在两层之下的 `majority()`，它同时被辩手的 drift 和最后的多数票调用。改成“票数最多的答案里取字母序最小的”。只在 `run_debate` 的最后一票上改不够：三个辩手各持一个答案时，每个人看到的两个 peer 是一比一，drift 里的平票也要按字母序，测试正着、倒着各跑一次。
3. `converged_round`：课里的代码只在第一次全体一致时记一下，之后不再看。docstring 要的是“从哪一轮开始一直一致到最后”，所以出现分歧要清回 -1，重新一致时再记。参考实现还处理了“连续两轮都一致、但一致在不同答案上”的情况，这时从后一轮重新算起。
4. `full_mesh_round`：原代码给每个辩手把其他 N − 1 个人的答案重新数一遍，5000 人一轮要做 2500 万次计数。全体只数一次，给每个人复制一份再减掉自己那一票，复制的代价只和不同答案的个数有关。

**护栏**：常见的提速写法有两种错法。一是数一次就直接发给每个人，自己那一票也在里面；二是减在同一个 Counter 上，第一个人减完，第二个人接着在少了一票的基础上再减。测试用会记录输入的假辩手核对每个人收到的票数，两种都会挂。

还有一处平方：原来的收敛判断 `all(v == list(new.values())[0] for v in new.values())` 每比较一次就复制一遍整个 dict。测试里 5000 人辩完一轮后，第 8 个辩手 d7 还是 Faro，和前面的人不同，`all` 比到第 8 个就停了，所以它不影响计时；参考实现改成了 `len(set(...)) == 1`。

## Part 2 二进制辩论记录

布局在模块 docstring 里写死了，参考实现照着写：一个 `_varint` 编码函数，一个 `_text`，一个带 `take/varint/text` 的 `_Reader`。

- **LEB128**：每字节 7 位，低位组在前，除最后一个字节外最高位置 1。300 = 0b1_0010_1100，低 7 位 0x2C 加上续位得 0xAC，剩下的 2 得 0x02，所以是 `ac 02`。测试逐字节比对一条小记录，组的顺序写反、换成定长整数都会挂。
- **double**：`struct.pack(">d")` 原样保存 64 位，0.1 + 0.2、1/3、5e-324、-0.0 都能还原。32 位 float 会丢精度；-0.0 和 0.0 比较相等，所以测试另外比对了打包后的字节。
- **文本**：长度是 `s.encode("utf-8")` 的字节数。按字符数写，`São Paulo` 少算一个字节，后面的字段全部错位，最后报“cut off”。长度前缀也让 `\x00` 和空串都不需要特殊处理。
- **校验**：`add()` 拒绝负的轮次、越界的辩手和 peer、读自己、重复读同一个 peer、[0, 1] 以外的置信度，全部检查完才 append。越界要写成 `0 <= i < len(roster)`，只查上界会放过 -1。`not 0.0 <= x <= 1.0` 能拦住 NaN，因为 NaN 和任何数比较都是 False；写成 `x < 0 or x > 1` 就放过去了。
- **损坏的数据**：`take()` 在越界时报 ValueError，所以任何位置截断都是 ValueError，不会变成 IndexError 或 struct.error。读完最后一个 turn 后检查没有多余字节；每个 turn 都经过 `add()`，越界的 peer 也会被拦下。turn 数写在前面，截在两个 turn 之间也能发现。

## Part 3 稀疏拓扑辩论

```python
for r in range(1, rounds + 1):
    prior = history[-1]
    current = {}
    for name in names:
        peers = tuple((peer, prior[peer]) for peer in reads[name])
        current[name] = ask(name, Ask(question, r, prior[name], peers))
```

- **同步**：读的永远是 `prior`，也就是上一轮的完整结果，这一轮的结果写进新的 dict。在环形拓扑上，边算边更新会让第二个人读到第一个人刚给出的答案，三个人第 1 轮就“收敛”了。
- **强制分歧**：开场按名单顺序问，`taken` 是已经出现过的答案，去重、保持第一次出现的顺序。辩手不听话就接受它的答案，不重问。
- **收敛**：第 r 轮全体一致，并且 r ≥ min_rounds，才停。测试里三个人第 1 轮一致地错成 Madrid（课里说的 convergence collapse），min_rounds=2 时辩论继续，第 3 轮一致改成 Lisbon。开场那一轮不算：三个人开场都说 Lisbon，辩论也要进到第 1 轮。
- **聚合**：只用最后一轮。按 (−总置信度, −支持人数, 第一个支持者的座次) 取最小，总置信度排在人数前面：只辩 2 轮的那次，b 一个人 1.0 说 Lisbon，压过 a、c 各 0.25 的 Madrid。0.75 和 0.5 + 0.25 是二进制下精确相等的平票，测试专门选了这样的数，让决胜规则真的起作用。
- **ops**：每读一个 peer 算一次，开场是 0。两个 hub 互读、三个 spoke 各读两个 hub，每轮 2 + 6 = 8。

## Part 4 并发轮次和 CSV

每一轮先根据上一轮回答了的人构造所有 Ask，再一起发出去：

```python
replies = await asyncio.gather(*(_ask(debaters[n], asks[n], timeout_s) for n in names))
```

`_ask` 用 `asyncio.wait_for`：超时时它会取消内部的调用，并且等取消完成后才抛出 TimeoutError，所以这一轮报告出来时，被放弃的调用已经结束了。用 `asyncio.wait(timeout=...)` 而不取消，调用还在后台跑，测试会在第 1 轮的记录出来时发现。

- 弃权者不进 `current`：它的单元格为空，agree_ratio 只按回答了的人算，下一轮读它的人跳过它。它的最后一次回答留在 `last` 里，下一轮作为 `own` 给它。
- 收敛要求每个人都回答了，并且答案相同。两个人一致、一个人弃权的那一轮，比例是 1.000，但不算收敛。第 0 轮是开场，大家一致也不停；循环跑满 `rounds` 轮就结束。
- 所有人都超时的那一轮，`answers` 是空的，agree_ratio 写空串，不能拿 0 去除；下一轮 `prior` 是空的，谁也读不到，ops 是 0。
- 每条记录用 `csv.writer` 写进一个新的 StringIO，取出来就是带 `\r\n` 的一整条记录。`Madrid, Spain` 和 `Porto "Invicta"` 会被正确加引号和转义。
- 每轮结束立刻 yield。消费者拿到第 0 轮的记录时，只发生了 3 次调用。
- elapsed_ms 在 gather 前后用 `time.perf_counter()` 量，乘 1000 取整。

## Part 5 读取图分析

先把 reads 反过来，得到“谁在听我”：a 读 b，就把 a 记进 `listeners[b]`。然后从每个辩手出发做 BFS，距离就是它的开场答案传到对方需要的轮数。

- **方向**：课里的星形 spoke 只读 hub，hub 的答案 1 轮传遍，spoke 的答案没人听，reach 是 None，rounds_needed 也是 None。这就是课里 hub failure 的另一面：hub 一个人决定所有人看到什么。
- **一轮一跳**：BFS 的第 k 层就是第 k 轮才听到的人。如果改成按轮模拟，又在同一个集合里边扫边加，一个答案一轮就能走好几跳，环形上 reach 会算成 1 而不是 4，这和 Part 3 的同步轮次是同一个错误。
- **BFS**：要的是最少轮数。递归 DFS 记第一次访问的深度，走的是第一条路，不是最短的路，在全连接上会沿着 a→b→c→d→e 算出 4。
- **去噪**：自己读自己和重复的 peer 在建图时就去掉（`dict.fromkeys` 保持顺序）。ops 是去重后的 (读者, 别人) 对数。
- **camp**：x 能传到 y、y 也能传到 x，就在同一个 camp。参考实现直接用 BFS 的可达集合判断，规模小，O(N·E) 足够。按名单顺序遍历，camp 的成员和 camp 之间的顺序自然都是名单顺序；deaf 也一样，不要再排序。

## 这套题证明了什么，没证明什么

通过了说明你能在课里的 debate 代码上调试计数口径、平票规则和收敛判断，并把它提速；能按固定布局写一个经得起损坏数据的二进制格式；能实现同步轮次、强制分歧和置信度加权的辩论；能用 asyncio 并发地跑每一轮、正确地超时取消，并按 CSV 逐轮输出；能在读取图上算传播轮数、成本和互通的分组。它不涉及真实模型的提示词设计、辩论在 MMLU 或 GSM8K 上的效果、置信度校准，也不涉及 LangGraph、OpenAI Agents SDK 这些框架里的实现方式。课里练习 3 到 5（异构模型、成本与准确率曲线、N=5、R=3 的论文复现）需要另外动手做。
