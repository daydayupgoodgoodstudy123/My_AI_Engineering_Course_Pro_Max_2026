# 参考答案讲解：Delegate（14/45）

计时结束后再看。参考实现在同目录 `delegate/`，`python3 -m pytest --solution --all-parts` 应显示 5 passed。

## Part 1 所有权预览

claim_parts 用 PurePosixPath 进行词法规范化，_claims 只留下写 worker。规范化错误会沿 _claims 传到 conflicts 报告，不是测试里的两个路径真的不相交。

冲突报告按 unit id 与规范化路径去重，重复 id 的计划仍被单独阻塞。owner 要 strip 后非空。依赖验证 helper 已给对，这关不再修一遍未知依赖异常包装。

参考实现把声明放进前缀树。插入时收集已有祖先声明与当前节点所有后代声明，只比较有可能重叠的分支；用 set 消除同一报告重复。兄弟路径不冲突。

## Part 2 证据

每个 unit 和文件名都使用给定的统一大写 Base32 可逆编码成为单个路径片段，解码时补齐到 8 位分组。这样大小写不敏感文件系统也不会把两个不同的编码名字当成同一项。os.open 的 O_EXCL 使已有证据不能被覆写，连空文件也拒绝。bytes 原样写读，重开只建立目录，不清空已有内容。列举时先解码再按原名字排序。

## Part 3 整合

review_handoff 依次检查身份、范围和真实 proof：command 完全相同、exit 为零、output 非空；claimed_passed 不参与证明。

整合前先检查所有交接，再找合格交接之间的共同改动路径。每个共同接口形成 decision，列出全部涉及单元，全部暂不合并。随后按依赖波次/id 生成 merge_order，被拒前置的下游同样拒绝。

最终 changed set 必须恰好等于拟整合改动并集，完整 gate 也须满足命令、退出码和输出要求。这里返回审查计划，没有执行 Git merge 或 shell 命令。

## Part 4 在线结论

先到的子项保留在 pending。只有前置都有 verdict 时才审本项；有前置拒绝则本项直接 dependency 拒绝。一次收到回执后，持续解开已暂存的波次并发完所有行，再继续拉取输入。

输入结束后先给未提交项 missing 拒绝，再解开被它们阻塞的暂存项。NDJSON 由给定 _line 编码；不是 Lamport 协议，也没有真实 worker 调度。

## Part 5 所有权树

沿路径树向下查询时累积各祖先与精确节点 owner，保留所有声明方。一个文件有多 owner 时，用给定 prerequisite_sets 查两项是否有传递先后关系；没有则列出并发冲突。不能用最长前缀只留下一个 owner 隐藏冲突。

同一单元重复声明用集合去重，只读 worker 不入写树。根节点声明参与每次查询，无 owner 的文件显式返回。

## 这套题证明了什么，没证明什么

通过说明能在这个离线规模下审查委派所有权、隔离证据、验证交接与整合回执、实现在线依赖门并审计嵌套写范围。它没有证明真实多 agent 协作效果、worktree隔离、跨进程证据事务、共享接口设计兼容、Git 合并安全或任何真实命令已执行。
