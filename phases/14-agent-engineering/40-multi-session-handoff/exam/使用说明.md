# 14/40 分关面试题：HandoffPkt

形式照 Edison 那场面试：一个写好一半的服务，5 个测试用 `@pytest.mark.skip("Part N")` 锁住，一次解锁一关，要求测试原样全部通过。题面只有英文的 [README.md](README.md)，和真实面试一样；具体要求在测试、断言消息和 docstring 里。

内容来自本课：交接包的七个字段从工作台产物生成，`handoff.json` 和 `handoff.md` 同源、不一致时以 JSON 为准，没有 `next_action` 的只是状态报告，feedback 日志只带最后 K 条加所有非零退出，交接包要小，生成前先做 Leave a clean state 的五项清理检查（为空才允许生成），以及 One active handoff per branch：任务分叉以后，每条分支从自己最新的那一份交接包接着做。

## 开始

在本目录打开终端：

```bash
python3 -m pip install pytest      # 只需一次
python3 -m pytest                  # 5 个 skipped 说明环境正常
```

然后照 README 注释掉 Part 1 的 skip，再运行 `python3 -m pytest`。

## 规则

- 建议 60 分钟，自己计时。参考分配：Part 1 14 分钟，Part 2 10 分钟，Part 3 14 分钟，Part 4 10 分钟，Part 5 12 分钟。难度和用时还没有经过实测校准。
- 只改 `handoffpkt/` 里的代码。题目里没有模型调用，也不联网，工作台产物（状态、gate 报告、review 报告、feedback 日志、diff、仓库快照）都是测试直接给的数据。测试不能改（解除 skip 除外），可以另外新建自己的测试文件。
- 可以查 Python 官方文档（json、shlex、dataclasses、collections、pathlib、os、tempfile、re）和 git 的文档。计时期间不要打开 `solution/` 和 `INTERVIEWER.md`。
- 有需求不清楚的地方就问面试官。自己练的时候，先把问题写下来，再去 INTERVIEWER.md 的“澄清问题”一节里只看这一条的答案。

## 常用命令

```bash
python3 -m pytest -x                       # 跑已解锁的关，遇到第一个失败就停
python3 -m pytest -k history -x            # 只跑名字里带 history 的测试
python3 -m pytest --all-parts              # 不解除 skip，一次看所有关的状态
python3 -m pytest --solution --all-parts   # 计时结束后：参考答案应该 5 passed
```

`--solution` 和 `--all-parts` 是本目录 conftest.py 提供的练习开关，真实面试里没有。

Part 1 有一个计时断言（限值 0.1 秒）。机器很忙时如果偶尔超时，先重跑一次再判断。

## 结束和重做

1. 到 60 分钟时停下，记下每关的状态，填 [REVIEW_TEMPLATE.md](REVIEW_TEMPLATE.md)。
2. 再看 [solution/EXPLANATION.md](solution/EXPLANATION.md)，然后关掉答案，把没做完的关重写一遍。
3. 重做前把自己的 `handoffpkt/` 另存一份，再用 `_starter/` 里的原始文件覆盖：

```bash
cp -R _starter/handoffpkt _starter/tests .
```
