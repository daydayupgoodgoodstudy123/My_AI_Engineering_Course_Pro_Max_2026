# 14/16 分关面试题：Handoffs

形式照 Edison 那场面试：一个写好一半的服务，5 个测试用 `@pytest.mark.skip("Part N")` 锁住，一次解锁一关，要求测试原样全部通过。题面只有英文的 [README.md](README.md)，和真实面试一样；具体要求在测试、断言消息和 docstring 里。

内容来自本课：Agents SDK 的五个原语（Agent、Handoff、Guardrail、Session、Tracing），handoff 是名为 `transfer_to_<agent>` 的工具，交接时复制整段对话或者用 `nest_handoff_history` 折叠，护栏只在第一个 agent 的输入、最后一个 agent 的输出和每个 function tool 上运行，handoff drift 要用 hop 计数器拦住，内置工具不归工具护栏管，以及用 `add_trace_processor` 把 span 同时送到自己的后端。

## 开始

在本目录打开终端：

```bash
python3 -m pip install pytest      # 只需一次
python3 -m pytest                  # 5 个 skipped 说明环境正常
```

然后照 README 注释掉 Part 1 的 skip，再运行 `python3 -m pytest`。

## 规则

- 建议 60 分钟，自己计时。参考分配：Part 1 12 分钟，Part 2 12 分钟，Part 3 10 分钟，Part 4 14 分钟，Part 5 12 分钟。难度和用时还没有经过实测校准。
- 只改 `handoffs/` 里的代码。测试里的 `Model` 是模型替身，按测试写好的函数作答，不调用真实的 LLM，也不联网。测试不能改（解除 skip 除外），可以另外新建自己的测试文件。
- 可以查 Python 官方文档（json、re、sqlite3、dataclasses、threading、queue）。计时期间不要打开 `solution/` 和 `INTERVIEWER.md`。
- 有需求不清楚的地方就问面试官。自己练的时候，先把问题写下来，再去 INTERVIEWER.md 的“澄清问题”一节里只看这一条的答案。

## 常用命令

```bash
python3 -m pytest -x                       # 跑已解锁的关，遇到第一个失败就停
python3 -m pytest -k session -x            # 只跑名字里带 session 的测试
python3 -m pytest --all-parts              # 不解除 skip，一次看所有关的状态
python3 -m pytest --solution --all-parts   # 计时结束后：参考答案应该 5 passed
```

`--solution` 和 `--all-parts` 是本目录 conftest.py 提供的练习开关，真实面试里没有。

Part 1 和 Part 4 各有一个计时断言。机器很忙时如果偶尔超时，先重跑一次再判断。

## 结束和重做

1. 到 60 分钟时停下，记下每关的状态，填 [REVIEW_TEMPLATE.md](REVIEW_TEMPLATE.md)。
2. 再看 [solution/EXPLANATION.md](solution/EXPLANATION.md)，然后关掉答案，把没做完的关重写一遍。
3. 重做前把自己的 `handoffs/` 另存一份，再用 `_starter/` 里的原始文件覆盖：

```bash
cp -R _starter/handoffs _starter/tests .
```
