## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | 直线插值路径 | `x_t = t·x₁ + (1−t)·x₀`，本节约定 `t=0` 是数据、`t=1` 是噪声 `N(0, I)` |
| 2 | 速度（velocity）目标 | 沿直线的时间导数是常数 `dx_t/dt = x₁ − x₀`，网络 `v_θ(x_t, t)` 就回归这个量 |
| 3 | 条件流匹配（CFM）损失 | `L = E‖v_θ(x_t, t) − (x₁ − x₀)‖²`；训练是 simulation-free 的：只采样 `(x₀, x₁, t)` 做回归，不展开 ODE |
| 4 | Euler 采样 | 推理时从 `x₁ ~ N(0, I)` 出发反向积分：`x_{t−Δt} = x_t − Δt·v_θ(x_t, t)`，步数 = 积分步数 |
| 5 | 学到的路径为何会弯 | 同一个 `x_t` 可能来自很多 `(x₀, x₁)` 配对，最优 `v` 是这些目标的条件平均，平均后的轨迹不再是直线 |
| 6 | Rectified flow / reflow | 用已训练的 `v₁` 积分得到"ODE 配对"的 `(x₁, x₀)`，再在这些配对上训练 `v₂`，路径更直；代价是每个配对一次完整推理 |
| 7 | 与扩散的关系 | 高斯路径 `x_t = α(t)x₀ + σ(t)x₁` 下二者代数等价，速度为 `α'·x₀ + σ'·x₁`；FM 的贡献是目标清晰、损失简洁、允许非高斯插值 |
| 8 | 时间采样分布 | 均匀采样 `t` 最简单；SD3 用 logit-normal 把样本集中在中段 `t`，那里预测最难、梯度最有用 |
| 9 | 速度版 CFG | 把 ε 换成 v 即可：`v_cfg = (1+w)·v_cond − w·v_uncond` |
| 10 | 少步推理的生产配方 | 流匹配底座 + 蒸馏（reflow / consistency / 对抗蒸馏）→ 1–4 步，如 Flux.1-schnell 4 步 vs Flux.1-dev 50 步 |

## 五、参考答案与解析

### Q1 — 答案：B

`x_t = t·x₁ + (1−t)·x₀` 对 `t` 求导得 `x₁ − x₀`，与 `t` 无关，是常数。代码里也是 `target = x1 - x0`。A 方向反了——如果目标写成 `x₀ − x₁`，采样时就得用 `x += dt·v`，方向约定必须前后一致。C 是 DDPM 的 ε-prediction；D 是 x₀-prediction，它们都是合法的参数化，但不是本节的速度目标。

### Q2 — 答案：B

`v` 是"沿 `t` 增加方向"的速度（指向噪声），采样是从 `t=1` 往 `t=0` 走，所以要减：`x_{t−Δt} = x_t − Δt·v`。代码 `x -= dt * v` 正是如此。C 少了步长，只有 1 步时才碰巧等于 `dt=1` 的情形。D 是 score-based / Langevin 的形式，不是本节的 ODE。

### Q3 — 答案：C

单个条件路径（给定一对 `x₀, x₁`）确实是直线，但网络看不到配对，只看到 `x_t`。最小化平方损失的最优解是条件期望 `v*(x, t) = E[x₁ − x₀ | x_t = x]`。在 `t` 较大时，一个 `x_t` 可能来自左峰也可能来自右峰，目标被平均，整体流场就会弯曲。A 是另一个问题（积分误差），它是"路径弯 → Euler 少步不准"的**结果**而不是原因；B、D 都不是根本原因。

### Q4 — 答案：B

训练时只需三次采样 + 一次插值 + 一次回归，不用像 Neural ODE / 连续归一化流那样在训练中解 ODE。D 说反了：推理恰恰需要积分，步数就是积分步数。

### Q5 — 答案：D

skill 文件明确写了：在 `v₁` 收敛前不要做 reflow——在坏模型上 reflow 只会把错误方向"固化"进配对数据。A、B、C 都是讲义原话的要点：reflow 用 ODE 生成配对、配对后插值更直、每个配对一次完整推理所以很贵，"只有真的需要 1–2 步推理时才做"。

### Q6 — 答案：B

logit-normal 即 `t = sigmoid(u)`，`u ~ N(m, s)`，样本集中在中段。讲义的关键术语表解释为"把 t 采样集中到中间值，那里梯度最强"。直觉上：`t≈0` 时 `x_t≈x₀`，`t≈1` 时 `x_t≈x₁`，速度都相对好估计；中段信息最混杂，最值得多练。A 方向反了；C 是 DDPM 的离散时间；D 混淆了训练分布与推理步长调度。

### Q7 — 答案：A

逐项求导即可：`d/dt[α(t)x₀ + σ(t)x₁] = α'(t)x₀ + σ'(t)x₁`。验证：线性调度 `α = 1−t`、`σ = t` 时 `α' = −1`、`σ' = 1`，得 `x₁ − x₀`，与 Q1 一致。⚠️ 讲义英文原文此处写作 `v = α'·x_0 - σ'·x_1`，代入线性调度会得到 `−x₀ − x₁`，与本节的目标矛盾，应为加号（属于原文笔误）。

### Q8 — 答案：B

`(1+2)·1.0 − 2·0.4 = 3.0 − 0.8 = 2.2`。等价写法 `v_uncond + (1+w)·(v_cond − v_uncond)`。`w = 0` 时退化为纯条件预测；`w` 越大，越往"条件方向"外推，提示词贴合度提高但多样性下降、可能过饱和。

### Q9 — 参考答案

(a) `num_steps=1` 时 `dt=1`，循环只跑 `i=0`，`t=1.0`，于是 `x_final = x₁ − v_θ(x₁, 1)`：在纯噪声端估一次速度，然后一步走完整条路径。

(b) 在 `t=1` 时 `x_t = x₁`，它与 `x₀` 相互独立，所以最优速度是 `E[x₁ − x₀ | x₁] = x₁ − E[x₀]`。代入得 `x_final ≈ E[x₀]`——数据的**均值**。这里两个峰在 ±2、各占一半，均值 ≈ 0，正好落在两峰之间的"空地"上。这就是"路径弯曲 + 一步走直线"的后果：第一步的方向是所有可能目标的平均。实际网络并不完美，所以没有精确塌到一个点，而是一团以 0 为中心的分布。我用同样的种子额外统计过：1 步时约 60% 的样本落在 `|x|<1`（真实数据几乎没有样本在那里），标准差约 1.25；20 步时这两个数字约为 1% 和 2.6（真实分布标准差约 2.02）。

(c) 打印的"left / right mode"只是按 `x>0` 计数。一个以 0 为中心对称的单峰分布，按符号切开也会接近 50/50。这个指标对"塌缩到中间"完全不敏感——正说明评估生成模型不能只看单一粗糙指标，必须结合分布形状（直方图）或分布距离（下一节的 FID 思想）。

### Q10 — 参考答案

`sin(2πt)` 和 `cos(2πt)` 的周期是 1：`t=0` 与 `t=1` 时两者完全相同（`sin=0`、`cos=1`）。如果只留它们，网络**无法区分数据端和噪声端**——而这两端的最优速度截然不同（`t=1` 处约为 `x − E[x₀]`，`t≈0` 处取决于离哪个峰近）。保留 `t`（线性、单调）和 `t²`（给出一点非线性）就打破了这种周期歧义。

延伸：真实模型（DiT / U-Net）一般用多频率的正弦时间嵌入，频率覆盖从低到高，最低频的周期远大于 `t` 的取值范围，所以不会出现这个问题；本代码只用了单一频率，才需要额外的 `t`、`t²` 来补。

### Q11 — 参考答案

```python
import math

def sample_t_logit_normal(rng, m=0.0, s=1.0):
    u = rng.gauss(m, s)
    return 1.0 / (1.0 + math.exp(-u))   # sigmoid，结果严格落在 (0, 1)
```

替换 `train` 中的 `t = rng.random()`，改为 `t = sample_t_logit_normal(rng)`。其他（`x_t`、目标、损失）都不用动。

说明：
- `m` 控制中心（`m=0` 时中心在 `t=0.5`），`s` 控制集中程度（`s` 越小越集中）。
- 它只改变"在哪些 `t` 上多训练"，不改变目标本身；推理时的 Euler 步还是均匀步长。
- 小心：两端（`t` 接近 0 或 1）样本变少，如果推理恰好在端点附近出问题（例如本代码 1 步采样只在 `t=1` 估一次），端点精度可能反而下降。所以这是一个需要实验验证的超参，而不是"换了一定更好"。

### Q12 — 参考答案

```python
def make_pairs(net, n, num_steps, rng):
    pairs = []
    for _ in range(n):
        x1 = rng.gauss(0, 1)
        x = x1
        dt = 1.0 / num_steps
        for i in range(num_steps):          # 与 sample() 相同的 Euler 积分
            t = 1.0 - i * dt
            v, _ = forward(x, t, net)
            x -= dt * v
        pairs.append((x, x1))               # (落点 x0, 起点 x1)：ODE 配对
    return pairs


def train_reflow(net, pairs, steps, lr, rng):
    for _ in range(steps):
        x0, x1 = pairs[rng.randrange(len(pairs))]   # 不再独立采样 x0、x1
        t = rng.random()
        x_t = t * x1 + (1 - t) * x0
        pred, cache = forward(x_t, t, net)
        grads = backward(x1 - x0, pred, cache, net)
        apply(net, grads, lr)


# 用法
net1 = init_net(5, 24, 1, rng); train(net1, 6000, 0.01, rng)
pairs = make_pairs(net1, 2000, 20, rng)      # 用较多步数保证配对精确
net2 = init_net(5, 24, 1, rng); train_reflow(net2, pairs, 6000, 0.01, rng)
```

要点：
- 和 `train` 唯一的本质区别是 `(x₀, x₁)` **不再独立**：`x₀` 是 `x₁` 沿 `v₁` 的 ODE 落点。于是 `x_t` 与 `x₀` 之间的歧义大大减小，条件平均不再"抹平"方向，路径更直。
- 生成配对要用足够多的步数（这里 20 步），否则配对本身就有积分误差。
- 我用种子 31 跑过一次：`v₁` 的 1 步采样约 59% 样本落在 `|x|<1`（塌在中间）；reflow 后的 `v₂` 1 步采样只有约 12% 落在中间，已经明显是双峰。具体数值随种子变化，但趋势稳定。

### Q13 — 参考回答要点

- **训练目标**：DDPM 预测加进去的噪声 ε（离散 `t ∈ {1..T}`，通常 T=1000），配合固定的 β 调度；FM 预测沿插值路径的速度 `v = x₁ − x₀`（连续 `t ∈ [0,1]`），损失就是对它的 MSE，训练 simulation-free。
- **为什么适合少步**：采样就是解 ODE `dx/dt = v`。路径越直，Euler 这种一阶积分器的截断误差越小；路径完全直时一步 Euler 就精确。直线插值让目标本身是常数速度，比 DDPM 的弯曲轨迹更容易少步积分。
- **数学关系**：对高斯路径 `x_t = α(t)x₀ + σ(t)x₁`，FM 就是一种特定噪声调度的扩散，速度 `α'x₀ + σ'x₁` 与 ε、x₀ 预测之间可以线性互换（讲义："对高斯路径代数等价"）。Stochastic Interpolants（Albergo & Vanden-Eijnden）把两者纳入同一框架。
- **FM 真正多出来的东西**：目标清晰（就是速度）、损失干净、允许非高斯插值 / 任意两个分布之间搬运。
- **常见误区**：说"FM 天然一步出图"。不对——随机配对下的流仍然弯（见 Q3、Q9），1 步要靠 reflow 或蒸馏。

### Q14 — 参考回答要点

- **问题**：CFM 的"直"是对**条件路径**而言；网络学到的是边缘（marginal）流场 `E[x₁ − x₀ | x_t]`，在不同配对的直线互相交叉的地方会被平均，所以积分轨迹是弯的。
- **reflow 做了什么**：用 `v₁` 把每个 `x₁` 积分到 `x₀`，得到一个确定性的配对（coupling）。ODE 轨迹之间不会相交，因此新配对下的直线插值交叉大大减少，条件平均几乎不"抹平"，`v₂` 学到的流场更接近直线。讲义说迭代 2 次即可接近线性、支持 2–4 步推理。Liu 等人的论文还证明 rectify 后的配对不会增加凸传输代价。
- **代价**：每个配对都要一次完整推理（多步积分），等于把一遍推理成本搬到训练里；配对数据集要足够大、要足够覆盖。
- **风险**：①`v₁` 没收敛就 reflow，会把错误方向固化（skill 文件的拒绝条件）；②积分误差会累积到配对里，多轮 reflow 可能让样本质量 / 多样性下降；③只在真的需要 1–2 步时才值得做。
- **加分点**：能画出"两个高斯之间随机配对线条交叉 vs reflow 后线条平行"的示意图；能说出 1 步通常还要叠加 consistency 蒸馏（skill 文件："不要在没有 consistency distillation 的情况下推荐 1 步推理"）。

### Q15 — 参考回答要点

- **算账**：讲义给出的 L4、1024² 参考：Flux.1-dev 50 步约 15 s；Flux.1-schnell 4 步约 1.2 s（约 12 倍快）；SDXL-base 30 步约 4 s；SDXL-Lightning 2 步约 0.3 s。< 1.5 s 的约束基本排除了 50 步底座，需要 1–4 步的蒸馏模型。
- **选型**：讲义的生产规则是"flow-matched 底座 + 蒸馏 = 2026 年快速文生图的默认组合"。Flux.1-schnell 是 Flux 系 DiT 经过蒸馏 / 拉直后可 1–4 步出图的版本；dev 是质量优先、多步的版本。
- **流水线**：T5 + CLIP 编码文本 → 量化后的 MMDiT 去噪 4 步 → VAE 解码（讲义提到的 8GB 机器部署思路）。延迟不只在去噪：文本编码与 VAE 解码在步数降到 4 后占比会上升，需要一起优化。
- **取舍**：少步模型通常多样性更低、对 CFG 更敏感（很多蒸馏模型干脆不再用或弱化 CFG）、细节可能略差；需要用 FID / CLIP score / 人工偏好在目标分布上对比验证，画"质量 vs 步数"曲线（见第 14 节）。
- **常见误区**：只盯模型参数量，不算步数；或者在 50 步模型上简单把步数砍到 4（不蒸馏就会明显变糊）。

### Q16 — 参考回答要点

- **时间方向**：本节和 SD3 约定 `t=0` 为数据、`t=1` 为噪声；DDPM 的 `t=0` 也是数据、`t=T` 是噪声，方向相同、尺度不同。但不同论文 / 代码库约定并不统一（有的把 `t=0` 设为噪声），搬代码时最容易出现"目标符号反了"或"采样往错误方向走"的 bug。检查方法：用解析可知的简单分布（如单个高斯）跑一次，看样本均值方差对不对。
- **时间采样分布**：均匀 `t` 简单但在两端浪费容量；SD3 用 logit-normal 集中在中段；也可以用 cosine 等调度。它影响的是训练"预算分配"，不改变目标。
- **CFG**：把 ε 换成 v 即可，`v_cfg = (1+w)v_cond − w·v_uncond`；训练时照样要随机丢弃条件以学到无条件分支。
- **其他**：插值/目标的符号必须和采样器一致；时间嵌入要能区分两端（见 Q10）；reflow 前确认 `v₁` 收敛。
- **加分点**：能主动提到"把框架 A 的 checkpoint 接到框架 B 的 sampler 上时，时间约定和预测目标（ε / x₀ / v）都要对齐"。

### Q17 — 参考回答要点

1. **插值与目标**：把 DDPM 的 `x_t = √ᾱ_t·x₀ + √(1−ᾱ_t)·ε` 换成直线 `x_t = t·x₁ + (1−t)·x₀`（或保留高斯调度但改成速度目标），网络输出从 ε 改成 `v`。
2. **时间**：离散 `t ∈ {1..1000}` 改为连续 `t ∈ [0,1]`；时间嵌入随之改；选择均匀或 logit-normal 采样。
3. **损失**：`‖v_θ − (x₁ − x₀)‖²`，不再需要 β 调度表。
4. **采样器**：DDPM/DDIM 采样器换成 ODE 积分器（Euler 或高阶）；CFG 公式中把 ε 换成 v。
5. **优化器**：skill 文件建议 Transformer 规模下用 AdamW 且 β₂=0.95，配合 lr warmup。
6. **少步计划**：决定是否 reflow（0/1/2 次）、是否做 consistency 蒸馏；目标推理步数（20/4/2/1）。skill 文件提醒：如果迁移后仍需要 > 20 步推理，说明重构没有带来收益。
7. **验收**：与 DDPM 基线在相同数据上对比 FID、CLIP score，画"质量 vs 步数"曲线；关键看 4–8 步时是否已接近基线多步质量。
- **常见误区**：只改损失不改采样器；混用时间约定；在 `v₁` 未收敛时就开始 reflow。
