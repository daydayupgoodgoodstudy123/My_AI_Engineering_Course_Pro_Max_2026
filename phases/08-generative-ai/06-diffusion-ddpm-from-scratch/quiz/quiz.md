## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | 扩散模型想解决什么 | 要一个**单一、稳定**的损失（不像 GAN 的 minimax），还是 `log p(x)` 的下界（不像 GAN 没有似然），样本质量又要达到 SOTA（不像 VAE 模糊） |
| 2 | 前向过程与闭式解 | 分 T 步逐渐加高斯噪声；累积结果仍是高斯：`q(x_t | x₀) = N(√ᾱ_t · x₀, (1 - ᾱ_t) · I)`，`ᾱ_t = ∏(1 - β_s)`，所以可以**一步**得到任意 `x_t` |
| 3 | 噪声调度 | DDPM 默认 β 在 T=1000 步内从 1e-4 线性增到 0.02，使 `x_T ≈ N(0, I)`；cosine 调度（Nichol & Dhariwal 2021）同等算力下 FID 更好 |
| 4 | 训练目标 `L_simple` | 采 `x₀`、随机 `t`、采 `ε`，算 `x_t = √ᾱ_t·x₀ + √(1-ᾱ_t)·ε`，回归 `||ε - ε_θ(x_t, t)||²`；没有 minimax、没有 KL |
| 5 | 反向一步 | `x_{t-1} = (1/√α_t) · (x_t - β_t/√(1-ᾱ_t) · ε_θ(x_t, t)) + σ_t · z`，`σ_t = √β_t` 或学习得到；最后一步不加噪声 |
| 6 | 为什么有效 | 两端的去噪都容易、所有噪声水平共享同一套权重；预测噪声 = 估计 score（差一个缩放与符号）；完整 ELBO 的每步 KL 化简为带系数的噪声 MSE，Ho 去掉系数后质量反而更好 |
| 7 | 时间条件 | 网络必须知道当前 t：正弦嵌入（类似 Transformer 位置编码）→ MLP → 拼接（本节玩具）或 FiLM（生产 U-Net）；图像上直接喂浮点 t 会失败 |
| 8 | 预测目标 | ε-prediction（DDPM 标准）、v-prediction（`v = α·ε - σ·x`，在极小/极大 t 处信噪比更好）、x₀-prediction |
| 9 | CFG | 训练时以 10% 概率丢掉条件；推理时 `ε_cfg = (1 + w)·ε_cond - w·ε_uncond`，`w ≈ 3–7` |
| 10 | 推理是"步数问题" | 延迟 = `num_steps × step_cost + VAE_decode`；三种降本：更快的采样器（DDIM 20–50 步、DPM-Solver++ 10–20 步）、蒸馏（1–4 步，需重训）、编译/低精度（单步约 2 倍） |

### 核心技能（能动手做到）

- [ ] 手写 β、α、ᾱ 三个调度数组，并能算出 `ᾱ_T`、判断前向过程终点是否真的接近 `N(0, 1)`
- [ ] 用闭式解一步加噪，写出完整的 `L_simple` 训练循环（随机 t、正弦时间嵌入、MLP 预测 ε、手写反向传播）
- [ ] 实现 DDPM 反向采样循环，并说明为什么 `t = 0` 时不加噪声
- [ ] 由 `ε̂` 反推 `x̂₀ = (x_t - √(1-ᾱ_t)·ε̂) / √ᾱ_t`，并在此基础上实现确定性 DDIM 采样器（跳步）
- [ ] 在 ε、x₀、v 三种预测目标之间互相换算
- [ ] 用"步数 × 单步成本 + VAE 解码"估算延迟，并为给定预算选择采样器 / 蒸馏 / 编译方案

## 五、参考答案与解析

### Q1 — 答案：A

`x_t = √ᾱ_t · x₀ + √(1-ᾱ_t) · ε = √0.64 · 2 + √0.36 · 0.5 = 0.8 × 2 + 0.6 × 0.5 = 1.90`。C（1.46）是忘了开方，直接用 `ᾱ_t · x₀ + (1-ᾱ_t) · ε`——这是实现中最常见的错误之一。注意两个系数的平方和为 1（`0.64 + 0.36`），保证当 `x₀` 也是单位方差时 `x_t` 方差保持为 1（方差保持，variance-preserving）。

### Q2 — 答案：B

`x_t = √α_t · x_{t-1} + √β_t · ε_t`，逐层代入后 `x_t` 是 `x₀` 的缩放加上 t 个独立高斯噪声的线性组合，而独立高斯之和仍是高斯，方差可以合并，得到 `N(√ᾱ_t·x₀, (1-ᾱ_t)I)`。讲义："The closed form — the reason the math is tractable — is that the cumulative step is also Gaussian." 这让训练时可以随机挑 t、一步加噪，训练效率极高。

### Q3 — 答案：B

讲义"Why it works"第 3 点：完整的变分下界每个时间步有一个 KL 项，在 DDPM 的参数化下这些 KL 化简为带特定系数的噪声 MSE；Ho 去掉这些系数（"simple" loss），质量反而提升。A 是 GAN；C 错，它是下界的一个（重新加权的）变体；D 错，正是 KL 有闭式解才化简成了 MSE。

### Q4 — 答案：B

`Σβ ≈ 40 × (1e-4 + 0.02)/2 ≈ 0.40`，`ᾱ_T ≈ e^{-0.40} ≈ 0.67`（精确值 0.6671），`√ᾱ_T ≈ 0.817`。也就是说 40 步加完噪后，数据仍保留约 82% 的幅度，噪声标准差只有约 0.58，远不是纯噪声。但 `sample` 却从 `N(0, 1)` 起步——训练和采样在起点处不一致。讲义说"over T=1000 steps... x_T is approximately N(0, I)"（T=1000 时 `ᾱ_T ≈ 4e-5`，确实接近 0），但代码把同一 β 区间用在了 T=40 上。详见 Q9。

### Q5 — 答案：B

`q(x_t | x₀)` 的 score 是 `-(x_t - √ᾱ_t·x₀)/(1-ᾱ_t) = -ε/√(1-ᾱ_t)`。去噪得分匹配（Vincent 2011）表明，回归这个条件 score 等价于（差常数）回归边缘分布 `p_t` 的 score。所以 `ε_θ ≈ -√(1-ᾱ_t)·∇ log p_t(x_t)`：预测噪声就是在估计 score，只差一个与 t 有关的缩放和负号。讲义："Score matching in disguise."

### Q6 — 答案：D

`ε_cfg = (1 + w)·ε_cond - w·ε_uncond = 4 × 0.5 - 3 × 0.2 = 2.0 - 0.6 = 1.4`。等价写法：`ε_uncond + (1 + w)·(ε_cond - ε_uncond) = 0.2 + 4 × 0.3 = 1.4`——即沿"有条件减无条件"的方向外推，放大条件的影响。注意常见库里的 "guidance scale" 往往指这里的 `1 + w`。

### Q7 — 答案：B

讲义 Production note 第 1 类："Faster sampler, same model. DDIM (20-50 steps), DPM-Solver++ (10-20), UniPC (8-16). Drop-in replacement of the reverse loop; the trained ε_θ weights are untouched. Cuts latency 20-50×." A 是蒸馏，需要重训（第 2 类）；C 会更慢；D 需要重训，而且 T 变小但 β 不变会让前向过程加不够噪声（见 Q9）。

### Q8 — 答案：B

`t` 决定了 `x_t` 中信号与噪声的比例：`t` 小时只需微调，`t` 大时要做大幅"想象"。同一个 `x_t = 1.0` 可能是"几乎干净的 1.0"，也可能是"噪声很大的某个样本"，最优的 `ε̂` 完全不同。一个网络服务所有噪声水平（讲义："many gradients flowing through the same weights from every noise level"），就必须用 t 区分。讲义还提醒：玩具 1-D 问题里直接喂浮点 t 可以凑合，图像上必须用正经的嵌入。

### Q9 — 参考答案

**(a)** `Σβ = T × (β_1 + β_T)/2`：
- T=40：`Σβ ≈ 40 × 0.01005 ≈ 0.40`，`ᾱ_T ≈ e^{-0.40} ≈ 0.67`（精确值 0.6671）；
- T=10：`Σβ ≈ 10 × 0.01005 ≈ 0.10`，`ᾱ_T ≈ 0.90`（精确值 0.9037）；
- 作为对照，T=1000 时 `ᾱ_T ≈ 4e-5`。

**(b) 不一致。** 训练时网络在 `t = T-1` 见到的是 `√ᾱ_T·x₀ + √(1-ᾱ_T)·ε`：T=40 时是中心约 ±1.63、标准差约 0.66 的两峰分布；T=10 时是中心约 ±1.90、标准差约 0.49 的两峰分布。而采样从单峰的 `N(0, 1)` 起步，大量起点落在两峰之间网络很少见过的区域。这是**训练/推理分布错位**。

**(c)** T=10 时问题更严重：
- 起点分布 `N(0, 1)` 与真实 `x_T` 分布（两峰 ±1.9）差得更远；
- 反向链每步只能去掉很少的噪声（β ≤ 0.02），均值项整体只放大约 `1/√ᾱ_T ≈ 1.05` 倍，10 步加起来根本没有能力把一个靠近 0 的起点"推"到 ±2；
- 于是样本停在 ±1.2 附近，42% 落在 `|x| < 1` 的低密度区，两峰明显向中间塌缩。
T=40 时 `1/√ᾱ_T ≈ 1.22`，加上 40 步的漂移项，勉强能把样本推到 -2.19 / +1.68，但正峰仍偏内、两峰都偏宽，6.8% 的样本落在低密度区（真实约 0.6%）。

**(d) 修法**：让调度随 T 调整，使 `ᾱ_T ≈ 0`（前向终点真的接近 `N(0, 1)`），例如按 `1000/T` 放大 β、或用 cosine 调度。注意事项：
1. **β_T 不能太大**：技能文件把 `β_T > 0.1` 标记为"容易饱和或不稳定"。反向一步要乘 `1/√α_t`，`β_t → 1` 时会把误差放大几十倍——我试过 cosine 调度把 β 截断在 0.999，最后一步放大约 `1/√0.001 ≈ 31.6` 倍，样本直接发散到上百。
2. **少步数 = 每步跨度大 = 学习更难**：我用 `β ∈ [1e-3, 0.2]`（`ᾱ_T ≈ 0.013`）重训同一个 24 单元 MLP、同样 4000 步，样本的两峰标准差反而变成 1.2–1.6，说明调度修正后还需要更大的网络或更多训练步数。
3. 这正是生产中"训练用较多步（如 T=1000），推理用 DDIM / DPM-Solver 跳步"的原因：训练时的调度保持细粒度，推理时少步而不改调度。

### Q10 — 参考答案

```python
import math

def predict_x0(x_t, eps_hat, a_bar):
    return (x_t - math.sqrt(1 - a_bar) * eps_hat) / math.sqrt(a_bar)

def ddim_sample(net, alpha_bars, T, t_dim, rng, num_steps=10):
    """eta=0 的确定性 DDIM：只在 num_steps 个时间步上调用网络。"""
    ts = [round(i * (T - 1) / (num_steps - 1)) for i in range(num_steps)][::-1]  # 39 ... 0
    x = rng.gauss(0, 1)
    for i, t in enumerate(ts):
        eps_hat = forward([x], sin_embed(t, T, t_dim), net)[0][0]
        x0_hat = predict_x0(x, eps_hat, alpha_bars[t])
        if i + 1 < len(ts):
            a_prev = alpha_bars[ts[i + 1]]
            x = math.sqrt(a_prev) * x0_hat + math.sqrt(1 - a_prev) * eps_hat
        else:
            x = x0_hat
    return x
```

（`forward`、`sin_embed` 从 `main` 导入；`num_steps=10` 时时间步为 `[39, 35, 30, 26, 22, 17, 13, 9, 4, 0]`。）

在 `main()` 同样训练出的网络上，用独立随机数各采 1000 个样本，实测：

```text
DDPM 40 steps: 负峰 mean -2.19 sd 0.61 | 正峰 mean +1.68 sd 0.54 | |x|<1 6.8%
DDIM 40 steps: 负峰 mean -1.74 sd 0.63 | 正峰 mean +1.30 sd 0.54 | |x|<1 20.5%
DDIM 10 steps: 负峰 mean -1.72 sd 0.63 | 正峰 mean +1.31 sd 0.55 | |x|<1 19.9%
DDIM  5 steps: 负峰 mean -1.71 sd 0.66 | 正峰 mean +1.32 sd 0.56 | |x|<1 19.7%
```

解读：
- **DDIM 的卖点得到验证**：40、10、5 步的结果几乎一样——同一个 `ε_θ`、不重训，步数砍到 1/8 质量基本不变。这就是讲义说的"drop-in replacement... cuts latency 20-50×"。
- **但 DDIM 在这里整体比 DDPM 差**（两峰更靠内、低密度区 20%）。原因是 Q9 的起点错位：DDIM 是确定性映射，起点 `N(0, 1)` 的"过于居中"被原样带到终点；DDPM 每步注入新噪声，再配合漂移项，部分纠正了起点错误。在 `ᾱ_T ≈ 0` 的正确调度下，DDIM 不会有这个劣势。
- `predict_x0` 是一切少步采样器、x₀/v 预测换算、以及可视化"当前步预测的干净图"的基础公式。

### Q11 — 参考答案

**(a)** 损失是 `(ε̂ - ε)²`，对 `ε̂` 求导得 `2(ε̂ - ε)`。很多实现会用 `0.5·(ε̂ - ε)²` 来消掉这个 2，二者只差学习率的一个常数倍。

**(b)** `tanh_grad(cache["h2"])` 每次都会对整个 24 维向量重新计算 `1 - h²` 并生成新列表，而它被写在列表推导式**内部**，对每个 `j` 都算一遍，然后只取第 `j` 个——总共 `24 × 24 = 576` 次计算，复杂度 `O(H²)`，本应是 `O(H)`。`d_pre1` 同理。改写：

```python
    g2 = tanh_grad(cache["h2"])                       # 只算一次
    d_pre2 = [dh * g for dh, g in zip(d_h2, g2)]
    # ...
    g1 = tanh_grad(cache["h1"])
    d_pre1 = [dh * g for dh, g in zip(d_h1, g1)]
```

这和 VAE、GAN 两节里 `[dg * g for dg, g in zip(d_h_dec, tanh_grad(h_dec))]` 的写法一致。H=24 时影响不大，但在循环里"重复计算整个向量只取一个元素"是很典型的性能坑。

**(c)** 不能。打印的是**单个样本**、**单个随机 t** 的平方误差：t 小时噪声几乎不可预测（输入几乎是干净数据，预测 ε 很难），t 大时则容易得多，单点损失天然在 0.02–2 之间大幅波动，日志里 1000、1500 步的 1.56、2.10 并不意味着训练发散。改进：
- 打印最近 500 步损失的滑动平均；
- 固定一组验证样本和**固定的 t 分桶**（如 t ∈ {0–9, 10–19, 20–29, 30–39}），分别报告平均损失；
- 定期采样并计算分布指标（两峰均值/方差、低密度区占比、1-D W1 距离），因为损失下降不等于样本变好。

### Q12 — 参考回答要点

- **前向过程**：固定的马尔可夫链 `q(x_t | x_{t-1}) = N(√(1-β_t)·x_{t-1}, β_t·I)`，闭式 `q(x_t | x₀) = N(√ᾱ_t·x₀, (1-ᾱ_t)I)`；调度使 `x_T ≈ N(0, I)`。
- **训练**：`x₀ ~ 数据`，`t ~ Uniform`，`ε ~ N(0, I)`，`x_t = √ᾱ_t·x₀ + √(1-ᾱ_t)·ε`，最小化 `||ε - ε_θ(x_t, t)||²`。
- **采样**：`x_T ~ N(0, I)`，从 `t = T` 到 1 迭代 `x_{t-1} = (1/√α_t)(x_t - β_t/√(1-ᾱ_t)·ε_θ) + σ_t·z`，最后一步不加噪。
- **优势**：
  - vs GAN：单一回归损失，没有鞍点和 minimax，训练稳定、不易模式崩溃；
  - vs VAE：生成拆成很多小步，每步条件分布接近高斯，没有一步解码的"平均化"模糊；latent 与数据同维；
  - 有似然下界。
- **代价**：采样要迭代很多步，推理慢（生产中用 DDIM / DPM-Solver / 蒸馏解决）。

### Q13 — 参考回答要点

- **ELBO 角度**：扩散模型是一个层级很深的 VAE，编码器（前向过程）固定、不学习。ELBO 分解为每个时间步的 `KL[q(x_{t-1}|x_t, x₀) || p_θ(x_{t-1}|x_t)]`，两边都是高斯，KL 有闭式解；把 `p_θ` 的均值参数化为"用预测噪声表示的后验均值"后，每项 KL 化简为 `λ_t · ||ε - ε_θ(x_t, t)||²`。
- **score 角度**：`ε_θ ≈ -√(1-ᾱ_t)·∇ log p_t(x_t)`，学去噪就是在学每个噪声水平下的 score；反向过程沿 score 往高密度区走，同时注入噪声（讲义："a guided random walk toward high-probability regions"）。Song 等人把它写成连续时间 SDE，统一了两种视角。
- **为什么去掉权重更好**：ELBO 的权重 `λ_t` 在小 t（几乎干净）处很大，会让训练把容量花在人眼几乎看不出差别的微小噪声上；均匀权重相当于**相对加大了大 t（高噪声）的权重**，那里决定了样本的整体结构和感知质量。代价是 `L_simple` 不再是严格的似然下界，对数似然指标可能变差——这也是后来 Improved DDPM 用混合目标学方差的原因之一。
- 常见误区：说"扩散模型不是似然模型"——它确实优化的是（加权的）ELBO。

### Q14 — 参考回答要点

- **三种目标**（记 `α = √ᾱ_t`，`σ = √(1-ᾱ_t)`，`x_t = α·x₀ + σ·ε`）：
  - ε-prediction：输出 `ε`；
  - x₀-prediction：输出 `x₀`；
  - v-prediction：输出 `v = α·ε - σ·x₀`（讲义写作 `α·ε - σ·x`）。
- **换算**：`x̂₀ = (x_t - σ·ε̂)/α`；`ε̂ = (x_t - α·x̂₀)/σ`；由 v：`x̂₀ = α·x_t - σ·v̂`，`ε̂ = σ·x_t + α·v̂`（利用 `α² + σ² = 1`）。
- **各自的弱点**：
  - ε-prediction 在 t 很大（`α → 0`）时，`x̂₀ = (x_t - σ·ε̂)/α` 要除以很小的 α，ε 的微小误差被放大；在 t 很小时，噪声几乎不可见，ε 难以预测（讲义："ε has poor signal-to-noise" 于两端）；
  - x₀-prediction 在 t 很小时几乎是恒等映射，在 t 很大时要凭空想象，输出容易平均化变糊；
  - v-prediction 在两端都表现得更均衡，常用于少步采样和蒸馏。
- 加分点：讲义称 SDXL、SD3、Flux 使用 v-prediction——严格说 SD 2.x 的 768 版本用 v-prediction，SDXL 基础模型是 ε-prediction，SD3 / Flux 用的是 rectified flow 的速度目标（形式上与 v 类似但定义不同）。面试中能区分这些会很加分。

### Q15 — 参考回答要点

- **延迟构成**：`latency = num_steps × step_cost + VAE_decode`；每步是一次 U-Net / DiT 在全分辨率 latent 上的前向（开 CFG 时每步两次前向，或 batch 翻倍）。吞吐 `≈ batch_size / (num_steps × step_cost)`。
- **三类手段**（讲义 Production note）：

| 类别 | 例子 | 需要重训？ | 效果 |
|------|------|----------|------|
| 更快的采样器 | DDIM（20–50 步）、DPM-Solver++（10–20）、UniPC（8–16） | 否 | 相对 1000 步降 20–50 倍 |
| 蒸馏 | Progressive Distillation、Consistency Models、LCM、SDXL-Turbo、SD3-Turbo（1–4 步） | 是 | 再降 5–10 倍 |
| 编译与精度 | `torch.compile(mode="reduce-overhead")`、SDPA / xformers 注意力、bf16 权重 | 否 | 单步约 2 倍 |

- **叠加**：三类可以叠加（讲义："Stacks with (1) and (2)"）。另外别忘了 VAE 解码在高分辨率下的显存与时间（上一节 VAE 的 tiling / slicing）。
- 加分点：从用户角度，图片是"一次性"返回的，TTFT 很小但没有意义，真正的指标是完整响应时间；可以按质量-延迟 Pareto 曲线选步数。

### Q16 — 参考回答要点

- **基本要求**：`ᾱ_T ≈ 0`（前向终点接近 `N(0, I)`，否则采样起点与训练分布错位）；`ᾱ_t` 从 1 平滑地降到 0，各噪声水平都有足够的训练覆盖。
- **常见调度**：linear（DDPM 默认，T=1000 时 β 从 1e-4 到 0.02）；cosine（Nichol & Dhariwal 2021，让 `ᾱ_t` 按余弦平方下降，避免线性调度在末段"过早变成纯噪声"、浪费步数，同等算力 FID 更好）；sigmoid 等。技能文件建议 T=1000 为 DDPM 基线，更快的变体用 256。
- **T 与 β 的耦合**：`ᾱ_T ≈ exp(-Σβ)`，总噪声量由 `Σβ` 决定。T 变小而 β 区间不变，总噪声就按比例变少——本节代码 T=40 时 `ᾱ_T ≈ 0.67` 就是这个问题（Q9）。
- **β 不能无限大**：反向一步要乘 `1/√α_t`，β 接近 1 时把误差放大几十倍；技能文件把 `β_T > 0.1` 标记为"可能饱和或不稳定"（Improved DDPM 的 cosine 调度也要把 β 截断在 0.999 以下）。所以**少步数应该靠采样器跳步，而不是靠训练时用大 β**。
- 加分点：提到"零终端信噪比（zero terminal SNR）"问题——很多调度的 `ᾱ_T` 并不严格为 0，训练与推理在最后一步不一致，会导致生成图像亮度偏中等；修正方法是重新缩放调度使 `ᾱ_T = 0` 并配合 v-prediction。

### Q17 — 参考回答要点

- **训练**：同一个网络同时学有条件和无条件预测——以约 10% 的概率把条件替换成"空条件"（讲义练习 3："drop it 10% of the time"）。
- **推理**：每步算两次（或拼成一个 batch）：`ε_cfg = (1 + w)·ε_cond - w·ε_uncond`，`w ≈ 3–7`；等价于沿 `ε_cond - ε_uncond` 方向外推。
- **w 的权衡**：w 大 → 更贴合条件（文本对齐、CLIP score 高）、对比度和饱和度更高，但多样性下降，过大时出现过饱和、伪影；w 小 → 更多样、更自然，但可能不贴题。需要按 FID 与 CLIP score 的权衡曲线扫描（技能文件要求给出 CFG w 的扫描协议）。
- **为什么不用 CFG 会退化**：条件模型学到的 `p(x | c)` 往往"条件信号不够强"，直接采样常出现与提示无关、结构松散的图；CFG 相当于用 `p(c | x)^w` 的隐式分类器加强条件（`∇ log p(x|c) + w·∇ log p(c|x)` 的形式），是让条件生成"可用"的关键。
- **成本**：CFG 让每步计算量翻倍——这也是蒸馏模型（如 Turbo 系列）常把 CFG 一起蒸掉的原因之一。
