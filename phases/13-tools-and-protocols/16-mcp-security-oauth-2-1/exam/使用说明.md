# 13/16 分关面试题：oauthflow

形式照 Edison 那场面试：一个写好一半的服务，5 个测试用 `@pytest.mark.skip("Part N")` 锁住，一次解锁一关，要求测试原样全部通过。题面只有英文的 [README.md](README.md)，和真实面试一样；具体要求在测试、断言消息和 docstring 里。

内容来自本课，只做客户端这一侧：从受保护资源元数据（RFC 9728）找到授权服务器，带 PKCE 的授权码流程，`iss` 逐字比较（RFC 9207），按 issuer 和 `(issuer, resource)` 隔离的凭据与刷新 token 轮换，403 scope 挑战触发的增量授权，预注册、CIMD、DCR 的注册优先级，原生应用的回环重定向和表单编码的换 token 请求，以及抓取 CIMD 和元数据时的 SSRF 规则。资源服务器一侧的 token 校验在第 18 课。

## 开始

在本目录打开终端：

```bash
python3 -m pip install pytest      # 只需一次
python3 -m pytest                  # 5 个 skipped 说明环境正常
```

然后照 README 注释掉 Part 1 的 skip，再运行 `python3 -m pytest`。

## 规则

- 建议 60 分钟，自己计时。参考分配：Part 1 10 分钟，Part 2 10 分钟，Part 3 14 分钟，Part 4 14 分钟，Part 5 12 分钟。难度和用时还没有经过实测校准。
- 只改 `oauthflow/` 里的代码。测试不能改（解除 skip 除外），可以另外新建自己的测试文件。授权服务器、MCP 服务器、DNS 和 HTTPS 都是测试文件里的假实现，读它们是了解需求的正当途径。
- 可以查 Python 官方文档（urllib.parse、base64、hashlib、secrets、ipaddress、tempfile、asyncio）和[本课讲义](../docs/en.md)。计时期间不要打开 `solution/`、`INTERVIEWER.md`，也不要看本课 `code/` 和 `coderpad/` 里的实现。
- 有需求不清楚的地方就问面试官。自己练的时候，先把问题写下来，再去 INTERVIEWER.md 的“澄清问题”一节里只看这一条的答案。
- 各关有先后依赖：Part 3 和 Part 4 要走 Part 1 修好的发现和 PKCE，Part 3 的注册部分要用 Part 2 的 `CredentialVault`。前面的关没做完时，后面的关会在用到它的地方挂掉。

## 常用命令

```bash
python3 -m pytest -x                       # 跑已解锁的关，遇到第一个失败就停
python3 -m pytest -k vault -x              # 只跑名字里带 vault 的测试
python3 -m pytest --all-parts              # 不解除 skip，一次看所有关的状态
python3 -m pytest --solution --all-parts   # 计时结束后：参考答案应该 5 passed
```

`--solution` 和 `--all-parts` 是本目录 conftest.py 提供的练习开关，真实面试里没有。

## 结束和重做

1. 到 60 分钟时停下，记下每关的状态，填 [REVIEW_TEMPLATE.md](REVIEW_TEMPLATE.md)。
2. 再看 [solution/EXPLANATION.md](solution/EXPLANATION.md)，然后关掉答案，把没做完的关重写一遍。
3. 重做前把自己的 `oauthflow/` 另存一份，再用 `_starter/` 里的原始文件覆盖：

```bash
cp -R _starter/oauthflow _starter/tests .
```
