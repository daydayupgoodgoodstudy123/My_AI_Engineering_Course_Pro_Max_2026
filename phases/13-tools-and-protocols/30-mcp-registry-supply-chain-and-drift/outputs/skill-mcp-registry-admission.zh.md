给定 MCP 注册处的答复、经核实的出版商身份、人工制品证据、现场服务器观察以及当地政策,都产生了一个入场决定和证据包。

<a id="required-inputs"></a>

## 所需投入

- 登记册来源、服务器记录、登记册管理的元数据和检索时间。
- 验证命名空间和确定该空间的认证方法。
- 软件包登记、识别符号、准确版本、所有权结果和计算出来的文物摘要。
- Live `server/discover` 结果、协议版本、能力、诊断服务器信息以及完整的工具描述符。
- 所需能力、被禁止的工具特性、审查员、证据保留以及 rollback policy.
- 以前是入院的针头、现有路线、检疫和最近的健康观察。

<a id="procedure"></a>

## Procedure

1. 验证登记处的记录形状。 需要非空白的名称、 版本、 描述, 至少一个软件包或远程 。 请处理书记官处的系统图版并激活 MCP 协议版本作为独立值 。
2. 从响应级别读取登记册管理状态 `_meta["io.modelcontextprotocol.registry/official"].status`,而不是直接从 `_meta.status` 拒绝自动入境,除非身份 `active`.
3. 将名称空间与信任的认证建立的命名空间完全比较。 拒绝前缀外观和空弹片 。
4. 加入一个已申报的执行源来验证证据。 对于软件包, 匹配注册类型、 标识符、 精确版本和运输。 对于远程记录, 匹配 URL 和传输为独立核实的终点证据。 需要为任一来源提供可信任的 SHA-256 证据摘要 。
5. 卷轴( Hash) 库库式登记册记录。 挂载源代码, 加入登记处源代码、 服务器名称、 登记册版本、 记录摘要、 选定的源代码和源代码证据摘要 。
6. 观察活端点。 需要接受的协议版本、 所需的能力和完整的工具描述符。 保存结果 `_meta["io.modelcontextprotocol/serverInfo"]` 只用于显示、日志和调试。 永远不要使用自报 `serverInfo`包括直接的别名,作为入境或安全机关。
7. 将语义上未排序的收藏标准化。 完全正统描述符表面的散列, 这样名称、 描述、 预示、 注释或工具集变化就会流动 。
8. 采用当地授权、数据、网络和审查政策,登记处的公布是证据,不是当地批准。
9. 批准后, 保存一个永久的针, 包含记录、 执行源、 来源和工具摘要 。 保持批准状态与活动路径状态分开 。
10. 将决定、 理由、 证据参考、 先前分类账的散列和当前条目散列附在入门分类账中。 在证据存储前, 编辑证书和敏感参数 。
11. 重新校正注册状态和活性描述符在启动前的时间段。 当状态被废弃或删除时, 其源证据会发生变化, 或者其活性行为会有所不同 。 隔离的针从来就不是 rollback target.
12. 仅返回到先前被认可、 目前符合资格、 健康且无限制的针。 记录路线恢复为新事件 。 永远不要重写旧的出版或接收决定 。

<a id="hard-rejects"></a>

## 艰难的拒绝

- 信托仅来自熟悉的显示名称或书记官处的存在。
- `startswith` 命名空间检查或仅由提交记录所要求名称空间。
- `latest`,版本范围,或包件坐标,没有人工制品摘要。
- 仿照登记册管理状态或核查的发布字段。
- 缺少或错误的规程、能力或描述证据。
- 处理自我报告 `serverInfo` 以命名空间、来源、终点或接收权限。
- 移动后静悄悄的描述符针更新 。
- 激活已折旧、删除、未知或隔离的版本。
- Rollback 目标没有完整的招生证据
- 载有持证人的线索证据 tokens, cookie, 包证书,或不必要的工具参数。

<a id="produce"></a>

## Produce

返回这些区域:

1. Decision: `approve`, `reject`, 或 `quarantine`,有稳定的理性代码。
2. 命名空间证明: 已校验的命名空间、 认证来源和准确名称比较 。
3. 出版品:登记处来源、服务器名称、确切版本、现状、形式和记录摘要。
4. 源 Pin: 软件包坐标和传送或远程 URL 和运输、所有结果参考和源证据摘要。
5. 运行时间 Pin: 接受的协议版本、 所需能力、 工具摘要和可选诊断 `serverInfo`.
6. 证明书合编:金刚石田和由此产生的出处摘要。
7. 政策结果:每一个通过、失败和不适用的控制。
8. 线索事件:序列、时间、事件、结果、理由代码、证据参考、先前的散列和条目散列。
9. 和解计划:下一个状态, 文物,发现,描述, 和健康检查。
10. Rollback 计划:符合资格的事先标记、验证步骤、路线改变、健康窗口和保留的证据。

最后, 缺少一个大多数会改变决定的事实。 如果没有所需的事实, 请声明下一个计划进行漂移检查 。
