# 13/30 分关面试题：regadmit

形式照 Edison 那场面试：一个写好一半的服务，5 个测试用 `@pytest.mark.skip("Part N")` 锁住，一次解锁一关，要求测试原样全部通过。题面只有英文的 [README.md](README.md)，和真实面试一样；具体要求在测试、断言消息和 docstring 里。

内容来自本课：Registry 状态在响应级 `_meta["io.modelcontextprotocol.registry/official"]` 里，命名空间来自认证结果而不是记录本身，工具列表只规范顺序、不丢字段（Seven Controls 的 1、4、5 节）；哈希链准入账本，以及把链头锚定到另一个信任域（第 7 节和 Production Failure Modes）；七项控制合成一次准入判定，pin 同时钉住记录、执行来源、工具集和 provenance 四个摘要（第 2、3 节）；准入之后按层对账：记录变了是 Registry 完整性失败，同一包坐标的字节变了是执行来源失败，工具集变了是运行时漂移；回滚是恢复路由，从账本的证据里选目标，不改写历史（第 6 节和 Operational Rule）。题目里没有模型调用，也不联网，Registry、制品校验器和在线端点都是测试里写死的数据。

## 开始

在本目录打开终端：

```bash
python3 -m pip install pytest      # 只需一次
python3 -m pytest                  # 5 个 skipped 说明环境正常
```

然后照 README 注释掉 Part 1 的 skip，再运行 `python3 -m pytest`。

## 规则

- 建议 60 分钟，自己计时。参考分配：Part 1 10 分钟，Part 2 11 分钟，Part 3 14 分钟，Part 4 13 分钟，Part 5 12 分钟。难度和用时还没有经过实测校准。
- 只改 `regadmit/` 里的代码。测试不能改（解除 skip 除外），可以另外新建自己的测试文件。
- 可以查 Python 官方文档（json、hashlib、pathlib、dataclasses、asyncio、urllib.parse）和本课讲义。计时期间不要打开 `solution/` 和 `INTERVIEWER.md`。
- 有需求不清楚的地方就问面试官。自己练的时候，先把问题写下来，再去 INTERVIEWER.md 的“澄清问题”一节里只看这一条的答案。

## 常用命令

```bash
python3 -m pytest -x                       # 跑已解锁的关，遇到第一个失败就停
python3 -m pytest -k ledger -x             # 只跑名字里带 ledger 的测试
python3 -m pytest --all-parts              # 不解除 skip，一次看所有关的状态
python3 -m pytest --solution --all-parts   # 计时结束后：参考答案应该 5 passed
```

`--solution` 和 `--all-parts` 是本目录 conftest.py 提供的练习开关，真实面试里没有。

## 结束和重做

1. 到 60 分钟时停下，记下每关的状态，填 [REVIEW_TEMPLATE.md](REVIEW_TEMPLATE.md)。
2. 再看 [solution/EXPLANATION.md](solution/EXPLANATION.md)，然后关掉答案，把没做完的关重写一遍。
3. 重做前把自己的 `regadmit/` 另存一份，再用 `_starter/` 里的原始文件覆盖：

```bash
cp -R _starter/regadmit _starter/tests .
```
