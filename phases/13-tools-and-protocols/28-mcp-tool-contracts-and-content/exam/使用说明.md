# 13/28 分关面试题：contractkit

形式照 Edison 那场面试：一个写好一半的服务，5 个测试用 `@pytest.mark.skip("Part N")` 锁住，一次解锁一关，要求测试原样全部通过。题面只有英文的 [README.md](README.md)，和真实面试一样；具体要求在测试、断言消息和 docstring 里。

内容来自本课：`structuredContent` 可以是任意 JSON 值，发布了 `outputSchema` 的工具连 `isError` 结果也要守约，空字符串也是合法游标，descriptor 在发现后校验一次；五种内容块及按类型配置的本地负载上限（不是 MCP 统一限值），MCB1 的物理编解码已给定；`x-mcp-header` 参数值的明文与 `=?base64?…?=` 编码，基础类型渲染已给定，候选人区分缺省参数与 false、0、空字符串，服务器端按 bindings 顺序解码后与 body 精确比对，不一致就是 HTTP 400 加 JSON-RPC `-32020`；`completion/complete` 的客户端防抖、最多 100 个值和 `total`/`hasMore`；遍历整棵 schema 树检查注解只出现在 `inputSchema.properties` 的直接成员上。

## 开始

在本目录打开终端：

```bash
python3 -m pip install pytest      # 只需一次
python3 -m pytest                  # 5 个 skipped 说明环境正常
```

然后照 README 注释掉 Part 1 的 skip，再运行 `python3 -m pytest`。

## 规则

- 建议 60 分钟，自己计时。参考分配：Part 1 10 分钟，Part 2 12 分钟，Part 3 14 分钟，Part 4 12 分钟，Part 5 12 分钟。难度和用时还没有经过实测校准。
- 只改 `contractkit/` 里的代码。测试不能改（解除 skip 除外），可以另外新建自己的测试文件。
- 可以查 Python 官方文档（json、base64、struct、re）和[本课讲义](../docs/en.md)。计时期间不要打开 `solution/`、`INTERVIEWER.md`，也不要看本课 `code/` 和 `coderpad/` 里的实现。
- 有需求不清楚的地方就问面试官。自己练的时候，先把问题写下来，再去 INTERVIEWER.md 的“澄清问题”一节里只看这一条的答案。

## 常用命令

```bash
python3 -m pytest -x                       # 跑已解锁的关，遇到第一个失败就停
python3 -m pytest -k headers -x            # 只跑名字里带 headers 的测试
python3 -m pytest --all-parts              # 不解除 skip，一次看所有关的状态
python3 -m pytest --solution --all-parts   # 计时结束后：参考答案应该 5 passed
```

`--solution` 和 `--all-parts` 是本目录 conftest.py 提供的练习开关，真实面试里没有。

## 结束和重做

1. 到 60 分钟时停下，记下每关的状态，填 [REVIEW_TEMPLATE.md](REVIEW_TEMPLATE.md)。
2. 再看 [solution/EXPLANATION.md](solution/EXPLANATION.md)，然后关掉答案，把没做完的关重写一遍。
3. 重做前把自己的 `contractkit/` 另存一份，再用 `_starter/` 里的原始文件覆盖：

```bash
cp -R _starter/contractkit _starter/tests .
```
