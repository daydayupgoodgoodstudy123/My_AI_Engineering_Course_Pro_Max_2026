## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | 链式法则 | `y = f(g(x))` 时 `dy/dx = f'(g(x))·g'(x)`；沿计算路径把每一环的局部导数相乘 |
| 2 | 计算图 | 每个运算是一个节点；前向传播沿边计算数值，反向传播沿边反向传递梯度 |
| 3 | 前向模式 vs 反向模式 | 前向模式每次对**一个输入**求导，适合输入少、输出多；反向模式每次对**一个输出**求所有输入的导数，适合神经网络（百万参数 → 一个 loss） |
| 4 | 对偶数（dual numbers） | `a + bε`，`ε² = 0`；把（值, 导数）打包一起运算，就是前向模式自动微分 |
| 5 | Autograd 三件套 | ①包装数值并存 `grad`；②每个运算记录输入节点和局部梯度闭包 `_backward`；③拓扑排序后逆序执行反向 |
| 6 | 梯度累加 `+=` | 一个值被多个运算使用时，总梯度是各路贡献之**和**；所以每轮训练前要把参数梯度清零 |
| 7 | 拓扑排序 | 保证一个节点收齐了所有上游梯度之后，才把梯度继续传给它的输入 |
| 8 | 复合运算"白送"梯度 | `a - b = a + (-b)`、`a / b = a · b⁻¹`，只要底层运算的反向正确，组合出来的梯度自动正确 |
| 9 | 动态图（define-by-run） | PyTorch 每次前向都重新建图，所以模型里可以写普通的 `if` / `for` 控制流 |
| 10 | 梯度检查 | 用中心差分数值梯度验证 autodiff 结果；新增算子时必做，正式训练时不做（太慢） |

## 五、参考答案与解析

### Q1 — 答案：B

链式法则：`dy/dx = cos(x²)·2x`。`x = 2` 时为 `cos(4)·4 ≈ (-0.6536)·4 ≈ -2.615`。A 只算了外层 `cos(4)`，漏乘内层导数 `2x = 4`——这正是讲义反向模式例子里的中间量 `dy/da`；D 是 `sin(4)`；C 只算了内层导数。

### Q2 — 答案：C

x 通过两条路径影响 f：路径 1 经过 `x*y`，贡献 `y = 3`；路径 2 直接相加，贡献 1。多元链式法则要求把各路径贡献**相加**：`3 + 1 = 4`。这就是代码里所有 `_backward` 都用 `+=` 的原因（见 Q9）。B 只算了一条路径。

### Q3 — 答案：B

前向模式一次遍历只能得到"所有输出对**某一个**输入"的导数（雅可比的一列），10⁶ 个参数要遍历 10⁶ 次；反向模式一次遍历得到"**某一个**输出对所有输入"的导数（雅可比的一行），loss 是标量，一次反向就够了。这就是讲义说"神经网络用反向模式"的原因。

### Q4 — 答案：A

对偶数规则 `(a, a')·(b, b') = (ab, a'b + ab')`、`(a, a') + (b, b') = (a+b, a'+b')`：
- `x·x = (3, 1)·(3, 1) = (9, 1·3 + 3·1) = (9, 6)`
- `2x = (6, 2)`
- 相加：`(15, 8)`。

验证：`f(3) = 9 + 6 = 15`，`f'(x) = 2x + 2 = 8`。B 漏了 `2x` 的导数 2；D 漏了 `x²` 的导数。

### Q5 — 答案：B

一个节点 v 的梯度是所有"使用了 v 的节点"传回来的贡献之和。拓扑序保证 v 排在所有使用它的节点之前，逆序遍历时，这些下游节点都先执行了 `_backward`，v 的 `grad` 已经累加完整，才轮到 v 把梯度继续传给它的输入。如果顺序错了，v 会用一个"只累加了一半"的梯度往下传，结果错误。C 不对：去重是 `visited` 集合的副作用，不是目的。

### Q6 — 答案：C

预激活 `0.5×3 + (-1.5)×2 + 0.1 = -1.4 < 0`，ReLU 输出 0，其局部导数也是 0（代码：`1.0 if out.data > 0 else 0.0`），于是所有上游梯度都被乘以 0。运行结果中 5 个梯度全部为 0，并打印 `PASSED (relu inactive, all grads zero)`。如果预激活为正，`dy/dw1` 才等于 `x1 = 3.0`（A）。这就是"死亡 ReLU"的微观机制：某个神经元对输入恒为负时，它的权重收不到任何梯度。

### Q7 — 答案：B

讲义原话："The graph is dynamic (define-by-run). A new graph is built on every forward pass." 本节的 `Value` 引擎也是如此：每次调用 `model(x)` 都新建一批 `Value` 节点，图由实际执行的运算决定，因此可以有依赖数据的分支和循环。A 描述的是静态图（如早期 TensorFlow 1.x 的风格）。

### Q8 — 答案：B

`-other` 调用 `__neg__`，即 `other * -1`，乘法的反向会给 `other` 传回 `-1 × 上游梯度`；再经过加法的反向，`self` 收到 `+1`、`other` 收到 `-1`，正是减法的导数。除法同理：`b ** -1` 的反向给出 `-b⁻²`，再经过乘法得到 `∂(a/b)/∂b = -a/b²`。讲义称之为"the clever part"：只要原子运算的反向正确，组合运算的梯度就自动正确——这也是自动微分可扩展的关键。

### Q9 — 参考答案

实测：改成 `=` 后 `x.grad = 3.0`，正确值是 `4.0`；`y.grad = 2.0` 两种写法相同。

推导：计算图为 `m = x*y`，`f = m + x`。逆拓扑序先执行 `f._backward`，再执行 `m._backward`：
1. `f._backward`：`m.grad = 1`，`x.grad = 1`（直接相加那条路径的贡献）。
2. `m._backward`：`x.grad = y.data × m.grad = 3`——用 `=` **覆盖**掉了第 1 步的贡献 1。

正确的 `+=` 会得到 `1 + 3 = 4`。`y` 只被使用了一次，只有一条路径，覆盖和累加没有区别，所以没出错。

教训：这种 bug 在"每个变量只用一次"的简单测试里完全发现不了，只有变量被复用（如残差连接 `x + f(x)`、权重共享、同一个参数出现在多处）时才暴露——这也是为什么要用 `gradient_check` 在各种表达式上做系统测试。

### Q10 — 参考答案

**(1) 删掉清零**：每次 `backward()` 都把新梯度**加**到旧梯度上，于是第 t 步实际使用的是 `g₁ + g₂ + … + g_t`，等价于**动量系数 β = 1（没有衰减）的动量法**：速度永远不衰减，参数更新量越积越大。

实测（随机种子 42、0、1、2、3 各跑一次，每次训练 300 步）：

| 学习率 | 正常训练（原代码） | 忘记清零 |
|-------|---------|---------|
| 0.05 | 100 步 loss ≈ 0.18 | loss 很快降到约 0，但参数最大绝对值涨到约 80～90 |
| 0.2 | — | loss 卡在 4.0（种子 42）或 8.0（其余种子）不动，参数最大绝对值涨到数百甚至上千 |

解读：lr=0.05 时 loss 看起来"更好"，但那是权重被无界放大、tanh 完全饱和到 ±1 的结果，不是正确的梯度下降；lr=0.2 时权重爆炸，tanh 饱和在**错误**的符号上，局部导数 `1 - t²` ≈ 0，梯度消失，loss 永远卡在 4（一个样本错，误差 `(±2)² = 4`）或 8（两个样本错）。"loss 下降了"不代表代码是对的。

**(2) 为什么只清零参数**：
- 每个 step 都会重新执行 `model(x)` 和 `sum(...)`，生成**全新**的中间节点（`grad` 初始为 0.0），上一步的旧图随后被垃圾回收，所以中间节点天然是"干净"的。
- 参数 `Value` 是跨 step 持续存在的叶子节点，必须手动清零。
- `xs` 里的输入也是跨 step 复用的 `Value`，它们也会收到梯度并一直累加（实测训练后输入的 `.grad` 达到几十）。因为它们不参与更新，这不影响训练，只是多余计算。PyTorch 中输入张量默认 `requires_grad=False`，不会计算这部分梯度。

### Q11 — 参考答案

```python
import math
from autodiff import Value, gradient_check

def __rtruediv__(self, other):          # other / self，other 是普通数字
    return Value(other) * (self ** -1)

def sigmoid(self):
    s = 1.0 / (1.0 + math.exp(-self.data))
    out = Value(s, (self,), 'sigmoid')
    def _backward():
        self.grad += s * (1 - s) * out.grad
    out._backward = _backward
    return out

Value.__rtruediv__ = __rtruediv__
Value.sigmoid = sigmoid

for name, expr in [("2 / x", lambda x: 2 / x),
                   ("sigmoid(3x)", lambda x: (x * 3).sigmoid()),
                   ("1 / (1 + exp(-x))", lambda x: 1 / (1 + (-x).exp()))]:
    ad, num, diff = gradient_check(expr, 0.5)
    print(f"{name:<18} autodiff={ad:.8f} numerical={num:.8f} diff={diff:.2e}")
```

实测输出：

```text
2 / x              autodiff=-8.00000000 numerical=-8.00000000 diff=2.30e-10
sigmoid(3x)        autodiff=0.44743936 numerical=0.44743936 diff=8.94e-11
1 / (1 + exp(-x))  autodiff=0.23500371 numerical=0.23500371 diff=1.56e-10
```

要点：
- `2 / x` 时 Python 先尝试 `int.__truediv__(2, x)`，返回 `NotImplemented` 后才调用 `x.__rtruediv__(2)`。没有定义它就报 `TypeError: unsupported operand type(s) for /: 'int' and 'Value'`。
- `sigmoid` 作为一个"融合算子"只产生 1 个节点；而 `1 / (1 + exp(-x))` 由取负、exp、加法、幂、乘法拼成，会产生多个节点。两者梯度相同（第三行就是 `sigmoid(0.5)` 的导数 `σ(1-σ) ≈ 0.235`），但融合算子更省内存、数值上也更可控——PyTorch 也为常用激活函数提供专门实现。
- 这里用"给类动态添加方法"（monkey patching）是为了不改源文件，正式实现应直接写进类定义。

### Q12 — 参考答案

**原因**：`sum(vals)` 等价于 `((0 + v₀) + v₁) + …`，生成一条深度约 1500 的链。`build_topo` 每深入一层就递归调用一次，而 Python 默认递归深度上限约为 1000（`sys.getrecursionlimit()`），于是抛出 `RecursionError`（实测 900 个能过，1500 个失败）。真实网络中，长序列 RNN 展开、大量参数求和都可能造成这么深的图。

**非递归版本**（显式栈 + "孩子是否已处理"标记，做后序遍历）：

```python
def backward_iterative(self):
    topo, visited = [], set()
    stack = [(self, False)]
    while stack:
        node, children_done = stack.pop()
        if children_done:
            topo.append(node)          # 所有输入都已入 topo，再放自己
            continue
        if node in visited:
            continue
        visited.add(node)
        stack.append((node, True))     # 先压"回来时再追加自己"的标记
        for child in node._prev:
            if child not in visited:
                stack.append((child, False))
    self.grad = 1.0
    for v in reversed(topo):
        v._backward()

Value.backward = backward_iterative
```

实测对 5000 个 `Value` 求和后反向传播正常完成，每个输入的梯度都是 1.0。

另一种做法是 `sys.setrecursionlimit(...)` 调大上限，但这只是治标——太深仍可能导致解释器栈溢出崩溃。工业框架（如 PyTorch 的 autograd 引擎）在 C++ 层用任务队列按依赖计数调度，不依赖语言级递归。

### Q13 — 参考回答要点

- **链式法则**是数学：复合函数的导数等于各环节局部导数的乘积（多路径时求和）。
- **自动微分**是算法：把程序分解成基本运算组成的计算图，对每个基本运算使用已知的局部导数，再按链式法则机械地组合，得到**精确**导数（不是近似）。分前向模式和反向模式。
- **反向传播**就是**反向模式自动微分**在神经网络上的应用：前向计算并缓存中间值 → 从 loss 处以种子梯度 1 开始，按逆拓扑序把梯度传回每个参数。
- **复杂度**：一次反向的计算量与一次前向同量级（常数倍），与参数数量无关——这是它能训练十亿参数模型的根本原因。
- **加分点**：能举出本节例子 `y = relu(x1*x2 + 1)`：`dy/dx1 = 1·1·x2 = 3`；能说出"梯度在加法节点原样分发、在乘法节点交换相乘"的规律。

### Q14 — 参考回答要点

- **前向模式**：从输入出发，同时传播"值"和"对某个输入方向的导数"（雅可比-向量积，JVP）。一次遍历得到雅可比矩阵的一列；n 个输入要 n 次。无需保存中间结果，内存开销小，可以用对偶数优雅实现。
- **反向模式**：先前向计算并**保存中间值**，再从输出反向传播（向量-雅可比积，VJP）。一次遍历得到雅可比的一行；m 个输出要 m 次。代价是要存储整个前向过程的中间激活。
- **选择规则**：`f: Rⁿ → Rᵐ`，n ≫ m 用反向（神经网络 loss，m=1）；n ≪ m 用前向（例如少量超参数对大量输出的敏感度分析）。
- **前向模式更合适的场景**：输入维度很小；需要雅可比-向量积时；计算 Hessian-向量积常用"前向套反向"（forward-over-reverse）；内存受限、不能保存中间激活时。JAX 同时提供 `jvp`（前向）和 `vjp`/`grad`（反向）。
- **常见误区**：认为反向模式"总是更好"——它用内存换来了对大量输入的效率。

### Q15 — 参考回答要点

- **三步分别做什么**：
  - `optimizer.zero_grad()`：把所有参数的 `.grad` 清零（新版本默认设为 `None`，省一次写内存）。对应本节代码 `p.grad = 0.0`。
  - `loss.backward()`：从 loss 出发做反向模式自动微分，把梯度**累加**到每个叶子参数的 `.grad` 上；默认随后释放计算图（再次 backward 需 `retain_graph=True`）。
  - `optimizer.step()`：读取 `.grad`，按优化器规则更新参数（SGD 就是本节的 `p.data -= lr * p.grad`）。
- **为什么默认累加**：
  1. 数学上本来就需要：同一参数在图中被多处使用时，梯度必须求和（Q2、Q9）。
  2. 工程用途——**梯度累积（gradient accumulation）**：显存放不下大 batch 时，连续做 k 次小 batch 的 `backward()` 而不清零，再 `step()` 一次，等效于 k 倍大的 batch（loss 通常要除以 k 保持尺度一致）。
  3. 多个 loss 分别 backward，梯度自然合并。
- **常见坑**：忘记 `zero_grad()` 导致梯度跨 step 累加（Q10 的现象）；把 `zero_grad()` 放在 `backward()` 和 `step()` 之间，结果更新量全为 0。
- **加分点**：提到梯度累积与 BatchNorm 的交互（BN 统计量仍按小 batch 计算，不完全等价）。

### Q16 — 参考回答要点

| 方法 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| 数值微分 | 有限差分 `(f(x+h)-f(x-h))/2h` | 实现简单，适用于任意黑盒函数 | 近似、有截断/舍入误差；n 个参数要 O(n) 次前向，太慢 |
| 符号微分 | 对数学表达式做代数变换（如 SymPy） | 得到精确的解析式 | 表达式膨胀（expression swell）；难以处理循环、分支等程序结构 |
| 自动微分 | 对程序执行轨迹逐个基本运算应用链式法则 | 精确到机器精度；反向模式代价约为常数倍前向；支持任意控制流 | 需要框架支持；反向模式要存中间值 |

- 深度学习选自动微分：需要对上亿参数求**精确**梯度，且模型是带控制流的程序而不是一个封闭公式。数值微分只用来做梯度检查（本节 `gradient_check`）。
- **加分点**：自动微分不是符号微分——它不产生导数的表达式，而是直接计算导数在某点的**数值**；也不是数值微分——它没有步长 h 带来的近似误差。

### Q17 — 参考回答要点

- **原因**：反向模式在计算 `_backward` 时需要前向的中间值（本节代码中，乘法的反向要用 `other.data`、tanh 的反向要用 `t`，这些都由闭包保存着）。所以训练时必须把**每一层的激活值**都留到反向传播结束；而推理时算完一层就可以丢掉上一层。此外训练还要存储梯度（与参数同大小）和优化器状态（Adam 每个参数额外两份：一阶矩和二阶矩）。
- **降低训练显存的方法**：
  1. **梯度检查点（gradient checkpointing / activation recomputation）**：只保存部分层的激活，反向时重新计算其余激活，以大约多一次前向的计算换取显存。
  2. **混合精度训练**：激活和计算用 FP16/BF16，激活显存约减半。
  3. **减小 micro-batch + 梯度累积**：用时间换空间（见 Q15）。
  4. **优化器状态/参数分片**（如 ZeRO/FSDP）：把参数、梯度、优化器状态切分到多张卡。
- **推理时**：用 `torch.no_grad()` / `torch.inference_mode()` 关闭建图，不保存中间值。
- **加分点**：能估算显存组成——参数 + 梯度 + 优化器状态 + 激活，并指出长序列 Transformer 中激活往往是大头。
