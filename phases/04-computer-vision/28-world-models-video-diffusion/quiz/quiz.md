## 五、参考答案与解析

### Q1 — 答案：C

Sora 2 是纯视频生成：提示词设定开头，之后不能"转向"。Genie 3 每一步以推断或给定的潜动作为条件预测下一帧，用户按键或移动相机，场景就会响应——这种交互性正是"世界模拟器"与"视频生成器"的区别。A、B、D 都不是本质区别。

### Q2 — 答案：C

分解注意力把一次时空联合注意力拆成两步：时间注意力在每个空间位置上沿时间维做（共 `H·W` 个长度为 `T` 的序列），空间注意力在每个时间步上沿空间维做（共 `T` 个长度为 `H·W` 的序列）。总代价 `(H·W)·T² + T·(H·W)²`，远小于 `(T·H·W)²`。这是 TimeSformer 提出、被大多数 video DiT 采用的模式。

### Q3 — 答案：B

三件套分工：VLM 负责规划，视频模型负责"想象"执行后会看到什么，逆动力学模型回答"什么动作能产生这个状态转移"——输入（状态，下一状态），输出连接二者的动作，从而闭合"想象 → 执行"的回路。C 是视频模型的工作。

### Q4 — 答案：C

长尾驾驶场景要靠数百万英里的实际驾驶才能采到。世界模型以轨迹、框、地图为条件按需生成这类场景，用于扩充训练集、在可复现条件下评估规划器，以及合成现实中无法（或不应）去开的危险场景。

### Q5 — 答案：B

`(16/2) × (32/2) × (32/2) = 8 × 16 × 16 = 2,048`。注意 C=4 不参与 token 数的计算——通道会被 3D 卷积投影成每个 token 的特征维 `dim`。

### Q6 — 答案：B

讲义：Genie 通过判别式地预测相邻两帧之间的动作来学习每帧的潜动作，解码器以推断出的潜动作为条件，而不是显式的键盘按键；推理时用户可以指定一个潜动作（或从新的先验中采样），模型生成与之一致的下一帧。正因为不需要动作标签，才能利用海量无标注视频。

### Q7 — 答案：C

FVD 是视频版的 FID，衡量的是生成视频与真实视频在特征分布上的距离，不能直接反映"杯子穿过了手"这类物理错误。讲义中物理合理性是"在基准套件上人工打分"（如 Sora 2 的内部基准、VBench）。A、B、D 都是讲义列出的对应关系。

### Q8 — 答案：B

DreamerV3 及经典 RL 世界模型在潜空间中以显式动作为条件做转移预测，并用奖励信号训练，"视觉性更弱，但对样本高效的 RL 更有用"。它不是视频产品（A、D 错），也离不开动作（C 错）。

### Q9 — 参考答案

1. 输出（纯整数运算，可直接复算）：

```text
  tokens per clip: 202,500
  attention pairs (joint): 41,006,250,000
  divided time total: 15,187,500
  divided space total: 546,750,000
  divided total: 561,937,500
```

   计算过程：时间 token 数 `150 / 2 = 75`，空间 token 数 `(480/8) × (360/8) = 60 × 45 = 2,700`，总数 `75 × 2,700 = 202,500`；
   - 联合：`202,500² ≈ 4.1 × 10¹⁰`；
   - 时间：`2,700 × 75² = 15,187,500`；
   - 空间：`75 × 2,700² = 546,750,000`。

2. 比值 `41,006,250,000 / 561,937,500 ≈ 73`，即分解注意力少约 73 倍。**空间项占主导**（约 97%），因为每帧有 2,700 个空间 token，而只有 75 个时间 token——空间序列远长于时间序列，平方之后差距更大。这也是为什么高分辨率视频模型往往还要在空间上用窗口注意力或更大的空间 patch。

3. `4.1 × 10¹⁰ × 2 字节 ≈ 82 GB`，**单个头、单层**就放不进一张 80 GB 的显卡。这就是讲义说全联合注意力"对长视频不可承受"的直观含义（实际系统还会用 FlashAttention 这类不显式物化注意力矩阵的实现，但计算量依然是平方级）。

4. "360p" 通常指**高度** 360 像素，`480 × 360` 中 480 是宽、360 是高，所以按参数名应写 `count_tokens(150, 360, 480)`。因为 `p_h = p_w = 8`，交换后 `(360/8) × (480/8) = 45 × 60` 结果完全相同，不影响输出；但如果 `p_h ≠ p_w` 或尺寸不能整除，就会算错。

### Q10 — 参考答案

1. 形状：
   - Conv3d 输出 `(1, 64, 4, 8, 8)`（T、H、W 各除以 2）；
   - `tokens`：`(1, 256, 64)`，`grid = (4, 8, 8)`，256 = 4 × 8 × 8；
   - 时间注意力输入 `xt`：`(n·H·W, T, d) = (64, 4, 64)`——64 个空间位置各是一条长度为 4 的时间序列；
   - 空间注意力输入 `xs`：`(n·T, H·W, d) = (4, 64, 64)`——4 帧各是一条长度为 64 的空间序列；
   - 最终输出：`(1, 256, 32)`，与讲义 Step 5 的预期一致。

2. `self.out = nn.Linear(dim, in_channels * 2 * 2 * 2)`，即 `4 × 2 × 2 × 2 = 32`：每个 token 要预测它所覆盖的 2×2×2 时空小块里、4 个通道的全部数值，这样才能 unpatchify 回原始视频潜变量（见 Q11）。

3. 参数量：

| 模块 | 计算 | 参数 |
|------|------|------|
| `Conv3d(4, 64, k=2×2×2)` | 64×4×8 + 64 | 2,112 |
| 每个 `MultiheadAttention(64, 2)` | in_proj 3×64×64 + 3×64，out_proj 64×64 + 64 | 16,640 |
| 每块 2 个注意力 | 2 × 16,640 | 33,280 |
| 每块 3 个 `LayerNorm(64)` | 3 × (64 + 64) | 384 |
| 每块 MLP | (64×256 + 256) + (256×64 + 64) | 33,088 |
| 每块合计 | | 66,752 |
| 2 块 | | 133,504 |
| `out = Linear(64, 32)` | 64×32 + 32 | 2,080 |
| **总计** | | **137,696** |

   注意 head 数（2）不影响参数量：多头只是把 64 维切成 2 份分别计算。

4. `permute` 只改变步长（stride）而不移动数据，结果在内存中不再连续；`view` 要求新形状能在原有内存布局上直接解释，对这种张量合并维度会报错。`reshape` 在必要时会自动复制一份连续的数据，所以安全。反过来，`xt.view(n, T, H * W, d)` 能用 `view`，是因为前一步的 `reshape` 已经产生了连续张量。

### Q11 — 参考答案

关键是约定每个 token 输出向量的排列顺序。这里约定为 `(C, pt, ph, pw)`，与 `Conv3d` 权重 `(out, in, kt, kh, kw)` 的排列一致：

```python
def unpatchify(out, grid, C=4, pt=2, ph=2, pw=2):
    n, seq, _ = out.shape
    t, h, w = grid
    x = out.reshape(n, t, h, w, C, pt, ph, pw)
    x = x.permute(0, 4, 1, 5, 2, 6, 3, 7)   # (n, C, t, pt, h, ph, w, pw)
    return x.reshape(n, C, t * pt, h * ph, w * pw)
```

- token 的顺序必须与 `VideoPatch3D` 一致：`x.reshape(n, c, t*h*w)` 是按 t → h → w 的顺序展平的，所以先拆成 `(t, h, w)`；
- `permute` 把每个 patch 内部的 `pt, ph, pw` 分别放到 `t, h, w` 后面，再 `reshape` 合并，就把小块"拼"回了大网格。

**往返测试**（不依赖模型权重）：手工做一次"无卷积的 patch 化"，再 unpatchify，检查是否逐元素相等：

```python
def patchify(x, pt=2, ph=2, pw=2):
    n, C, T, H, W = x.shape
    t, h, w = T // pt, H // ph, W // pw
    p = x.reshape(n, C, t, pt, h, ph, w, pw).permute(0, 2, 4, 6, 1, 3, 5, 7)
    return p.reshape(n, t * h * w, C * pt * ph * pw), (t, h, w)

x = torch.randn(2, 4, 8, 16, 16)
p, grid = patchify(x)
assert p.shape == (2, 256, 32)
assert torch.equal(unpatchify(p, grid), x)
```

（当前环境没有 torch，我用 NumPy 写了同样的 reshape / transpose 逻辑验证过：形状为 `(2, 256, 32)`，往返结果与原张量完全相等。）

### Q12 — 参考回答要点

- **定义**：讲义的定义是"给定状态与动作，预测未来观测的模型"——一个可学习的模拟器。
- **与视频生成的关系**：能生成连贯长视频的模型，隐式地学到了物体恒存、重力、因果、风格；把预测以动作为条件，视频模型就变成可交互的模拟器，可以替代游戏引擎、驾驶模拟器或机器人仿真环境。
- **三类**：
  - 纯视频生成（Sora 2）：提示词条件，无动作接口，用于创意视频；
  - 动作条件世界模型（Genie 3、GWM-1 Worlds、Mirage / Magica）：从视频中推断潜动作，可交互，用于可玩环境、AI 原生游戏引擎；
  - RL 世界模型（DreamerV3）：潜空间转移 + 奖励，用于样本高效的强化学习。
- **落地**：自动驾驶长尾数据合成（Cosmos-Drive-Dreams、Gaia-2），机器人"想象 + 逆动力学"闭环。
- 加分点：指出物理合理性仍是主要失效模式，"会生成视频"不等于"懂物理"。

### Q13 — 参考回答要点

- **Token 化**：先用 VAE 把视频压到潜空间 `(C, T, H, W)`，再用步长等于核大小的 3D 卷积做时空 patch 化，token 数 `(T/P_t)(H/P_h)(W/P_w)`。patch 越大 token 越少，但细节越粗。
- **位置编码**：按 t、h、w 三个轴分别做 RoPE 或可学习编码，再拼接；让模型知道每个 token 的时空坐标。
- **注意力**：

| 模式 | 每层代价 | 优点 | 缺点 |
|------|---------|------|------|
| 全联合 | `(T·H·W)²` | 任意时空 token 直接交互，表达力最强 | 长视频不可承受 |
| 分解（时间 + 空间） | `(H·W)·T² + T·(H·W)²` | 便宜得多，TimeSformer 及大多数 video DiT 采用 | 跨时空的"斜向"交互要经过两步间接完成 |
| 窗口（Video Swin） | 与窗口大小成正比 | 线性扩展 | 感受野受限，需多层或移位窗口扩大 |

- **其余组件**：AdaLN 注入时间步与文本条件，rectified flow 作为训练目标（见第 23 节）。
- 加分点：能算出 Q9 中的数字，指出空间项主导，所以空间侧往往还要再做窗口或更大 patch。

### Q14 — 参考回答要点

- **为什么需要潜动作**：互联网视频没有动作标签，人工标注不可扩展。Genie 把"动作"当作隐变量从视频中学出来。
- **训练**：对相邻两帧 `(frame_t, frame_{t+1})`，用一个模型判别式地推断"两帧之间发生了什么动作"，得到每帧的潜动作；视频解码器以过去的帧 + 这个潜动作为条件，预测下一帧。潜动作必须携带"足以解释帧间变化"的信息，于是它自然学成了类似"向左走、跳跃"的控制信号。
- **推理**：用户指定潜动作（或从先验采样），模型生成与之一致的下一帧；把生成帧接回输入，循环下去就是可交互的推演。
- **对比 Sora**：Sora 没有动作接口，提示词只决定开头。
- 常见误区：以为 Genie 需要键盘日志做监督——它的卖点恰恰是**不需要**。

### Q15 — 参考回答要点

- **上线前自动化检查**（参考本节 `outputs/skill-physical-plausibility-checks.md`）：
  - 物体恒存：用跟踪器（如 SAM 3.1 Object Multiplex）跟踪物体，稳定轨迹短暂消失又出现即标记，画面中央消失比边缘更严重；
  - 运动平滑：用光流检测"瞬移"（99 分位流速远大于中位数）；
  - 重力 / 支撑：固体物体在没有抓取动作时不应向上漂移；
  - 身份一致性：人物的人脸 embedding 在相邻窗口内余弦相似度应保持较高；
  - 手与肢体：姿态估计检测手指数量、肢体长度突变；
  - 文字渲染：如果提示要求文字，OCR 后计算字符错误率。
  - 原则：不因单项检查硬拦截，而是汇总异常数决定 ship / hold / reject；涉及真人、儿童、公众人物一律人工复核；被标记的视频保留用于排查。
- **离线评测**（讲义）：FVD + 用户研究（视觉质量）、逐帧 CLIPScore + VQA（提示对齐）、人工打分的合理性基准如 VBench（物理）、交互模型还要测可控性。
- 加分点：按时间监控各项检查的失败率，上升通常意味着底座模型更新或提示分布漂移。

### Q16 — 参考回答要点

- **数据流**（讲义的机器人栈）：
  1. 语言目标 → VLM（如 Qwen3-VL）→ 高层计划（"抓住红杯子 → 移到水槽上方 → 放下"）；
  2. 计划 + 当前观测 → 潜动作视频模型 → 想象出的未来若干帧；
  3. （当前观测，想象的下一观测）→ 逆动力学模型 → 底层电机指令；
  4. 执行动作 → 新观测 → 回到第 1 步（闭环）。
- **模块输入输出**：VLM 输入图像 + 指令、输出子目标；视频模型输入历史帧 + 子目标 / 潜动作、输出未来帧；逆动力学输入相邻两帧观测、输出动作。
- **风险与缓解**：
  - 视频模型"想象"出物理上不可能的画面（杯子穿过手、物体消失）→ 对想象帧做合理性检查（Q15），不合理就重新采样或回退；
  - 误差累积：长时域开环推演会漂移 → 短时域想象、每步用真实观测重新规划；
  - 逆动力学在分布外失效 → 用真实机器人数据微调，并设置动作安全限幅；
  - 延迟：视频生成慢 → 降低分辨率 / 帧数，只想象关键帧。
- 加分点：讲义称这种结构"用世界模型做想象、用逆动力学闭合执行"，替代了奖励设计和大样本 RL；Genie Envisioner 是一个实例。可对比端到端的 VLA 路线（阶段 12 第 21 节）。
