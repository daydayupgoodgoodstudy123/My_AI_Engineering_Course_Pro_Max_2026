## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | 关键点任务的统一形式 | 人体 17 点、人脸 68/478 点、手 21 点……本质都是"在物体上检测 K 个有序点，输出 (x, y)" |
| 2 | Top-down vs Bottom-up | 先检测人再逐个估计（HRNet、ViTPose，精度高、耗时随人数线性增长）vs 一次前向出全部关键点再分组（OpenPose、HigherHRNet，人群中耗时恒定） |
| 3 | 热图回归 | 每个关键点预测一张 H×W 热图，目标是以真值为中心的高斯：`exp(-((x-cx)² + (y-cy)²) / (2σ²))` |
| 4 | 为什么热图优于直接回归 | 卷积特征图的空间结构与空间输出天然对齐；高斯目标让小的定位误差只产生小的损失 |
| 5 | 坐标解码与亚像素 | 推理时对每张热图取 argmax；整数 argmax 有量化误差，可用邻域抛物线拟合或"四分之一像素偏移"细化 |
| 6 | Part Affinity Fields（PAF） | 每条肢体一个 2 通道单位向量场；沿候选连线对 `PAF · 连线方向` 积分，积分越大越可能属于同一个人 |
| 7 | 评测指标 | PCK（正确关键点百分比）与 OKS（关键点版的 IoU）；COCO 报告基于 OKS 的 mAP |
| 8 | 2D vs 3D | 2D 已达生产质量（MediaPipe、HRNet、ViTPose）；3D 仍是研究前沿：2D→3D lifting（VideoPose3D）、直接回归、多视角 |

## 五、参考答案与解析

### Q1 — 答案：B

讲义："Top-down … scales linearly with number of people"，"Bottom-up — one forward pass predicts all keypoints plus an association field; group them. Constant time regardless of crowd size." 200 人的场景下 top-down 要跑 200 次单人模型，bottom-up 只需一次前向加分组。A 错在 top-down 耗时随人数线性增长；C 说反了。代价是 bottom-up 单人精度通常不如 top-down。

### Q2 — 答案：C

讲义给出的两条理由：①"the network's spatial structure (conv feature map) aligns naturally with spatial output"；②"Gaussian targets also regularise — a small localisation error produces a small loss"。直接回归要求网络把整张特征图压缩成两个数，丢掉了空间对应关系。A 不对，热图输出反而更大；B、D 没有依据。

### Q3 — 答案：B

`hm[32, 34]` 表示第 32 行、第 34 列，即 `y = 32, x = 34`，与中心 `(32, 32)` 的距离平方为 4。`exp(-4 / (2·2²)) = exp(-0.5) ≈ 0.607`。C 是距离平方为 8 时的值（`exp(-1)`），D 是距离平方为 16 时的值（`exp(-2)`）。

### Q4 — 答案：B

`ys = idx // W = 2085 // 64 = 32`，`xs = idx % W = 2085 % 64 = 37`（2085 = 32×64 + 37）。函数用 `torch.stack([xs, ys], dim=-1)` 返回 **(x, y)** 顺序，即 `(37, 32)`。A 是把顺序弄反成 (row, col) 的常见错误；D 混淆了亚像素细化。

### Q5 — 答案：B

讲义：每个连接（limb）预测 2 通道（单位向量的 x、y 分量），"integrate the PAF along the line connecting candidate pairs; the pair with the highest integral is matched"。这让 bottom-up 方法无需逐人裁剪即可完成分组。C 描述的是热图本身；D 说反了，PAF 是 bottom-up 的核心组件。

### Q6 — 答案：B

讲义："OKS is the keypoint analogue of IoU and is what COCO mAP@OKS reports." OKS 取值 0–1，与 IoU 一样被用来判定"预测是否与真值匹配"，再在多个阈值上计算 AP。

### Q7 — 答案：C

整数 argmax 把连续峰值四舍五入到最近的网格点，每个轴最大误差 0.5 个**热图**像素；热图相对输入下采样 4 倍，换算到输入图像就是 0.5 × 4 = 2 像素（如果再映射回原图，还要乘以裁剪框的缩放比例）。这就是为什么低分辨率热图必须做亚像素细化。

### Q8 — 参考答案

1. 形状（N = 16）：
   - `h1 = down1(x)`：3×3、stride 2、padding 1 → `(16, 16, 32, 32)`
   - `h2 = down2(h1)` → `(16, 32, 16, 16)`
   - `h3 = mid(h2)`：stride 1 → `(16, 32, 16, 16)`
   - `u1 = up1(h3)`：`ConvTranspose2d(32, 16, kernel=2, stride=2)`，尺寸翻倍 → `(16, 16, 32, 32)`
   - 输出 `up2(u1)` → `(16, 4, 64, 64)`
2. **没有实际作用**。两次 stride-2 下采样之后又做了两次 2 倍的转置卷积上采样，输出本来就是 64×64，与目标 `hms` 一样大。双线性插值在 `align_corners=False`、缩放比例为 1 时，采样点正好落在原像素上，结果与输入相同。它是讲义"Upsample pred to full resolution"留下的防御性代码：如果网络输出分辨率低于目标（真实模型通常输出 1/4 分辨率），这一行才真正生效。
3. 少了：①**跳跃连接（skip connections）**——U-Net 会把编码器的高分辨率特征（如 `h1`）拼接到解码器对应层，这对精确定位尤其重要；②**上采样层之间的非线性**——`up1` 之后直接接 `up2`，中间没有 ReLU，两个转置卷积合起来仍是一个线性变换。（参数量只有 16,660，是刻意做小的。）

### Q9 — 参考答案

1. **不能。** 4 个关键点画出来是完全相同的 4×4 黑块，而 `kps` 的行顺序是随机抽样的顺序，与位置无关。给定一张图，"第 k 号关键点是哪个黑块"在 4 个黑块之间是等概率的。MSE 的最优预测是条件期望：`E[target_k | image] = 4 个高斯的平均`，而且**所有 4 个通道的最优输出都一样**。我用 NumPy 模拟了这个"最优但无法分辨身份"的预测器：MSE 约 0.00225，只比"全输出 0"的 0.00307 低一点。
2. 若 4 个通道输出相同的热图，argmax 会选中同一个黑块，最多 1 个通道正确，其余的误差等于两个随机关键点之间的距离（坐标在 [10, 53] 内均匀分布，平均二十多像素）。同一个最优预测器的模拟结果：**平均 L2 误差约 16 像素**，亚像素细化几乎不改变这个数。所以 `main()` 最后打印的误差预计在**十几像素**的量级，而不是讲义暗示的"小模型一分钟就能学会"。
3. 修复思路（任选）：
   - **让每个关键点外观可区分**：例如第 k 个关键点只在不同的颜色通道上置 0（4 种颜色），就像真实人体中"左手腕"和"右膝"在外观和上下文上本来就不同；
   - **规定一个由图像决定的顺序**：例如按 x 坐标排序后再生成热图——但这需要网络具备全局比较能力，这个感受野很小的模型不一定学得会；
   - **改成与顺序无关的任务**：只预测 1 个通道"所有关键点的热图"，评测时用匈牙利匹配把预测点与真值配对。
4. 切片 `cy-2:cy+2` 覆盖行 `cy-2, cy-1, cy, cy+1`，共 4 行，中心在 `cy - 0.5`；列同理，中心在 `cx - 0.5`。也就是说黑块中心是 `(cx-0.5, cy-0.5)`，与热图中心 `(cx, cy)` 有**半个像素**的系统偏差。这个偏差是固定的，网络可以学会补偿，但如果要研究亚像素精度，这类"半像素约定"问题必须先统一（例如画 5×5 的块 `cy-2:cy+3`）。

### Q10 — 参考答案

1. 真实中心 30.3、σ = 2：
   - `hm[x-1] = hm[29] = exp(-1.3²/8) ≈ 0.810`，`hm[x+1] = hm[31] = exp(-0.7²/8) ≈ 0.941`，差值约 0.131；
   - 代码公式：`30 + 0.25 × 0.131 ≈ 30.033`，几乎没修正（真实偏移 0.3）；
   - 经典 `sign` 版本：`30 + 0.25 = 30.25`，误差从 0.3 降到 0.05。
   - 原因：代码把"四分之一像素偏移"写成了"0.25 × 原始差值"。对 σ = 2、峰值为 1 的热图，相邻两点差值通常只有零点几，修正量被压缩了一个数量级，而且会随热图的幅值变化。经典实现（SimpleBaseline / HRNet 的推理代码）用的是 `np.sign(diff) * 0.25`——讲义的描述里也说的是"offset … direction"。
   - 另外，本节合成数据的真值坐标都是**整数**，热图中心正好落在网格上，亚像素细化在这个演示中本来就没有可提升的空间。
2. 参考实现（高斯取对数后恰好是抛物线，所以对理想高斯是精确的）：

```python
import math


def parabola_refine(hm, x, y, eps=1e-10):
    def offset(l, c, r):
        l, c, r = (math.log(max(float(v), eps)) for v in (l, c, r))
        den = l - 2 * c + r                 # 二阶差分，峰值处应为负
        return 0.0 if den >= 0 else 0.5 * (l - r) / den
    if not (0 < x < hm.shape[1] - 1 and 0 < y < hm.shape[0] - 1):
        return float(x), float(y)            # 边界上不细化
    return (x + offset(hm[y, x - 1], hm[y, x], hm[y, x + 1]),
            y + offset(hm[y - 1, x], hm[y, x], hm[y + 1, x]))
```

三点 `(-1, l), (0, c), (1, r)` 确定的抛物线顶点在 `0.5·(l - r) / (l - 2c + r)`。我用 NumPy 验证：真实中心 30.3 时返回 30.300，29.8 时返回 29.800；而代码公式分别给出 30.032 和 29.978。`eps` 防止对 0 取对数；`den >= 0` 说明不是局部峰（平坦或谷底），放弃细化。

### Q11 — 参考回答要点

- **Top-down**：人体检测器 → 逐个裁剪 → 单人关键点模型（HRNet、ViTPose）。优点：每个人都缩放到固定分辨率，精度最高；缺点：耗时随人数线性增长，受检测器质量影响（漏检的人直接丢失，框不准会截断肢体）。
- **Bottom-up**：一次前向预测所有关键点热图 + 关联信息（PAF 等），再分组（OpenPose、HigherHRNet）。优点：耗时与人数基本无关；缺点：小尺度的人精度差，人群严重遮挡时分组易出错。
- **选型**：单人或少量人、追求精度（健身、医疗、动捕）→ top-down；密集人群、实时监控 → bottom-up；讲义还提到 YOLOv8-pose 这类单次前向的实时多人方案，以及移动端的 MediaPipe Pose。
- **加分点**：top-down 的总延迟 = 检测 + N × 单人模型，可以通过批处理多个裁剪框缓解；视频中可以用上一帧的姿态生成下一帧的框，跳过检测器。

### Q12 — 参考回答要点

- **热图的优势**：保持空间结构、全卷积可复用位置无关的特征；高斯目标提供平滑的监督（离真值近的像素也有较高目标值），训练稳定；一张热图还能自然表达"多峰"的不确定性。
- **代价**：
  - 输出是 K 张热图，显存和计算随分辨率平方增长，所以常在 1/4 分辨率上预测；
  - 整数 argmax 有量化误差，必须亚像素细化（见 Q7、Q10）；
  - argmax 不可导，训练与推理目标不一致；
  - 前景像素极少，MSE 容易被大片背景主导——"全预测 0"也能得到很低的损失。
- **改进思路**：更高分辨率的特征（HRNet 全程保持高分辨率分支）；亚像素解码（抛物线/泰勒展开）；可导的 soft-argmax（integral regression），让坐标损失直接参与训练；用 Transformer 骨干（ViTPose）。
- **常见误区**：认为"MSE 很低 = 模型学好了"——必须看坐标误差、PCK/OKS。

### Q13 — 参考回答要点

1. **网络输出**：K 张关键点热图 + 每条肢体 2 通道的 PAF（肢体所在像素上是从起点指向终点的单位向量，其他地方为 0）。
2. **候选点**：对每张热图做非极大值抑制，得到每类关键点的若干候选（场景里有几个人，大概就有几个左肩）。
3. **打分**：对每条肢体（如左肩→左肘），枚举"候选左肩 × 候选左肘"的所有配对，在两点连线上均匀采样若干点，累加 `PAF(采样点) · 连线单位方向`。方向一致、确实位于同一条肢体上的配对得分高。
4. **匹配**：每条肢体内部是一个二分图匹配问题（按得分贪心或用匈牙利算法），讲义中称为 "greedy matching"。
5. **组装**：把共享关键点的肢体逐条连接，拼成完整的人体骨架。
- **为什么不能简单就近配对**：两个人靠得很近或肢体交叉时，最近的肘不一定属于同一个人；PAF 编码了"方向"和"肢体是否连续存在"的信息。
- **加分点**：复杂度与人数无关的是网络前向；分组阶段与候选点数量相关，但比 top-down 逐人跑网络便宜得多。

### Q14 — 参考回答要点

- **模型**：移动端实时首选 MediaPipe Pose（讲义：有移动端与 WebGL 运行时，延迟低于 10 ms）；单人场景用 top-down 足够，可借助上一帧结果跟踪裁剪框。
- **计数逻辑**：从关键点计算关节角度（如深蹲看髋–膝–踝夹角），用带滞回的状态机（角度低于阈值 A 进入"下"、高于阈值 B 回到"上"计一次），避免在阈值附近抖动重复计数。
- **姿势纠正**：基于角度、左右对称性、躯干倾斜等规则，或与标准动作序列对齐（如 DTW）后比较。
- **稳定性**：关键点有帧间抖动 → 时间滤波（滑动平均、卡尔曼、One-Euro 一类自适应滤波）；用关键点置信度过滤被遮挡的点。
- **工程难点**：自遮挡与侧身视角（2D 角度失真，必要时用 3D 关键点）；光照与宽松衣服；机位不同导致阈值需要自适应；耗电与发热（降帧率、降分辨率）；隐私（全程本地推理）。
- **评测**：录制带人工计数的测试视频，统计计数准确率和误报率；按体型、机位、光照分组评估。

### Q15 — 参考回答要点

- **定义**（COCO）：`OKS = Σᵢ exp(-dᵢ² / (2·s²·κᵢ²))·δ(vᵢ > 0) / Σᵢ δ(vᵢ > 0)`。
  - `dᵢ`：第 i 个关键点预测与真值的欧氏距离；
  - `s`：目标尺度（`s²` 取该人的分割面积），让大人和小人可比；
  - `κᵢ`：每类关键点的常数，来自人工标注的一致性——眼睛、鼻子标注一致性高、容差小，髋部等容差大；
  - 只统计有标注（`vᵢ > 0`）的关键点。
- **为什么不用平均像素距离**：①与尺度相关，近处大人 5 像素误差和远处小人 5 像素误差意义完全不同；②不同关节天然的标注噪声不同，应该区别对待；③需要一个 0–1 的相似度来判定"是否匹配"，才能像检测一样算 AP。
- **用法**：在 OKS 阈值 0.50:0.05:0.95 上计算 AP 再平均（与检测中的 IoU 阈值做法相同）。
- **PCK**：误差小于 `α × 参考长度`（如头部尺寸 PCKh、包围盒尺寸）的关键点比例；简单直观，常用于单人基准，也是本节练习评测的好选择。
