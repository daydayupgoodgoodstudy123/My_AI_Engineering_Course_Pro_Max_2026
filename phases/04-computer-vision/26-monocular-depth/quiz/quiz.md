## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | 相对深度 vs 度量深度 | 相对深度只有顺序、没有真实单位（MiDaS、Depth Anything、Marigold）；度量深度以米为单位（ZoeDepth、UniDepth、Metric3D），对相机内参敏感 |
| 2 | 编码器-解码器模式 | 冻结的 ViT 编码器（DINOv2 / DINOv3）出 `(H/14, W/14, d)` 的稠密特征，DPT 风格的卷积上采样解码器回归出 `(H, W, 1)` 深度图 |
| 3 | 单目线索 | 透视（平行线汇聚）、纹理梯度、遮挡顺序、大小恒常、大气透视；大模型在海量图像上内化了这些线索 |
| 4 | 单目深度做不到的事 | 没有内参或已知物体时无法得到绝对尺度；被遮挡的几何；无纹理 / 反光 / 透明表面（镜子、玻璃、白墙）会给出"看似合理但错误"的深度 |
| 5 | Marigold | 把深度估计改写成以 RGB 为条件的图到图扩散，用预训练 SD2 U-Net 作骨干；边界极其锐利，但需要 10–50 步去噪，推理慢 |
| 6 | 针孔相机反投影 | `X = (u - cx)·d / fx`，`Y = (v - cy)·d / fy`，`Z = d`；内参来自 EXIF、标定板或内参估计器；没有内参时假设 60–70° 视场角只够可视化 |
| 7 | 评测指标 | AbsRel = `mean(|d_pred - d_gt| / d_gt)`（越低越好，生产模型 0.05–0.1）；δ<1.25 = `max(pred/gt, gt/pred) < 1.25` 的像素比例（越高越好，SOTA 0.9+）；评测前必须屏蔽无效像素 |
| 8 | 尺度-平移对齐 | 相对深度模型评测前先用最小二乘拟合 `a·pred + b ≈ gt`，再算指标（尺度-平移不变版本） |
| 9 | 2D → 3D 集成模式 | RGB → 深度图 + 检测框 → 用深度和内参把框中心抬升到 3D → AR 遮挡、路径规划、尺寸估计 |

### 核心技能（能动手做到）

- [ ] 能实现 `abs_rel_error` 和 `delta_accuracy`，并能对一个像素手算两个指标
- [ ] 能用 `torch.linalg.lstsq` 实现尺度-平移对齐，并解释为什么对齐后误差下降但不会归零
- [ ] 能用 `np.meshgrid(..., indexing="ij")` 实现 `depth_to_point_cloud`，并手算任意像素的 3D 坐标
- [ ] 能由视场角和图像宽度估算焦距：`fx = (W/2) / tan(FOV/2)`
- [ ] 能把一个检测框抬升到 3D（框内取有效深度的中位数 + 针孔反投影），并处理无效深度
- [ ] 能写出 ASCII 格式的 `.ply` 文件，并在 MeshLab / CloudCompare 中打开查看
- [ ] 能根据"相对还是度量、延迟、边界质量"在 Depth Anything、Marigold、UniDepth、ZoeDepth、MiDaS 之间做选型

## 五、参考答案与解析

### Q1 — 答案：C

讲义：MiDaS 和 Depth Anything V3 输出相对深度，Marigold 也输出相对深度；ZoeDepth、UniDepth、Metric3D 输出度量深度。度量模型对相机内参敏感，相对模型不敏感。D 显然错误。

### Q2 — 答案：B

DINOv2 / DINOv3 这类自监督 ViT 的特征稍加训练就能迁移到稠密预测任务。冻结编码器 + 轻量解码器意味着只需在深度数据上训练很少的参数，同时"免费"继承编码器在室内、室外、医学、卫星等领域的泛化能力。C 不全面：省算力是附带收益，核心是保住泛化；A、D 不成立。

### Q3 — 答案：B

`fx`、`fy` 是以像素为单位的焦距，`cx`、`cy` 是主点坐标（通常接近图像中心）。它们是针孔相机的**内参**，来自 EXIF、标定板标定，或 Perspective Fields、UniDepth 这类内参估计器。

### Q4 — 答案：C

相对深度模型只保证顺序和比例有意义，输出的尺度和偏移是任意的。不对齐直接算 AbsRel，测到的主要是"尺度不匹配"；用最小二乘拟合 `a·pred + b = target` 后再算，才能公平衡量模型真正被训练出来的能力。这是 MiDaS / Depth Anything 论文的标准协议。

### Q5 — 答案：C

单目深度依赖纹理梯度、遮挡顺序和透视线索。镜子里有一整个"自带深度"的场景，玻璃后面的内容也是可见的，网络于是给出一个与看到的内容一致、但不是玻璃表面真实距离的深度——"自信地错"。这是单目深度的根本局限，不是 bug；材料重要的场景应融合双目、LiDAR 或偏振相机。

### Q6 — 答案：B

Marigold（Ke 等，CVPR 2024）把深度估计重新表述为条件图到图扩散：条件是 RGB，目标是深度图，骨干是预训练的 Stable Diffusion 2 U-Net。优点是边界锐利，代价是需要 10–50 步去噪。讲义把它归为相对深度（C 错），骨干是 SD2 U-Net 而不是 DINOv2（D 错）。

### Q7 — 答案：C

计算 `max(pred/gt, gt/pred)`：

| 选项 | pred/gt | gt/pred | max | < 1.25？ |
|------|---------|---------|-----|----------|
| A (1.5, 2.0) | 0.75 | 1.333 | 1.333 | 否 |
| B (2.6, 2.0) | 1.30 | 0.769 | 1.30 | 否 |
| C (2.4, 2.0) | 1.20 | 0.833 | 1.20 | **是** |
| D (3.0, 2.0) | 1.50 | 0.667 | 1.50 | 否 |

注意这个指标看的是**比值**而不是差值：同样差 0.5，低估（1.5 vs 2.0）的比值是 1.333，高估（2.5 vs 2.0）的比值是 1.25——按差值看是对称的，按比值看并不对称；而且 1.25 恰好等于阈值，用的是严格小于 `<`，所以 2.5 也不算"正确"。

### Q8 — 答案：B

`fx = (W/2) / tan(FOV/2) = 320 / tan(30°) = 320 / 0.5774 ≈ 554`。焦距越长，视场角越窄。讲义提醒：没有内参时这样假设"可以用于可视化，不能用于测量"。

### Q9 — 参考答案

1. 第 24 行不在盒子范围内（盒子在第 42–73 行），所以 `d = 1 + 24/96 × 4 = 2.0`：
   - `X = (72 - 48) × 2.0 / 96 = 0.5`
   - `Y = (24 - 48) × 2.0 / 96 = -0.5`
   - `Z = 2.0`

   即 `(0.5, -0.5, 2.0)`。

2. `Y = (v - 48) × d / 96`，而地面深度 `d = 1 + v/24` 随行号 `v` 增大。在图像上半部分 `(v - 48)` 为负，但 `|v - 48|` 在变小的同时 `d` 在变大，两者的乘积在 `v ≈ 11` 附近取到最负：`(11 - 48) × (1 + 11/24) / 96 ≈ -0.562`，比第 0 行的 `(0 - 48) × 1.0 / 96 = -0.50` 更负。这提醒我们：**点云的范围由像素位置和深度共同决定**，远处的像素会被"放大"。

3. 默认的 `indexing="xy"` 下，`np.meshgrid(np.arange(H), np.arange(W))` 返回形状为 `(W, H)` 的数组：
   - 96×96 时 `(W, H) == (H, W)`，**不会报错，但 `u`、`v` 被悄悄转置**——`v` 实际上变成了列号，点云会沿对角线翻转，而且形状检查完全发现不了；
   - 240×320 时得到 `(320, 240)`，与 `depth` 的 `(240, 320)` 相乘会抛广播错误。

   这正是正方形测试图的危险之处：最容易漏掉坐标转置 bug。用 `indexing="ij"` 明确"第一个输出对应第一个输入（行）"可以避免。

### Q10 — 参考答案

（`main.py` 依赖 torch，以下数值是用 NumPy 以同样分布重复 5 个随机种子复算得到的近似值。）

1. **`scaled`**：`scaled_pred - gt ≈ 2·gt + 0.7 + 1.2·noise`，所以 `|scaled - gt| / gt ≈ 2 + 0.7/gt`。这张深度图上 `mean(1/gt) ≈ 0.43`，于是 AbsRel ≈ 2 + 0.7 × 0.43 ≈ **2.30**。δ<1.25：几乎所有像素的比值都在 3 左右，远超 1.25，所以约为 **0.001**（接近 0）。这正是"相对深度不对齐就直接算指标"会看到的荒唐数字。

2. **`aligned`**：误差**不会归零**。尺度-平移对齐只能消除线性的尺度和偏移，消除不了 `0.4 × randn` 这部分噪声。复算得到 AbsRel ≈ 0.13、δ<1.25 ≈ 0.84，反而比 `pred`（AbsRel ≈ 0.137、δ ≈ 0.81）**略好**。原因是最小二乘的"回归稀释"：当预测里带噪声时，拟合出的有效斜率会小于 1，等于把预测向均值收缩了一点，平均平方误差因此略降。

   拟合系数：如果没有噪声，`a` 应为 1/3；带噪声时 `a ≈ (1/3) × var(gt) / (var(gt) + 0.16)`。这张图 `var(gt) ≈ 1.38`，所以 `a ≈ 0.333 × 0.896 ≈ 0.30`，与复算值 0.297–0.299 一致；`b` 约 0.08–0.10。

### Q11 — 参考答案

```python
import numpy as np

def box_to_3d(depth, box, intrinsics):
    fx, fy, cx, cy = intrinsics
    x1, y1, x2, y2 = (int(round(v)) for v in box)
    patch = depth[y1:y2, x1:x2]                         # 行是 y、列是 x
    valid = patch[np.isfinite(patch) & (patch > 0)]     # 去掉 NaN / inf / 0
    if valid.size == 0:
        return None
    d = float(np.median(valid))                         # 中位数抗背景 / 噪声
    u = (x1 + x2) / 2.0
    v = (y1 + y2) / 2.0
    return ((u - cx) * d / fx, (v - cy) * d / fy, d)
```

验证：`box_to_3d(synthetic_depth(96), (33, 42, 64, 74), (96., 96., 48., 48.))` 返回 `(0.0104…, 0.2083…, 2.0)`。框中心 `u = 48.5`、`v = 58`，盒子深度 2.0，所以 `X = 0.5 × 2 / 96 ≈ 0.0104`，`Y = 10 × 2 / 96 ≈ 0.208`。即使把框内一块区域置 0、塞一个 NaN，中位数仍为 2.0；空框返回 `None`（已验证）。

要点：
- 切片是 `depth[y1:y2, x1:x2]`——数组先行后列，框是先 x 后 y；
- 用中位数而不是均值：框里难免混进背景像素，中位数更稳健；更好的做法是用实例分割 mask 代替框；
- 相对深度模型的输出不能直接这样当"米"用，必须先拿到度量尺度。

### Q12 — 参考回答要点

- **区别**：相对深度只给出顺序 / 相对结构（"A 比 B 近"），尺度和偏移任意；度量深度给出米为单位的距离，需要模型从训练数据中学到图像线索与真实距离的统计关系，对相机内参敏感。
- **拿到度量尺度的办法**：
  - 换用度量深度模型：UniDepth（同时估计内参）、ZoeDepth、Metric3D；
  - 用场景中已知尺寸的物体（门、A4 纸、车道线宽）反推尺度；
  - 用稀疏的度量观测（少量 LiDAR 点、双目、ToF、AR 框架给出的稀疏点）做尺度-平移拟合——与评测时的 `align_scale_shift` 是同一个最小二乘；
  - 多帧 + 相机位姿（SLAM / IMU）恢复尺度。
- **常见误区**：以为"有了内参，相对深度就自动变成米"——内参解决的是像素到射线的方向问题，并不能确定相对深度的尺度。

### Q13 — 参考回答要点

- **为什么能估计**：单张图里有大量与深度相关的线索——透视（平行线汇聚）、纹理梯度（远处纹理更小更密）、遮挡顺序、大小恒常（已知物体给出大致尺度）、大气透视（远处更朦胧偏蓝）。在数十亿张图上训练的 ViT 内化了这些先验，所以无需显式 3D 监督也能得到不错的精度。
- **为什么定不了绝对尺度**：针孔投影 `u = fx·X/Z + cx`、`v = fy·Y/Z + cy`。把整个场景放大 s 倍 `(X, Y, Z) → (sX, sY, sZ)`，`X/Z`、`Y/Z` 不变，投影出的图像完全相同。所以"1 米外的小杯子"和"10 米外的大杯子"在像素上可以一模一样——只能靠先验（杯子通常多大）去猜。
- **其他局限**：被遮挡的几何（椅子背面）、无纹理 / 反光 / 透明表面。
- 加分点：说明这正是度量模型需要内参或"已知尺度物体"的原因，以及为什么相对模型的评测要做尺度-平移对齐。

### Q14 — 参考回答要点

- **数据处理**：
  - 屏蔽无效像素（0、NaN、饱和值），讲义强调"评测前一定要 mask"；
  - 统一分辨率（把预测插值回 GT 分辨率），注意插值方式不能在边界处混合前景与背景；
  - 按场景类型分桶（室内、室外、有玻璃 / 镜面）。
- **指标**：AbsRel（越低越好，生产模型约 0.05–0.1）和 δ<1.25（越高越好，SOTA 0.9+）；可补充 RMSE 等。
- **对齐方式**：
  - 相对模型：先在有效像素上做最小二乘尺度-平移对齐，再算指标（尺度-平移不变版本）；
  - 度量模型：**不做对齐**，直接算——对齐会掩盖它们最重要的能力（尺度是否准确）；
  - 报告时把两类结果分开，不要放在同一张表里直接比较。
- **常见陷阱**：
  - 对齐用的像素与评测像素相同，会略微偏乐观——严格做法可以在一部分像素上拟合、在另一部分上评测；
  - 预测出现 0 或负值时，比值类指标会爆炸，需要 clamp（代码里用了 `clamp(min=1e-6)`）；
  - 只看平均值会掩盖玻璃 / 远处区域的大误差，应看分桶结果和误差图。

### Q15 — 参考回答要点

- **模块组成**（对应讲义的集成模式）：RGB 帧 → 开放词表检测 / 分割（找到"杯子"）→ 深度模型 → 用内参把杯子区域抬升到 3D → 输出抓取点给规划器。
- **关键公式**：`X = (u - cx)·d / fx`，`Y = (v - cy)·d / fy`，`Z = d`；再用相机外参（手眼标定）把相机坐标系转换到机械臂基坐标系。
- **模型选择**：
  - 抓取需要**米**，所以要么用度量深度模型（如 UniDepth、ZoeDepth），要么用相对模型 + 桌面已知尺寸 / 少量标定点做尺度拟合；
  - 相机内参必须**标定**，不能靠假设的 60–70° 视场角（那只够可视化）；
  - 物体区域用实例 mask 内深度的中位数，比框更稳健。
- **风险点**：
  - 玻璃杯、不锈钢杯、反光桌面会让单目深度"自信地错"——重要场景加 RGB-D / 双目，或加偏振相机；
  - 杯子背面不可见，只能估计可见表面，抓取点要留余量；
  - 实时性：讲义给出 Depth Anything V2 Small（INT8 量化）在消费级 GPU、518×518 输入下约 30 fps。

### Q16 — 参考回答要点

| 维度 | Depth Anything（冻结 ViT + DPT） | Marigold（条件扩散） |
|------|-------------------------------|---------------------|
| 骨干 | DINOv2 ViT-L/14（冻结） | 预训练 Stable Diffusion 2 U-Net |
| 推理 | 一次前向，快 | 10–50 步去噪，慢 |
| 输出质量 | 泛化强、整体结构好 | 物体边界非常锐利，视觉质量最高 |
| 深度类型 | 相对（讲义） | 相对 |
| 适用 | 实时 / 大规模批处理、默认首选 | 离线高质量：视觉特效、精修、数据标注 |

- 为什么扩散能给出锐利边界：它借用了图像生成模型在像素级细节上的强先验，把深度图当作"另一种图像"去生成；回归模型在边界处往往输出前景与背景的平均值，导致"拖尾"。
- 选型：需要实时或海量处理 → Depth Anything；要最好的视觉质量且能接受延迟 → Marigold；需要米 → UniDepth / ZoeDepth；做基线对比 → MiDaS v3.1。
