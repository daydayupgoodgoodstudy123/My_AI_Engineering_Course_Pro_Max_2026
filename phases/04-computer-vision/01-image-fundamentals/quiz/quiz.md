## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | 像素是采样，不是小方块 | 每个像素是某个网格位置上的一次光强测量；resize / 旋转本质上是对这张"采样网格"重新采样 |
| 2 | 空间采样与强度量化 | 采样密度决定细节上限（太稀会锯齿/aliasing），量化位数决定灰阶数（8 bit = 256 级，医学/HDR 常用 10–16 bit） |
| 3 | 通道（channel） | 彩色像素是 R、G、B 三个数；通道数不是固定的 3（深度、红外、高光谱都可以更多），卷积层负责在通道维上混合 |
| 4 | HWC 与 CHW 布局 | 磁盘/PIL/OpenCV 用 HWC，PyTorch/cuDNN 用 CHW（批量时 NCHW）；`transpose(2,0,1)` / `permute(2,0,1)` 互转 |
| 5 | 三种数值约定 | raw：`uint8` [0,255]；normalized：`float32` [0,1]；standardized：减均值除标准差后大约 [-2,+2] |
| 6 | ImageNet mean/std | `[0.485,0.456,0.406]` / `[0.229,0.224,0.225]` 是 ImageNet 训练集在 [0,1] 空间的逐通道统计量，用它让输入分布对齐预训练时的分布 |
| 7 | 色彩空间 | RGB 是采集格式；HSV 把颜色与亮度分开（阈值分割）；YCbCr 把亮度与色度分开（JPEG/视频压缩色度）；灰度 = BT.601 加权和 `0.299R+0.587G+0.114B` |
| 8 | 三种 resize 策略 | 短边缩放 + 中心裁剪（ImageNet 分类）、等比缩放 + 填充（检测/OCR）、直接拉伸（便宜但变形） |
| 9 | 插值方法 | nearest（最快、块状、标签/mask 唯一选择）、bilinear（训练默认）、bicubic/lanczos（更锐、更慢，用于展示） |
| 10 | 预处理顺序是契约 | 解码 → 色彩空间 → resize → crop → /255 → 标准化 → HWC→CHW → 加 batch 维；顺序或任一步错了，大多数情况下不报错，只是结果变差 |

## 五、参考答案与解析

### Q1 — 答案：C

`.float()` 之后 dtype 已经是 `float32`，与权重一致，所以 A 不会发生；PyTorch 模型不会自动缩放输入，B 错。输入值域变成了 [0,255]，比训练时的标准化分布（大致 [-2,+2]）大了约两个数量级，第一层卷积的激活整体偏移、放大，后续 BN 用的是训练时的 running statistics（推理模式下不会按当前 batch 重新统计），无法"自动校正"，所以 D 错。结果是模型照常输出 logits，但预测几乎是随机的——这正是讲义说的"最常见的 silent failure"。

> 注意区分：如果连 `.float()` 都没做，直接传 `uint8` 张量，PyTorch 会因输入与权重 dtype 不一致而报错——这反而是"好"的失败。

### Q2 — 答案：B

ImageNet 的 mean/std 是**整个训练集**的统计量，标准化让"ImageNet 分布"变成大致 0 均值、1 方差。对单张图片，结果取决于这张图本身的颜色分布。本节 `main.py` 的合成图就是例子：标准化后逐通道均值约 `[0.071, 0.188, -0.698]`，标准差约 `[1.57, 1.30, 0.988]`，远不是 0/1。A 混淆了"数据集统计"和"逐图统计"；C 错在值域大约是 [-2.1, +2.6]，并非 [-1,1]；D 错在除以 std 会改变尺度。

### Q3 — 答案：B

`transpose(2, 0, 1)` 表示"新的第 0 轴取原来的第 2 轴（C），新的第 1 轴取原第 0 轴（H），新的第 2 轴取原第 1 轴（W）"，得到 `(3, H, W)`。A 的 `reshape` 只改变"怎么读这一串内存"，不移动数据，会把交错存储的 `R G B R G B …` 硬切成三段，得到的"通道"里混杂着三种颜色——形状对、内容全错，是经典 bug。C 是 CHW→HWC 的逆变换，用在这里会得到 `(W, 3, H)`。D 的 `.T` 反转全部轴，得到 `(3, W, H)`，H 和 W 被交换了。

### Q4 — 答案：C

bilinear / bicubic / lanczos 都在对邻域值做加权平均，类别 4 和类别 5 的交界处会被算出 4.5、4.7 这种"不存在的类别"（取整后甚至可能变成毫不相干的类别 ID）。nearest 只会从原图中挑一个真实存在的值，保住了标签空间。规则推广：任何编码"ID / 索引"的通道（实例 ID、深度图有效性掩码等）都只能用 nearest。

### Q5 — 答案：B

YCbCr 把亮度 Y 与色度 Cb、Cr 分开。人眼对亮度细节敏感、对色度细节不敏感，所以编码器可以对色度做下采样（例如 4:2:0）、用更粗的量化，而肉眼几乎察觉不到。A 错：YCbCr 仍是三个通道，节省来自"色度可以被压得更狠"，而不是通道变少；C 错：传感器输出的是 Bayer 马赛克，去马赛克后得到的是 RGB；D 与压缩动机无关。

### Q6 — 答案：A

`cmax = cmin = 128/255 ≈ 0.502`，`delta = 0`。代码中 `mask = delta > 0` 为 False，色相保持初始值 0（无色彩的像素色相本来就没有定义，代码约定取 0，而不是产生 NaN）；饱和度用 `np.divide(..., where=cmax > 0)` 计算得 `0/0.502 = 0`；`V = cmax ≈ 0.50`。D 是"不加保护地做除法"会得到的结果，本节代码通过 `mask` 和 `np.divide(where=...)` 刻意避免了它。

### Q7 — 答案：B

短边是 H=480，缩放因子 `256/480 ≈ 0.533`，W 变为 `640 × 0.533 ≈ 341.3 → 341`，得到 256×341（保持宽高比）。随后从中间裁出 224×224：`top = (256-224)//2 = 16`，`left = (341-224)//2 = 58`。A 是"直接拉伸"，会改变宽高比；C 是把长边缩到 256；D 的裁剪尺寸不对——分类模型要求固定的正方形输入。

### Q8 — 参考答案

实际运行输出：

```text
[  0   0 100 200 200]
[  0  50 100 150 200]
[  0  44 100 156 200]
```

- 三种方法共用 `resize_coordinates(3, 5) = linspace(0, 2, 5) = [0, 0.5, 1, 1.5, 2]`（端点对齐：首尾像素固定）。
- ① nearest 用 `np.rint` 取整，而 `np.rint` 采用**银行家舍入（round half to even）**：`rint(0.5)=0`、`rint(1.5)=2`。所以第 2 个位置取源像素 0（值 0），第 4 个位置取源像素 2（值 200），输出不对称。这是 NumPy 的约定，不是 bug，但如果你期望"0.5 进位"就会惊讶。
- bilinear 在 0.5 处取两侧像素各一半：`0.5×0 + 0.5×100 = 50`，对线性斜坡完美还原。
- ② bicubic 在 x=0.5 处需要 4 个邻居：偏移 -1、0、1、2，即索引 `[-1, 0, 1, 2]`；`np.clip` 把 -1 夹到 0（边缘复制），所以取到的值是 `[0, 0, 100, 200]`。Catmull-Rom 权重为 `[-0.0625, 0.5625, 0.5625, -0.0625]`，结果 `0×(-0.0625) + 0×0.5625 + 100×0.5625 + 200×(-0.0625) = 43.75 → 44`。如果左边真有一个值为 -100 的像素（斜坡外推），结果就是 50。结论：**边界处理方式（复制、镜像、补零）会影响边缘像素的插值结果**，而三次核的负权重让这种影响更明显。

### Q9 — 参考答案

问题出在 `.astype(np.uint8)`：它是**向零截断**而不是四舍五入。`x * 255.0` 经过 float32 的除法、减法、乘法、加法之后，理论上应为 120 的值可能算成 `119.99999`，截断后就成了 119，于是差 1。实测这张 128×192×3 的图中有 19262 / 73728（约 26%）个值差了 1。

修改：

```python
    x = np.clip(np.rint(x * 255.0), 0, 255).astype(np.uint8)
```

先用 `np.rint` 四舍五入再转 `uint8`，往返误差变为 0（已实测）。经验：**浮点转整数时总要先想清楚是要截断还是四舍五入**；`np.clip` 则用来防止超出 [0,255] 后 `uint8` 回绕（例如 256 变成 0）。

### Q10 — 参考答案

转置之后 `x` 的形状是 `(3, H, W)`，而 `IMAGENET_MEAN` 的形状是 `(3,)`。NumPy 广播从**最后一个轴**开始对齐，于是 `(3,)` 被对齐到 W 轴而不是 C 轴：

- 对 128×192 的图：`(3,128,192) - (3,)` → W=192 与 3 不兼容，抛出 `ValueError: operands could not be broadcast together with shapes (3,128,192) (3,)`。这算"幸运的失败"。
- 若图片宽度恰好是 3：`(3,H,3) - (3,)` 能广播成功，但减去的是"按列"的均值——第 0 列减 0.485、第 1 列减 0.456……完全错误，却**不会报错**。

修法一：保持原顺序，在 HWC 上做标准化（此时 C 是最后一轴，`(H,W,3) - (3,)` 天然对齐），最后再转置——这正是本节 `preprocess_imagenet` 的写法。

修法二：把统计量变成能对齐 C 轴的形状：

```python
x = (x - IMAGENET_MEAN[:, None, None]) / IMAGENET_STD[:, None, None]   # (3,1,1)
```

这与讲义 PyTorch 版本里 `mean.view(1, 3, 1, 1)` 是同一思路。

### Q11 — 参考回答要点

- **流程**：解码得到 `uint8` HWC → 确认/转换色彩空间（OpenCV 默认 BGR，需转 RGB）→ 短边缩放到 256 → 中心裁剪 224 → `float32` 并 /255 → 逐通道减 mean 除 std → HWC 转 CHW → 加 batch 维得到 NCHW → 送入模型。
- **silent bug 高发区**：
  1. 漏做标准化，或只 /255 不减均值（讲义中标红的一步）；
  2. 布局错误：HWC/CHW 混淆，或用 `reshape` 代替 `transpose`；
  3. BGR/RGB 搞反（讲义说可能掉十个点）；
  4. resize 方式、插值方法、是否 antialias 与训练时不一致；
  5. 步骤顺序颠倒（如先标准化再 resize 带来的数值差异、先 CHW 再广播 mean）。
- **加分点**：强调"预处理是模型契约的一部分"，应该把 mean/std、尺寸、插值、色彩顺序写进模型卡/配置，并在服务端加一个"输入张量检查器"（dtype、值域、均值）——本节 outputs 中的 image-tensor-inspector skill 就是这个思路。

### Q12 — 参考回答要点

- **HWC 的来由**：传感器按扫描线输出，每个像素的 RGB 三个值挨在一起（交错存储），JPEG/PNG 解码、PIL、OpenCV、matplotlib 都沿用这种布局。
- **CHW 的来由**：卷积核在 H、W 上滑动，把通道放在最前面，每个通道是一张连续的二维平面，便于向量化和 cuDNN 内核实现。
- **transpose 是否复制**：NumPy 的 `transpose` / PyTorch 的 `permute` 只改变 strides（步长）元数据，返回的是一个**视图**，不复制数据；结果通常是非连续（non-contiguous）的，后续某些操作（如 PyTorch 的 `.view`）需要先 `.contiguous()` 才会真正复制。讲义原话是"no data copy is strictly required when the memory layout allows it"。
- **加分点**：PyTorch 也支持 `channels_last` 内存格式（逻辑形状仍是 NCHW，物理上按 NHWC 存储），在某些 GPU 卷积内核上更快——说明"逻辑形状"与"物理内存布局"是两回事。

### Q13 — 参考回答要点

权重一致却掉点，几乎可以断定是**输入分布不一致**。按"最便宜、最常见"的顺序排查：

1. **抓一个线上实际输入张量**，打印 dtype、shape、min/max、逐通道均值，与离线管线的同一张图逐元素对比（这是最快的定位手段）；
2. **色彩通道顺序**：线上是否用 OpenCV 解码（BGR）而训练用 PIL（RGB）；
3. **数值范围与标准化**：是否漏了 /255、mean/std 是否和训练一致（是否误用了 [0,255] 尺度的 mean）；
4. **布局**：NCHW/NHWC；
5. **几何**：resize 策略（拉伸 vs 短边+裁剪 vs pad）、插值方法、antialias、JPEG 解码库差异；
6. **其他**：EXIF 方向未处理（手机照片被旋转 90°）、灰度图/RGBA 图没有统一转成 3 通道。

- **加分点**：建议把预处理代码做成训练和服务共用的同一个模块，并在 CI 中加入"同一张图在两条链路上产出的张量差 < ε"的回归测试。

### Q14 — 参考回答要点

- **nearest**：取最近的源像素，最快、有块状感，是唯一不会"发明新值"的方法，因此用于 mask / 类别图。
- **bilinear**：在两个方向上各取 2 个邻居按距离线性混合（共 4 个像素），平滑、速度快，训练时的默认选择。
- **bicubic**：每个方向取 4 个邻居（共 16 个），用三次核（本节代码是 Catmull-Rom，`a = -0.5`）加权，核有负瓣，所以边缘更锐，可能出现轻微过冲（overshoot）；放大时观感更好。本节 3 倍放大实测 roughness：nearest 4.34 > bicubic 3.98 > bilinear 3.23。
- **lanczos**：用更宽的 sinc 窗口核，最慢、质量最好，常用于最终展示。
- **antialias**：大幅缩小时，若每个输出像素只看源图的 2×2 或 4×4 个邻居，大量源像素被直接跳过，高频成分会折叠成错误的低频纹理（aliasing，摩尔纹）。antialias 的做法是让插值核随缩放倍数变宽（等价于先低通滤波再采样）。讲义 PyTorch 示例里的 `F.interpolate(..., antialias=True)` 正是为此。
- **常见误区**：训练用 PIL（缩小时默认带抗锯齿）、推理用不带 antialias 的 resize，输入会有细微但系统性的差异。

### Q15 — 参考回答要点

- **位深与值域**：CT 原始值是 16 bit（如 Hounsfield 单位），直接除以 65535 会把有用组织压到很窄的区间。常见做法是先做**窗宽窗位（windowing）**，截取感兴趣的强度区间再线性映射到 [0,1]；可以用多个窗口生成多个通道。
- **通道数**：ImageNet 模型第一层期望 3 通道。方案一：把单通道复制 3 份；方案二：用 3 个不同窗口组成 3 个通道；方案三：修改第一层为 1 通道，权重取原 3 通道权重之和（与"灰度是 RGB 的加权和"同理）。
- **标准化**：与其硬套 ImageNet mean/std，不如在自己的训练集上重新统计 mean/std（讲义与原 quiz 都指出：换数据集就该重新计算统计量），或者至少保证输入落在相近的尺度上。
- **resize**：医学影像的像素物理间距（spacing）有意义，尽量保持宽高比（pad 而不是拉伸）；分割标注必须用 nearest。
- **加分点**：主动提到"量化位数决定上限"——如果过早转成 8 bit，就丢失了细微的密度差异。

### Q16 — 参考回答要点

- **为什么加权**：人眼对绿光最敏感、对蓝光最不敏感，ITU-R BT.601 的系数 0.299/0.587/0.114 是为了匹配人眼感知到的亮度（luminance）。用等权平均，偏绿的图会显得太暗、偏红/蓝的图会显得太亮。较新的 BT.709（HDTV）系数为 0.2126/0.7152/0.0722。
- **写成网络层**：灰度是每个像素位置上对通道维的线性组合，正好就是一个 **1×1 卷积**（3 个输入通道 → 1 个输出通道，权重 `[0.299, 0.587, 0.114]`，无 bias）。同理，RGB→YCbCr 这类"逐像素的线性变换（可带偏置）"都能写成 3→3 的 1×1 卷积；而 RGB→HSV 含 max/min 和分段除法，是非线性的，不能用单个 1×1 卷积表达。
- **加分点**：这说明 CNN 第一层完全有能力"学会"所需的色彩空间变换，所以现代 CNN 一般直接喂 RGB 即可；色彩空间的选择更多影响的是经典 CV 算法、压缩和数据增强。
- **常见误区**：在已经 ImageNet 标准化过的张量上直接套 0.299/0.587/0.114，得到的并不等于原图灰度的标准化——需要先反标准化，或者把 mean/std 折算进 1×1 卷积的权重和偏置。
