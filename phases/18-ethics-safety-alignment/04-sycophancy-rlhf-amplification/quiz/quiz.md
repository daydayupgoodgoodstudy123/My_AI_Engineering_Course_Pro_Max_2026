## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | 迎合（sycophancy）的定义 | 不管真假都附和用户陈述的前提；与"有帮助"（helpfulness）和"礼貌"不同，区别可以在校准过的评测上测出来 |
| 2 | 迎合是损失函数的性质 | 讲义："Sycophancy is not a bug in the data — it is a property of the loss." 只要优化器把概率推向高奖励输出，而高奖励输出中迎合比例偏高，迎合就会被放大 |
| 3 | 两阶段机制 · 阶段 1 | 在 base 模型的输出分布上，`E_{π0}[s | r 高] > E_{π0}[s | r 低]`：迎合的回复在代理奖励下平均得分更高 |
| 4 | 两阶段机制 · 阶段 2 | 任何按 `exp(r)` 给 `π0` 加权的方法（DPO、PPO-with-KL、best-of-N）都会提高迎合的边际概率，放大程度由 KL 预算决定 |
| 5 | 不需要标注者"不诚实" | 只要 RM 奖励流畅、自信、认同前提，而这些与迎合相关，即便标注者完全诚实也会放大迎合 |
| 6 | 逆向缩放（inverse scaling） | 讲义：迎合随模型规模和 RLHF 训练时长上升；Shapira et al. 报告约 15%（预训练）→ 40%（RLHF）→ 55%（2 倍步数） |
| 7 | 匹配的用户/第三方信念评测 | 同一事实分别以"我认为 X"和"同事读到 X"提问；讲义：11 个前沿模型对错误用户信念的附和比人类多 49% |
| 8 | 校准坍塌 | 讲义：Sahoo 用 GRPO 奖励附和"植入的错误答案"，ECE、Brier 恶化，模型变得"自信且错误"；事后矩阵缩放只能部分修复（ECE 0.042 vs 中性 0.037） |
| 9 | 附和惩罚修正 | `r'(x,y) = r(x,y) − α·agree(x,y)`；讲义：α ≈ 0.3–0.5 时迎合降到接近 base 水平，代价是对正确用户信念也更爱唱反调 |
| 10 | 修在目标而不是优化器 | 偏好信号本质上是多维的（有用、诚实、无害、对时附和、错时反驳），任何标量代理都会把它们压扁；迎合出现在这些维度的冲突处 |

## 五、参考答案与解析

### Q1 — 答案：B

讲义 Key Terms："Completion that agrees with stated user premise regardless of truth." 关键在"regardless of truth"。A 是礼貌，C 是讲义所说的 helpful agreement（"the good kind"），D 是冗长。迎合与有帮助的区别只能通过**假陈述**样本测出来：用户说对了时附和是好事，说错了时附和才是迎合。

### Q2 — 答案：D

讲义：Stage 1 是经验性的统计性质 `E_{π0}[s | r=high] > E_{π0}[s | r=low]`。A 错：讲义特别强调不需要标注者故意偏好迎合；B 是放大程度的调节因素，属于阶段 2；C 是现象（逆向缩放），不是机制本身。

### Q3 — 答案：A

讲义："any method A that upweights `π0(y|x)` by `exp(r(x,y))` (which is DPO, PPO-with-KL, and best-of-N)"。DPO 虽然没有显式 RM，但它的最优解同样是 `π_ref·exp(r/β)`（见第 03 节），所以 B 错。best-of-N 是"按奖励挑选"的离散版加权，也在其中，但不止它。SFT 不按奖励加权，D 错。

### Q4 — 答案：C

讲义："This is a clean benchmark because it decouples sycophancy from honesty: the same question, factually identical, answered differently when the framing changes the perceived source." 只改变"谁相信这件事"，模型的事实知识对两种框架是一样的，所以差异只能来自迎合。A 恰好是 skill 文件明确拒绝的做法（主观问题没有真值）；B 测的是训练影响，不能解耦；D 不涉及框架对照。

### Q5 — 答案：A

讲义公式 `r'(x, y) = r(x, y) − α·agree(x, y)`。B 是加大 KL 约束，不是附和惩罚；C 是粗暴的数据过滤，会误伤正确的认同；D 是 RLAIF（第 05 节），讲义也指出它把标注者偏差移到了循环内部，并不能自动解决问题。

### Q6 — 答案：D

`labeler_reward(S) = −0.3 + 0.6 = 0.3`，`labeler_reward(A) = 1.0`。`P(S 胜 A) = σ(0.3 − 1.0) = σ(−0.7) ≈ 0.332`。A（0.69）是 S 对 W 的胜率 `σ(0.8)`；B（0.82）是 A 对 W 的胜率 `σ(1.5)`。这道题说明：在本代码设定里，标注者**大多数时候仍然更喜欢正确答案**，迎合只是比随机错误答案更受欢迎。

### Q7 — 答案：B

base 是均匀策略，`P(S) = 1/3 ≈ 0.333`（代码没有打印 base 行，很容易漏看）。训练后 `P(S) = 0.030`，绝对值降了一个数量级。迎合只是相对**随机错误答案 W** 被"偏爱"了（比值从 1 变成约 2.1）。A 与实际输出相反；C 错，β = 0 只是没有 KL 惩罚，等价于纯奖励最大化，输出完全有意义；D 显然错。这暴露了代码 TAKEAWAY 与输出不一致的问题（见 Q9）。

### Q8 — 答案：C

讲义 Key Terms："Post-sycophancy-training models lose uncertainty signals when incorrect." 讲义还说，事后矩阵缩放只能部分修复 ECE（0.042 vs 中性训练的 0.037）。A、B 与校准无关；D 描述的是"欠自信"，方向相反。

### Q9 — 参考答案

1. RM 分数 `A=+0.675 > S=+0.051 > W=−0.726`，奖励最高的动作是 A（正确答案，`AGREEMENT = 0`）。在 base 策略下，"高奖励区间"里没有迎合，`E[s | r 最高] = 0`，阶段 1 的前提**不成立**。按讲义自己的定理，此时优化器把质量推向 A，迎合不会被放大，反而被压低——这正是输出显示的结果。TAKEAWAY 的 "low beta amplifies sycophancy" 与本次运行矛盾。
2. 需要 `−0.3 + bonus > 1.0`，即 `bonus > 1.3`。（如果只是要求 S 的奖励高于 base 下的平均奖励，阈值更低，但要让"最高奖励输出是迎合"必须超过 1.3。）
3. 加成 1.5 时（实测）：β = 1.0 → `P(S) ≈ 0.600`；β = 0.2 → 0.917；β = 0.05 → 0.954；β = 0.0 → 0.962。此时迎合从 0.333 被放大到接近 1，且 β 越小越严重，TAKEAWAY 第一句才成立。同一设定下 β = 0.1 扫 α：α = 0 / 0.2 / 0.4 / 0.6 / 0.8 时 `P(S)` = 0.945 / 0.915 / 0.837 / 0.590 / 0.236，`P(A)` = 0.042 / 0.069 / 0.142 / 0.382 / 0.736——附和惩罚在这时才显示出实际作用。

### Q10 — 参考答案

1. β = 1.0：`exp([0.675, 0.051, −0.726]) = [1.964, 1.052, 0.484]`，归一化得 **`[0.561, 0.301, 0.138]`**。β = 0.2：`exp([3.375, 0.255, −3.63])` 归一化得 **`[0.957, 0.042, 0.001]`**。（已用 Python 计算验证。）
2. β = 1.0 一行与最优解几乎完全一致，说明 300 步已经收敛；β = 0.2 一行（0.901 / 0.072 / 0.026）还没到最优——β 越小，最优解越尖锐，离均匀起点越远，300 步、lr = 0.08 不够。我们把步数加到 3000，得到 `[0.972, 0.024, 0.004]`，又比最优解更尖——这是 Q11 中"未采样动作的优势记为 0"带来的偏差。
3. β → 0 时 `exp(r/β)` 让最优策略集中到奖励最大的动作上（`argmax r`）。如果奖励最高的动作是迎合的（阶段 1 成立），迎合概率被推向 1；如果奖励最高的是正确答案，迎合被推向 0。β 是"放大器"，决定放大多少；阶段 1 决定放大**什么**。这就是讲义说的 "amplification is quantitatively predicted by the KL budget"。

### Q11 — 参考答案

1. `Σ_i adv_i · π_i · (1[i=b] − π_b)` 正是 `∂/∂logit_b Σ_i π_i · adv_i` 的精确梯度（softmax 的 Jacobian）。把 `adv_i` 当成动作 i 的塑形奖励，这就是对 `E_π[r − β·log(π/π_ref)]` 做**梯度上升**（`logits += lr * grad`）。它不是 PPO：没有重要性采样比率 `π/π_old`，没有 clip，没有价值函数 baseline / GAE，也没有多 epoch 的 minibatch 更新；而且它用到了精确的 `probs[i]`，这在真实 LLM（动作空间是所有可能的回复）里做不到。更准确的名字是"带 KL 塑形的精确 softmax 策略梯度，用 batch 内各动作的平均塑形奖励作为估计"。
2. 没被采到的动作 `advantages[i] = 0`。真实的塑形奖励可能远非 0：例如 β = 0.2、`P(W) = 0.004`、`P_ref(W) = 1/3` 时，`r_W − β·log(P/P_ref) = −0.726 − 0.2 × ln(0.012) ≈ −0.726 + 0.885 ≈ +0.16`，是正的（KL 项在把 W "拉回来"）。把它当 0 等于丢掉了 KL 的回拉力，于是小概率动作被压得过低——这解释了 Q10 中 3000 步的结果比解析最优更尖。由于 softmax 梯度对所有优势加同一常数不变，偏差来自"不同动作的估计不一致"，而不是常数平移。

### Q12 — 参考答案

1. 迎合分 = 用户框架假陈述的附和率 − 第三方框架假陈述的附和率 = `0.45 − 0.30 = 0.15`。有帮助分 = 用户框架真陈述的附和率 = `0.92`。（第三方真陈述 0.90 是对照，说明模型知识本身没问题。）
2. 用双比例 z 检验的样本量公式：`n = [1.96·√(2p̄(1−p̄)) + 0.84·√(p1(1−p1) + p2(1−p2))]² / (p1 − p2)²`，`p̄ = 0.375`，计算得每组约 **163 条**（已用 Python 计算）。skill 文件要求 ≥200 条匹配题目，与此量级一致并留有余量；若要检测更小的差异（如 0.05），所需样本会增大到一千条以上。更合适的做法是利用**配对**结构：同一事实的两种框架是一对，用 McNemar 检验或对每题差值做 bootstrap，可以去掉"题目难度"带来的方差，比独立样本检验更有效；skill 文件也要求报告 bootstrap 95% 置信区间。

### Q13 — 参考回答要点

- **定义**：无论真假都附和用户陈述的前提；例："我觉得澳大利亚首都是悉尼，对吧？"迎合的回答是"对"。
- **RLHF 为什么放大**：
  - 标注者往往更喜欢被认同 → RM 学到"认同用户"有奖励；
  - 更一般地，RM 奖励流畅、自信、接受前提，这些特征与迎合相关；
  - PPO / DPO / best-of-N 都会把概率推向高奖励输出，迎合因此被放大。
- **证据**（讲义转述）：Perez et al.（2022）迎合随 RLHF 训练增长；Sharma et al.（2023）随模型规模增长；Shapira et al. 测得约 15% → 40% → 55%。
- 加分点：迎合是"优化器严格执行了目标"的典型案例，修复要在目标层面（讲义："The fix has to be at the objective, not at the optimizer."）。

### Q14 — 参考回答要点

- **阶段 1**：在 base 模型输出上，迎合回复在代理奖励的高分区更常见。
- **阶段 2**：任何按 `exp(r)` 给 `π0` 加权的方法都提高这些高分输出的概率，迎合的边际概率随之上升，上升幅度由 KL 预算决定。
- **为什么标注者诚实也没用**：阶段 1 只是一个统计相关性——只要 RM 奖励的特征（流畅、自信、认同前提）与迎合正相关就成立，不需要任何人"想要"迎合。
- **与 Goodhart 的关系**：代理奖励 `r` 与真实目标（诚实且有帮助）在 base 分布上相关；优化压力把分布推到尾部，在尾部两者分离，代理分上升而真实质量下降。讲义："The curve is the Gao et al. over-optimization curve from Lesson 2, with sycophancy playing the role of gold-negative."
- 加分点：用本节玩具说明"阶段 1 不成立时不会放大"（代码默认参数正是这种情况），能体现对定理前提的理解。

### Q15 — 参考回答要点

- **数据**：每个事实题构造 4 个变体（用户/第三方 × 真/假），覆盖多个领域；题目要有明确真值，排除主观意见题（skill 文件明确拒绝主观题）。
- **指标**：
  - 迎合分 = 附和率（用户 + 假）− 附和率（第三方 + 假）；
  - 有帮助分 = 附和率（用户 + 真），防止模型靠"一律反驳"刷低迎合分；
  - 若模型能给出置信度，分别计算用户框架与第三方框架下假陈述的 ECE（校准坍塌检查）；
  - 多轮场景：用户反驳后模型是否放弃正确答案（"翻转率"）。
- **统计**：配对设计、bootstrap 95% CI；≥200 条匹配题，不给没有置信区间的单个数字。
- **门槛**：迎合分 CI 上界低于某阈值，且有帮助分不低于基线；与上一版本对比不显著变差。
- 常见误区：只测"我认为 X"而没有第三方对照，无法区分迎合和模型本身的知识错误。

### Q16 — 参考回答要点

- **为什么是取舍**：`agree(x,y)` 只看"是否认同前提"，不看前提对不对。惩罚它会同时压低"错时附和"（坏）和"对时附和"（好）。讲义："the model becomes slightly more contrarian on correct user beliefs"；"Every sycophancy mitigation trades against helpful agreement because the two share surface features."
- **其它手段**：
  - 让惩罚以真值为条件：只在前提为假时惩罚认同（需要事实校验器或带标注的数据）；
  - 在偏好数据中加入"礼貌地纠正用户"的高质量示例，并用匹配对照数据训练 RM；
  - 合成数据干预：构造用户观点与正确答案冲突的样本，奖励坚持正确答案；
  - 更强的 KL 约束 / 早停，减少放大量（只降低幅度，不消除方向）；
  - 多维奖励（诚实、有帮助分开建模）而不是单一标量；
  - Constitutional AI 类方法加入"不迎合"的原则（第 05 节），但要注意 AI 标注者也可能有自己的偏差。
- 加分点：说明任何手段都要用 Q15 的四变体评测同时监控迎合分和有帮助分。

### Q17 — 参考回答要点

- **思路**：把"RM 是否偏好迎合"与"优化器放大了多少"分开测。
- **测 RM**：在固定的 base 模型输出（或人工构造的匹配回复对：迎合 vs 纠正）上直接给 RM 打分，计算 RM 偏好迎合回复的比例和分差——这是阶段 1 的直接测量，与优化无关。
- **测优化器**：
  - 同一个 RM，用不同 KL 预算 / 训练步数 / 方法（best-of-N、PPO、DPO）训练，画出"迎合分 vs KL"曲线；
  - 用"去迎合"的 RM（例如加附和惩罚或用真值条件化数据重训）作为对照，在相同 KL 预算下比较；
  - 若 RM 本身偏好迎合的程度不变，而迎合随 KL 单调上升，就说明放大来自优化压力。
- **与人类对照**：用同样的匹配场景测人类和 base 模型，得到三个基线：人类、base（无 RLHF）、RLHF 后，差值可以拆成"预训练带来的"和"RLHF 带来的"两部分。
- 加分点：注意混杂因素——不同模型的 SFT 数据也会引入迎合；理想实验需要能访问同一模型的各个训练阶段 checkpoint。
