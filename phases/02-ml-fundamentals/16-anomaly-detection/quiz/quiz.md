## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | 建模"正常"而不是"异常" | 异常极少、类型不断变化，学不出"异常长什么样"；改为刻画正常数据，偏离者即可疑，不需要标签，还能发现新类型的异常 |
| 2 | 三类异常 | 点异常（单个值离谱）、上下文异常（同一个值换个时间/地点才异常）、集体异常（单个都正常，连在一起才异常） |
| 3 | 三种监督设定 | 无监督（全部数据直接拟合）、半监督（只用干净的正常数据拟合，最强）、弱监督（少量标签只用于评估） |
| 4 | Z-score | `\|x−μ\|/σ > 3`；简单、可解释，但假设近似正态；训练数据中的异常会拉偏均值、撑大标准差（masking），多峰数据会失效 |
| 5 | IQR | `[Q1−1.5·IQR, Q3+1.5·IQR]` 之外为异常（箱线图须线）；分位数对极端值稳健；但仍是逐特征判断，发现不了"组合异常" |
| 6 | Isolation Forest | 随机选特征、随机选切分点；异常"少而不同"，更少的切分就能被隔离；`score = 2^(−E[h(x)]/c(ψ))`，接近 1 为异常，约 0.5 为普通 |
| 7 | LOF | 比较一个点与其 k 近邻的局部密度；≈1 正常，明显大于 1 为异常；能处理密度不同的多个簇，但 O(n²)、怕高维 |
| 8 | contamination 只影响阈值 | 它决定"把分数最高的多少比例判为异常"，不改变分数本身；真实异常率未知时直接用分数，按成本自定阈值 |
| 9 | 评估要用对指标 | 0.1% 的异常率下 accuracy 毫无意义，AUROC 也可能好看但不实用；用 Precision@k、AUPRC、固定误报率下的召回 |
| 10 | 阈值是业务决策 | 按误报与漏报的成本比选阈值；注意告警疲劳、分数分布漂移、反馈闭环和可解释性 |

### 核心技能（能动手做到）

- [ ] 实现稳健 Z-score（中位数 + MAD），演示它在训练数据被极端值污染时仍能检出异常
- [ ] 在多峰数据上比较 Z-score / IQR / Isolation Forest，解释为什么逐特征方法会失败
- [ ] 根据误报与漏报成本为检测器选阈值，并画出不同阈值下的 precision / recall

## 五、参考答案与解析

### Q1 — 答案：B

值本身（85%）在历史上很常见，异常之处在于它出现的**上下文**（凌晨、没有流量）。对应讲义 "A temperature of 90 degrees is normal in summer, anomalous in winter"。检测这类异常需要把时间等上下文信息做成特征（例如"同一时段的历史均值"），否则任何只看取值的方法都会认为它正常。集体异常是"单个点都正常、一串连起来才异常"，例如连续 50 次登录失败。

### Q2 — 答案：B

讲义："Semi-supervised. You have a clean dataset of normal data only... This is the strongest setup when possible."。干净的正常数据让检测器学到的"正常"不被异常污染（对比 Q3、Q8 中的 masking 问题）。C 是讲义中"弱监督"的反面：少量标签建议**用于评估**而不是训练，因为太少的异常样本训练出的分类器只认得见过的类型。

### Q3 — 答案：B

这就是讲义中 Z-score 的弱点："the outliers shift the mean and inflate the std, making them harder to detect"，也叫 **masking（掩蔽）**。Q11 中的数据实测：一个 1000 的极端值把标准差撑到约 68.7，原本 6σ 的 10 个异常点 z 值只剩约 0.01，全部漏检。C 说反了：标准差变大会让 z 值变小。

### Q4 — 答案：B

`score = 2^(−E[h]/c(ψ)) = 2^(−1) = 0.5`。`c(ψ)` 是 ψ 个点的二叉搜索树中"不成功查找"的平均路径长度，可以理解为"一个普通点"的期望路径长度。路径明显更短 → 分数接近 1 → 异常；路径更长 → 分数小于 0.5 → 很正常。如果所有点的分数都在 0.5 附近，说明数据里没有明显的异常。

### Q5 — 答案：B

讲义："It does not change the underlying scores."。`contamination=0.05` 与 `0.10` 得到的分数完全相同，只是一个标出前 5%、一个标出前 10%。D 错：真实比例通常未知，讲义建议设成 `"auto"` 直接使用分数，再按误报/漏报成本自己设阈值。

### Q6 — 答案：C

全部预测为"正常"就有 99.9% 的 accuracy，它对检测器好坏没有任何区分能力。A、B、D 都是讲义推荐的指标：Precision@k 对应"分析师每天只能看 k 条告警"的现实约束；AUPRC 关注少数类；固定误报率下的召回对应"可承受的误报量"。

### Q7 — 答案：C

LOF 比较的是一个点与**其邻居**的局部密度。这个点虽然到邻居的绝对距离不大（全局看不突出），但它的邻居都在稠密簇里、密度远高于它自己，LOF 值会明显大于 1。全局 Z-score / IQR 只看每个特征的整体分布，稀疏簇把整体方差撑大后，这个点完全"淹没"在里面；单纯调低阈值只会带来大量误报。

### Q8 — 参考答案

(a)

```
IQR:     labels = [False, False, False, False, True],  scores = [0, 0, 0, 0, 46.5]
Z-score: labels = [False, False, False, False, False]  (100 的 z 值约为 1.9993)
```

IQR 的计算：`np.percentile` 默认线性插值，Q1 = 2、Q3 = 4、IQR = 2，上界 = 4 + 1.5×2 = 7。100 超出上界 93，以 IQR 为单位的分数为 93/2 = 46.5；其余点都在界内，分数为 0。

(b) 均值 = 22，被 100 自己拉高；总体标准差 ≈ 39.0，也被 100 自己撑大。于是 `(100 − 22)/39.0 ≈ 2.0 < 3`。极端值同时"污染"了均值和标准差，等于把尺子换成了被它自己拉长的尺子——这就是 masking。IQR 用分位数，不受这一个点的影响，所以能检出。

(c) 设某个点偏离均值 d，其余 n−1 个点的偏差之和为 −d。由柯西-施瓦茨不等式，其余点的偏差平方和至少为 `d²/(n−1)`（当它们相等时取到）。所以

```
n·σ² = Σ(偏差²) ≥ d² + d²/(n−1) = d²·n/(n−1)
⇒ d²/σ² ≤ n − 1  ⇒ |z| ≤ √(n−1)
```

实测 n = 5 时最大 z 恰好为 2.0，n = 10 时为 3.0（达不到"> 3"）。含义：**样本数 n ≤ 10 时，`threshold=3` 的 Z-score 永远不会报任何异常**，无论那个点有多离谱。小样本时要么用稳健方法（IQR、MAD），要么在"不含待检点"的数据上估计均值和标准差（半监督设定）。

### Q9 — 参考答案

(a) `sample_size = min(256, 525) = 256`，`max_depth = ceil(log₂ 256) = 8`。归一化用 `c(256)`，因为每棵树只在 256 个子样本上建立，路径长度的"参照物"应当是 256 个点的随机二叉树的平均深度；`anomaly_score` 中 `sample_size = min(self.max_samples, self.n_train)` 正是这样计算的。若误用 `c(525) ≈ 11.68`，所有分数都会被系统性抬高。

(b) `score = 2^(−L/10.24)`：

| 平均路径 L | 分数 | 含义 |
|-----------|------|------|
| 4 | `2^(−0.39) ≈ 0.76` | 比普通点少一半以上的切分就被隔离，很可能是异常 |
| 10.24 | `0.5` | 与普通点一样，不突出 |
| 15 | `2^(−1.46) ≈ 0.36` | 比普通点还难隔离，位于稠密区域，非常正常 |

本节 `demo_isolation_forest` 实测：正常点平均分数 0.41，异常点平均分数 0.71。

(c) 树有深度上限 8，到达上限时叶子里可能还有多个点没有被完全隔离。如果只返回 `depth`，所有停在深度 8 的点都会得到同样的路径长度，无法区分"叶子里只剩 1 个点"和"叶子里还挤着 30 个点"。加上 `c(size)` 是对"如果继续切下去，平均还需要多少步才能隔离"的估计：叶子里点越多，说明这片区域越稠密，路径就越长、越正常。这也是原论文的做法，深度上限因此只是节省计算，而不会丢失区分度（对正常点的影响很小，因为我们关心的是路径短的异常点）。

### Q10 — 参考答案

(a) `np.argsort(scores)[-0:]` 中 `-0 == 0`，切片 `[0:]` 取到的是**整个数组**，所以返回的是全部样本中异常的比例，而不是报错或返回 0。例如 `y = [0, 0, 1, 0]` 时 `precision_at_k(y, s, 0)` 返回 0.25。这是 Python 负索引切片的经典陷阱。

(b) 当所有分数并列为 0 时，`argsort` 的"前 k 名"完全由排序算法对并列元素的处理顺序决定，与异常与否无关。0.1000 只是随机抽 20 个点碰到 2 个异常的结果（基础异常率 20/620 ≈ 3%），**不代表 IQR 有任何排序能力**——实测 IQR 在这份数据上的 AUROC 恰好是 0.5。报告 P@k 时应当同时检查分数是否有大量并列。

(c)

```python
def precision_at_k(y_true, scores, k):
    if k <= 0:
        raise ValueError("k must be a positive integer")
    k = min(k, len(scores))
    top_k_idx = np.argsort(-scores, kind="stable")[:k]
    kth = scores[top_k_idx[-1]]
    # 第 k 名的分数如果在前 k 名之外还有并列，前 k 名的组成就取决于排序顺序
    if np.sum(scores == kth) > np.sum(scores[top_k_idx] == kth):
        print(f"warning: ties at the k-th score cross the top-{k} boundary; P@k is order-dependent")
    return np.mean(y_true[top_k_idx] == 1)
```

要点：检查 k 的合法性（k=0 直接报错）；用 `argsort(-scores)[:k]` 表达"降序取前 k"更直观；只有当并列跨越了第 k 名的边界时才提示（更严格的做法是对并列部分按比例计算期望精度）。实测：`y=[0,0,1,0]`、`s=[0.1,0.2,0.9,0.3]` 时 P@1 = 1.0、P@2 = 0.5；全部分数为 0 时会打印警告。

### Q11 — 参考答案

```python
def robust_zscore_detect(X, threshold=3.5):
    med = np.median(X, axis=0)
    mad = np.median(np.abs(X - med), axis=0)
    mad[mad == 0] = 1.0
    z = 0.6745 * np.abs(X - med) / mad
    scores = z.max(axis=1)
    return scores > threshold, scores
```

实测结果：

| 方法 | 标记数 | precision | recall |
|------|-------|-----------|--------|
| `zscore_detect(x, 3.0)` | 1 | 1.00 | 0.09（只抓到 1000） |
| `robust_zscore_detect(x, 3.5)` | 11 | 1.00 | 1.00 |

原因：1000 这个点把均值拉到约 5.09、标准差撑到约 68.7，值为 6 的点 z 只有约 0.01；而中位数和 MAD 都不受少数极端值影响（崩溃点为 50%），值为 6 的点的稳健 z 值约为 6。
- 常数 0.6745 是标准正态分布 75% 分位数，使得在正态数据上 `MAD/0.6745 ≈ σ`，从而稳健 z 与普通 z 的尺度可比；阈值 3.5 是这种修正 z 值的常用经验阈值。
- 它仍然是**逐特征**的方法：在本节的三簇数据上，它的召回只有 0.35，解决不了多峰和组合异常问题。

### Q12 — 参考回答要点

- **区别**：二分类有两类充足的标签，学习决策边界；异常检测通常没有（或极少）异常标签，而且未来的异常可能与过去的完全不同，所以学的是"正常数据的分布/结构"，偏离即可疑。
- **为什么建模正常**：①正常数据多、容易获得；②能发现从未见过的新类型异常；③不需要标签就能上线。代价是误报率更高——"不寻常"不等于"有害"。
- **三种设定**：无监督（全量数据直接拟合，依赖"异常足够少"）、半监督（只用干净的正常数据拟合，最强）、弱监督（少量标签用于评估和选阈值）。
- **少量标签怎么用**：①首先用于评估（P@k、AUPRC）、比较不同检测器、选阈值；②积累到一定数量后，对高优先级的已知类型训练有监督模型，和无监督检测器组合——讲义的观点："unsupervised detection for broad coverage, supervised models for known high-priority anomaly types, and human review for ambiguous cases"。
- **加分点**：提到告警的人工审核结果可以作为反馈，持续积累标签；把异常检测看作"活的系统"。

### Q13 — 参考回答要点

- **原理**：随机选一个特征，在它的 [min, max] 之间随机选一个切分点，递归切分直到每个点被隔离（或到达深度上限）。异常点"少而不同"，位于稀疏区域，随机切几刀就会被单独分出来；正常点挤在稠密区域，需要很多刀。用多棵树的平均路径长度作为度量。
- **分数**：`s(x) = 2^(−E[h(x)]/c(ψ))`，其中 `c(n) = 2H(n−1) − 2(n−1)/n`，`H(i) ≈ ln(i) + 0.5772`（欧拉常数），是 n 个点的二叉搜索树中"不成功查找"的平均路径长度，用来归一化，使不同子样本量下的分数可比。s → 1 为异常，≈ 0.5 为普通，远小于 0.5 为非常正常。
- **为什么子采样**：①速度：每棵树只建在 ψ（默认 256）个点上，深度上限 `⌈log₂ψ⌉`，训练和打分的成本与总样本量几乎无关；②效果：原论文指出子采样能缓解 **swamping**（正常点离异常太近而被误判）和 **masking**（异常太多、聚成一团而相互掩护）；子样本中异常更稀疏，更容易被隔离。
- **局限**：①稠密区域内的异常（masking）难以检测；②大量无关特征时，随机选到有用特征的概率降低，效果变差；③切分平行于坐标轴，对斜向结构不够敏感（后续有 Extended Isolation Forest 等改进）；④对"局部"异常的处理不如 LOF（讲义对比表中标为 "Partially"）。
- **加分点**：能说出 sklearn 的 `score_samples` 返回的是分数的相反数（越小越异常），`decision_function` 在其基础上减去由 `contamination` 决定的偏移量。

### Q14 — 参考回答要点

| 方法 | 假设 / 原理 | 适用 | 不适用 |
|------|-----------|------|-------|
| Z-score | 每个特征近似正态、单峰 | 单指标监控（响应时间、传感器读数），需要强可解释性 | 偏态、多峰、训练数据被污染 |
| IQR | 无分布假设，基于分位数，对极端值稳健 | 单特征、有少量极端值的数据 | 组合异常；分布严重偏态时会在长尾一侧大量误报 |
| Isolation Forest | 异常"少而不同"，容易被随机切分隔离 | 中高维表格数据，速度快，是常用的第一选择 | 稠密区域内的异常、大量无关特征 |
| LOF | 距离有意义，比较局部密度 | 密度不同的多个簇、局部异常 | 大数据（朴素实现 O(n²)）、高维 |

- **组合异常**（每个特征都在正常范围内，但组合起来不正常，例如身高正常、体重正常，但"身高 190cm 体重 40kg"）：逐特征的 Z-score/IQR 必然失效（本节三簇数据上 IQR 召回为 0）。可以用：①多元方法，如马氏距离（考虑协方差）、Isolation Forest、LOF、One-Class SVM；②构造比值/交互特征（如 BMI）；③基于重构误差的方法（PCA、自编码器）。
- **加分点**：讲义的观点"好的特征集比选哪个检测器更重要"；也可以把多个检测器的归一化分数取平均做集成，降低单一方法的误报。

### Q15 — 参考回答要点

1. **数据与特征**：交易金额、商户类别、地点、设备；更重要的是**相对用户自身历史**的特征——金额 / 该用户 30 天平均金额、距上次交易的时间、与上次交易地点的距离/时间（"纽约 → 东京 5 分钟"）、过去 1 小时交易次数。这些滚动特征在线上必须用与训练相同的方式计算，需要缓存足够的历史（讲义 "Feature computation must match"）。
2. **方法**：Isolation Forest 等无监督方法负责广覆盖、发现新型欺诈；在已标注的欺诈上训练有监督模型，负责已知的高优先级类型；可以把多个检测器的分数归一化后集成，最后由规则和人工审核兜底。
3. **训练与打分**：定期（每天/每周）用最近的正常数据批量训练，线上实时打分（"Batch training, online scoring"）。
4. **阈值**：按成本定——漏掉一笔欺诈的损失 vs 分析师审核一笔的成本（或打扰用户的成本）；画出不同阈值下的 precision/recall，叠加成本曲线，取成本最低点；也可以按审核团队的处理能力设定为"每天 top-k 条"。
5. **运营**：
   - 告警疲劳：先用较高阈值，确保告警可信，再逐步放宽；
   - 反馈闭环：记录审核结论（真欺诈/误报），用于评估、调阈值，并逐步积累有监督模型的训练数据；
   - 漂移：监控异常分数分布（如中位数是否上漂）和告警量，定期重训；
   - 可解释性：告警附带原因，例如"金额是该用户平均值的 12 倍"或"该交易平均 3.1 次切分即被隔离，普通交易需要 8.5 次"。
- **加分点**：讨论延迟预算（实时打分必须在毫秒级完成）、冷启动用户（缺少历史，可用同类人群的统计量）、欺诈者的对抗性适应。

### Q16 — 参考回答要点

- **有少量标签时**：用 Precision@k（与"每天审核 k 条"的运营现实一致）、AUPRC、固定误报率（如 1%）下的召回率；按时间切分，在"未来"的数据上评估。
- **几乎没有标签时**：①人工审核每个检测器的 top-k，比较命中率；②在正常数据中注入合成异常，测检出率（注意合成异常不一定像真实异常）；③观察分数分布是否有清晰的长尾；④多个检测器的一致性。
- **为什么 AUROC 可能误导**：AUROC 的横轴是误报率 FPR = FP / 负样本总数。负样本有 100 万个时，FPR = 1% 就意味着 1 万条误报，而异常可能只有 1000 个——ROC 曲线左侧看起来很"高"，实际在任何可用的阈值上 precision 都很低。PR 曲线的 precision = TP / (TP + FP) 直接反映"告警中有多少是真的"，对少数类敏感得多。本节的三簇数据上，Z-score 的 AUROC 有 0.80，看起来还不错，但 AUPRC 只有 0.55，在阈值 3 时召回只有 0.10。
- **常见误区**：报告 accuracy；只报告 AUROC；用全部数据选阈值后在同一份数据上报告指标（相当于在测试集上调参）。
