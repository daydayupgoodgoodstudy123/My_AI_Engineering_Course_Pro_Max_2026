## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | KNN 算法流程 | 算 query 到所有训练点的距离 → 排序 → 取前 K 个 → 分类投票 / 回归取平均 |
| 2 | 惰性学习（lazy learning） | 训练只是"存数据"，所有计算都在预测时：训练 ≈ `O(1)`，每次查询暴力搜索 `O(n·d)` |
| 3 | K 与偏差-方差 | K=1 训练集零误差、高方差；K 增大边界变平滑；K=N 永远预测多数类（最大偏差）；二分类常用奇数 K |
| 4 | 距离度量 | L2 默认；L1 对离群更稳；余弦只看方向（文本/embedding）；Minkowski 统一 L1/L2/L∞，且 `L∞ ≤ L2 ≤ L1` |
| 5 | 特征缩放 | 距离对量纲极敏感，大数值特征会主导距离；必须先标准化，且统计量只能来自训练集 |
| 6 | 距离加权 KNN | 权重 `1/(d + ε)`，近邻说话更有分量，对 K 的选择更不敏感；ε 防止除零 |
| 7 | 维度灾难 | 高维下距离集中（max/min → 1）、邻域体积膨胀；无关噪声维会淹没信号 |
| 8 | KD-tree / Ball tree | 按坐标轴中位数递归切分 + 回溯剪枝，低维平均 `O(log n)`；高维（d > 20 左右）退化到接近暴力 |
| 9 | KNN 与现代 AI | 向量数据库、RAG 检索、推荐"相似物品"本质都是 KNN；大规模用 ANN（HNSW、IVF、PQ） |

## 五、参考答案与解析

### Q1 — 答案：B

惰性学习 = 训练阶段只存数据（本节代码 `fit` 只有两行 `list(X)` / `list(y)`），预测时才计算所有距离。对应的"急切学习（eager）"如线性回归、SVM、神经网络，在训练阶段花大量计算换来紧凑模型、预测很快。C 是 KNN 的一个**后果**（预测慢），不是"lazy"的定义。

### Q2 — 答案：D

K 越大，越多邻居参与平均，预测越平滑、方差越**小**、偏差越大，更容易**欠**拟合；过拟合的是小 K。A 正确：K=1 时每个训练点的最近邻就是它自己（距离 0）。C 正确：K=N 时所有点都参与投票，结果与 query 无关。

### Q3 — 答案：A

`d(A,B) = √(30² + 100²) = √10900 ≈ 104.4`，`d(A,C) = √(1² + 2000²) ≈ 2000.0`。年薪的数值量级把年龄完全淹没：相差 30 岁的 B 反而成了"最近邻"。这正是代码 `demo_scaling_importance` 想说明的问题——标准化后两个特征才能公平地贡献距离（该演示中准确率从 0.875 提升到 0.95）。

### Q4 — 答案：A

`L1 = 3+2+3 = 8`；`L2 = √(9+4+9) = √22 ≈ 4.69`；`L∞ = max(3,2,3) = 3`。D 错在把 L2 的平方当成 L2。p 越大，最大分量差的"话语权"越大，最终 p→∞ 时只剩最大分量。

### Q5 — 答案：A

两向量方向完全相同，`cos = 1`，余弦距离 = 0。余弦距离**忽略长度**：对文本来说，一篇文章和它复制 10 遍的版本"意思一样"，这正是它适合 TF-IDF / embedding 的原因。反过来也要警惕：如果"长度"本身有意义（比如购买金额），余弦会丢掉这部分信息。

### Q6 — 答案：B

在 `[0,1]^d` 均匀分布下，平均距离约为 `√(d/6)`（本节运行结果：d=100 时均值 4.08，恰好 ≈ `√(100/6)`），而标准差基本保持在 0.24 左右不变，于是相对差异越来越小，max/min 从 d=2 时的 44 降到 d=100 时的 1.37。A 正好说反；C 错：所需样本量随维度指数增长，"足够多"在高维几乎不可能；D 错：代码第二部分显示，只有前 2 维有信号时，加到 50 维噪声后准确率从 0.975 掉到约 0.75。

### Q7 — 答案：C

KD-tree 和 Ball tree 都是**精确**算法（A 错，近似的是 HNSW/IVF/LSH 等）。低维时剪枝能排除大部分子树；高维时以 query 为中心、以当前第 k 近距离为半径的球几乎和所有切分超平面相交，剪不掉分支，退化为接近暴力搜索（B 错）。本节实现用的是 L2 距离（D 错）。

### Q8 — 答案：B

KNN 回归的预测是若干训练目标值的（加权）平均，凸组合永远落在 `[min(y), max(y)]` 之内，无法外推。这一点和线性回归截然不同。应用时要注意：时间序列趋势、价格持续上涨等需要外推的问题，KNN 回归天然不合适。

### Q10 — 参考答案

（1）不加权：`votes = {"B": 2, "A": 2}`，平票。`max` 遇到相等的最大值时返回**迭代顺序中第一个**，而 dict 按插入顺序迭代，"B" 先插入（来自最近的那个邻居），所以返回 **"B"**。也就是说，这份实现的平票规则是"谁的最近成员离 query 更近，谁赢"——这是 dict 有序性带来的隐式行为，并非显式设计。

（2）加权：
- B：`1/0.5 + 1/2.0 = 2.0 + 0.5 = 2.5`
- A：`1/1.0 + 1/1.2 ≈ 1.0 + 0.833 = 1.833`

返回 **"B"**。（忽略 `1e-10` 的影响。）

（3）距离为 0 时 `w = 1/1e-10 = 1e10`，这个邻居几乎独占全部票数——query 与某个训练点完全重合时，直接采用该点的标签，这在语义上是合理的。`1e-10` 的作用是防止 `ZeroDivisionError`，讲义中称为 epsilon。

### Q11 — 参考答案

（1）`diff = point[axis] − node.point[axis]` 是 query 到当前切分超平面的**有符号距离**（沿该坐标轴）。`|diff|` 是 query 到"另一侧"任何点的距离下界。如果这个下界都已经不小于当前第 k 近的距离 `best[-1][0]`，另一侧就不可能有更近的点，可以整枝剪掉。

（2）`best` 还没装满 k 个时，`best[-1][0]` 只是"目前找到的最远点"，并不是第 k 近距离的上界。此时如果因为 `abs(diff) >= best[-1][0]` 剪掉另一侧，可能导致最终返回的邻居**少于 k 个**，或者漏掉本应入选的点。所以必须先保证"没装满就一定继续搜"。

（3）结果不会错，但会变慢：当 `diff ≤ 0`（query 在左侧）时，`diff < best[-1][0]` 恒为真，右子树永远不会被剪枝——正确性保持，但剪枝大量失效，而且这种失效在每一层递归都会发生、层层叠加。当 `diff > 0` 时与原逻辑相同。实测（500 个 2D 点、100 次 k=5 查询）：两种写法结果都与暴力搜索一致，但访问的节点数从约 2,600 增加到约 21,000，接近 8 倍。这类"不影响正确性、只影响性能"的 bug 最难通过测试发现，代码里的 "Results match: True" 验证不出来，需要计时或统计访问节点数。

### Q12 — 参考答案

（1）计算 n 个距离 `O(n·d)`，排序 `O(n log n)`，合计 `O(n·d + n log n)`。

（2）用 `heapq.nsmallest`：

```python
import heapq

    def _predict_one(self, x):
        pairs = (
            (self.distance_fn(x, xi), yi)
            for xi, yi in zip(self.X_train, self.y_train)
        )
        neighbors = heapq.nsmallest(self.k, pairs, key=lambda p: p[0])
        if self.task == "classification":
            return self._classify(neighbors)
        return self._regress(neighbors)
```

复杂度变为 `O(n·d + n log k)`。k 很小、n 很大时明显更快；`nsmallest` 返回结果已按距离升序排列，`_classify` 的平票规则不变。

（3）`demo_scaling_importance` 的做法正确：`standardize(X_train)` 得到 `means, stds`，再 `apply_standardize(X_test, means, stds)`。先在全量数据上标准化，相当于让测试集的均值/方差信息"泄漏"进训练过程，评估结果会偏乐观（在这些演示中影响很小，但在小数据或分布漂移场景下可能显著）。生产中用 `Pipeline([StandardScaler(), KNeighborsClassifier()])`，交叉验证时每一折都单独 fit 缩放器。

### Q13 — 参考回答要点

- **复杂度**：训练 `O(1)`（或 `O(n)` 拷贝数据）；暴力预测每次查询 `O(n·d)`，加上选 top-k 的 `O(n log k)`；内存 `O(n·d)`，必须保存全部训练数据。
- **1 亿 × 768 维**：暴力不可行（每次查询约 768 亿次乘加，存储约 300GB float32）。方案：
  - ANN 索引：HNSW（图索引，召回高、内存大）、IVF（先聚类分桶，只搜最近的几个桶）、PQ（乘积量化压缩向量，显著降内存），常用组合如 IVF-PQ；工具有 FAISS、各类向量数据库。
  - 预先归一化，用内积代替余弦；必要时降维或使用量化。
  - 用召回率@k 和延迟 P99 评估，调 HNSW 的 `ef`、IVF 的 `nprobe` 在速度与召回之间折中。
- **加分点**：指出 RAG 检索本质就是 KNN，ANN 的召回损失会直接影响生成质量，所以常配合 rerank。

### Q14 — 参考回答要点

- **维度灾难**：①距离集中：均匀高维数据中，最近与最远距离的比值趋近 1；②体积膨胀：要覆盖固定比例的邻居，邻域半径必须接近整个空间；③数据稀疏：维持同样密度所需样本随维度指数增长。
- **为什么 embedding 仍然有效**：维度灾难的经典结论建立在"各维独立同分布/均匀分布"的假设上。真实 embedding 并非均匀铺满空间，而是集中在**低内在维度**的流形/子空间上，并且是被训练成"语义相近 → 方向相近"的；相关样本之间的距离显著小于无关样本，对比度仍然存在。
- **工程补充**：使用余弦/内积而非原始 L2；通过训练目标（对比学习）显式拉开正负样本；用 ANN 而不是 KD-tree（KD-tree 在几百维已失效）。
- **常见误区**：把"高维"等同于"一定不能用距离"。真正的问题是**无关维度/噪声维度**（本节第二部分实验）和数据分布，而不是维度数字本身。

### Q15 — 参考回答要点

- **定义**：点积 `a·b`；余弦 `a·b/(‖a‖‖b‖)`；欧氏 `‖a−b‖`。
- **等价条件**：向量都 L2 归一化后，`‖a−b‖² = 2 − 2·a·b`，三者给出**完全相同的排序**。
- **怎么选**：
  - 文本 / 句向量 embedding：余弦（或先归一化再用内积，最快）。
  - 长度有意义（如推荐中的热度、置信度）：原始点积（MIPS）。
  - 低维数值特征、需要满足三角不等式（KD-tree/Ball tree、聚类）：欧氏或 L1。
- **加分点**：检索时用的相似度要与 embedding 模型训练时的相似度一致；余弦距离 `1 − cos` 不满足三角不等式，不能直接用于依赖度量公理的树结构。

### Q16 — 参考回答要点

- **预处理**：数值特征标准化（只在训练集 fit）；类别特征 one-hot 或专门的距离；处理缺失值；去掉无关/噪声特征（KNN 对此极敏感），必要时 PCA 降维。
- **选 K**：交叉验证网格搜索（如本节 `demo_k_selection` 的 5 折 CV）；二分类用奇数；经验起点 `√N`。注意 CV 结果中多个 K 并列时，选更大的 K 往往更稳（方差小）。
- **距离度量**：按数据类型选（见讲义表格），同样可以纳入 CV。
- **加权**：数据密度不均、K 较大时加权通常更稳；本节回归实验中，不加权 MSE 随 K 从 0.022 恶化到 0.073，加权始终在 0.024～0.029 之间。
- **常见误区**：在全量数据上做缩放再 CV（数据泄漏）；只看准确率而忽略类别不平衡（多数类会主导投票）。

### Q17 — 参考回答要点

- **表示**：价格做对数 + 标准化；类目 one-hot 或学习到的 embedding；文本描述用句向量 embedding；图片用视觉模型 embedding。
- **距离组合**：各模态分别归一化，再加权拼接或对各自相似度加权求和（混合类型数据需要自定义距离，讲义称为 "Custom distance"）；权重通过离线指标（点击率、人工标注相关性）调。
- **检索**：商品量大时离线建 ANN 索引，在线只查 top-k；可先按类目过滤再做向量检索。
- **坑**：①某个模态的数值尺度主导距离（缩放问题的翻版）；②热门商品"枢纽化"（hubness，高维中少数点成为大量 query 的近邻）；③新品冷启动没有行为数据，只能依赖内容特征；④只按相似度推荐会缺乏多样性，需要重排。
- **加分点**：提到离线评估（召回率、NDCG）与线上 A/B 测试结合。

### Q18 — 参考回答要点

| 方法 | 原理 | 适用 |
|------|------|------|
| 暴力搜索 | 计算到所有点的距离 | n 小，或维度很高；可向量化/GPU 加速，结果精确 |
| KD-tree | 按坐标轴中位数切分 + 回溯剪枝 | 低维（讲义：d > 20 左右开始退化） |
| Ball tree | 嵌套超球体 + 三角不等式剪枝 | 中等维度（讲义：约 50 维以内），非轴对齐结构 |
| HNSW / IVF / PQ | 近似搜索：图导航 / 倒排分桶 / 量化压缩 | 百万～十亿级、几百维的 embedding 检索 |

- **为什么高维退回暴力**：高维中树的剪枝几乎失效，还要承担建树和树遍历的额外开销，不如一次矩阵运算算完所有距离（可以利用 BLAS 的高度优化）。讲义也提到 sklearn 会根据数据规模与维度自动选择，可通过 `algorithm` 参数控制。
- **加分点**：精确 vs 近似的取舍——ANN 用少量召回损失换取数量级的速度提升；KD-tree 依赖坐标轴切分，Ball tree 依赖三角不等式，所以两者都要求距离是真正的度量。
