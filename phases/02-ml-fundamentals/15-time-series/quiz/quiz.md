## 一、学完本节你应该掌握

### 核心知识点

| # | 知识点 | 一句话要点 |
|---|--------|-----------|
| 1 | 时间序列不满足 i.i.d. | 样本之间不独立（今天依赖昨天）、分布也不恒定（12 月和 3 月不一样），打乱顺序就毁掉了信号 |
| 2 | 趋势 / 季节性 / 残差 | 观测值 = 长期方向 + 固定周期的重复模式 + 剩余噪声；残差像白噪声说明分解抓住了信号 |
| 3 | 平稳性与差分 | 均值、方差、自相关结构不随时间变化才叫平稳；一阶差分 `y[t]−y[t−1]` 去掉线性趋势，二阶差分去掉二次趋势；ADF 检验的原假设是"非平稳" |
| 4 | ACF / PACF | ACF 是序列与自身滞后 k 步的相关；在季节周期处出现尖峰；PACF 去掉了更短滞后的间接影响 |
| 5 | 滞后特征 | 用 `y[t−1], …, y[t−k]` 作为特征预测 `y[t]`，把时间序列变成普通的监督回归问题 |
| 6 | 目标对齐陷阱 | 所有特征只能用 t−1 及更早的信息；把 t 时刻的值（或包含它的滚动统计）放进特征，会得到一个"完美"但毫无用处的模型 |
| 7 | Walk-forward 验证 | 训练集永远早于测试集；expanding window 用全部历史，sliding window 用固定长度的最近历史 |
| 8 | AR 与 ARIMA | AR(p) 就是对 p 个滞后值做线性回归；ARIMA(p, d, q) = 自回归 + d 次差分 + 过去 q 个预测误差 |
| 9 | 多步预测策略 | 递归（用预测值继续预测，误差累积）、直接（每个步长一个模型）、多输出（一个模型同时输出所有步长） |
| 10 | 基线与指标 | 必须先打败 persistence（明天=今天）、seasonal naive、移动平均；MAE / RMSE / MAPE（真值为 0 时无定义） |

## 五、参考答案与解析

### Q1 — 答案：B

单个样本的特征确实只用了过去的值，但**样本与样本之间**仍有时间顺序。随机划分后，测试样本 t 的前后邻居（t−1、t+1 …）大多在训练集中，模型在相邻时刻上学到的局部水平几乎可以直接"抄"给 t，相当于做插值而不是外推。本节 `demo_random_vs_walk_forward` 实测：随机 80/20 的 MSE 为 5.92，walk-forward 为 9.41，随机切分低估了约 37% 的误差。D 错：特征值本身不会变，变的是"训练集包含了什么时间段"。

### Q2 — 答案：B

白噪声的均值、方差恒定，任意非零滞后的自相关为 0，是最典型的平稳序列。A 随机游走的方差随时间线性增长（一阶差分后才平稳）；C 的均值随时间变化；D 的方差随时间变化。

### Q3 — 答案：C

一阶差分 `[2, 4, 6, 8]` 仍在线性增长，二阶差分为常数 `[2, 2, 2]`，说明原序列是二次多项式趋势（讲义原例）。线性趋势一阶差分就是常数；指数趋势无论做多少次差分都不会变成常数，通常先取 log 再做差分。

### Q4 — 答案：A

7 的整数倍处出现尖峰是周度季节性的标志，正好对应讲义 "If there is weekly seasonality, include lag 7 (and possibly 14)"。本节 `demo_autocorrelation` 中周期为 7 的序列在差分后，ACF 在 lag 7、14 处约为 0.68 和 0.67。D 错：滞后越多，特征越多，过拟合风险越大，应根据 ACF/PACF 选出有用的滞后，而不是无限增加。

### Q5 — 答案：B

ARIMA(p, d, q)：p 是自回归阶数（用过去 p 个观测值），d 是差分次数，q 是移动平均阶数（用过去 q 个预测误差）。A 对应 q，C 对应 p。

### Q6 — 答案：B

讲义："Use sliding when the world changes and old data hurts"，以及 "Beware of regime changes ... use a sliding window that forgets old data"。也可以加入"变化前/后"的指示特征。C 违反时间顺序；A 会让旧模式持续干扰。

### Q7 — 答案：C

递归：预测 t+1，把预测值放回历史再预测 t+2 …，误差会叠加；直接：为每个步长 h 训练一个模型，没有误差累积，但每个模型彼此独立；多输出：一个模型同时输出所有步长。A 和 B 把递归与直接说反了。

### Q8 — 参考答案

```
[[12. 10.]
 [14. 12.]
 [13. 14.]]
[14. 13. 15.]
[2. 2. 2.]
```

- `make_lag_features` 中 `X[lag:, lag - 1] = series[:-lag]`：第 0 列是 lag 1，第 1 列是 lag 2。所以每行是 `[lag_1, lag_2]`，**最近的值在最前面**；讲义表格的列顺序是 `lag_2 | lag_1`，最近的值在最后，两者正好相反。
- 前 2 行因为存在 NaN 被 `valid_mask` 丢掉，所以 5 个点只剩 3 个样本，目标是 `s[2:] = [14, 13, 15]`。
- 列顺序本身不影响模型，但**训练和预测必须一致**——这正是 Q10 中 `[::-1]` 存在的原因。

### Q9 — 参考答案

(a) `step = max(1, (23 − 10) // 3) = 4`：

```
10 10 14
14 14 18
18 18 22
```

即训练 `[0, 10)` 测试 `[10, 14)`；训练 `[0, 14)` 测试 `[14, 18)`；训练 `[0, 18)` 测试 `[18, 22)`。

(b) 下标 22 的样本永远不会被测试。原因是整除 `13 // 3 = 4` 丢掉了余数 1，最后一折的 `test_end = 18 + 4 = 22`。一般地，最后 `(n_samples − min_train) % n_splits` 个样本不会被评估——而这恰恰是**最新**、最接近上线场景的数据。（在 `demo_walk_forward` 中 `(390 − 100) % 5 = 0`，所以碰巧没有丢失。）

(c) 让最后一折吃掉余数：

```python
        test_end = n_samples if i == n_splits - 1 else min(train_end + step, n_samples)
```

这与第 13 节 `cross_validate_pipeline` 中 "最后一折 `val_end = n`" 的处理方式相同。

### Q10 — 参考答案

(a) `history[-self.n_lags:]` 按时间顺序排列，**最旧的在前、最新的在后**；而训练时 `make_lag_features` 的第 0 列是 lag 1（最新）。`[::-1]` 把它反转成 `[y[t−1], y[t−2], …, y[t−p]]`，与训练特征的列顺序一致，学到的权重 `weights[0]`（lag 1 的权重）才会乘到最新的值上。可以这样验证：`forecast` 第 1 步的结果与 `ar.predict(make_lag_features(series[:251], 10)[0][-1:])` 完全相等（实测都是 71.44）。

(b) 去掉之后，权重和特征错位，模型仍然能输出数字、不会报错，但结果是错的。实测：第 1 步预测从 71.44 变成 58.54（真实值 68.64）；20 步 MSE 从 54.57 变成 116.35，翻了一倍多。这类"静默错误"是时间序列代码最危险的 bug。

(c) `self.predict` 里是 `X @ self.weights`，期望输入是二维的 `(样本数, 特征数)`。`reshape(1, -1)` 把一维的 p 个值变成形状 `(1, p)` 的"一行样本"，`-1` 让 NumPy 自动推断列数；返回的是长度为 1 的数组，所以后面要取 `[0]`。

### Q11 — 参考答案

(a) `check_stationarity` 的滚动窗口是 `series[start:i + 1]`，**包含第 i 个点自己**。所以 `rm[t]` 是 `y[t−4..t]` 的平均值，里面就有目标 `y[t]`。模型很快找到了一个精确解：

```
y[t] = 5·rm[t] − y[t−1] − y[t−2] − y[t−3] − y[t−4]
```

实测拟合出的权重正是 `[-1, -1, -1, -1, 0, …, 0, 5]`，偏置为 0，MSE ≈ 1e−25。这就是讲义的 "target alignment trap"：一个"完美的预测器"，上线后完全没用，因为预测时刻根本拿不到 `y[t]`。

(b) 用到 t−1 为止的滚动均值，也就是整体后移一位：

```python
X_new = np.column_stack([X, rm[9:-1]])      # rm[t-1] = mean(y[t-5 .. t-1])
```

(c) 修正后 MSE 回到约 9.41，与只用滞后特征**完全相同**。因为 `mean(y[t−5..t−1])` 恰好是现有 lag 1~lag 5 的线性组合，对线性模型来说是完全共线的冗余特征，不提供任何新信息。滚动统计对树模型（无法自己做线性组合）或者窗口长度超过最大滞后时才有增益。

### Q12 — 参考回答要点

- **为什么不能 K 折**：K 折假设样本可交换（i.i.d.）。时间序列有自相关，随机分折后训练集中有测试时刻之后的数据，模型用"未来"预测"过去"，或者借相邻时刻插值，评估结果虚高；并且会掩盖分布随时间漂移带来的性能下降。
- **walk-forward**：按时间排序；用 `[0, t)` 训练、`[t, t+h)` 测试；向前滑动 t，重复若干次，取平均。每折的测试集都严格晚于训练集，模拟"上线后每隔一段时间重训一次"。对应 sklearn 的 `TimeSeriesSplit`。
- **expanding vs sliding**：旧数据仍然有代表性、数据量少 → expanding；存在结构变化、旧数据有害、或者训练成本需要固定 → sliding。也可以用 expanding 加时间衰减的样本权重作为折中。
- **加分点**：
  - 当特征使用了未来 k 步的标签（例如目标是"未来 7 天销量之和"）时，训练集末尾与测试集开头会有重叠，需要在两者之间留出 **gap**（sklearn `TimeSeriesSplit(gap=...)`）；
  - 测试折的长度应当与真实的预测周期一致，并至少覆盖一个完整的季节周期（讲义 Practical Tips 第 3 条）。

### Q13 — 参考回答要点

- **定义**：（弱）平稳 = 均值、方差恒定，且自协方差只依赖滞后 k、不依赖时间 t。
- **为什么重要**：模型从历史中学到的统计规律要能用于未来，前提是这些规律不随时间变化；AR/ARMA 类模型的理论性质也建立在平稳性上。均值漂移的序列，用一月份数据训练的模型在二月份会出现系统性偏差。
- **检验**：画图看趋势和方差；滚动均值/滚动标准差是否漂移（本节 `check_stationarity` 还用了"前后两半的均值差 < 0.5 倍标准差、方差比 < 2"的经验规则）；ADF 检验（原假设：存在单位根、非平稳；p < 0.05 则拒绝原假设）；也可以配合 KPSS 检验（原假设相反：平稳）。
- **处理**：一阶差分去线性趋势、季节差分 `y[t] − y[t−s]` 去季节性、log 变换稳定方差（乘法型模式变加法型）、去趋势（减去拟合的趋势线）。
- **副作用**：过度差分会引入人为的负自相关、放大噪声（白噪声差分后方差翻倍，lag 1 的自相关变成 −0.5）；差分后的模型预测的是"变化量"，需要累加还原，误差也会累积。因此讲义里"差分从不有害"的说法需要谨慎看待，应当按检验结果决定差分次数。
- **常见误区**：认为"去掉趋势就平稳了"——方差变化、季节性同样会破坏平稳性。

### Q14 — 参考回答要点

1. **目标对齐与泄漏**：所有滞后/滚动特征都必须先 shift，只用 t−1 及更早的信息；审查每个外部特征在预测时刻是否真的可得（例如未来的促销计划通常是已知的，未来的天气只能用预报值）。
2. **树模型不会外推趋势**：回归树的预测是叶子节点内训练目标的平均；输入一旦超出训练时见过的范围，树（以及 GBDT 中多棵树之和）给出的都是常数，无法沿着趋势继续外推。序列有上升趋势时，GBDT 会把未来"压平"在历史高位附近。常用的处理方法是预测差分值或比率（`y[t]/y[t−7]`），或先去趋势再建模，或者与线性模型组合。
3. **验证方式**：walk-forward / `TimeSeriesSplit`，测试窗口长度等于预测周期，必要时留 gap。
4. **多步预测**：如果要预测未来 14 天，第 10 天的 lag 1 在预测时刻是未知的——要么递归填入预测值，要么为每个步长构造只使用"预测时刻已知"信息的特征（直接策略）。
5. **特征**：lag 1、lag 7、lag 14（来自 ACF），滚动均值/标准差（窗口 7、28，注意 shift），日历特征（周几、月份、节假日、发薪日），价格/促销等外部变量。
6. **基线**：先算 persistence 和 seasonal naive；本节数据上 persistence 的 walk-forward MSE 约为 10.3，AR(10) 约为 9.4，提升并不大——打不过基线说明有 bug 或者序列本身不可预测。
7. **尺度**：销量右偏时对 log1p 后的目标建模；多个商品的量级不同时考虑按商品归一化，或者训练一个跨商品的全局模型。

### Q15 — 参考回答要点

1. **先画图、先做基线**：看趋势、周/年季节性、节假日、异常值、结构断点；建立 persistence、seasonal naive（上周同一天）、7 日移动平均三个基线，并记录它们在验证集上的指标。
2. **特征**：滞后（按预测步长调整：若用直接策略，预测第 h 天时只能用 lag ≥ h 的值）、滚动统计（shift 后）、日历特征（周几、是否节假日、节前节后）、已知的未来信息（促销日历、营销活动）。
3. **模型**：从"滞后特征 + 梯度提升"或线性模型起步；如有趋势，预测差分值或比率；必要时与统计模型（ETS / ARIMA）或 Prophet 做对比或融合。
4. **验证**：walk-forward，每折测试 14 天，至少覆盖若干个完整周（最好也覆盖节假日）；超参调优只在训练折内部进行。
5. **多步策略**：14 天属于较长的预测周期，可以用直接策略（14 个模型，或把"步长 h"作为特征的单一模型），或者多输出模型；也可以与递归策略比较。
6. **指标**：MAE（业务易解释）、RMSE（关注大误差）、MAPE（注意订单量为 0 的日期无定义，可改用 WAPE = Σ|误差| / Σ真实值）；按步长分别报告误差，通常第 1 天最准、第 14 天最差；需要备货时还要给出预测区间。
7. **上线**：每天滚动预测；监控滚动误差、特征分布和与基线的差距；误差上升或出现结构变化时重训（可以用 sliding window）；按固定周期自动重训，并保留随时回滚到上一版本的能力。

### Q16 — 参考回答要点

- **原因**：递归预测第 h 步时，输入里有 h−1 个是**模型自己的预测值**，它们带着误差。第 1 步的误差进入第 2 步的输入，第 2 步的误差又进入第 3 步……误差层层叠加；如果模型略有偏差（例如均值回归的方向不对），预测轨迹会系统性地偏离真实轨迹。
- **本节观察**：`demo_forecasting` 中，前 6 步的误差在 ±5 以内（第 6 步只有 +0.12），但从第 10 步开始误差基本在 +5 以上，第 17 步达到 +15.27。预测曲线在 44 附近"走平"，而真实序列已经随正弦周期回升到 60 左右——递归的 AR 模型逐渐失去了对周期的跟踪。20 步 MSE 为 54.6，而 walk-forward 一步预测的 MSE 只有 9 左右。
- **替代方案**：
  - **直接策略**：每个步长一个模型，没有误差累积；代价是训练 H 个模型，彼此不共享信息，步长越远可用的特征越少；
  - **多输出**：一个模型输出 H 个值，共享表示；需要支持多输出的模型或自定义损失；
  - **混合（DirRec 等）**：直接策略的模型也把前面步长的预测作为输入。
- **讲义建议**：短期（1–5 步）先用递归，长期用直接。
- **加分点**：在训练时把"模型自己的预测"作为输入一起训练，可以缓解训练与推理时的输入分布不一致（思路类似序列模型中的 scheduled sampling）；报告误差时要按步长分别给出。
